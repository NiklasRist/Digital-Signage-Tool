### Issue M7-13: [queue-panel] Die eingeklappte Zeile

## Ziel (in einem Satz)
Die Warteschlangen-Leiste sagt im eingeklappten Zustand in **einer** Zeile, was gerade los ist –
„Render läuft · 3 von 7", „2 fehlgeschlagen", „Warteschlange leer" oder ausdrücklich „noch nicht
geladen" –, und hebt sich hervor, wenn ein Auftrag fehlgeschlagen ist, ohne von selbst aufzuklappen.

## Modul & Datei
- Modul: `queue-panel` (Renderer)
- Dateien dieses Issues (+ zugehörige Testdateien):
  - `src/renderer/queue-panel/leiste-zusammenfassung.ts` – die **reine** Ableitung
    (ohne React, ohne JSX, vollständig ohne Browser prüfbar)
  - `src/renderer/queue-panel/leiste-zeile.tsx` – die Darstellung; so wenig Logik wie möglich
- Vertrag: Technisches Konzept **9.14.1** (Grundstruktur: Modus-Reiter + Warteschlangen-Leiste),
  **9.14.2** (Invarianten), **9.3.1** (der `Auftrag` und seine Felder), **9.3.3** (Zustände) –
  Quelle der Wahrheit
- Prozess/Speicher: P6 mittelbar; **kein** Zustand, **keine** IPC-Aufrufe, **kein** Abonnement

## Warum das im Gesamtsystem wichtig ist
Die eingeklappte Zeile ist im Regelbetrieb die **einzige** sichtbare Rückmeldung des ganzen
Auftragswesens: Sie ist in jedem Reiter zu sehen (TK 9.14.2) und beantwortet die Frage „passiert
gerade etwas?" ohne einen Klick. FA-16 verlangt genau das.

Der teuerste lokale Fehlgriff wäre eine Zeile, die **lügt, indem sie schweigt**. Wenn der Bestand
noch nicht geholt wurde (M7-12 liefert dann `{ zustand: 'unbekannt' }`), sieht „Warteschlange leer"
für den Nutzer genauso aus wie „alles erledigt" – und ein gestern gescheiterter Render, der
persistent in Q2 liegt (TK 9.3.5), wäre für ihn nicht existent. Deshalb muss der Zustand
*unbekannt* eine **eigene**, sichtbar andere Zeile bekommen und darf nicht mit „leer"
zusammenfallen.

Der zweitteuerste: eine Zeile, die selbst rechnet. Wer hier aus `Auftrag[]` einen zweiten
Fortschrittswert ableitet, einen eigenen Statusbegriff erfindet oder die Liste umsortiert, hat eine
zweite Wahrheit neben `Auftrag.status`/`Auftrag.fortschritt` – und die beiden laufen auseinander,
sobald ein Randfall auftritt (z. B. `fortschritt: null`).

## Signatur (verbindlich – NICHT ändern)
```ts
// src/renderer/queue-panel/leiste-zusammenfassung.ts
import type { Auftrag } from '../../shared/contracts/auftrag'
import type { AuftragsSicht } from './auftrags-sicht'

/** Wie die Leiste optisch auftreten soll. `hervorgehoben` = es gibt mindestens einen Fehlschlag. */
export type LeistenTon = 'ruhig' | 'aktiv' | 'hervorgehoben' | 'unbekannt'

export interface LeistenZusammenfassung {
  /** Die eine Zeile, fertig zusammengesetzt. Nie leer. */
  text: string
  ton: LeistenTon
  /** Fortschritt des laufenden Auftrags, 0–100, oder null (unbestimmt bzw. nichts laeuft). */
  fortschritt: number | null
  /** Anzahl der anstehenden Auftraege (ohne den laufenden). */
  anstehend: number
  /** Anzahl der fehlgeschlagenen Auftraege. */
  fehlgeschlagen: number
  /** Der laufende Auftrag, falls einer laeuft – fuer das Label der Zeile. */
  laufender: Auftrag | null
}

export function fasseZusammen(sicht: AuftragsSicht): LeistenZusammenfassung
```

**ENTSCHIEDEN – die Zeile bekommt die `AuftragsSicht`, nicht `Auftrag[]`.** Nur so kann sie den
Zustand *unbekannt* überhaupt darstellen. Ein Parameter `auftraege: Auftrag[]` hätte für
„noch nicht geholt" und „nichts da" **denselben** Wert (`[]`) – genau die Verwechslung, die
Invariante 1 dieses Meilensteins verbietet.

**ENTSCHIEDEN – die Textbausteine (verbindlich, damit nicht drei Issues drei Formulierungen
erfinden).** `fasseZusammen` setzt den Text nach genau dieser Kaskade zusammen; die Teile werden
mit ` · ` (Leerzeichen, Mittelpunkt U+00B7, Leerzeichen) verbunden:

| `sicht.zustand` | Bedingung | `text` | `ton` |
|---|---|---|---|
| `unbekannt` | – | `Warteschlange wird geladen …` | `unbekannt` |
| `fehler` | – | `Warteschlange nicht lesbar` | `hervorgehoben` |
| `geladen` | ein Auftrag mit `status: 'laeuft'` | `<label des laufenden>` + bei `fortschritt !== null` ` · <fortschritt> %` + bei `anstehend > 0` ` · <anstehend> in der Warteschlange` + bei `fehlgeschlagen > 0` ` · <fehlgeschlagen> fehlgeschlagen` | `hervorgehoben`, wenn `fehlgeschlagen > 0`, sonst `aktiv` |
| `geladen` | keiner läuft, `anstehend > 0` | `<anstehend> in der Warteschlange` + bei `fehlgeschlagen > 0` ` · <fehlgeschlagen> fehlgeschlagen` | `hervorgehoben`, wenn `fehlgeschlagen > 0`, sonst `aktiv` |
| `geladen` | keiner läuft, `anstehend === 0`, `fehlgeschlagen > 0` | `<fehlgeschlagen> fehlgeschlagen` | `hervorgehoben` |
| `geladen` | Liste enthält keinen dieser Fälle | `Warteschlange leer` | `ruhig` |

Der Beispieltext aus TK 9.14.1 („Render läuft · 3 von 7") ist damit abgedeckt: `label` des
laufenden Render-Auftrags, gefolgt von Prozent und Anzahl. Das `label` wird **übernommen, nicht
gebaut** – es kommt fertig aus dem Main („UI-Klartext, z. B. „Import: sommer-aktion.mp4"", TK 9.3.1).

**Zählweise (verbindlich):** `anstehend` = Anzahl der Aufträge mit `status: 'anstehend'`;
`fehlgeschlagen` = Anzahl mit `status: 'fehlgeschlagen'`. `erfolg` und `abgebrochen` werden **nicht**
gezählt und erscheinen in der Zeile **nicht**. `laufender` = der **erste** Auftrag mit
`status: 'laeuft'`; es kann nach TK 9.3.5 nur einen geben („höchstens **ein** Auftrag in
`laeuft`"), und wären es wider Erwarten zwei, gewinnt der erste – **ohne** Ausnahme und **ohne**
eigene Fehlermeldung (die serielle Invariante zu überwachen ist nicht Aufgabe der Anzeige).

**Fremde Typen, die du benutzt** – vollständig ausgeschrieben, du siehst die anderen Issues nicht:

```ts
// M7-12 – src/renderer/queue-panel/auftrags-sicht.ts (DEFINIERENDE QUELLE)
export type AuftragsSicht =
  | { zustand: 'unbekannt' }

// #16 – src/shared/contracts/auftrag.ts (Ausschnitt)
export type AuftragArt = 'import' | 'loeschen' | 'render' | 'export'
export type AuftragStatus = 'anstehend' | 'laeuft' | 'erfolg' | 'fehlgeschlagen' | 'abgebrochen'
export type Auftrag =
  | { auftragId: string; art: 'import'; status: AuftragStatus; label: string;
      payload: ImportRequest; fortschritt: number | null; versuche: number;
      fehler: { code: string; meldung: string; daten?: unknown } | null;
      ergebnis: unknown | null; erstelltAm: string }
  | { /* … 'loeschen' | 'render' | 'export' – gleicher Aufbau, andere payload … */ }
```

**MELDE-KLAUSEL (bindend).** Weicht eine dieser Signaturen von der tatsächlichen Fassung der
definierenden Datei ab, ist das ein **Vertragsfehler** – **melden, NICHT eigenmächtig anpassen.**

## Eingang → Ausgang
| Eingang | Bedeutung | Grenzen/Validierung |
|---|---|---|
| `sicht` (`fasseZusammen`) | der volle Zustand aus M7-12 | alle drei Varianten müssen behandelt sein; keine wirft |
| `sicht` (`LeisteZeile`) | dasselbe, unverändert durchgereicht | die Komponente ruft `fasseZusammen` und stellt dar |
| `aufgeklappt` | ob die volle Liste (M7-14) gerade sichtbar ist | wirkt **nur** auf die Richtung des Klapp-Sinnbilds und die Beschriftung des Schalters |
| `aufKlappenUmschalten` | meldet den Klapp-Wunsch nach oben | die Komponente hält den Klappzustand **nicht** selbst (s. STOPP) |

Ausgang `fasseZusammen`: eine vollständig belegte `LeistenZusammenfassung`; `text` ist **nie**
leer.
Ausgang `LeisteZeile`: ein `JSX.Element` – **eine** Zeile, die die Zusammenfassung zeigt und den
Klapp-Schalter trägt.
Ausgang bei Fehler: **keiner**. Beide Funktionen werfen nie und tragen keine `Ergebnis`-Hülle;
sie überqueren keine IPC-Grenze.

## Verbindliche Invarianten (wörtlich – Verletzung = Issue nicht erfüllt)
- „**Die Warteschlangen-Leiste ist in *jedem* Reiter sichtbar.** Sie ist die einzige Stelle, an der
  laufende, anstehende und fehlgeschlagene Aufträge erkennbar sind (FA-16) – sie darf nie hinter
  einem Moduswechsel verschwinden. Eingeklappt zeigt sie den Zustand in einer Zeile, aufgeklappt
  die volle Liste (9.3.4)." (TK 9.14.2)
- „queue-panel als schmale Leiste: „Render läuft · 3 von 7"  ▸ aufklappbar" (TK 9.14.1) – der
  Beispieltext, an dem sich die Zeile misst.
- „**Seriell:** höchstens **ein** Auftrag in `laeuft`." (TK 9.3.5) – deshalb gibt es genau **einen**
  `laufender`, nicht eine Liste.
- „| `label` | UI-Klartext, z. B. „Import: sommer-aktion.mp4" | Anzeige im `queue-panel` |"
  (TK 9.3.1) – das Label wird **übernommen**, nicht in dieser Datei zusammengesetzt.
- „| `fortschritt` | 0–100 oder `null` | grober Fortschritt (bei `render` aus `RenderProgress`,
  9.2.7); `null` wo unbestimmt |" (TK 9.3.1) – `null` heißt **unbestimmt** und wird als „kein
  Prozentwert" dargestellt, **nicht** als 0 %.
- „Zu jedem Zeitpunkt ist erkennbar, welcher Auftrag gerade läuft, welche anstehen und welche
  fehlgeschlagen sind (jeweils mit Klartext-Bezeichnung, bei Fehlern mit Fehlergrund)."
  (Anforderungsdokument 4.3, FA-16) – die drei Zahlen der Zeile bedienen den ersten Teil; der
  **Fehlergrund** steht in der aufgeklappten Liste (M7-14/M7-18), nicht in der einen Zeile.
- **Invariante 1 des Meilensteins (bindend, ausgeschrieben):** Kein Ereignis heißt „Zustand
  unbekannt", nicht „alles in Ordnung". `{ zustand: 'unbekannt' }` bekommt deshalb **eigenen** Text
  und **eigenen** Ton und wird **nie** auf „Warteschlange leer" abgebildet.
- **ENTSCHIEDEN aus dem M7-Zuschnitt (bindend):** Die Warteschlangen-Leiste klappt bei einem
  Fehlschlag **nicht** automatisch auf, sondern **hebt sich hervor**. Ein automatisches Aufklappen
  nähme dem Nutzer mitten in der Arbeit die Fläche weg und wäre nicht rückgängig zu machen, ohne
  dass er den Fehler gesehen hat; die Hervorhebung erreicht dasselbe, ohne ihn zu unterbrechen.
  Deshalb gibt es den Ton `hervorgehoben` – und **keinen** Aufruf von `aufKlappenUmschalten` aus
  dieser Komponente heraus, der nicht vom Nutzer ausgelöst wurde.

## Fehlerpfade (vollständig)
| Situation | Code | Verhalten |
|---|---|---|
| `sicht.zustand === 'unbekannt'` | – | eigene Zeile „Warteschlange wird geladen …", Ton `unbekannt`; **nicht** „leer" |
| `sicht.zustand === 'fehler'` | – | Zeile „Warteschlange nicht lesbar", Ton `hervorgehoben`; die technische `meldung` erscheint **nicht** in der einen Zeile (sie gehört in die aufgeklappte Liste, M7-14/M7-18) |
| `auftraege` ist leer | – | „Warteschlange leer", Ton `ruhig` |
| `laufender.fortschritt === null` | – | **kein** Prozentteil im Text; **kein** Ersatzwert 0 |
| `fortschritt` außerhalb 0–100 | – | auf 0–100 klemmen, **kein** Fehler, **keine** Meldung – die Anzeige ist nicht der Ort, an dem ein Vertragsbruch des Senders auffällt |
| Zwei Aufträge mit `status: 'laeuft'` | – | der **erste** gewinnt; keine Ausnahme, keine Sondermeldung |
| unbekannter `status`-Wert | – | zählt weder als anstehend noch als fehlgeschlagen und ist **nicht** `laufender`; **kein** `throw` |

Es gibt in diesem Issue **keinen** Fehlercode: Beide Funktionen sind rein und überqueren keine
IPC-Grenze.

## Nicht selbst entscheiden – STOPP und fragen
- **Verbot – kein eigener Klappzustand.** `aufgeklappt` kommt als Parameter herein und wird über
  `aufKlappenUmschalten` nach oben gemeldet. Diese Komponente hält ihn **nicht** in einem
  `useState`. Begründung: Der Klappzustand hat zwei benannte Besitzer, und keiner davon ist diese
  Datei. Zur **Laufzeit** hält ihn die Modul-Wurzel des `queue-panel` (**M7-66**) – die Leiste ist
  **eine** Instanz im Rahmen (TK 9.14.2, M7-02), und ein zweiter Halter ließe sie beim
  Reiterwechsel zuklappen. Über die **Sitzung** hinweg merkt ihn M7-03 unter dem Schlüssel
  `'queue-panel.aufgeklappt'` (`leseQueueAufgeklappt` / `merkeQueueAufgeklappt`, exportierte
  Konstante `UI_SCHLUESSEL_QUEUE_AUFGEKLAPPT`); M7-03 ist die einzige Stelle der Shell, die eine
  UI-Voreinstellung schreibt. Diese Datei kennt weder den Schlüssel noch eine der beiden
  Funktionen.
- **Verbot – kein Beschaffen von Daten.** Kein `rufeAuf`, kein `abonniere`, kein `holeStand`, kein
  Kanalname. Der Bestand kommt **ausschließlich** als `sicht`-Parameter aus M7-12.
- **Verbot – keine Bedienung in dieser Zeile.** Kein Entfernen-, Abbrechen- oder
  Wiederholen-Schalter in der **eingeklappten** Zeile. Diese Schalter gehören in die aufgeklappte
  Liste (M7-16, M7-17), wo der betroffene Auftrag namentlich danebensteht. Ein Abbruch-Knopf in
  einer einzeiligen Zusammenfassung träfe einen Auftrag, den der Nutzer nicht sicher benennen kann.
- **Verbot – keine eigene Sortierung, kein Filtern, kein Kappen** des Arrays. Es wird **gezählt**
  und der laufende **gesucht**, mehr nicht.
- **Verbot – keine Fehlertext-Übersetzung.** Aus `sicht.code` wird hier **kein** Klartext gemacht;
  das ist M7-18. Diese Zeile zeigt einen festen, allgemeinen Satz.
- **Verbot – keine Fachlogik in der `.tsx`.** Alles, was zählt, entscheidet oder Text
  zusammensetzt, steht in `leiste-zusammenfassung.ts`. Die `.tsx` ruft `fasseZusammen` **einmal**
  und stellt das Ergebnis dar.
- **Offene Frage (echte Entscheidung nötig): Wie wird `ton: 'hervorgehoben'` gestaltet?** Farbe,
  Rahmen, Sinnbild – das ist eine **Marken**-Entscheidung (Primärfarbe #FF4040, Markenrahmen
  TK 9.10.5) und keine, die ein Agent nebenbei treffen sollte, weil sie in jedem Reiter dauerhaft
  sichtbar ist. **Nicht selbst wählen** – fragen. Bis zur Antwort bleibt der Ton ein **Datenwert**
  im Rückgabetyp, damit die Gestaltung nachgezogen werden kann, ohne die Ableitung anzufassen.
- **Offene Frage (echte Entscheidung nötig): Soll die eingeklappte Zeile auch dann eine
  Fehlschlag-Zahl zeigen, wenn ein Auftrag LÄUFT?** Die Tabelle oben sagt ja (angehängter Teil
  „· N fehlgeschlagen"). Das macht die Zeile in der ungünstigsten Lage vierteilig und damit
  möglicherweise zu lang für schmale Fenster. Ob stattdessen bei laufendem Auftrag nur ein
  stummes Warnzeichen erscheint, ist eine Bedienfrage – **nicht** selbst umentscheiden.
