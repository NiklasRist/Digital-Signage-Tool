### Issue M7-20: [preview-player] Die frame-gerundete Zeitachse und die Gesamtdauer der Vorschau

## Ziel (in einem Satz)
Aus der Wiedergabeliste entsteht eine Achse aus **Frames** – jedes Element bekommt seinen Abschnitt
`[startFrame, endeFrame)` –, die exakt dieselbe Gesamtlänge ergibt wie die später gerenderte
Ausgabedatei.

## Modul & Datei
- Modul: `preview-player` (Renderer) [P5]
- Datei: `src/renderer/preview-player/zeitachse.ts` – **die einzige** Datei dieses Issues
  (+ zugehörige Testdatei). Reine Rechnung, **kein** JSX, **kein** `react`-Import.
- **Nicht** erlaubt: jede andere Datei unter `src/renderer/preview-player/`, insbesondere
  `transport.ts` (M7-21) und `band-takt.ts` (M7-27); ebenso `src/renderer/composer/**`
  (insbesondere **nicht** `gesamtlaenge.ts` – die wird nur **gelesen und aufgerufen**) und alles
  unter `src/main/**`
- Vertrag: Technisches Konzept **9.9.3** (erste Invariante – Quelle der Wahrheit), **9.2.6**
  (die Rundungsregel des Renders), **9.7.4** (dieselbe Regel im `composer`), **9.2.4**
  (30 fps CFR)
- Prozess/Speicher: P5 – **kein** IPC, **kein** Dateisystem, **kein** `ffmpeg`, **kein** Zustand

## Warum das im Gesamtsystem wichtig ist
Die Vorschau macht eine Zusage: Was hier 4:32 lang ist, ist in der fertigen MP4 auch 4:32 lang. Die
Zusage ist nur haltbar, wenn die Vorschau **dieselben** Dauern benutzt wie der Render – und der
Render rechnet nicht in Sekunden, sondern in **Frames**: „Die effektive Elementdauer ist damit
`(endFrame − startFrame) / 30` – **nicht** die rohe Sekundendifferenz." (TK 9.2.6)

Der naheliegende Fehler ist unscheinbar: Man addiert `element.dauer` bzw. `trimEnde − trimStart` in
Sekunden und rundet am Schluss. Bei einem einzelnen Element sieht das identisch aus. Bei sechzig
Elementen summieren sich sechzig halbe Frames zu einer Sekunde Abweichung, und die Vorschau zeigt
eine andere Länge als die Datei, die auf den Fernseher geht. Genau deshalb steht die Rundung im
System **genau einmal**: in `frameDauer` (#127), das der `composer` bereits für seine
Gesamtlängen-Anzeige benutzt. Diese Datei **ruft sie auf** und rechnet **nicht** selbst.

Die Achse ist außerdem die Grundlage für alles Weitere: Der Transport (M7-21) läuft auf ihr, die
Markierung des aktuellen Elements (TK 9.9.1) wird aus ihr abgeleitet, und der Takt des Werbebandes
(M7-27) rechnet in der lokalen Frame-Position innerhalb eines Abschnitts. Eine falsche Achse ist
damit nicht ein Fehler, sondern der gemeinsame Ursprung von vieren.

## Signatur (verbindlich – NICHT ändern)
```ts
// src/renderer/preview-player/zeitachse.ts
import type { Listenelement } from '../../shared/contracts/project'
import type { Ergebnis } from '../../shared/contracts/ergebnis'
import { RENDER_PROFILE } from '../../shared/contracts/render-profile'
import { frameDauer } from '../composer/gesamtlaenge'

/** Der Platz genau eines Listenelements auf der Achse. Halboffen: [startFrame, endeFrame). */
export interface Achsenabschnitt {
  elementId: string
  /** Position in der übergebenen Liste (0-basiert) – die „Markierung des aktuellen Elements". */
  index: number
  /** Erster Frame dieses Elements, einschliesslich. */
  startFrame: number
  /** Erster Frame des NÄCHSTEN Elements, ausschliesslich. */
  endeFrame: number
  /** endeFrame − startFrame. */
  frames: number
}

export interface Zeitachse {
  abschnitte: readonly Achsenabschnitt[]
  /** Summe aller Abschnitts-Frames. */
  gesamtFrames: number
  /** gesamtFrames / RENDER_PROFILE.fps – exaktes Vielfaches von 1/fps. */
  gesamtSekunden: number
}

/**
 * Baut die Achse. Eine LEERE Liste ergibt eine leere Achse mit 0 Frames und ist KEIN Fehler.
 * Scheitert `frameDauer` an EINEM Element, bricht der Aufbau ab und der Fehler des ersten
 * gescheiterten Elements wird UNVERÄNDERT durchgereicht (Code und Meldung).
 */
export function baueZeitachse(liste: readonly Listenelement[]): Ergebnis<Zeitachse, string>

/** Der Abschnitt, in dem `frame` liegt; null ausserhalb von [0, gesamtFrames). */
export function findeAbschnitt(achse: Zeitachse, frame: number): Achsenabschnitt | null

/** Position INNERHALB des Abschnitts: frame − abschnitt.startFrame. Klemmt nicht. */
export function lokalerFrame(abschnitt: Achsenabschnitt, frame: number): number

/** frame / RENDER_PROFILE.fps. */
export function frameZuSekunden(frame: number): number

/** Math.round(sekunden × RENDER_PROFILE.fps) – die EINZIGE Rundung dieser Datei, s. ENTSCHIEDEN 3. */
export function sekundenZuFrame(sekunden: number): number
```

**ENTSCHIEDEN 1 – der Fehlercode reist als `string`.** Die fachlichen Fehlercode-Unionen der
Main-Module liegen in `src/main/**`; der Renderer darf wegen der getrennten tsconfigs (#1) **nicht**
von dort importieren. Dieselbe Lage ist im geteilten Vertrag bereits so gelöst
(`Auftrag.fehler.code` ist dort `string`) – die Enge sitzt dort, wo der Code **entsteht**.
**Deklariere keine Union ein zweites Mal** in `src/renderer/**`.

**ENTSCHIEDEN 2 – ein gescheitertes Element lässt die GANZE Achse scheitern.** Der naheliegende
Ausweg wäre, das Element zu überspringen und den Rest zu zeigen. Das ist der schlimmste aller
Ausgänge: Die Vorschau liefe durch, sähe gesund aus und zeigte eine **andere Reihenfolge** und eine
**andere Länge** als der Render. Ein Abbruch mit dem durchgereichten Code ist unbequem und ehrlich.
*Wichtig zur Einordnung:* Ein **kaputtes** Element (fehlende Mediendatei, TK 9.4.7) scheitert hier
**nicht** – seine `dauer` bzw. sein Trim stehen weiterhin am Listenelement, es behält seinen Platz
und seine Länge auf der Achse und wird lediglich als Platzhalter dargestellt (M7-28). Kaputt heisst
**nicht** dauerlos.

**ENTSCHIEDEN 3 – `sekundenZuFrame` rundet mit `Math.round`, und das ist die einzige Rundung hier.**
Diese Funktion übersetzt **keine Elementdauer**, sondern eine Bedienposition (der Nutzer zieht an
der Zeitleiste, die in Sekunden beschriftet ist) in die Frame-Achse. Sie darf deshalb existieren.
Die Rundungsrichtung folgt derselben Regel wie im Render – „Beide Grenzen werden auf **dasselbe**
30-fps-Raster gerundet: `startFrame = round(trimStart × 30)`, `endFrame = round(trimEnde × 30)`"
(TK 9.2.6). **Jede** andere Rundung in dieser Datei ist verboten, insbesondere jede eigene Rechnung
einer Elementdauer.

**ENTSCHIEDEN 4 – `formatiereLaenge` wird NICHT nachgebaut.** Die Anzeigeform der Länge („M:SS"
bzw. „H:MM:SS") gibt es bereits als `formatiereLaenge(sekunden)` in #127. Diese Datei exportiert
**keine** eigene Formatierfunktion; wer eine Beschriftung braucht, ruft die vorhandene auf.

**Fremde Funktionen und Typen, die du benutzt** – vollständig ausgeschrieben, du siehst die anderen
Issues nicht:

**MELDE-KLAUSEL (bindend).** Weicht die tatsächliche Signatur von `frameDauer`,
`formatiereLaenge` oder `RENDER_PROFILE` von der hier ausgeschriebenen ab, ist das ein
**Vertragsfehler**: **melden, NICHT eigenmächtig anpassen** – insbesondere **nicht** ersatzweise
selbst runden. Wer den Aufruf still an eine abweichende Signatur anpasst, macht aus einem
Vertragsfehler einen unsichtbaren, und dieselbe Rundung existiert dann in zwei Fassungen.

## Eingang → Ausgang
| Eingang | Bedeutung | Grenzen/Validierung |
|---|---|---|
| `liste` | die Wiedergabeliste des Projekts, in Array-Reihenfolge | leer erlaubt (0 Frames); wird **nicht** verändert und **nicht** umsortiert |
| `achse` | eine zuvor gebaute Zeitachse | wird nur gelesen |
| `frame` | Position auf der Achse | jede Zahl; ausserhalb von `[0, gesamtFrames)` ergibt `null` |
| `sekunden` | Bedienposition in Sekunden | jede Zahl; `sekundenZuFrame` klemmt **nicht** |

Ausgang bei Erfolg: `{ ok: true, wert: Zeitachse }` mit lückenlosen, aneinandergrenzenden
Abschnitten: `abschnitte[0].startFrame === 0`, `abschnitte[i].endeFrame ===
abschnitte[i+1].startFrame`, und `gesamtFrames === abschnitte.at(-1)?.endeFrame ?? 0`.
Ausgang bei Fehler: der **unveränderte** Fehler des ersten gescheiterten `frameDauer`-Aufrufs –
Code **und** Meldung werden durchgereicht, nicht ersetzt und nicht ergänzt.

## Verbindliche Invarianten (wörtlich – Verletzung = Issue nicht erfüllt)
- „**Zeitleiste ist frame-gerundet** – die maßgebliche Uhr nutzt **dieselben** frame-gerundeten
  Dauern wie `render-service` (9.2.6) und `composer` (9.7.4). Die native `<video>`-Wiedergabe ist
  Best-Effort; die Zeitleiste bleibt deterministisch und deckt sich mit der Gesamtlänge der
  Ausgabedatei." (TK 9.9.3) – **die Kernregel dieses Issues.**
- „Die effektive Elementdauer ist damit `(endFrame − startFrame) / 30` – **nicht** die rohe
  Sekundendifferenz." (TK 9.2.6)
- „Beide Grenzen werden auf **dasselbe** 30-fps-Raster gerundet: `startFrame = round(trimStart ×
  30)`, `endFrame = round(trimEnde × 30)`; behalten werden die Frames `[startFrame, endFrame)`."
  (TK 9.2.6) – die **halboffene** Zählweise `[start, ende)` wird hier übernommen; deshalb ist
  `endeFrame` ausschliesslich.
- „**`gesamtdauer` zählt gerundete Frame-Dauern:** Die im `RenderResult` gemeldete `gesamtdauer`
  summiert die **gerundeten** Elementdauern (Frame-Anzahl / 30), nicht die rohen Trim-Sekunden –
  sonst driften die angezeigte Gesamtlänge (5.3, 30-Minuten-Warnung) und die tatsächliche Länge der
  Ausgabedatei auseinander." (TK 9.2.6)
- „**Standbild → Clip:** `"segment"`-Items werden als Standbild über ihre `dauer` bei
  30 fps im Profil ausgehalten; harter Schnitt an den Grenzen." (TK 9.2.6) – es gibt **keine**
  Überblendung und **keinen** Übergang zwischen zwei Abschnitten; die Achse ist lückenlos.
- „**Bewusste Grenze (Abschnitt 8):** Farbe, Kompression und Bitrate des finalen H.264 sind in der
  Simulation **nicht** sichtbar; der schnelle Trim kann um bis zu einen Frame anders schneiden. Die
  **finale Kontrolle bleibt die gerenderte Ausgabedatei** (Akzeptanzkriterium 2/3)." (TK 9.9.3) –
  die Abweichung betrifft die **native Wiedergabe**, **nicht** diese Achse. Die Achse ist
  deterministisch.
- „Die Elementdauer bestimmt **allein das Video** (Trim). Das Band verlängert oder verkürzt sie
  **nie**." (TK 9.2.8) – deshalb kennt diese Datei die `einblendung` **nicht** und liest sie nicht.
- **Invariante 4 des Meilensteins (bindend, ausgeschrieben):** Der Renderer rechnet nichts nach, was
  schon gerechnet wird. Frame-Rundung, Bandgeometrie, Pfadauflösung, Fehlercode-Bedeutung – jeweils
  genau eine Quelle. Reine Rechenfunktionen darf der `preview-player` importieren; **Zustand**
  bekommt er als Parameter.

## Fehlerpfade (vollständig)
| Situation | Code | Verhalten |
|---|---|---|
| `frameDauer` liefert für ein Element `ok: false` | der Code **unverändert** aus `frameDauer` | Abbruch beim ersten Fehlschlag; **keine** Teil-Achse, **kein** Überspringen, **kein** Ersatzwert |
| Liste ist leer | – | `{ ok: true, wert: { abschnitte: [], gesamtFrames: 0, gesamtSekunden: 0 } }` |
| `findeAbschnitt` mit `frame < 0`, `frame >= gesamtFrames`, `NaN` | – | `null`. **Kein** `throw`, **kein** Klemmen auf den ersten/letzten Abschnitt |
| `lokalerFrame` mit einem Frame ausserhalb des Abschnitts | – | liefert die Differenz, auch wenn sie negativ oder zu gross ist. **Kein** Klemmen – das Urteil fällt der Aufrufer |
| `sekundenZuFrame(NaN)` / `(Infinity)` | – | das Ergebnis von `Math.round` auf diesen Werten. **Kein** `throw`, **kein** Ersatzwert |

Diese Datei vergibt **keinen eigenen** Fehlercode. Sie reicht ausschliesslich durch.

## Nicht selbst entscheiden – STOPP und fragen
- **Verbot – keine eigene Dauer-Rechnung.** Kein `element.dauer * 30`, kein
  `trimEnde - trimStart`, kein `RENDER_PROFILE.fps` in Verbindung mit einem Feld des
  Listenelements. Die Frames eines Elements kommen **ausschliesslich** aus `frameDauer` (#127).
- **Verbot – keine zweite Rundungsstelle.** `Math.round` steht **genau einmal** in der Datei, in
  `sekundenZuFrame`. Kein `Math.floor`, kein `Math.ceil`, kein `toFixed`.
- **Verbot – kein `formatiereLaenge`-Nachbau**, keine eigene Zeitbeschriftung, kein
  `toLocaleString`, kein Datumsformat.
- **Verbot – kein Zustand.** Keine Modulvariable, kein Zwischenspeicher der letzten Achse, keine
  Klasse. Jede Funktion rechnet aus ihren Parametern. Die Achse ist ein **Wert**, den der Aufrufer
  hält (dieselbe Bauweise wie der `ReparaturStand` in #132, damit sie einen Reiterwechsel
  übersteht).
- **Verbot – keine Kenntnis von Medien, Aktionen, Vorlagen oder Bändern.** Diese Datei liest
  `element.id` und übergibt das Element an `frameDauer`. Sie löst **kein** `ref` auf, kennt
  **kein** `Asset`, **keine** `Aktion`, **keine** `Vorlage` und **keine** `Einblendung`.
- **Verbot – keine Sortierung, kein Filtern.** „Reihenfolge = Array-Reihenfolge, KEIN
  position-Feld" (#15). Ein Element wird nie ausgelassen, auch kein kaputtes.
- **Verbot – kein IPC, kein `rufeAuf`, kein `abonniere`, kein `window.api`, kein `media://`, kein
  JSX, kein `react`-Import.**
- **Verbot – keine Wiederholung.** Die Achse endet bei `gesamtFrames`; sie beginnt **nicht** von
  vorn. Die Endlosschleife entsteht am Fernseher, nicht hier (Anforderungsdokument Abschnitt 7).
