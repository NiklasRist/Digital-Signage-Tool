### Issue M7-21: [preview-player] Transport – Abspielen, Pause, Springen und die Markierung des aktuellen Elements

## Ziel (in einem Satz)
Die Vorschau hat eine Uhr, die auf der frame-gerundeten Zeitachse läuft: abspielen, pausieren,
an eine Stelle springen, das gerade laufende Element benennen – und sie bleibt beim Pausieren
genau dort stehen, wo sie war.

## Modul & Datei
- Modul: `preview-player` (Renderer) [P5]
- Datei: `src/renderer/preview-player/transport.ts` – **die einzige** Datei dieses Issues
  (+ zugehörige Testdatei). Reine Rechnung, **kein** JSX, **kein** `react`-Import.
- **Nicht** erlaubt: jede andere Datei unter `src/renderer/preview-player/`, insbesondere
  `zeitachse.ts` (M7-20 – wird nur **gelesen und aufgerufen**), `video.tsx` (M7-23) und
  `band-takt.ts` (M7-27); ebenso `src/renderer/app-shell/**`, `src/renderer/composer/**` und
  alles unter `src/main/**`
- Vertrag: Technisches Konzept **9.9.1** (Transport: Play/Pause, Zeitleiste, Markierung),
  **9.9.3** (erste und dritte Invariante – Quelle der Wahrheit), **9.14.2** (ein Reiterwechsel
  verwirft nie Arbeit), **9.2.6** (die Frame-Rundung, auf der die Uhr läuft)
- Prozess/Speicher: P5 – **kein** IPC, **kein** Dateisystem, **kein** `ffmpeg`, **kein**
  Auftrag der Warteschlange

## Warum das im Gesamtsystem wichtig ist
Der Transport ist die **maßgebliche Uhr** der Vorschau. Alles, was der Nutzer sieht, hängt an ihr:
welches Element gerade dargestellt wird (M7-22 bis M7-26, M7-28), an welcher Stelle das Video steht
(M7-23) und welcher Abschnitt im Werbeband sichtbar ist (M7-27). Läuft diese Uhr falsch, laufen alle
vier falsch – und zwar gleichzeitig und in dieselbe Richtung, was den Fehler besonders schwer
sichtbar macht.

**Die gefährlichste Bauweise – ausgeschrieben, damit sie nicht entsteht.** Die naheliegendste
Umsetzung einer Videovorschau nimmt die Uhr des `<video>`-Elements: Man liest `currentTime` aus und
leitet daraus die Position auf der Zeitachse ab. Das ist bequem, weil dann Bild und Zeitanzeige
niemals auseinanderlaufen können – und es ist **falsch**. Die native Wiedergabe eines Browsers ist
Best-Effort: Sie überspringt Frames, wenn der Rechner ausgelastet ist, sie trifft einen Sprung nur
auf den nächstgelegenen Keyframe genau, und sie läuft bei einer Quelle mit variabler Bildrate nicht
im 30-fps-Raster. Eine Uhr, die sich davon nachführen lässt, zeigt am Ende eine **andere Gesamtlänge
als die gerenderte Datei** – genau das, was TK 9.9.3 ausschliesst. Deshalb gilt hier die
Einbahnstrasse: Die Uhr sagt dem Video, wo es hin soll. Das Video sagt der Uhr **nie** etwas.

Der zweite Fehler ist leiser. Wechselt der Nutzer den Reiter, läuft die Vorschau ohne diesen
Baustein im Hintergrund weiter – unsichtbar, mit laufendem Ton-losem Video und weiterlaufender
Uhr –, und beim Zurückkommen steht sie an einer Stelle, die niemand gewählt hat. Deshalb ist
„beim Verlassen pausieren und die Stelle merken" hier ein Vertragsbestandteil und keine Feinheit.

## Signatur (verbindlich – NICHT ändern)
```ts
// src/renderer/preview-player/transport.ts
import type { Zeitachse } from './zeitachse'

/**
 * Der vollstaendige Stand der Vorschau-Uhr. Ein WERT, keine Klasse und kein Modul-Zustand:
 * Jede Funktion liefert einen NEUEN Stand, keine mutiert ihre Eingabe.
 */
export interface TransportStand {
  /** true = die Uhr laeuft. Sagt NICHTS darueber, ob ein <video> gerade wirklich abspielt. */
  laeuft: boolean
  /** Aktuelle Position in Frames, ganzzahlig, immer 0 <= frame <= achse.gesamtFrames. */
  frame: number
  /**
   * Angesammelter Bruchteil eines Frames in Millisekunden, 0 <= restMs < 1000 / fps.
   * Nur `tick` schreibt ihn; jeder Sprung setzt ihn auf 0.
   */
  restMs: number
}

/** Der Anfangsstand: pausiert, bei Frame 0. */
export function baueTransport(): TransportStand

/** Startet die Uhr. Steht sie am Ende, beginnt sie wieder bei 0 (s. ENTSCHIEDEN 3). */
export function spieleAb(stand: TransportStand, achse: Zeitachse): TransportStand

/** Haelt die Uhr an und BEHAELT die Position – das ist das „merkt sich die Stelle". */
export function pausiere(stand: TransportStand): TransportStand

/** Springt an eine Frame-Position; klemmt auf [0, gesamtFrames]. `laeuft` bleibt unveraendert. */
export function springeZuFrame(stand: TransportStand, achse: Zeitachse, frame: number): TransportStand

/** Springt an den Anfang des Elements mit diesem Listen-Index; klemmt auf gueltige Indizes. */
export function springeZuElement(stand: TransportStand, achse: Zeitachse, index: number): TransportStand

/**
 * Laesst die Uhr um `vergangeneMs` weiterlaufen. Tut NICHTS, wenn `laeuft` false ist.
 * Erreicht sie das Ende, bleibt sie bei gesamtFrames stehen und `laeuft` wird false.
 */
export function tick(stand: TransportStand, achse: Zeitachse, vergangeneMs: number): TransportStand

/** Listen-Index des gerade laufenden Elements; null am Ende und bei leerer Achse. ABGELEITET. */
export function markierterIndex(stand: TransportStand, achse: Zeitachse): number | null
```

**ENTSCHIEDEN 1 – der Stand ist ein Wert und liegt NICHT in dieser Datei.** Es gibt hier keine
Modulvariable, keine Klasse, keinen Zeitgeber und kein `useState`. Der Aufrufer hält den Stand und
reicht ihn hinein. *Begründung:* „**Ein Reiterwechsel verwirft nie Arbeit.**" (TK 9.14.2) Läge der
Stand als Modulvariable hier, wäre er an die Lebensdauer dieses Renderer-Moduls gebunden und die
Zusage nicht mehr prüfbar. Dieselbe Bauweise hat der `ReparaturStand` (#132) aus genau diesem Grund.

**ENTSCHIEDEN 2 – diese Datei hat keinen Taktgeber.** Kein `requestAnimationFrame`, kein
`setInterval`, kein `setTimeout`, kein `performance.now()`, kein `Date.now()`. Die verstrichene Zeit
kommt als Parameter `vergangeneMs` herein. *Begründung:* Nur so ist die Uhr ohne Browser prüfbar –
ein Test kann `tick(stand, achse, 1000)` aufrufen und die Position nachrechnen. Wer den Taktgeber
antreibt, ist der Aufrufer (die Stelle, die die Bühne einhängt).

**ENTSCHIEDEN 3 – `spieleAb` am Ende beginnt wieder bei 0.** Steht die Uhr auf `gesamtFrames`
(sie ist durchgelaufen) und der Nutzer drückt Abspielen, springt sie auf Frame 0 und läuft. Die
Alternative – nichts tun – sähe wie ein defekter Knopf aus. Ein **automatisches** Wiederholen
gibt es dagegen **nicht**: Die Endlosschleife entsteht am Fernseher (Anforderungsdokument
Abschnitt 7), nicht in der Vorschau; eine Vorschau, die von selbst wieder anfängt, verwischt die
Grenze zwischen „das Video ist zu Ende" und „es geht weiter".

**ENTSCHIEDEN 4 – `vergangeneMs` wird NICHT gedeckelt.** Ein grosser Wert (z. B. weil das Fenster
kurz im Hintergrund war) lässt die Uhr entsprechend weit springen. Ein Deckel würde die Vorschau
langsamer laufen lassen als die Wirklichkeit und damit genau die Zusage brechen, dass sich die
Zeitleiste „mit der Gesamtlänge der Ausgabedatei" deckt (TK 9.9.3). Unbrauchbare Werte (negativ,
`NaN`, `Infinity`) werden dagegen wie `0` behandelt – sie sind kein Zeitverlauf, sondern eine
Störung.

**ENTSCHIEDEN 5 – die Markierung wird abgeleitet, nicht gespeichert.** `markierterIndex` rechnet
aus `frame` und `achse`. Ein zusätzliches Feld im Stand wäre eine zweite Wahrheit, die nach jedem
Sprung nachgeführt werden müsste – und die genau dann falsch stünde, wenn jemand sie einmal
vergisst.

**Fremde Funktionen und Typen, die du benutzt** – vollständig ausgeschrieben, du siehst die anderen
Issues nicht:

**MELDE-KLAUSEL (bindend).** Weicht die tatsächliche Signatur von der hier ausgeschriebenen ab, ist
das ein **Vertragsfehler**: **melden, NICHT eigenmächtig anpassen** – insbesondere **nicht**
ersatzweise eine eigene Abschnittssuche oder eine eigene Sekunden-Rechnung einbauen. Wer den Aufruf
still an eine abweichende Signatur anpasst, macht aus einem Vertragsfehler einen unsichtbaren.

## Eingang → Ausgang
| Eingang | Bedeutung | Grenzen/Validierung |
|---|---|---|
| `stand` | der bisherige Stand | wird **nie** verändert; jede Funktion liefert einen neuen |
| `achse` | die Zeitachse aus M7-20 | wird nur gelesen; leere Achse (`gesamtFrames === 0`) ist erlaubt |
| `frame` | Zielposition in Frames | jede Zahl; wird auf `[0, gesamtFrames]` geklemmt, `NaN` ergibt `0` |
| `index` | Listen-Index eines Elements | jede Zahl; wird auf gültige Indizes geklemmt |
| `vergangeneMs` | seit dem letzten `tick` verstrichene Zeit | `<= 0`, `NaN`, `Infinity` werden wie `0` behandelt |

Ausgang: immer ein vollständiger `TransportStand` mit `Number.isInteger(frame)`,
`0 <= frame <= achse.gesamtFrames` und `0 <= restMs < 1000 / RENDER_PROFILE.fps`.
Ausgang bei Fehler: **keiner** – alle Funktionen sind total, werfen nie, tragen **keine**
`Ergebnis`-Hülle und **keinen** Fehlercode. Diese Datei überquert keine IPC-Grenze.

## Die Rechnung von `tick`, ausgeschrieben (verbindlich)
`msProFrame` = `1000 / RENDER_PROFILE.fps`.

1. Ist `laeuft` false oder `vergangeneMs` unbrauchbar (`<= 0`, `NaN`, `Infinity`), wird der Stand
   **unverändert** zurückgegeben.
2. `gesamt = stand.restMs + vergangeneMs`
3. `ganzeFrames = Math.floor(gesamt / msProFrame)`
4. `neuerFrame = stand.frame + ganzeFrames`, `neuerRest = gesamt − ganzeFrames × msProFrame`
5. Ist `neuerFrame >= achse.gesamtFrames`: Ergebnis ist
   `{ laeuft: false, frame: achse.gesamtFrames, restMs: 0 }` – die Uhr bleibt am Ende stehen.
6. Sonst: `{ laeuft: true, frame: neuerFrame, restMs: neuerRest }`.

**Warum der Rest mitgeführt wird:** Ein Bildtakt liefert typischerweise rund 16,7 ms, ein Frame
dauert 33,3 ms. Ohne `restMs` würde jeder zweite Aufruf abgerundet auf null Frames und der Rest
verworfen – die Vorschau liefe dauerhaft zu langsam, und zwar geräteabhängig unterschiedlich.
`Math.floor` ist hier richtig und **nicht** verhandelbar: Ein Frame gilt erst als vergangen, wenn
seine Zeit vollständig abgelaufen ist; `Math.round` würde einen halb vergangenen Frame vorziehen und
die Uhr im Mittel um einen halben Frame vorlaufen lassen.

## Fehlerpfade (vollständig)
| Situation | Verhalten |
|---|---|
| `vergangeneMs <= 0`, `NaN` oder `Infinity` | Stand **unverändert** zurück. **Kein** `throw`, **kein** Ersatzwert |
| `tick` bei `laeuft: false` | Stand **unverändert** zurück |
| Leere Achse (`gesamtFrames === 0`) | `spieleAb` liefert `laeuft: false`, `frame: 0`; `tick` bewegt nichts; `markierterIndex` liefert `null` |
| `springeZuFrame` mit `frame < 0`, `> gesamtFrames`, `NaN` oder nicht ganzzahlig | geklemmt auf `[0, gesamtFrames]`, nicht ganzzahlige Werte werden mit `Math.round` auf einen Frame gelegt, `NaN` ergibt `0`; `restMs` wird `0` |
| `springeZuElement` mit unbekanntem Index | geklemmt auf den ersten bzw. letzten Abschnitt; bei leerer Achse Stand mit `frame: 0` |
| `markierterIndex` bei `frame === gesamtFrames` | `null` – die Uhr steht am Ende, es läuft kein Element mehr |

Diese Datei vergibt **keinen** Fehlercode und wirft **nie**.
