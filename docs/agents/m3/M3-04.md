### Issue M3-04: [media-service] öffneMedienDialog implementieren

## Ziel (in einem Satz)
Der Nutzer kann über den nativen Datei-Dialog eine oder mehrere Mediendateien auswählen, und der Main
liefert deren absolute Pfade zurück – ein Abbruch ist dabei ein normales, erfolgreiches Ergebnis.

## Modul & Datei
- Modul: `media-service` (Main)
- Datei: `src/main/media-service/dialog.ts`
- Vertrag: Technisches Konzept **9.4.3** (Operationen), ergänzend **9.4.1** (Verantwortungsgrenze),
  **9.4.2** (Whitelist), **9.3.2** (Instant statt Auftrag), **9.1.1** (Ergebnis-Hülle) – Quelle der
  Wahrheit
- Prozess/Speicher: P1; **kein** Speicherzugriff, **kein** Lesen oder Schreiben von Dateien – der
  Dialog liefert nur Pfade

## Warum das im Gesamtsystem wichtig ist
Das ist der Einstiegspunkt jedes Imports (FA-01) und die einzige Stelle, an der ein absoluter
Fremdpfad ins System kommt. Zwei lokale Fehlentscheidungen sind hier teuer:

Erstens der **Abbruch**. Klickt der Nutzer „Abbrechen", ist das kein Fehler, sondern der häufigste
Ausgang überhaupt. Wird er als Fehler gemeldet, zeigt die Oberfläche bei jedem versehentlich
geöffneten Dialog eine Fehlermeldung – und schlimmer: ein Aufrufer, der Fehler protokolliert oder
einen Wiederholungsversuch anbietet, tut das dann für einen Vorgang, den der Nutzer bewusst
abgebrochen hat.

Zweitens der **Filter**. Er muss aus derselben Konstante kommen wie die Import-Prüfung. Zeigt der
Dialog Formate an, die der Import danach ablehnt, führt die Anwendung den Nutzer in eine Sackgasse:
Er darf die Datei auswählen und bekommt danach `format_nicht_unterstuetzt`. Umgekehrt versteckt ein
zu enger Filter Dateien, die eigentlich importierbar wären.

## Signatur (verbindlich – NICHT ändern)
```ts
// src/main/media-service/dialog.ts
import { dialog } from 'electron'
import { FORMAT_WHITELIST } from '../../shared/contracts/asset'
import type { Ergebnis } from '../../shared/contracts/ergebnis'

export async function öffneMedienDialog(): Promise<Ergebnis<{ pfade: string[] }>>
```

Kein Parameter, kein zweiter Fehlercode-Typparameter: Diese Operation kann keinen **fachlichen**
Fehler erzeugen – nur die generischen Codes aus `Ergebnis<T>` (Default-Typparameter) kommen infrage.

**Fremde Werte und fremde APIs, die du benutzt, vollständig ausgeschrieben** (der umsetzende Agent
sieht die anderen Issues nicht):

```ts
// #13 – src/shared/contracts/asset.ts, bereits angelegt. DIE EINZIGE Quelle für Dateiendungen:
export const FORMAT_WHITELIST = {
  video: ['mp4'] as const,
  bild: ['jpg', 'jpeg', 'png', 'webp'] as const,
} as const

// #22 – src/shared/contracts/ergebnis.ts:
export type Ergebnis<T, F extends string = GenerischerFehlercode> =
  | { ok: true; wert: T }
  | { ok: false; fehler: { code: F | GenerischerFehlercode; meldung: string; daten?: unknown } }
// `daten` trägt strukturierte Fehlerdaten, deren Form je Fehlercode festgelegt ist (TK 9.1.1).
// KEINER der hier möglichen Codes hat solche Daten – das Feld bleibt in dieser Datei ungesetzt.
// Schreibweise beachten: Das TK nennt den Platzhalter `Fehlerdaten`; in `ergebnis.ts` steht
// `unknown` (#12) – die Form wird dort zugesichert, wo der Code vergeben wird.

// Electron (externe Bibliothek), die verwendete Überladung OHNE Elternfenster:
dialog.showOpenDialog(options: {
  title?: string
  properties?: Array<'openFile' | 'multiSelections' | ...>
  filters?: Array<{ name: string; extensions: string[] }>   // extensions OHNE führenden Punkt
}): Promise<{ canceled: boolean; filePaths: string[] }>
```

**Der Ablauf, verbindlich:**

1. Die Filterliste **aus `FORMAT_WHITELIST` erzeugen**, in dieser Reihenfolge (der erste Eintrag ist
   im Dialog vorausgewählt):
   - `{ name: 'Medien', extensions: [...FORMAT_WHITELIST.video, ...FORMAT_WHITELIST.bild] }`
   - `{ name: 'Videos', extensions: [...FORMAT_WHITELIST.video] }`
   - `{ name: 'Bilder', extensions: [...FORMAT_WHITELIST.bild] }`

   Begründung für den kombinierten ersten Eintrag: Der Nutzer stellt eine Werbeschleife aus Videos
   **und** Bildern zusammen; müsste er erst den Typ wählen, könnte er nicht beides in einem Zug
   auswählen. Die Namen sind reine Anzeigetexte; die Endungen stehen **ohne** führenden Punkt, so
   erwartet es Electron.
2. `properties: ['openFile', 'multiSelections']` – Mehrfachauswahl ist Pflicht, weil der Vertrag ein
   **Array** zurückgibt: „| Nutzer wählt Dateien | `pfade` = Array absoluter Quellpfade |" (TK 9.4.3).
   **Kein** `'openDirectory'`, **kein** `'promptToCreate'`.
3. `dialog.showOpenDialog(…)` **await**en.
4. `canceled === true` **oder** `filePaths` leer → `{ ok: true, wert: { pfade: [] } }`. Beides ist
   Erfolg, kein Fehler.
5. Sonst → `{ ok: true, wert: { pfade: filePaths } }`, **unverändert** durchgereicht: nicht sortiert,
   nicht dedupliziert, nicht normalisiert, nicht auf Existenz geprüft.
6. Wirft der Aufruf wider Erwarten (z. B. weil noch kein Fenster bereit ist), wird die Ausnahme
   **hier** gefangen und als `{ ok: false, fehler: { code: 'unbekannter_fehler', meldung } }`
   zurückgegeben. Die Meldung enthält **keinen** Stacktrace.

**ENTSCHIEDEN – der Dialog wird ohne Elternfenster geöffnet.** Die Signatur nimmt kein
`BrowserWindow` entgegen, und der `media-service` soll die Fensterverwaltung nicht kennen; ein
`BrowserWindow.getFocusedWindow()`-Griff aus diesem Modul heraus wäre eine zusätzliche, unnötige
Abhängigkeit vom Renderer-Lebenszyklus. Praktische Folge: Der Dialog ist nicht als Sheet am Fenster
angeheftet. Das ist ein bewusst in Kauf genommener kosmetischer Nachteil, kein Versehen.

**ENTSCHIEDEN – kein `defaultPath`, kein Merken des zuletzt benutzten Ordners.** Der `config-store`
(D3) hält laut Planung das zuletzt benutzte **Export**-Ziel, kein Medien-Verzeichnis; ein neues Feld
dort wäre eine fremde Datei und eine Erweiterung des Konfigurationsvertrags. Das Betriebssystem merkt
sich den zuletzt benutzten Ordner ohnehin selbst.

**ENTSCHIEDEN – was mit den mehreren Pfaden geschieht, ist geklärt und nicht deine Sache.** Die
**Oberfläche** fächert die Mehrfachauswahl auf: Sie reiht für **jeden** zurückgegebenen Pfad einen
eigenen Auftrag ein (`reiheEin('import', …)` je Pfad), weil die Warteschlange sie dann einzeln und
sichtbar abarbeitet und jeder Fehlschlag einzeln wiederholbar ist (FA-17); ein Sammel-Auftrag wäre
unteilbar. Das zugehörige Issue ist im Oberflächen-Meilenstein vorgemerkt. Für **diese** Datei folgt
daraus nur: Du lieferst das Array unverändert ab, reihst selbst **nichts** ein und baust **keine**
Schleife über die Pfade.

## Eingang → Ausgang
| Eingang | Bedeutung | Grenzen/Validierung |
|---|---|---|
| – | die Funktion nimmt keine Parameter; ihr „Eingang" ist die Nutzeraktion im Dialog | die zurückgegebenen Pfade werden **nicht** validiert – die Prüfungen (Format, Existenz) geschehen beim Import (M3-03, M3-08) |

Ausgang bei Erfolg: `{ ok: true, wert: { pfade } }` – `pfade` ist ein Array absoluter Quellpfade und
ist bei Abbruch **leer**.
Ausgang bei Fehler: `unbekannter_fehler` (einziger möglicher Code; ein Abbruch ist **kein** Fehler).

## Verbindliche Invarianten (wörtlich – Verletzung = Issue nicht erfüllt)
- „| Nutzer wählt Dateien | `pfade` = Array absoluter Quellpfade |" (TK 9.4.3)
- „| Nutzer bricht ab | `ok: true` mit `pfade = []` – Abbruch ist **kein** Fehler |" (TK 9.4.3)
- „Der Formatfilter des Dialogs (9.4.3) und die Prüfung beim Import lesen **denselben** konstanten
  Wert aus `contracts/types` — sie dürfen nie auseinanderlaufen." (TK 9.4.2)
  → **In dieser Datei steht kein einziges Endungs-Literal.** Der Filter wird aus
  `FORMAT_WHITELIST` erzeugt.
- „**Format-Whitelist** kommt aus **einem** konstanten Wert in `contracts/types` (Dialog-Filter
  **und** Import-Prüfung)." (TK 9.4.8, Punkt 7)
- Der Dialog gehört zum `media-service`: „den nativen Datei-Dialog (weil der Formatfilter zum Dienst
  gehört)" (TK 9.4.1).
- **Dies ist eine Instant-Operation, kein Auftrag.** „**Nicht** über die Queue laufen
  **Instant-Operationen** (Millisekunden, reine D1-Schreibvorgänge): Aktion anlegen/bearbeiten, Liste
  umsortieren, Trim setzen, **Aktion** löschen, Datei-Dialog öffnen." (TK 9.3.2) Sie trägt deshalb
  die Ergebnis-Hülle: „**Nur Instant-Aufrufe tragen die Hülle.**" (TK 9.1.1) Sie ruft **nicht**
  `reiheEin`, erzeugt **keinen** `Auftrag` und erscheint **nicht** im `queue-panel`.
- **Der Filter ist eine Bequemlichkeit, keine Garantie.** Auf beiden Betriebssystemen kann der Nutzer
  den Filter umgehen (Dateinamen tippen, „Alle Dateien" wählen, per Automatisierung aufrufen). Die
  verbindliche Prüfung ist `pruefeFormat` beim Import (M3-03). Diese Datei prüft **nicht** selbst und
  filtert die Rückgabe **nicht** nach.
- **Niemals `throw` über die Prozessgrenze** (TK 9.1.1): Jeder Ausgang ist die Hülle. Grund wörtlich:
  „Wirft der Main `new Error(...)` mit einem eigenen Feld `code`, kommt beim Renderer **nicht** dieser
  Fehler an" – übrig bliebe Text.
- **Diese Datei registriert keinen IPC-Kanal.** Die Verdrahtung (Kanalname, Validierung,
  `registriereHandler`) geschieht in **M3-16**; `src/shared/contracts/kanaele.ts` (#25) wird hier
  **nicht** angefasst. Grund: Kanalnamen und Validierung liegen gebündelt an einer Stelle je Modul,
  sonst registriert später ein zweites Issue denselben Kanal ein zweites Mal.

## Fehlerpfade (vollständig)
| Situation | Code | Verhalten |
|---|---|---|
| Nutzer bricht den Dialog ab (`canceled: true`) | – (**kein** Fehler) | `ok: true`, `pfade: []` |
| Dialog liefert `canceled: false`, aber `filePaths` ist leer | – (**kein** Fehler) | `ok: true`, `pfade: []` – gleicher Ausgang, kein Sonderfall |
| `dialog.showOpenDialog` wirft (kein Fenster/App nicht bereit, OS-Fehler) | `unbekannter_fehler` | keine Wirkung; Meldung ohne Stacktrace, Ausnahme intern vermerken (der Mechanismus ist projektweit offen, s. #23) |

Es gibt **keinen** weiteren Fehlerpfad: Diese Funktion fasst keine Datei an und kann daher weder
`datei_nicht_gefunden` noch `format_nicht_unterstuetzt` erzeugen.

## Nicht selbst entscheiden – STOPP und fragen
- **Verbot – Abbruch ist niemals ein Fehler.** Kein `nicht_gefunden`, kein
  `ungueltige_eingabe`, kein eigens erfundener Code `abgebrochen` für diesen Fall. Der Vertrag ist
  hier eindeutig (TK 9.4.3) und wird nicht „verbessert".
- **Verbot – keine Formatprüfung und kein Nachfiltern der Rückgabe.** Auch nicht „zur Sicherheit".
  Zwei Prüforte laufen auseinander; die Prüfung gehört zu M3-03/M3-08.
- **Verbot – keine Endungs-Literale.** Der Filter kommt aus `FORMAT_WHITELIST` (#13). Wer hier
  `['mp4','mov']` hinschreibt, hebelt die Invariante aus TK 9.4.2 aus.
- **Verbot – kein IPC-Kanal, kein Eintrag in `kanaele.ts`, kein `ipcMain.handle`.** Das ist M3-16.
- **Verbot – kein Dateizugriff.** Kein `fs.existsSync`, keine Größenermittlung, kein Vorab-Lesen.
- **Verbot – kein Auftrag.** Kein `reiheEin`, kein `HandlerErgebnis`, kein Eintrag in Q1/Q2/Q3. Auch
  **keine** Auffächerung der Mehrfachauswahl – die macht die Oberfläche (s. „ENTSCHIEDEN – was mit
  den mehreren Pfaden geschieht").
- **Verbot – kein eigener Logger.** Wo oben „intern vermerken" steht, ist genau das gemeint: keine
  eigene Protokolldatei, kein selbst gebauter Logger, kein `console.log` in der Oberfläche. Ein
  projektweiter Mechanismus dafür ist noch offen (s. #23) und wird **nicht** in diesem Issue
  erfunden.
