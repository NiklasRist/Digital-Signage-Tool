### Issue M3-03: [media-service] Format gegen die Whitelist prüfen

## Ziel (in einem Satz)
Aus einem Dateinamen wird bestimmt, ob die Datei überhaupt importiert werden darf, und falls ja, ob
sie ein Video oder ein Bild ist und mit welcher kleingeschriebenen Endung sie im Medienordner landet.

## Modul & Datei
- Modul: `media-service` (Main)
- Datei: `src/main/media-service/format-pruefung.ts`
- Vertrag: Technisches Konzept **9.4.2** (Format-Whitelist), ergänzend **9.4.8** Punkte 1 und 7,
  **9.4.9** – Quelle der Wahrheit
- Prozess/Speicher: P1; **kein** Speicher- und **kein** Dateizugriff (reine Funktion)

## Warum das im Gesamtsystem wichtig ist
Diese Funktion ist der Türsteher des Medienbestands. Was sie durchlässt, landet in `media/` und
später in einem Render und in der Vorschau. Lässt sie ein Format durch, das Chromium nicht abspielt,
sieht der Nutzer in der Vorschau (P5) ein **schwarzes Bild ohne Fehlermeldung** – und merkt es
womöglich erst am Fernseher im Studio. Das ist nicht durch eine spätere Korrektur heilbar, weil das
Medium dann bereits im Projekt und in Listen referenziert ist.

Zweitens liefert sie die `endung`, aus der der spätere Dateiname `<uuid>.<ext>` gebaut wird. Kommt
sie großgeschrieben oder mit Punkt zurück, entstehen Dateinamen wie `…​..MP4` oder `…​.MP4` – auf
macOS (case-sensitive Dateisysteme möglich) findet der Reconcile die Datei dann nicht wieder und
markiert das Asset als „fehlt", obwohl sie da ist.

Drittens ist diese Funktion die eine Stelle, an der die Whitelist **angewendet** wird. Wer die
Endungen hier noch einmal hinschreibt, erzeugt eine zweite Wahrheit neben dem Dialog-Filter – und die
beiden laufen mit der ersten Formatänderung auseinander.

## Signatur (verbindlich – NICHT ändern)
```ts
// src/main/media-service/format-pruefung.ts
import { FORMAT_WHITELIST } from '../../shared/contracts/asset'
import type { Ergebnis } from '../../shared/contracts/ergebnis'
import type { ImportFehlercode } from './fehlercodes'

export function pruefeFormat(
  dateiname: string,
): Ergebnis<{ typ: 'video' | 'bild'; endung: string }, 'format_nicht_unterstuetzt'>
```

Der Fehlercode-Typparameter ist bewusst auf das **eine** Literal verengt, nicht auf die ganze
`ImportFehlercode`-Union: Diese Funktion kann gar keinen anderen fachlichen Fehler erzeugen, weil sie
keine Datei anfasst. (`ImportFehlercode` wird trotzdem importiert – als Beleg, dass das Literal aus
der Modul-Union stammt und nicht frei erfunden ist. Löst der sonst ungenutzte Import eine Compiler-
oder Lint-Warnung aus, gehört der Beleg stattdessen in die Testdatei:
`const c: ImportFehlercode = 'format_nicht_unterstuetzt'`.)

**Fremde Werte, die du benutzt, vollständig ausgeschrieben** (der umsetzende Agent sieht die anderen
Issues nicht):

```ts
// #13 – src/shared/contracts/asset.ts, bereits angelegt. DIE EINZIGE Quelle für Dateiendungen:
export const FORMAT_WHITELIST = {
  video: ['mp4'] as const,       // H.264/H.265 innerhalb MP4
  // 'jpeg' ist eine bewusste Ergänzung ÜBER den TK hinaus (TK 9.4.2/9.11.4 nennen nur
  // JPG, PNG, WebP): dieselbe Bilddatei trägt real zwei übliche Endungen, eine Datei
  // "foto.jpeg" würde sonst grundlos abgewiesen.
  bild: ['jpg', 'jpeg', 'png', 'webp'] as const,
} as const

// #22 – src/shared/contracts/ergebnis.ts:
export type Ergebnis<T, F extends string = GenerischerFehlercode> =
  | { ok: true; wert: T }
  | { ok: false; fehler: { code: F | GenerischerFehlercode; meldung: string; daten?: unknown } }
// `daten` trägt strukturierte Fehlerdaten, deren Form je Fehlercode festgelegt ist (TK 9.1.1).
// KEINER der hier möglichen Codes hat solche Daten – das Feld bleibt in dieser Datei ungesetzt.
// Schreibweise beachten: Das TK nennt den Platzhalter `Fehlerdaten`; in `ergebnis.ts` steht
// `unknown` (#12) – die Form wird dort zugesichert, wo der Code vergeben wird.

// M3-02 – src/main/media-service/fehlercodes.ts:
export type ImportFehlercode =
  | 'datei_nicht_gefunden' | 'format_nicht_unterstuetzt' | 'probe_fehler'
  | 'kopier_fehler' | 'speicher_fehler'
```

**Der Ablauf, verbindlich:**

1. Aus `dateiname` das **letzte Pfadsegment** nehmen: alles nach dem letzten `/` **oder** `\`. Grund:
   Der Aufrufer reicht meist den `quellPfad` durch, und der ist ein absoluter Windows- oder
   macOS-Pfad. Ohne diesen Schritt liefert ein Ordner mit Punkt im Namen
   (`C:\Kampagne.2026\clipohneendung`) eine erfundene „Endung" `2026\clipohneendung`.
2. Aus dem Segment die Endung nehmen: alles **nach dem letzten Punkt**, ohne den Punkt. Enthält das
   Segment keinen Punkt, oder steht der Punkt an erster Stelle (`.gitkeep`), oder ist der Teil nach
   dem Punkt leer (`film.`) → `format_nicht_unterstuetzt`.
3. Die Endung mit `toLowerCase()` normalisieren – **nicht** mit `toLocaleLowerCase()`. Letzteres
   hängt an der Systemsprache des Nutzers und liefert z. B. im türkischen Gebietsschema aus `I` ein
   punktloses `ı`; die App läuft auf fremden Rechnern, deren Gebietsschema niemand kennt.
4. In `FORMAT_WHITELIST.video` suchen → Treffer: `{ typ: 'video', endung }`. Sonst in
   `FORMAT_WHITELIST.bild` suchen → Treffer: `{ typ: 'bild', endung }`. Kein Treffer →
   `format_nicht_unterstuetzt`.
5. Die zurückgegebene `endung` ist die **kleingeschriebene** Form ohne Punkt (`mp4`, `jpg`, …), genau
   so, wie sie in der Whitelist steht.

## Eingang → Ausgang
| Eingang | Bedeutung | Grenzen/Validierung |
|---|---|---|
| `dateiname` | Dateiname **oder** vollständiger Pfad der Quelldatei | beliebiger String; leer, ohne Punkt, ohne Endung oder mit unbekannter Endung → `format_nicht_unterstuetzt`. Es wird **nie** auf Existenz geprüft (kein Dateizugriff) |

Ausgang bei Erfolg: `{ ok: true, wert: { typ, endung } }` – `typ` ist `'video'` oder `'bild'`,
`endung` ist kleingeschrieben und ohne Punkt.
Ausgang bei Fehler: Code `format_nicht_unterstuetzt` (geschlossener Satz: dies ist der **einzige**
fachliche Code, den diese Funktion erzeugen kann).

## Verbindliche Invarianten (wörtlich – Verletzung = Issue nicht erfüllt)
- „**Format-Whitelist** kommt aus **einem** konstanten Wert in `contracts/types` (Dialog-Filter
  **und** Import-Prüfung)." (TK 9.4.8, Punkt 7)
- „Der Formatfilter des Dialogs (9.4.3) und die Prüfung beim Import lesen **denselben** konstanten
  Wert aus `contracts/types` — sie dürfen nie auseinanderlaufen." (TK 9.4.2, Invariante)
  → **In dieser Datei steht kein einziges Endungs-Literal.** Kein `'mp4'`, kein `'.jpg'`, keine
  Ersatzliste „für den Fall der Fälle". Jede Endung kommt aus `FORMAT_WHITELIST`.
- **Warum MKV/MOV/AVI ausgeschlossen sind – ausgeschrieben, damit niemand „hilft" und sie ergänzt:**
  „*Begründung:* MP4 ist das einzige Videoformat, das Chromium in der Vorschau (`<video>`)
  zuverlässig nativ abspielt. MKV/MOV/AVI werden **ausgeschlossen** — sie würden im Render (ffmpeg)
  zwar lesbar, aber die Vorschau (P5) bliebe je nach OS **lautlos** schwarz; das widerspricht der
  Pixel-/Darstellungsgleichheit und ist durch keine lokale 30-Zeilen-Entscheidung heilbar.
  Quelldateien in anderen Formaten muss der Nutzer vorab konvertieren." (TK 9.4.2)
  → Dass ffmpeg ein Format lesen könnte, ist **kein** Argument, es zuzulassen. Die Vorschau
  entscheidet, nicht der Render.
- „**`dateiname` = `<uuid>.<ext_kleingeschrieben>`, ohne Verzeichnisanteil.**" (TK 9.4.8, Punkt 1)
  → Deshalb ist die zurückgegebene `endung` **kleingeschrieben** und **ohne** Punkt; der Aufrufer
  setzt daraus `<uuid>.<endung>` zusammen.
- „| `format_nicht_unterstuetzt` | Endung/MIME nicht in der Whitelist (9.4.2) |" (TK 9.4.9)
- **ENTSCHIEDEN – diese Funktion prüft die Endung, nicht den Inhalt.** TK 9.4.9 nennt „Endung/MIME";
  eine Inhaltsprüfung (Magic Bytes, MIME-Sniffing) setzt einen Dateizugriff voraus, den diese reine
  Funktion per Vertrag nicht hat, und wäre zudem nicht ohne echte Datei testbar. Sie prüft deshalb
  ausschließlich die Endung. Das ist bewusst und **keine** Lücke, die du hier schließt: Eine als
  `.mp4` umbenannte MKV-Datei fällt später beim `ffprobe`-Lesen bzw. spätestens im Render auf.
- **Niemals `throw`** – auch nicht bei `dateiname = ''` oder bei seltsamen Zeichen. Diese Funktion
  wird aus einer Auftrags-Ausführung heraus benutzt; eine Ausnahme dort ließe den Auftrag scheitern,
  ohne einen brauchbaren Code zu liefern (TK 9.1.1).
- **Rein und synchron.** Kein `fs`, kein `path.extname` mit Dateizugriff, kein `await`, kein Cache,
  keine globale Variable. Zweimal derselbe Eingang → zweimal dasselbe Ergebnis.

## Fehlerpfade (vollständig)
| Situation | Code | Verhalten |
|---|---|---|
| `dateiname` ist leer oder besteht nur aus Pfadtrennern | `format_nicht_unterstuetzt` | keine Wirkung; Meldung nennt den gelieferten Namen |
| Kein Punkt im letzten Pfadsegment (`C:\Videos\clip`) | `format_nicht_unterstuetzt` | keine Wirkung |
| Punkt nur an erster Stelle (`.gitkeep`) | `format_nicht_unterstuetzt` | keine Wirkung (Dateien ohne Endung, mit führendem Punkt) |
| Endung leer (`film.`) | `format_nicht_unterstuetzt` | keine Wirkung |
| Endung nicht in `FORMAT_WHITELIST` (`film.mkv`, `clip.mov`, `bild.gif`, `text.txt`) | `format_nicht_unterstuetzt` | keine Wirkung; Meldung nennt die abgelehnte Endung und den Hinweis, dass die Datei vorab konvertiert werden muss |
| Punkt im **Ordnernamen**, Datei ohne Endung (`C:\Kampagne.2026\clip`) | `format_nicht_unterstuetzt` | keine Wirkung – die Ordner-Endung wird **nicht** als Datei-Endung gewertet |

Erfolgsfälle zur Klarstellung (keine Fehlerpfade): `FILM.MP4` → `{ typ: 'video', endung: 'mp4' }`;
`Foto.JPEG` → `{ typ: 'bild', endung: 'jpeg' }`; `sommer.aktion.final.png` →
`{ typ: 'bild', endung: 'png' }`.

## Nicht selbst entscheiden – STOPP und fragen
- **Verbot – die Whitelist wird hier nicht dupliziert und nicht erweitert.** Auch nicht „nur MOV,
  das kann ffmpeg doch" und auch nicht `tif`, `bmp`, `heic`. Eine Erweiterung ist eine
  Produktentscheidung und geschieht in `src/shared/contracts/asset.ts` (#13) – einer **fremden**
  Datei (Regel E).
- **Verbot – keine Codec-Prüfung.** Ob ein MP4 H.264 oder H.265 enthält, steht nicht in der Endung
  und wird hier nicht geprüft. Ob H.265 überhaupt zugelassen bleibt, ist in #13 als offener Punkt
  vermerkt und wird hier **nicht** vorweggenommen.
- **Verbot – kein Dateizugriff, auch nicht „nur zum Prüfen, ob es existiert".** Ob `quellPfad` noch
  existiert, ist ein **anderer** Fehlerfall (`datei_nicht_gefunden`) und gehört in den Import-Ablauf
  (M3-08). Zwei Existenzprüfungen an zwei Stellen liefern früher oder später widersprüchliche
  Antworten.
- **Verbot – keine Umbenennung, keine Konvertierung, kein „Reparieren" des Namens.** „jede
  Normalisierung/Konvertierung der Quelldatei (die bleibt **roh**; das Normalisieren auf das Profil
  geschieht erst zur Render-Zeit, 9.2.4/9.2.6)" gehört ausdrücklich **nicht** zum `media-service`
  (TK 9.4.1).
- **Verbot – keine Sonderbehandlung für Aktions-Bilder.** „eine Sonderbehandlung von Aktions-Bildern
  (jedes importierte Bild ist ein gleichwertiges `Asset`)" besitzt der `media-service`
  ausdrücklich **nicht** (TK 9.4.1).
