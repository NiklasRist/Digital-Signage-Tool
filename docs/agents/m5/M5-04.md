### Issue M5-04: [composer] Ein Element zur Wiedergabeliste hinzufügen

## Ziel (in einem Satz)
Aus der Medien- oder Aktions-Bibliothek wird ein Eintrag ans Ende der Wiedergabeliste gestellt –
mit **einer** Referenz, über **einen** Aufruf, und mit den Startwerten, die der `project-store`
festlegt.

## Modul & Datei
- Modul: `composer` [P3] (Renderer)
- Datei: `src/renderer/composer/element-hinzufuegen.ts`
- Vertrag: Technisches Konzept **9.7.2** (Instant-Mutationen des composer), **9.5.2**
  (`fügeElementHinzu`), **9.8.4** (`standardDauer` ist nur ein Default), **9.11.3** (Belegung je
  `art`) – Quelle der Wahrheit
- Prozess/Speicher: P3

## Warum das im Gesamtsystem wichtig ist
Hier entsteht jedes Listenelement. Die gefährliche Versuchung ist, im Renderer **mitzudenken**: die
`art` aus der Dateiendung ableiten, die Startdauer aus `Aktion.standardDauer` selbst setzen, bei
einem Video schon einmal `trimStart: 0` mitschicken. Jede dieser Vorbelegungen ist eine **zweite**
Fachlogik neben #41 – und die beiden laufen bei der nächsten Änderung auseinander. Das Ergebnis wäre
ein Listenelement mit falscher Feldbelegung (z. B. `dauer` gesetzt **und** `trimStart` gesetzt), das
weder der Vorschau noch dem Render eindeutig sagt, was es darstellt.

Der zweite Punkt betrifft die Mehrfachnutzung: Eine Aktion darf **mehrfach** in der Liste stehen
(sie ist referenzierbar, nicht besitzend). Wer hier „schon vorhanden" prüft und den zweiten Eintrag
verhindert, nimmt dem Nutzer genau die Betriebsart weg, für die das Datenmodell gebaut wurde – eine
Werbeaktion mehrfach über die Schleife verteilt.

## Signatur (verbindlich – NICHT ändern)
```ts
// src/renderer/composer/element-hinzufuegen.ts
import type { Listenelement } from '../../shared/contracts/project'
import type { Ergebnis } from '../../shared/contracts/ergebnis'

/** Stellt den Eintrag mit dieser Referenz ans Ende der Liste. `referenz` ist ENTWEDER eine
 *  Asset-ID (Video/Bild) ODER eine Aktions-ID (Segment) – welche es ist, entscheidet der Main. */
export async function fuegeElementHinzu(referenz: string): Promise<Ergebnis<Listenelement>>
```

## Eingang → Ausgang
| Eingang | Bedeutung | Grenzen/Validierung |
|---|---|---|
| `referenz` | Asset-ID **oder** Aktions-ID aus dem geladenen Projekt | nicht leerer String; **keine** Typ-Unterscheidung im Renderer, **keine** Existenzprüfung – das macht #41 |

Ausgang bei Erfolg: das vom `project-store` erzeugte `Listenelement` (mit seiner vom Main vergebenen
UUID und der vom Main gesetzten Feldbelegung); es wird ans **Ende** der Sicht angehängt.
Ausgang bei Fehler: das **unveränderte** `Ergebnis` des Main – bei einer unbekannten Referenz
`nicht_gefunden` (#41). Die Sicht bleibt dann unverändert.

## ENTSCHIEDEN (lokale Festlegungen dieses Issues)
1. **Hinzufügen läuft NICHT optimistisch.** TK 9.7.3 nennt ausdrücklich „Reorder/Trim/Dauer" als die
   optimistisch bedienten Vorgänge – Hinzufügen steht dort nicht. Der zwingende technische Grund:
   Die `id` des neuen Elements ist eine UUID, die **der Main** vergibt (TK 9.11.4). Ein optimistisch
   eingefügtes Element hätte entweder keine oder eine erfundene ID – und beim Abgleich mit dem
   Rückgabestand müsste der Renderer raten, welches der beiden Objekte dasselbe meint. Angehängt
   wird deshalb **erst** das zurückgegebene Element.
2. **Ein Aufruf, eine Referenz.** Keine Stapel-Variante („alle markierten hinzufügen") in dieser
   Datei. Wer mehrere Einträge hinzufügen will, ruft mehrfach auf – und die Reihenfolge der Aufrufe
   ist dann auch die Reihenfolge in der Liste. Begründung: `fügeElementHinzu` (#41) nimmt genau eine
   Referenz; eine Stapelfunktion müsste bei einem Fehlschlag in der Mitte entscheiden, ob sie
   abbricht oder weitermacht – eine Fachentscheidung, die nirgends im Vertrag steht.
3. **Kein Vorfiltern nach `Asset.zustand`.** Ein Asset mit `zustand: 'fehlt'` (#13) wird
   **nicht** vom Hinzufügen ausgeschlossen. Begründung: Ob der Main das blockiert, ist in #41
   ausdrücklich als offener Punkt geführt – eine Renderer-seitige Sperre würde diese Entscheidung
   vorwegnehmen und wäre bei einer anderen Antwort eine stille zweite Regel. Ein kaputtes Element
   fängt ohnehin der Reparatur-Modus (TK 9.7.5, M5-12 bis M5-14).

## Verbindliche Invarianten (wörtlich – Verletzung = Issue nicht erfüllt)
- „**Ausgang – Instant-Mutationen** (`project-store` 9.5.2): `fügeElementHinzu` (Asset- **oder**
  Aktions-Referenz; mehrere Listenelemente dürfen dieselbe Aktion referenzieren)" (TK 9.7.2) – es
  gibt deshalb **keine** „schon in der Liste"-Prüfung und **keine** Entdopplung.
- „`fügeElementHinzu` | `referenz` (Asset- **oder** Aktions-ID) → `Ergebnis<Listenelement>`"
  (TK 9.5.2)
- „**`standardDauer` ist nur ein Default:** … Beim Platzieren wird `standardDauer` als Startwert
  übernommen, danach überschreibbar." (TK 9.8.4) – **der Main** übernimmt sie (#41); diese Datei
  liest `Aktion.standardDauer` **nicht** und schickt **keine** Dauer mit.
- „**`project-store` ist die Wahrheit:** die Liste im composer ist nur eine Sicht; nach jeder
  Mutation mit dem Rückgabestand abgleichen." (TK 9.7.4) – angehängt wird **exakt** das
  zurückgegebene Objekt, nicht eine daraus nachgebaute Variante.
- „**Die Reihenfolge ist die Array-Reihenfolge von `liste`** – es gibt **kein** separates
  `position`-Feld." (TK 9.11.3) – das neue Element kommt ans **Ende**; eine Einfügeposition gibt es
  nicht (Umsortieren danach ist Sache von M5-03).
- „**Ist NICHT:** … bearbeitet **keine** Aktions-Inhalte (`action-editor` [P2]) – er *platziert*
  Aktionen nur" (TK 9.7.1) – diese Datei ändert **nie** eine `Aktion` oder ein `Asset`.

## Fehlerpfade (vollständig)
| Situation | Code | Verhalten |
|---|---|---|
| `referenz` ist leer oder kein String | `ungueltige_eingabe` | **kein** IPC-Aufruf, Sicht unverändert |
| kein Projekt geladen (`holeSicht().projekt === null`) | `ungueltige_eingabe` | **kein** IPC-Aufruf |
| Main antwortet `nicht_gefunden` (Referenz existiert nicht) | Code **unverändert** vom Main | Sicht unverändert; die Meldung wird an den Aufrufer gereicht (Anzeige ist Sache der Oberfläche) |
| Main antwortet mit einem anderen `ok: false` | Code **unverändert** | Sicht unverändert |
| Auto-Speichern schlägt später fehl | – | **kein** Rollback, **keine** Zuständigkeit dieser Datei – das behandelt M5-07 (Klasse 2) |

## Nicht selbst entscheiden – STOPP und fragen
- **Verbot – keine Vorbelegung im Renderer.** Kein `dauer`, kein `trimStart`/`trimEnde`, kein `art`,
  keine `id` wird hier erzeugt oder mitgeschickt. Die Nutzlast ist **ausschließlich**
  `{ referenz }`. Wer hier vorbelegt, baut die Regeln aus #41/TK 9.11.3 ein zweites Mal – und beim
  nächsten Vertragswechsel ändert sich nur eine der beiden Stellen.
- **Verbot – keine Bibliotheks-Oberfläche in dieser Datei.** Woher die `referenz` kommt (Medienliste,
  Aktions-Bibliothek, Drag aus der Bibliothek in die Liste), entscheidet die Oberfläche; diese Datei
  bekommt nur die ID.
- **Verbot – kein Medien-Import.** Ein Import ist ein **Auftrag** über die Warteschlange (TK 9.1.1,
  Punkt 2; `media-service`), kein Instant-Aufruf. Wenn beim Bedienen auffällt, dass ein „Datei
  hinzufügen"-Weg fehlt: Der gehört in den Import-Pfad (`media-service`, M3), **nicht** hierher.
- **Offen: Auswahl/Fokus nach dem Hinzufügen.** Ob das neue Element markiert, in den sichtbaren
  Bereich gescrollt oder direkt zum Bearbeiten geöffnet wird, legt weder AD noch TK fest – das ist
  Verhalten der Oberfläche und wird hier **nicht** entschieden.
