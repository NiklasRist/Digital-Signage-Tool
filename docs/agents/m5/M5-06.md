### Issue M5-06: [composer] Der einheitliche Dauer- und Trim-Regler

## Ziel (in einem Satz)
Ein einziger Bedien-Baustein steuert die effektive Dauer **aller** Elementtypen – Video über zwei
Griffe innerhalb der Quelllänge, Bild und Aktions-Segment über den Dauer-Bereich – und übergibt das
Ergebnis an die jeweils zuständige Instant-Operation.

## Modul & Datei
- Modul: `composer` [P3] (Renderer)
- Datei: `src/renderer/composer/dauer-regler.ts`
- Vertrag: Anforderungsdokument **4.4** (einheitliche Bedienung, FA-06 + FA-14), Technisches Konzept
  **9.5.2** (`setzeTrim`, `setzeDauer`), **9.7.3** (optimistisch), **9.11.3** (Belegung je `art`),
  **9.11.4** (Konstanten) – Quelle der Wahrheit
- Prozess/Speicher: P3

## Warum das im Gesamtsystem wichtig ist
Das Anforderungsdokument verlangt ausdrücklich **einen** Bedien-Baustein für alle Elementtypen –
technisch stehen dahinter aber zwei völlig verschiedene Dinge: ein **Ausschnitt** aus vorhandenem
Material (Video, nicht-destruktiv) und eine frei gewählte **Standzeit** (Bild/Segment). Wenn diese
Datei die Grenzen nicht als einziges Modell liefert, entstehen zwangsläufig zwei Regler mit zwei
Grenzberechnungen; einer davon wird irgendwann die Quelllänge um ein paar Zehntel überschreiten
lassen oder den Bereich 10–45 s anders auslegen. Der Nutzer sieht dann eine Dauer, die der Store
ablehnt – oder schlimmer: eine, die er annimmt und die im Render anders herauskommt.

Der zweite teure Fehler wäre, die Grenzwerte hier als Zahlen hinzuschreiben. `10` und `45` stehen in
**einer** Konstante (TK 9.11.4, #21); die Obergrenze eines Videos ist **immer** `Asset.dauer` und
nie ein geschätzter Wert aus dem Player oder dem Thumbnail.

## Signatur (verbindlich – NICHT ändern)
```ts
// src/renderer/composer/dauer-regler.ts
import type { Listenelement } from '../../shared/contracts/project'
import type { Asset } from '../../shared/contracts/asset'
import type { Ergebnis } from '../../shared/contracts/ergebnis'

/** Das eine Modell hinter dem einen Regler – für Video, Bild und Aktions-Segment gleich geformt. */
export interface ReglerModell {
  elementId: string
  griffe: 1 | 2            // Video: 2 (Anfang/Ende); Bild/Segment: 1 (nur die Länge)
  untergrenze: number      // Sekunden – kleinstmöglicher Wert für `anfang`
  obergrenze: number       // Sekunden – größtmöglicher Wert für `ende`
  anfang: number           // Sekunden – bei Bild/Segment immer 0
  ende: number             // Sekunden
  effektiveDauer: number   // Sekunden = ende − anfang (roh, s. „ENTSCHIEDEN" 3)
}

/** Baut das Modell aus dem Listenelement. `asset` ist das über `element.ref` referenzierte Asset –
 *  nur bei art 'video' nötig, sonst null. */
export function baueReglerModell(
  element: Listenelement,
  asset: Asset | null,
): Ergebnis<ReglerModell>

/** Begrenzt ein gezogenes Griffpaar auf das Modell. Rein rechnend, kein IPC. */
export function begrenze(
  modell: ReglerModell,
  anfang: number,
  ende: number,
): { anfang: number; ende: number }

/** Übernimmt die neuen Grenzen – EIN Einstiegspunkt für alle Elementtypen. */
export async function uebernehmeGrenzen(
  element: Listenelement,
  anfang: number,
  ende: number,
): Promise<Ergebnis<Listenelement>>
```

## Eingang → Ausgang
| Eingang | Bedeutung | Grenzen/Validierung |
|---|---|---|
| `element` | das Listenelement, dessen Dauer bedient wird | `art` entscheidet über Griffe, Grenzen und Zieloperation |
| `asset` | das über `element.ref` referenzierte Asset | nur bei `art: 'video'` erforderlich; muss `typ: 'video'` und eine `dauer` haben |
| `anfang`/`ende` (`begrenze`, `uebernehmeGrenzen`) | die vom Regler gezogenen Sekundenwerte | endliche Zahlen; `anfang < ende` |

**Die Grenzen je `art` (verbindlich):**

| `art` | `griffe` | `untergrenze` | `obergrenze` | `anfang` / `ende` aus | Zieloperation |
|---|---|---|---|---|---|
| `video` | 2 | `0` | `asset.dauer` | `element.trimStart` / `element.trimEnde` | `setzeTrim(elementId, anfang, ende)` (#44) |
| `bild` | 1 | `DAUER_BEREICH.min` | `DAUER_BEREICH.max` | `0` / `element.dauer` | `setzeDauer(elementId, ende − anfang)` (#45) |
| `segment` | 1 | `DAUER_BEREICH.min` | `DAUER_BEREICH.max` | `0` / `element.dauer` | `setzeDauer(elementId, ende − anfang)` (#45) |

Ausgang bei Erfolg (`uebernehmeGrenzen`): das vom Store zurückgegebene, aktualisierte
`Listenelement`; die Sicht trägt danach genau diesen Stand.
Ausgang bei Fehler: das **unveränderte** `Ergebnis` des Main (`ungueltige_eingabe` oder
`nicht_gefunden`, #44/#45); die Sicht steht wieder auf dem Stand **vor** dem Ziehen.

## ENTSCHIEDEN (lokale Festlegungen dieses Issues)
1. **Ein Einstiegspunkt, zwei Zieloperationen.** `uebernehmeGrenzen` verzweigt anhand `element.art`
   auf `setzeTrim` bzw. `setzeDauer` (Tabelle oben). Begründung: Genau so wird „**derselbe**
   Bedien-Baustein" (AD 4.4) strukturell wahr – die Oberfläche kennt nur **einen** Aufruf und kann
   die beiden Fälle gar nicht verschieden behandeln. Zwei Einstiegspunkte hätten unweigerlich zwei
   Bedienlogiken zur Folge.
2. **Bei Bild und Segment ist `anfang` immer 0.** Der Regler hat dort nur einen Griff; die
   übergebene `dauer` ist `ende − anfang`. Ein Aufruf mit `anfang !== 0` auf einem Bild/Segment ist
   ein Programmierfehler und wird mit `ungueltige_eingabe` abgewiesen (Fehlerpfade).
3. **`effektiveDauer` ist die ROHE Differenz, nicht frame-gerundet.** Begründung: `setzeTrim` (#44)
   speichert ausdrücklich die rohen Sekundenwerte, und die Frame-Rundung sitzt beim `render-service`
   (TK 9.2.6). Die Abweichung eines einzelnen Elements liegt unter einem halben Frame und ist
   unsichtbar; **relevant ist die Summe**, und die rechnet M5-08 ausdrücklich frame-gerundet
   (TK 9.7.4). Zwei Rundungsstellen im Renderer wären zwei Regeln – genau das, was 9.2.6 verbietet.
4. **`begrenze` klemmt, es lehnt nicht ab.** Zieht der Nutzer über die Grenze hinaus, wird der Wert
   auf die Grenze gesetzt (kein Sprung, keine Fehlermeldung). Das ist reines Bedienverhalten; die
   fachliche Prüfung bleibt bei #44/#45 – der Renderer ist nicht die Prüfstelle (TK 9.1.1, Punkt 6).
5. **Diese Datei enthält kein JSX.** Sie ist das Modell und der Übergabeweg des Reglers; die
   Darstellung (Balken, Griffe, Zahlenfeld) gehört zur Oberflächen-Datei. Begründung: So sind
   Grenzen, Klemmung und Verzweigung ohne Browser prüfbar.

## Verbindliche Invarianten (wörtlich – Verletzung = Issue nicht erfüllt)
- „Dauer (FA-06) und Trim (FA-14) werden für **alle** Elementtypen über **denselben** Bedien-Baustein
  gesteuert – einen Balken mit Griffen, an denen der Nutzer die effektive Dauer zieht." 
  (Anforderungsdokument 4.4)
- „**Video (FA-14):** zwei Griffe (Anfang/Ende) innerhalb der **Quelllänge** des Videos. Kürzen
  schneidet Anfang/Ende weg; Verlängern ist **nur bis zur Quelllänge** möglich (mehr Material
  existiert nicht). Der Schnitt ist **nicht-destruktiv** – die Originaldatei bleibt unverändert."
  (Anforderungsdokument 4.4)
- „**Bild / Aktions-Segment (FA-06):** die effektive Anzeigedauer ist frei im Bereich **10–45 s**
  einstellbar (Standard 10 s). Da es keine Quelllänge gibt, ist die Obergrenze die konfigurierte
  Maximaldauer; Kürzen und Verlängern laufen über denselben Regler." (Anforderungsdokument 4.4)
- „Der Regler zeigt die aktuelle effektive Dauer numerisch an." (Anforderungsdokument 4.4) –
  `effektiveDauer` ist deshalb Teil des Modells, nicht eine Berechnung der Oberfläche.
- „`setzeTrim` | `elementId`, `trimStart`, `trimEnde` → `Ergebnis<Listenelement>` (validiert
  `0 ≤ start < ende ≤ Videodauer`)" (TK 9.5.2)
- „`setzeDauer` | `elementId`, `dauer` → `Ergebnis<Listenelement>` (validiert Bereich **10–45 s**
  für Bild/Segment)" (TK 9.5.2)
- „Dauer-Bereich | **10–45 s** | Validierung in `setzeDauer` (9.5.2)" (TK 9.11.4) – die Grenzen
  kommen aus `DAUER_BEREICH` (#21), **nie** als Literal in dieser Datei.
- „`video` | `Asset` (typ `video`) | `null` – die Dauer ergibt sich aus dem Trim | gesetzt | erlaubt"
  (TK 9.11.3, Belegungstabelle) – bei einem Video wird **nie** `setzeDauer` gerufen.
- „**Optimistisch mit Abgleich:** Reorder/Trim/Dauer werden **lokal sofort** angezeigt, dann per
  Instant-Op bestätigt; der zurückgegebene Stand wird abgeglichen (nie dauerhaft driften)."
  (TK 9.7.3)
- „**Fehlerklasse 1 – Operation abgelehnt (synchron):** z. B. ungültiger Wert. → optimistischen
  Schritt **rückgängig** machen (letzter bestätigter Stand) + kurze Inline-Meldung." (TK 9.7.3)

## Fehlerpfade (vollständig)
| Situation | Code | Verhalten |
|---|---|---|
| `art: 'video'`, aber `asset` ist `null` oder hat `typ !== 'video'` | `nicht_gefunden` | kein Modell, kein IPC-Aufruf |
| `art: 'video'`, `asset.dauer` ist `null` oder `≤ 0` | `ungueltige_eingabe` | kein Modell (ohne Quelllänge gibt es keine Obergrenze) |
| `art: 'bild'`/`'segment'`, `element.dauer` ist `null` | `ungueltige_eingabe` | kein Modell |
| `anfang`/`ende` nicht endlich (`NaN`, `Infinity`) | `ungueltige_eingabe` | kein IPC-Aufruf |
| `anfang >= ende` nach dem Klemmen | `ungueltige_eingabe` | kein IPC-Aufruf, Sicht unverändert |
| `art: 'bild'`/`'segment'` und `anfang !== 0` | `ungueltige_eingabe` | kein IPC-Aufruf (Programmierfehler des Aufrufers) |
| Store antwortet `ok: false` | Code **unverändert** vom Main | Rollback auf den Stand vor dem Ziehen + Inline-Meldung (Klasse 1) |
| Auto-Speichern schlägt später fehl | – | **kein** Rollback – das behandelt M5-07 (Klasse 2) |

## Nicht selbst entscheiden – STOPP und fragen
- **Kein Mindestabstand der beiden Griffe außer `anfang < ende`.** Ob ein Video-Ausschnitt eine
  praktische Mindestdauer haben muss (ein Frame? eine Sekunde?), führt #44 ausdrücklich als offenen
  Punkt – die Entscheidung fällt dort, nicht hier. Baue **keine** eigene Untergrenze ein; sie wäre
  eine zweite Regel und würde bei einer anderen Antwort still danebenstehen.
- **Kein Raster, keine Rundung auf „schöne" Werte.** Ob `dauer` auf ganze Sekunden oder auf das
  30-fps-Raster eingeschränkt wird, ist in #45 als offener Punkt geführt. Der Regler gibt die
  gezogenen Werte unverändert (nur geklemmt) weiter.
- **Verbot – keine Quelllänge aus anderer Quelle.** Die Obergrenze eines Videos ist **`Asset.dauer`**
  (#13, aus `ffprobe` beim Import). **Nicht** aus einem `<video>`-Element ablesen, **nicht** aus der
  Vorschau, **nicht** schätzen. Ein `<video>` kann je nach Container und Browser eine leicht andere
  Länge melden – dann ließe der Regler einen Wert zu, den #44 ablehnt.
- **Verbot – keine eigene Rollback-Regel.** Die Unterscheidung der zwei Fehlerklassen (TK 9.7.3)
  liegt ausschließlich in M5-07.
- **Offen: Verhalten bei einem Asset mit `zustand: 'fehlt'`.** #44 führt ausdrücklich als offenen
  Punkt, ob `setzeTrim` dann mit der zuletzt bekannten `Asset.dauer` weiterrechnet oder ablehnt.
  Diese Datei baut das Modell vorerst mit der vorhandenen `dauer` (das Element ist ohnehin über den
  Reparatur-Modus markiert) und trifft **keine** eigene Sperre – bei einer anderen Antwort ist das
  hier nachzuziehen.

## Definition of Done
**Ohne Browser prüfbar** (Vitest; `rufeAuf`, die Sicht-Funktionen aus M5-02 und
`fuehreOptimistischAus` werden durch Doppel ersetzt):

- [ ] `baueReglerModell` liefert für ein Video mit `asset.dauer = 90` → `griffe: 2`,
      `untergrenze: 0`, `obergrenze: 90`, `anfang/ende` aus `trimStart`/`trimEnde`
- [ ] `baueReglerModell` liefert für ein `bild` und ein `segment` jeweils `griffe: 1`, `anfang: 0`,
      `untergrenze === DAUER_BEREICH.min`, `obergrenze === DAUER_BEREICH.max`
- [ ] `effektiveDauer === ende − anfang` in allen drei Fällen (kein Runden, kein Formatieren)
- [ ] `begrenze` klemmt Werte unterhalb `untergrenze` und oberhalb `obergrenze` auf die Grenze und
      lässt Werte dazwischen unverändert
- [ ] `uebernehmeGrenzen` ruft für ein `video` **ausschließlich** `KANAELE.project.setzeTrim` mit
      `{ elementId, trimStart, trimEnde }` auf (Spy: `setzeDauer` nachweislich **nicht** gerufen)
- [ ] `uebernehmeGrenzen` ruft für `bild` und `segment` **ausschließlich**
      `KANAELE.project.setzeDauer` mit `{ elementId, dauer: ende − anfang }` auf (Spy: `setzeTrim`
      nachweislich **nicht** gerufen)
- [ ] Nach `ok: true` trägt die Sicht **exakt** das zurückgegebene `Listenelement` (Deep-Vergleich)
- [ ] Nach `ok: false` steht das Element in der Sicht wieder auf seinen Werten vor dem Ziehen
- [ ] Die Zahlen `10` und `45` kommen in der Datei nicht als Literal vor (Grep-Probe); die Grenzen
      stammen aus `DAUER_BEREICH`
- [ ] Die Datei enthält kein `Math.round`/`Math.floor`/`Math.ceil` auf Frame-Basis und keine `30`
      (Grep-Probe) – gerundet wird hier nichts
- [ ] Die Datei enthält kein String-Literal `'project:'`, kein JSX, keinen Import aus `react`,
      kein `window.api`, kein `fs`
- [ ] Alle Fehlerpfade oben liefern den genannten Code (kein `throw` an den Aufrufer)
- [ ] Keine Datei außerhalb von `src/renderer/composer/dauer-regler.ts` (+ zugehörige Testdatei)
      geändert
