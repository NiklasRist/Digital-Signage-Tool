### Issue M5-08: [composer] Gesamtlänge der Wiedergabeliste und die 30-Minuten-Warnung

## Ziel (in einem Satz)
Die angezeigte Gesamtlänge der Wiedergabeliste entsteht aus der Summe der **frame-gerundeten**
Elementdauern – also nach **derselben** Regel, nach der später die Ausgabedatei entsteht – und löst
ab dreißig Minuten eine Warnung aus.

## Modul & Datei
- Modul: `composer` [P3] (Renderer)
- Datei: `src/renderer/composer/gesamtlaenge.ts`
- Vertrag: Technisches Konzept **9.7.4** (Gesamtlänge = frame-gerundete Summe), **9.2.6**
  (Rundungsregel des `render-service`), **9.2.8** (das Band ändert die Elementdauer nie),
  **9.11.3** (Belegung je `art`) – Quelle der Wahrheit
- Prozess/Speicher: P3

## Warum das im Gesamtsystem wichtig ist
Diese Zahl ist das einzige Versprechen, das der `composer` über die **fertige Datei** macht, bevor
sie existiert. Sie muss deshalb exakt so rechnen wie der Render – nicht „ungefähr so".

Der konkrete Fehler, der hier entsteht, wenn man die rohen Sekunden addiert: Jede Trim-Grenze wird
im Render auf das 30-fps-Raster gerundet (TK 9.2.6). Je Video weicht die gerundete Dauer um bis zu
einen halben Frame **je Grenze** von der rohen Sekundendifferenz ab. Bei einem einzelnen Element ist
das unsichtbar; über eine Schleife mit hundert Elementen summiert es sich auf mehrere Sekunden. Die
angezeigte Länge und die echte Datei driften auseinander – und die 30-Minuten-Warnung, die genau an
dieser Summe hängt, schlägt dann zum falschen Zeitpunkt an oder gar nicht.

Der zweite typische Fehlgriff wäre, die Dauern der **Band-Abschnitte** mitzuzählen. Ein Werbeband
läuft **parallel** zum Video; es verlängert die Elementdauer nie. Wer es addiert, zeigt eine Länge
an, die das Doppelte der echten sein kann.

## Signatur (verbindlich – NICHT ändern)
```ts
// src/renderer/composer/gesamtlaenge.ts
import type { Listenelement } from '../../shared/contracts/project'
import type { Ergebnis } from '../../shared/contracts/ergebnis'

export interface Gesamtlaenge {
  frames: number        // Summe der frame-gerundeten Elementdauern, in Frames
  sekunden: number      // frames / RENDER_PROFILE.fps – exaktes Vielfaches von 1/fps
  warnung: boolean      // true, sobald WARNSCHWELLE_SEKUNDEN überschritten ist
}

/** Frames eines einzelnen Elements – dieselbe Rundungsregel wie der render-service (TK 9.2.6). */
export function frameDauer(element: Listenelement): Ergebnis<number>

/** Summe über die ganze Liste. Eine leere Liste ergibt 0 Frames und ist KEIN Fehler. */
export function berechneGesamtlaenge(liste: Listenelement[]): Ergebnis<Gesamtlaenge>

/** Anzeigeform der Länge: "M:SS" unter einer Stunde, sonst "H:MM:SS". */
export function formatiereLaenge(sekunden: number): string

/** Schwelle der Warnung aus TK 9.7 („Gesamtlänge + 30-Minuten-Warnung anzeigen"). */
export const WARNSCHWELLE_SEKUNDEN = 1800
```

## Eingang → Ausgang
| Eingang | Bedeutung | Grenzen/Validierung |
|---|---|---|
| `element` (`frameDauer`) | ein Listenelement der Sicht | die Feldbelegung muss zur `art` passen (TK 9.11.3) |
| `liste` | die vollständige Wiedergabeliste in Array-Reihenfolge | leeres Array erlaubt |
| `sekunden` (`formatiereLaenge`) | Länge in Sekunden | endlich, `≥ 0` |

**Die Rundung je `art` (verbindlich):**

| `art` | Frames | Quelle |
|---|---|---|
| `video` | `round(trimEnde × fps) − round(trimStart × fps)` | TK 9.2.6, wörtlich unten |
| `bild` | `round(dauer × fps)` | TK 9.2.6, „Dieselbe Rundungsregel gilt ausnahmslos" |
| `segment` | `round(dauer × fps)` | TK 9.2.6, dieselbe Stelle |

`fps` kommt **ausschließlich** aus `RENDER_PROFILE.fps` (#18) – die Zahl 30 steht nicht in dieser
Datei.

Ausgang bei Erfolg: `{ frames, sekunden, warnung }`; `sekunden = frames / RENDER_PROFILE.fps`;
`warnung = sekunden > WARNSCHWELLE_SEKUNDEN`.
Ausgang bei Fehler: `ungueltige_eingabe`, wenn ein Element eine Feldbelegung hat, aus der sich keine
Dauer ergibt (s. Fehlerpfade). Die `meldung` nennt die `id` des betroffenen Elements, damit die
Oberfläche darauf zeigen kann.

## ENTSCHIEDEN (lokale Festlegungen dieses Issues)
1. **`round` gilt auch für Bild und Segment.** TK 9.2.6 schreibt die Formel ausdrücklich für den
   Video-Trim aus und stellt im selben Absatz fest: „Dieselbe Rundungsregel gilt ausnahmslos (kein
   `floor` an einer, `round` an anderer Stelle) – sonst weicht die Dauer um einen Frame ab." Damit
   ist die Regel für Standbilder mitentschieden; hier wird **nicht** gerundet abgeschnitten und
   **nicht** aufgerundet. *(Abgrenzung: #45 führt als offenen Punkt, ob `setzeDauer` die **Eingabe**
   auf ein Raster einschränkt. Das ist eine andere Frage – hier geht es um die **Umrechnung** einer
   bereits gespeicherten Dauer in Frames.)*
2. **Die Schwelle ist 30 Minuten, sie warnt nur, und sie liegt lokal in dieser Datei.** TK 9.7 und
   9.7.4 nennen die „30-Minuten-Warnung" zweimal; überschritten heißt **echt größer** als 1800 s
   (genau 30:00 ist noch keine Überschreitung). Die Warnung **blockiert nichts** – TK 9.7.4 nennt
   als blockierenden Grund ausschließlich kaputte Stellen. Die Konstante wird **nicht** in
   `konstanten.ts` (#21) ergänzt: Dort steht laut TK 9.11.4 ein abgeschlossener Satz von fünf
   Werten, und diese Schwelle hat genau **einen** Nutzer – diese Datei.
   **Vermerk für den Auftraggeber:** TK 9.7.4 verweist für die Warnung auf „(5.3)" im
   Anforderungsdokument. Einen Abschnitt 5.3 gibt es dort **nicht** (Abschnitt 5 ist die
   NFA-Tabelle), und die Zahl „30 Minuten" steht **nirgends** im Anforderungsdokument. Der Verweis
   ist nachzuziehen; die Schwelle selbst ist damit nur im TK belegt.
3. **Das Werbeband zählt nicht mit.** `einblendung.abschnitte[].dauer` geht in **keine** Summe ein –
   weder in `frameDauer` noch in `berechneGesamtlaenge`.
4. **Diese Datei ist rein rechnend.** Kein IPC, kein Zustand, kein Abonnement. Sie bekommt die Liste
   übergeben (aus `holeSicht()`, M5-02) und liefert Zahlen. Begründung: So kann sie in jedem
   Zusammenhang benutzt werden – Anzeige, Warnung, spätere Prüfungen – ohne dass eine zweite
   Rechenstelle entsteht.
5. **`formatiereLaenge` rundet die Anzeige auf ganze Sekunden ab** (`Math.floor`), damit die
   angezeigte Zahl nie größer wirkt als die tatsächliche Länge.

## Verbindliche Invarianten (wörtlich – Verletzung = Issue nicht erfüllt)
- „**Gesamtlänge = frame-gerundete Summe** der Elementdauern – **dieselbe** Rundungsregel wie
  `render-service` (9.2.6), sonst weicht die angezeigte Länge von der echten Ausgabedatei ab. Die
  30-Minuten-Warnung (5.3) hängt daran." (TK 9.7.4)
- „Beide Grenzen werden auf **dasselbe** 30-fps-Raster gerundet: `startFrame = round(trimStart × 30)`,
  `endFrame = round(trimEnde × 30)`; behalten werden die Frames `[startFrame, endFrame)`. Die
  effektive Elementdauer ist damit `(endFrame − startFrame) / 30` – **nicht** die rohe
  Sekundendifferenz." (TK 9.2.6)
- „Dieselbe Rundungsregel gilt ausnahmslos (kein `floor` an einer, `round` an anderer Stelle) –
  sonst weicht die Dauer um einen Frame ab." (TK 9.2.6)
- „**`gesamtdauer` zählt gerundete Frame-Dauern:** Die im `RenderResult` gemeldete `gesamtdauer`
  summiert die **gerundeten** Elementdauern (Frame-Anzahl / 30), nicht die rohen Trim-Sekunden –
  sonst driften die angezeigte Gesamtlänge (5.3, 30-Minuten-Warnung) und die tatsächliche Länge der
  Ausgabedatei auseinander." (TK 9.2.6) – **beide** Stellen müssen dieselbe Zahl liefern. Weicht die
  Umsetzung im `render-service` (M6) von der hier festgelegten Regel ab, ist das ein Vertragsfehler:
  **melden**, nicht hier anpassen.
- „Die Elementdauer bestimmt **allein das Video** (Trim). Das Band verlängert oder verkürzt sie
  **nie**." (TK 9.2.8)
- „Abschnitts-Dauern unterliegen **derselben Frame-Rundung** wie alles andere (30 fps, 9.2.6) –
  sonst driftet das Band gegen das Video." (TK 9.2.8) – das betrifft die **Bandspur** im Render, nicht
  die Gesamtlänge der Liste; die Abschnitts-Dauern werden hier **nicht** summiert.
- „**Standbild → Clip:** `"segment"`- und `"bild"`-Items werden als Standbild über ihre `dauer` bei
  30 fps im Profil ausgehalten; harter Schnitt an den Grenzen." (TK 9.2.6) – ihre Dauer ist die
  Elementdauer, ohne Zu- oder Abschlag für Übergänge (es gibt keine).
- „`video` | `Asset` (typ `video`) | `null` – die Dauer ergibt sich aus dem Trim | gesetzt | erlaubt"
  (TK 9.11.3, Belegungstabelle) – bei einem Video wird **nie** `dauer` gelesen, bei Bild/Segment
  **nie** `trimStart`/`trimEnde`.
- „| Bildrate | **30 fps, CFR** (konstant) | Voraussetzung für die Frame-Rundung (9.2.6) |"
  (TK 9.2.4, Tabelle `RenderProfile`) – die Zahl kommt aus `RENDER_PROFILE.fps` (#18), nicht als
  Literal in diese Datei.

## Fehlerpfade (vollständig)
| Situation | Code | Verhalten |
|---|---|---|
| `art: 'video'`, aber `trimStart` oder `trimEnde` ist `null` / nicht endlich | `ungueltige_eingabe` | keine Summe; `meldung` nennt die `id` |
| `art: 'video'`, `trimEnde ≤ trimStart` | `ungueltige_eingabe` | keine Summe; `meldung` nennt die `id` |
| `art: 'bild'`/`'segment'`, `dauer` ist `null` / nicht endlich / `≤ 0` | `ungueltige_eingabe` | keine Summe; `meldung` nennt die `id` |
| `art` ist keiner der drei Werte | `ungueltige_eingabe` | keine Summe; `meldung` nennt die `id` |
| Rundung ergibt für ein Element `0` Frames | `ungueltige_eingabe` | keine Summe; ein Element ohne einen einzigen Frame kann im Render nicht entstehen |
| `liste` ist leer | – (kein Fehler) | `{ frames: 0, sekunden: 0, warnung: false }` |
| ein Element ist „kaputt" (`ref` zeigt auf ein fehlendes Asset) | – (kein Fehler) | zählt normal mit; kaputte Stellen behandelt der Reparatur-Modus (M5-12 ff.), nicht diese Rechnung |

## Nicht selbst entscheiden – STOPP und fragen
- **Verbot – keine zweite Rundungsregel.** Kein `floor`, kein `ceil`, keine „Toleranz", kein
  Epsilon-Vergleich, keine Millisekunden-Zwischenrechnung. Exakt `Math.round(sekunden × fps)` je
  Grenze bzw. je Standbild-Dauer, danach nur noch ganzzahlige Frame-Arithmetik.
- **Verbot – kein Blockieren.** Die Warnung ist eine Warnung. Sie sperrt weder den Render noch das
  Hinzufügen weiterer Elemente; der einzige blockierende Grund im `composer` sind kaputte Stellen
  (TK 9.7.4/9.7.5).
- **Verbot – keine Bandzeiten in der Summe.** `einblendung` wird in dieser Datei nicht gelesen
  (Grep-Probe in der DoD).
- **Verbot – kein Überspringen unbrauchbarer Elemente.** Lässt sich die Dauer eines Elements nicht
  bestimmen, scheitert die **gesamte** Rechnung mit `ungueltige_eingabe` (s. Fehlerpfade). Ein
  Überspringen mit „ungefährer" Länge ist verboten: Es würde eine zu kurze Gesamtlänge
  stillschweigend als Tatsache anzeigen. Wie die Oberfläche diesen Fall darstellt, entscheidet die
  Oberfläche – hier wird dafür **nichts** vorbereitet.
- **Offen: ob die Warnung eine Zahl mitliefern soll** (z. B. „um 4:12 zu lang"). Umgesetzt wird ein
  reines `warnung: boolean`; der Aufrufer hat mit `sekunden` und `WARNSCHWELLE_SEKUNDEN` alles, um
  einen Text zu bilden. Eine zweite, fertig formulierte Meldung in dieser Datei wäre Darstellung.
