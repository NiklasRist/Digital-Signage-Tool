### Issue M5-17: [action-editor] Aktion anlegen und bearbeiten – Titel ist Pflicht

## Ziel (in einem Satz)
Der Nutzer kann eine Aktion mit allen Feldern aus TK 9.8.2 anlegen und später bearbeiten; ein leerer
Titel wird schon in der Oberfläche abgewiesen, und der Speichervorgang läuft ausschließlich über die
Instant-Operationen des `project-store`.

## Modul & Datei
- Modul: `action-editor` (Renderer)
- Datei: `src/renderer/action-editor/aktion-bearbeiten.ts`
- Vertrag: Technisches Konzept **9.8.2** (der `Aktion`-Datensatz), **9.8.3** (Operationen),
  **9.8.4** (Invarianten), **9.5.2** (Instant-Operationen), **9.1.1** (IPC-Konventionen) – Quelle
  der Wahrheit
- Prozess/Speicher: P2; schreibt D1 **mittelbar** über `ipc-client` → `project-store`; **kein**
  Dateisystem, **kein** ffmpeg

## Warum das im Gesamtsystem wichtig ist
Dies ist die Schreibseite des `action-editor` und damit die Stelle, an der die Werbeinhalte des
Studios überhaupt entstehen (FA-02). Drei lokale Fehlentscheidungen wären teuer.

**Erstens der Titel.** „**Titel ist Pflicht:** eine Aktion ohne Titel ist nicht speicherbar."
(TK 9.8.4). Der Main setzt das bereits durch (#38/#39) – aber wenn die Oberfläche es nicht
**vorher** prüft, tippt der Nutzer eine vollständige Aktion, drückt Speichern und bekommt einen
generischen `ungueltige_eingabe`-Fehler zurück, ohne dass ihm gesagt wird, welches Feld gemeint ist.

**Zweitens `standardDauer`.** „**`standardDauer` ist nur ein Default:** maßgeblich für den Render
ist die **Listenelement-Dauer** (composer, Anforderungsdokument 4.4)." (TK 9.8.4) Wer sie hier als
„die Dauer der Aktion" beschriftet oder beim Bearbeiten rückwirkend in bestehende Listenelemente
schreibt, ändert stillschweigend die Länge
bereits zusammengestellter Wiedergabelisten – Aktionen sind referenzierbar, ein einziger Tastendruck
träfe alle Verwendungen gleichzeitig.

**Drittens der Schreibweg.** Läuft eine Änderung an `project:bearbeiteAktion` vorbei (etwa weil die
Oberfläche das `Aktion`-Objekt aus dem Projektzustand direkt mutiert), sieht der Nutzer seine
Änderung, D1 kennt sie aber nicht – und das Auto-Speichern schreibt sie nie auf die Platte.

## Signatur (verbindlich – NICHT ändern)
```ts
// src/renderer/action-editor/aktion-bearbeiten.ts
import type { Aktion } from '../../shared/contracts/aktion'
import type { Ergebnis } from '../../shared/contracts/ergebnis'
import { istAkzentRolle, type AkzentRolle } from './akzentfarbe'

/** Der Entwurf im Formular: alle Felder der Aktion außer der ID, die der Main vergibt. */
export type AktionsEntwurf = Omit<Aktion, 'id'>

/** Feldbezogene Befunde für die Formularanzeige – KEIN IPC-Fehlercode. */
export type EntwurfBefund =
  | { feld: 'titel'; grund: 'leer' }
  | { feld: 'vorlagenId'; grund: 'leer' }
  | { feld: 'standardDauer'; grund: 'ausserhalb_bereich' }
  | { feld: 'akzentfarbe'; grund: 'keine_rolle' }

/** Reine, synchrone Vorabprüfung. Geprüft wird AUSSCHLIESSLICH, was im übergebenen Objekt
 *  tatsächlich vorkommt – ein fehlendes Feld erzeugt KEINEN Befund. Leeres Array heißt
 *  „nichts zu beanstanden", NICHT „vollständig". */
export function pruefeEntwurf(entwurf: Partial<AktionsEntwurf>): EntwurfBefund[]

/** Ein leerer Entwurf mit den Vorbelegungen für „Neue Aktion". */
export function leererEntwurf(vorlagenId: string, akzentfarbe: AkzentRolle): AktionsEntwurf

/** Legt die Aktion über den Kanal `project:erstelleAktion` an.
 *  Prüft ZUSÄTZLICH zu `pruefeEntwurf`, dass die Pflichtfelder überhaupt vorhanden sind. */
export async function legeAktionAn(entwurf: AktionsEntwurf): Promise<Ergebnis<Aktion>>

/** Schreibt geänderte Felder über den Kanal `project:bearbeiteAktion`. */
export async function speichereAktion(
  id: string,
  aenderungen: Partial<AktionsEntwurf>,
): Promise<Ergebnis<Aktion>>
```

**`AktionsEntwurf` ist bewusst `Omit<Aktion, 'id'>` und keine zweite Feldliste.** Eine eigene
Formular-Struktur mit denselben acht Feldern wäre eine zweite Wahrheit über den `Aktion`-Datensatz:
Ein neues Feld in #14 müsste an zwei Stellen nachgezogen werden, und die Abweichung fiele erst beim
Speichern auf. Aus demselben Grund entsteht hier **kein** eigener Aktions-Typ.

**`pruefeEntwurf` ist eine Bequemlichkeit, keine Garantie.** Die verbindliche Prüfung sitzt im Main
(#38/#39) und läuft dort unverändert weiter – „**6. Der Main validiert jede eingehende Nutzlast** –
er vertraut dem Renderer **nicht**." (TK 9.1.1). Diese Funktion existiert nur, damit der Nutzer
den Fehler **vor** dem Absenden am richtigen Feld sieht.

**ENTSCHIEDEN – `pruefeEntwurf` nimmt `Partial<AktionsEntwurf>` und prüft nur vorhandene Felder.**
Beide Schreibwege müssen dieselbe Prüfung benutzen können, und `speichereAktion` schickt
grundsätzlich nur eine **Teilmenge** der Felder (#39: ein nicht mitgeschicktes Feld bleibt
unverändert). Nähme die Prüfung ein vollständiges `AktionsEntwurf` entgegen, passte sie auf
`legeAktionAn`, aber **nicht** auf `speichereAktion` – und der umsetzende Agent baute sich dort eine
zweite, leicht abweichende Prüfung. Es gibt genau **eine** Feldprüfung in dieser Datei. Die
**Vollständigkeit** ist deshalb kein Fall für `pruefeEntwurf`, sondern eine eigene Bedingung in
`legeAktionAn`: Dort müssen `titel`, `vorlagenId` und `akzentfarbe` überhaupt vorhanden sein – bei
einer neuen Aktion gibt es kein „bleibt unverändert", auf das man ausweichen könnte. Dass der
Parameter typseitig ein **vollständiges** `AktionsEntwurf` ist, ersetzt diese Prüfung **nicht**:
Der Entwurf entsteht aus Formulareingaben, und ein `undefined` in einem Pflichtfeld überlebt jede
Typannahme zur Laufzeit. Der Typ dokumentiert die Erwartung, die Prüfung setzt sie durch.

**ENTSCHIEDEN – „nie strenger als der Main" gilt mit genau einer benannten Ausnahme.** Wo der Main
annimmt, nimmt auch diese Datei an – **ausser** bei `standardDauer`. #38 und #39 prüfen dieses Feld
nicht; der Bereich steht aber im Anforderungsdokument 4.4: „die effektive Anzeigedauer ist frei im
Bereich **10–45 s** einstellbar". Der **Bereich** ist seit AD v1.5 / TK v3.16 weiterhin **fest**;
konfigurierbar ist nur der Standardwert darin (TK 9.11.4). Ohne die Prüfung hier gäbe es **nirgends** eine,
und eine Aktion trüge eine `standardDauer` von 300 s, die beim Platzieren als Startwert in ein
Listenelement wanderte (TK 9.8.4) – dort greift dann `setzeDauer` (#45) und lehnt ab, aber erst
Schritte später und an einem anderen Feld. Die Abweichung ist damit **bewusst** und **einseitig**:
Diese Datei ist an dieser einen Stelle strenger, weil der Main dort gar nichts prüft. Sie wird
**nicht** auf weitere Felder ausgedehnt, und die Lücke im Main wird gemeldet (s. STOPP), nicht
stillschweigend hier ersetzt.

**ENTSCHIEDEN – `akzentfarbe` wird gegen die Rollen-Liste geprüft.** `Aktion.akzentfarbe` ist ein
Rollen-Verweis, kein Hex-Wert (#14). Seit TK v3.0 ist das Feld **`string | null`**; `null` heißt
„keine gewählt, es gilt der Markenwert" (TK 9.8.2/9.10.9) und ist ein **gültiger** Wert, kein
Befund – die Prüfung greift nur bei einem **gesetzten** Wert. Geprüft wird mit `istAkzentRolle` aus
M5-20 – derselben
Modulmappe, **keine** zweite Liste hier. Ohne diese Zeile schützt M5-20 die Akzentfarbe zwar beim
Ändern lückenlos, aber der **Anlegepfad** ginge daran vorbei, und ein `#FF4040` landete
unbeanstandet in D1. Die beiden Dateien verweisen wechselseitig aufeinander, benutzen dabei aber
**getrennte** Exporte (hier `istAkzentRolle` + der Typ `AkzentRolle`, dort `speichereAktion`); es
entsteht kein Kreis in der Fachlogik. Aus demselben Grund ist der Parameter von `leererEntwurf` auf
`AkzentRolle` typisiert und nicht auf `string`.

**`speichereAktion` schickt nur die geänderten Felder.** `Partial<AktionsEntwurf>` entspricht genau
dem, was #39 erwartet: „wird `titel` mitgeschickt und ist leer → Fehler; `titel` NICHT mitschicken
lässt den bestehenden Wert unverändert". Ein vollständiges Objekt zu schicken wäre erlaubt, aber
gefährlich: Es überschreibt Felder, die inzwischen woanders geändert wurden, mit dem Stand des
Formulars.

Der umsetzende Agent sieht die anderen Issues **nicht**; deshalb hier vollständig ausgeschrieben:

**Die Nutzlast je Kanal ist festgelegt und wird nicht neu erfunden** (aus der Handler-Tabelle von
#76, der die vierzehn `project`-Kanäle registriert – #77 ist die config-store-Verdrahtung und hält
ausdrücklich fest: „**Die Einträge unter `project` gehören #76**"):

| Kanal | Nutzlast | ruft im Main |
|---|---|---|
| `project:erstelleAktion` | `{ aktionsdaten }` | `erstelleAktion(nutzlast.aktionsdaten)` |
| `project:bearbeiteAktion` | `{ id, aktionsdaten }` | `bearbeiteAktion(nutzlast.id, nutzlast.aktionsdaten)` |

Die Main-Gegenstücke, deren Antwort du unverändert weiterreichst:

```ts
// #38 – src/main/project-store/erstelle-aktion.ts
export async function erstelleAktion(aktionsdaten: Omit<Aktion, 'id'>): Promise<Ergebnis<Aktion>>

// #39 – src/main/project-store/bearbeite-aktion.ts
export async function bearbeiteAktion(
  id: string,
  aktionsdaten: Partial<Omit<Aktion, 'id'>>,
): Promise<Ergebnis<Aktion>>
```

**Weicht die tatsächliche Signatur von der hier ausgeschriebenen ab, ist das ein Vertragsfehler:
melden und NICHT eigenmächtig anpassen.** Wer den Aufruf still an eine abweichende Signatur anpasst,
macht aus einem Vertragsfehler einen unsichtbaren – und dieselbe Funktion existiert dann in zwei
Fassungen im Projekt.

**Der Ablauf von `legeAktionAn`, verbindlich:**

1. **Vollständigkeit:** Fehlt eines der drei Pflichtfelder `titel`, `vorlagenId`, `akzentfarbe` im
   Entwurf ganz (`undefined`), wird **nicht** gesendet; die Antwort ist
   `{ ok: false, fehler: { code: 'ungueltige_eingabe', meldung } }`, und die Meldung nennt das
   fehlende Feld. Diese Stufe gibt es nur hier – `pruefeEntwurf` prüft ausdrücklich **nicht** auf
   Vollständigkeit.
2. `pruefeEntwurf(entwurf)` aufrufen. Ist das Ergebnis **nicht** leer, wird **nicht** gesendet;
   die Funktion antwortet mit `{ ok: false, fehler: { code: 'ungueltige_eingabe', meldung } }`, und
   die Meldung nennt das betroffene Feld im Klartext.
3. Sonst `rufeAuf<Aktion>(KANAELE.project.erstelleAktion, { aktionsdaten: entwurf })` aufrufen.
4. Das Ergebnis **unverändert** zurückgeben – nicht auspacken, nicht umformen, im Fehlerfall
   nicht werfen.

`speichereAktion` läuft gleich, mit drei Unterschieden: Es gibt **keine** Vollständigkeitsstufe
(Schritt 1 entfällt – eine Teilmenge ist hier der Normalfall), geprüft wird über **dieselbe**
Funktion `pruefeEntwurf(aenderungen)` und damit nur, was in `aenderungen` tatsächlich vorkommt (ein
nicht mitgeschickter Titel ist kein leerer Titel), und die Nutzlast lautet
`{ id, aktionsdaten: aenderungen }`.

**`leererEntwurf` – die Vorbelegungen sind entschieden:** `titel: ''`, `beschreibung: null`,
`preis: null`, `bildRef: null`, `cta: null`, `standardDauer: STANDARD_ANZEIGEDAUER_SEKUNDEN` (die
Konstante aus #21, TK 9.11.4 – **kein** Literal `10` in dieser Datei), `vorlagenId` und
`akzentfarbe` wie übergeben. Die beiden Parameter stehen in der Signatur, weil die **Auswahl** der
Vorlage (M5-18) und der Akzentfarbe (M5-20) **nicht** hierher gehört: Diese Datei kennt weder die
Vorlagen-Bibliothek noch die Markenpalette und darf deshalb weder eine `vorlagenId` noch eine
Vorbelegung der Akzentfarbe erfinden – `AKZENT_STANDARD` liegt in M5-20 und wird von dort
**übergeben**, nicht hier eingesetzt. Der Typ `AkzentRolle` am Parameter ist kein Widerspruch dazu:
Er sagt nur, **welche Form** ein gültiger Wert hat, und wählt keinen aus.

## Eingang → Ausgang
| Eingang | Bedeutung | Grenzen/Validierung |
|---|---|---|
| `entwurf` | vollständiger Formularstand einer neuen Aktion | `titel`, `vorlagenId` und `akzentfarbe` müssen **vorhanden** sein (Vollständigkeitsstufe, nur hier); `titel` nach Entfernen der Randleerzeichen nicht leer; `vorlagenId` nicht leer; `standardDauer` entweder `null` oder im Dauer-Bereich; `akzentfarbe` eine Akzent-Rolle |
| `id` | ID der zu bearbeitenden Aktion | nicht leer; die Existenzprüfung macht der Main (`nicht_gefunden`) |
| `aenderungen` | **nur** die geänderten Felder | nicht mitgeschickte Felder bleiben im Main unverändert; ein mitgeschickter leerer `titel` ist ein Fehler |
| Parameter von `pruefeEntwurf` | ein **Teil**-Entwurf: derselbe Eingang für beide Schreibwege | fehlende Felder erzeugen **keinen** Befund; das leere Objekt liefert ein leeres Ergebnis |
| `vorlagenId`, `akzentfarbe` (für `leererEntwurf`) | Vorbelegung aus M5-18 bzw. M5-20 | werden unverändert übernommen und zur Laufzeit **nicht** geprüft; `akzentfarbe` ist über den Typ `AkzentRolle` bereits beim Übersetzen abgesichert |

Ausgang bei Erfolg: `Ergebnis<Aktion>` mit `ok: true` – die vom Main zurückgegebene, vollständige
`Aktion` (bei `legeAktionAn` mit der neu vergebenen `id`). Dieser Rückgabestand ist der maßgebliche;
der Formularstand wird damit abgeglichen, nicht umgekehrt.
Ausgang bei Fehler: `ungueltige_eingabe` (Vorabprüfung oder Main-Prüfung), `nicht_gefunden` (nur bei
`speichereAktion`, wenn die `id` im Projekt nicht existiert), `unbekannter_fehler` (vom Gateway
übersetzte unerwartete Ausnahme). Weitere Codes gibt es hier nicht.

## Verbindliche Invarianten (wörtlich – Verletzung = Issue nicht erfüllt)
- „**Titel ist Pflicht:** eine Aktion ohne Titel ist nicht speicherbar." (TK 9.8.4)
- „**`standardDauer` ist nur ein Default:** maßgeblich für den Render ist die
  **Listenelement-Dauer** (composer, Anforderungsdokument 4.4). Beim Platzieren wird der Startwert
  übernommen, danach ist er überschreibbar." (TK 9.8.4) – der Startwert entsteht seit TK v3.16 über
  die Kette `aktion.standardDauer ?? projekt.standardSegmentdauer ?? 10`; ein `null` in
  `standardDauer` bedeutet seither **folgt dem Projektstandard** und nicht mehr den festen
  10-Sekunden-Rückfall.
- Der `Aktion`-Datensatz, wörtlich (TK 9.8.2):
  ```
  Aktion {
    id:           string
    titel:        string          // Pflicht
    beschreibung: string | null
    preis:        string | null
    bildRef:      string | null   // Referenz auf eine Asset-ID (NICHT eingebettet)
    cta:          string | null   // Call-to-Action, z. B. "Gratis Probetraining"
    standardDauer:number | null   // Default-Anzeigedauer; nur Vorgabe (s. 9.8.4).
                                  //   null = folgt der Projekt-Standarddauer (Project.standardSegmentdauer)
    vorlagenId:   string          // gewählte Vorlage (eingebaut oder eigene, FA-13)
    markeId:      string          // GENAU EINE Marke (FA-23, 9.15.1). Pflicht; vorbelegt mit
                                  //   Project.standardMarkeId. Bestimmt Logo, Schriften und Farb-Rollen
    akzentfarbe:  string | null   // FREIER Hex-Wert (FA-24; bis v3.3 nur Auswahl aus der Palette).
                                  //   ERSETZT beim Zeichnen die Akzent-Rollen der Vorlage (9.10.9).
                                  //   null = Markenwert gilt
  }
  ```
- „Über `project-store` (9.5.2, instant): `erstelleAktion`, `bearbeiteAktion`, `löscheAktion`
  (Kaskade, 9.5.3)." (TK 9.8.3) – es gibt **keinen** anderen Schreibweg für eine Aktion.
- „**Ist NICHT:** platziert Aktionen **nicht** in die Liste (`composer` [P3]); macht **keinen**
  finalen Render; **kein** Dateisystem/ffmpeg (alles über `ipc-client` an den Main)." (TK 9.8.1)
- „**Instant-Op vs. Speichern getrennt:** Eine Instant-Operation (9.5.2) validiert und wendet **im
  Speicher** an, *bevor* sie „ok" meldet – ihr Erfolg bedeutet „gültig übernommen", **nicht** „schon
  auf Platte"." (TK 9.5.4) – ein `ok` heißt hier also **nicht**, dass die Aktion gesichert ist.
- „**6. Der Main validiert jede eingehende Nutzlast** – er vertraut dem Renderer **nicht**.
  Ungültige Eingabe → `ungueltige_eingabe`, **ohne** jede Wirkung auf die Daten. Ein Fehler im
  Renderer darf D1 niemals beschädigen." (TK 9.1.1)
- „**7. Kein stiller Fehlschlag:** Jede Operation antwortet – `ok` oder Code." (TK 9.1.1, Punkt 7)

**Die zwei Fehlerklassen (TK 9.7.3), auch hier gültig:** Wird der Aufruf **synchron abgelehnt**
(`ok: false`), bleibt das Formular auf dem eingegebenen Stand stehen und zeigt die Meldung am
betroffenen Feld – der Nutzer verliert seine Eingabe **nicht**. Scheitert später das
**Auto-Speichern** (asynchron, 9.5.4), wird **nichts** zurückgenommen; dieser Hinweis gehört in die
Anwendungshülle (M6) und nicht in diese Datei.

## Fehlerpfade (vollständig)
| Situation | Code | Verhalten |
|---|---|---|
| `entwurf.titel` ist leer oder nur Leerzeichen | `ungueltige_eingabe` | **kein** IPC-Aufruf; Meldung nennt das Feld `titel` |
| `entwurf.vorlagenId` ist leer | `ungueltige_eingabe` | **kein** IPC-Aufruf; Meldung nennt das Feld `vorlagenId` |
| `entwurf.standardDauer` außerhalb des Dauer-Bereichs | `ungueltige_eingabe` | **kein** IPC-Aufruf; Meldung nennt den erlaubten Bereich. Der Main prüft dieses Feld **nicht** – die Abweichung ist begründet und gewollt |
| `entwurf.akzentfarbe` ist keine Akzent-Rolle (z. B. `'#FF4040'`) | `ungueltige_eingabe` | **kein** IPC-Aufruf; Meldung nennt das Feld `akzentfarbe`. Kein stiller Rückfall auf eine Standardrolle |
| eines der Pflichtfelder fehlt im `entwurf` ganz (nur `legeAktionAn`) | `ungueltige_eingabe` | **kein** IPC-Aufruf; Meldung nennt das fehlende Feld |
| `aenderungen.titel` ist mitgeschickt und leer | `ungueltige_eingabe` | **kein** IPC-Aufruf |
| `aenderungen.akzentfarbe` ist mitgeschickt und keine Akzent-Rolle | `ungueltige_eingabe` | **kein** IPC-Aufruf |
| `entwurf.akzentfarbe` bzw. `aenderungen.akzentfarbe` ist **`null`** | – (**kein** Fehler) | gültiger Wert im Sinne von TK 9.8.2 / 9.10.9: keine Akzentfarbe gewählt, es gilt der Markenwert. Wird unverändert gesendet; **kein** stilles Ersetzen durch `AKZENT_STANDARD` |
| `aenderungen` ist ein leeres Objekt | – | s. „Nicht selbst entscheiden" – **nicht** eigenmächtig als Erfolg oder als Fehler behandeln |
| Main lehnt ab (leerer Titel, fehlende `vorlagenId`) | `ungueltige_eingabe` | Antwort **unverändert** durchreichen; kein zweiter Versuch |
| `id` existiert im Projekt nicht (nur `speichereAktion`) | `nicht_gefunden` | Antwort unverändert durchreichen |
| unerwartete Ausnahme im Main | `unbekannter_fehler` | Antwort unverändert durchreichen; **kein** `throw` in dieser Datei |

## Nicht selbst entscheiden – STOPP und fragen
- **Wird `vorlagenId` gegen die tatsächlich existierende Vorlagen-Bibliothek geprüft – und wenn ja,
  hier?** #38 und #39 lassen diese Frage ausdrücklich offen und vermuten, die tiefere Prüfung
  („existiert diese Vorlage wirklich?") gehöre „erst zum `action-editor` (M5), der die
  Vorlagen-Bibliothek ohnehin kennt – aber das ist eine Architektur-Entscheidung, die zu bestätigen
  ist, nicht stillschweigend anzunehmen". Genau diese Bestätigung fehlt noch. **Nicht selbst
  entscheiden** – melden und `pruefeEntwurf` unverändert lassen.
