## Ziel (in einem Satz)
Jedes Element in der Wiedergabeliste zeigt ein Vorschaubild, damit der Nutzer sieht, was ein Clip zeigt.

## Modul & Datei
- Modul: `composer` (Renderer)
- Datei: `src/renderer/composer/thumbnails.ts`
- Vertrag: Technisches Konzept **9.7.4** (Quelle der Wahrheit)
- Prozess/Speicher: P3

## Warum das im Gesamtsystem wichtig ist
Der Nutzer muss sehen, was ein Clip zeigt. Ohne Thumbnails ist die Liste ein Text-Verzeichnis. Die Logik für Thumbnails ist bereits im Technischen Konzept festgelegt (TK 9.7.4), aber die UI-Komponente fehlt.

## Signatur (verbindlich – NICHT ändern)
```ts
export function baueThumbnailUrl(element: Listenelement, projekt: Project): string | null
```

## Eingang → Ausgang
| Eingang | Bedeutung | Grenzen/Validierung |
|---|---|---|
| `element` | Listenelement | `art: "video" \| "segment"` |
| `projekt` | Projekt | muss geladen sein |

Ausgang bei Erfolg: `media://`-URL für das Thumbnail.
Ausgang bei Fehler: `null` (kein Thumbnail verfügbar).

## Verbindliche Invarianten (wörtlich – Verletzung = Issue nicht erfüllt)
- „Thumbnails renderer-seitig, ohne ffmpeg: Video-Vorschaubild per nativem `<video>` (auf `trimStart` spulen → Frame ins Canvas), Aktions-Segment per `template-canvas` (pixelgleich zur Vorschau)." (TK 9.7.4)
- „Medienzugriff ausschließlich über das `media://`-Protokoll (Pfad-Autorität `project-store`, 9.5.7) – der Renderer sieht nie absolute Pfade." (TK 8)

## Fehlerpfade (vollständig)
| Situation | Code | Verhalten |
|---|---|---|
| Element hat kein Medium | – | `null` zurückgeben |
| Video kann nicht geladen werden | – | `null` zurückgeben |
| Segment ohne Bild | – | `null` zurückgeben |
