### Issue M8-15: [marken-store] importiereMarkenDatei / entferneMarkenDatei

## Ziel (in einem Satz)
Der Nutzer importiert ein Logo oder eine Schriftdatei in eine Marke (Datei wird **kopiert**, die
Marke zeigt danach über `herkunft: 'importiert'` darauf) oder entfernt eine zuvor importierte Datei
wieder (die Marke fällt zurück auf den **geerbten** bzw. **gebündelten** Wert) – dieselbe Datei,
dieselbe Whitelist, das Entfernen ist die Umkehrung des Imports.

## Modul & Datei
- Modul: `marken-store` [V2] (Main)
- Datei: `src/main/marken-store/dateien.ts`
- Vertrag: Technisches Konzept **9.15.1** (Operationstabelle), **9.15.3** (Import-Ablauf,
  Bündelungs-Riegel, Whitelist), **9.4.2**/**9.4.5** (Bild-Whitelist bzw. Import-Ablauf-Vorbild),
  **9.11.2** (Herkunft, Ableitung) – Quelle der Wahrheit
- Prozess/Speicher: V2 (`marken.json`, `marken-assets/<markeId>/`)

## Warum das im Gesamtsystem wichtig ist
Diese Datei ist der **Bündelungs-Riegel**, der mit v3.4 aufgebrochen wird: „Bis v3.3 verwiesen
`Schrift.datei` und `logo.datei` auf **zur Bauzeit gebündelte** Dateien … Eine vom Nutzer angelegte
Marke hätte dort **keine Datei, auf die sie zeigen könnte**." (TK 9.15.3) Ohne eine funktionierende
Datei-Verwaltung bleibt FA-24 („Import von Logo und Schriftdateien") unerfüllbar, und jede
eigenständige oder abgeleitete Marke ohne eigenes Logo hätte **kein** Mittel, überhaupt eines zu
bekommen.

Drei Fehler wären hier besonders teuer, weil sie erst am Fernseher auffallen: **Erstens** eine
fehlende oder falsch geprüfte Whitelist – eine falsch importierte Datei bringt `template-canvas`
(M8-17) in einen Zustand, der nicht mehr dem TK 9.10.3-Determinismus folgt. **Zweitens** ein
Kopiervorgang, der die Quelldatei verändert oder verschiebt – TK 9.15.3 verlangt ausdrücklich „Import
kopiert. Die Quelldatei bleibt unberührt". **Drittens** ein Entfernen, das die Marke ohne gültigen
Rückfallwert zurücklässt: `template-canvas` (9.10.3) verlangt geladene Schriften **vor** dem
Zeichnen – eine Marke mit einer Rolle ohne Datei wäre nicht zeichenbar.

## Signatur (verbindlich – NICHT ändern)
```ts
// src/main/marken-store/dateien.ts
import type { Ergebnis } from '../../shared/contracts/ergebnis'
import type { Marke, SchriftRolle } from '../../shared/contracts/marke'
import type { MarkenFehlercode } from './fehlercodes'
import { FORMAT_WHITELIST } from '../../shared/contracts/asset'
import { ladeBestand } from './schreibe-marken'
import { bearbeiteMarke } from './bearbeite-marke'
import { markenOrdner, loeseMarkenDateiPfad } from './pfade'
import { eingebauteMarke } from './anfangsbestand'

// Fremde Aufrufe – vollstaendige Signaturen, damit hier nichts geraten wird:
//   #13:   export const FORMAT_WHITELIST = {
//            video: ['mp4'] as const,
//            bild: ['jpg', 'jpeg', 'png', 'webp'] as const,
//          } as const                                    // src/shared/contracts/asset.ts
//   M8-03: ladeBestand(): Promise<Ergebnis<MarkenEintrag[], MarkenFehlercode>>
//   M8-11: bearbeiteMarke(markeId: string, teilwerte: MarkenTeilwerte): Promise<Ergebnis<Marke, MarkenFehlercode>>
//          // MarkenTeilwerte.logo: MarkenFeld<{datei,herkunft,seitenverhaeltnis} | null>
//          // MarkenTeilwerte.schriften: Partial<Record<SchriftRolle, MarkenFeld<Schrift>>>
//          // MarkenFeld<T> = T | { geerbt: true }
//   M8-14: markenOrdner(markeId: string): string
//          loeseMarkenDateiPfad(markeId: string, dateiname: string): Ergebnis<string, MarkenFehlercode>
//   M8-06: eingebauteMarke(): MarkenEintrag   // liefert die GEBÜNDELTEN Standardwerte (vier
//          // OFL-Schriften, Fitnessworld24-Logo), aus denen der gebündelte Rückfall entnommen wird
//   M8-02: type MarkenFehlercode =
//            'marke_referenziert' | 'marke_eingebaut' | 'marke_nicht_gefunden'
//            | 'marken_datei_fehlt' | 'speicher_fehler'

/** Nur .woff2 – "ein Ladepfad statt zwei" (TK 9.15.3). Modul-lokal: KEINE Bild-/Video-Endung, also
 *  keine Erweiterung von FORMAT_WHITELIST (#13), die ausschließlich Projekt-Assets beschreibt. */
export const MARKEN_SCHRIFT_ENDUNG = 'woff2'

export async function importiereMarkenDatei(
  markeId: string,
  art: 'logo' | 'schrift',
  schriftRolle: SchriftRolle | null,
  quellPfad: string,
): Promise<Ergebnis<Marke, MarkenFehlercode>>
// - art === 'schrift'  => schriftRolle ist PFLICHT (eine der 4 SchriftRolle-Werte)
// - art === 'logo'     => schriftRolle MUSS null sein
// - kopiert quellPfad in einen NEUEN, mit dieser Version noch NICHT entschiedenen Zieldateinamen
//   innerhalb von markenOrdner(markeId) (s. STOPP-Block) und aktualisiert die Marke über
//   bearbeiteMarke mit herkunft: 'importiert'

export async function entferneMarkenDatei(
  markeId: string,
  art: 'logo' | 'schrift',
  schriftRolle: SchriftRolle | null,
): Promise<Ergebnis<Marke, MarkenFehlercode>>
// - loescht die zuvor importierte Datei aus markenOrdner(markeId) (falls physisch vorhanden)
// - setzt das Feld ueber bearbeiteMarke zurueck: bei parent !== null auf { geerbt: true },
//   sonst (eigenstaendig ODER eingebaut) auf den GEBUENDELTEN Wert aus eingebauteMarke()
```

**Warum `schriftRolle` ein Pflichtparameter mit `| null` ist und nicht optional.** Wie bei
`erstelleVorlage`s `höhe` (M4-06/M8-10): Ein wirklich optionaler Parameter **in der Mitte** ist in
TypeScript nicht ausdrückbar, ohne die von TK 9.15.1 vorgegebene Reihenfolge `markeId, art,
schriftRolle?, quellPfad` zu verlassen. Mit `SchriftRolle | null` muss der Aufrufer bei `art:
'logo'` ausdrücklich `null` übergeben statt das Argument zu vergessen.

## Eingang → Ausgang
| Eingang | Bedeutung | Grenzen/Validierung |
|---|---|---|
| `markeId` | Ziel-Marke | muss im Bestand stehen |
| `art` | `'logo'` oder `'schrift'` | genau einer der zwei Werte |
| `schriftRolle` | welche `SchriftRolle` befüllt wird | `null` bei `art: 'logo'`; bei `art: 'schrift'` eine der 4 bekannten Rollen, sonst `ungueltige_eingabe` |
| `quellPfad` (nur Import) | absoluter Pfad der Quelldatei | Endung muss zur Whitelist der `art` passen: `.woff2` für Schriften, `FORMAT_WHITELIST.bild` (`jpg`, `jpeg`, `png`, `webp`) für Logos |

Ausgang bei Erfolg: `Ergebnis<Marke>` – die **aufgelöste** Marke nach der Änderung (importiert:
`herkunft: 'importiert'` am geänderten Feld; entfernt: `herkunft: 'gebuendelt'` bzw. geerbt).
Ausgang bei Fehler: `ungueltige_eingabe` (Validierung, falsches Format), `marke_nicht_gefunden`,
`speicher_fehler` (Kopieren, Löschen oder das Schreiben von `marken.json` schlägt fehl),
`unbekannter_fehler`.

## Verbindliche Invarianten (wörtlich – Verletzung = Issue nicht erfüllt)
- Die Operations-Zeilen, wörtlich (TK 9.15.1): „`importiereMarkenDatei` | `markeId`, `art:
  "logo"\|"schrift"`, `schriftRolle?`, `quellPfad` → `Ergebnis<Marke>` (kopiert nach
  `marken-assets/<markeId>/`, 9.15.3)" / „`entferneMarkenDatei` | `markeId`, `art`, `schriftRolle?`
  → `Ergebnis<Marke>` – zurück auf den geerbten bzw. gebündelten Wert"
- „**Import kopiert.** Die Quelldatei bleibt unberührt, die Kopie gehört der Marke – wie beim
  Medien-Import (9.4.5). Format-Whitelist: **`.woff2`** für Schriften, die Bild-Whitelist (9.4.2)
  für Logos." (TK 9.15.3)
- „*Nur `.woff2`, weil die gebündelten Schriften dasselbe Format haben: ein Ladepfad statt zwei, und
  `FontFace` verlangt für andere Formate eigene Behandlung.*" (TK 9.15.3)
- „**Zwei Herkünfte, eine Auflösung.** `gebuendelt` löst auf den Bundle-Pfad auf …, `importiert` auf
  `marken-assets/<markeId>/`." (TK 9.15.3)
- „**Ablage neben den Daten, nicht im Programmordner.** `marken-assets/` liegt im Datenort
  (Abschnitt 6). So wandern importierte Schriften mit den Daten – bei portabler Auslieferung genau
  richtig." (TK 9.15.3)
- „**Lizenzen:** Für importierte Schriften trägt der Nutzer die Rechte (Risiko R-07)." (TK 9.15.3)
  – diese Funktion prüft **keine** Lizenz, sie kopiert nur; der Hinweis ist Sache des Editors
  (M8-24).
- „Der Main validiert jede eingehende Nutzlast – er vertraut dem Renderer **nicht**." (TK 9.1.1,
  Punkt 6)
- Die Bild-Whitelist, wörtlich (TK 9.4.2): „`bild` | JPG, PNG, WebP" – bezogen aus `FORMAT_WHITELIST`
  (#13), **nicht** neu geschrieben (dieselbe Invariante wie in M3-03/M3-04: „Der Formatfilter des
  Dialogs und die Prüfung beim Import lesen **denselben** konstanten Wert").

## Fehlerpfade (vollständig)
| Situation | Code | Verhalten |
|---|---|---|
| `markeId` unbekannt | `marke_nicht_gefunden` | keine Wirkung |
| `art` ist kein Wert der Union | `ungueltige_eingabe` | keine Wirkung |
| `art === 'logo'` und `schriftRolle !== null` | `ungueltige_eingabe` | keine Wirkung |
| `art === 'schrift'` und `schriftRolle` ist keine der 4 bekannten Rollen | `ungueltige_eingabe` | keine Wirkung |
| (Import) Endung von `quellPfad` nicht in der passenden Whitelist | `ungueltige_eingabe` | keine Wirkung, **kein** Kopiervorgang; Meldung nennt die erlaubten Formate |
| (Import) `quellPfad` nicht lesbar (fehlt, keine Rechte) | `speicher_fehler` | keine Wirkung; **kein** Änderungsversuch an `marken.json` |
| (Import) Kopieren scheitert (Platte voll, Rechte am Ziel) | `speicher_fehler` | Ziel bleibt unangetastet; `marken.json` wird **nicht** geändert |
| (Import) das Schreiben von `marken.json` (über `bearbeiteMarke`) schlägt fehl, obwohl die Datei bereits kopiert ist | `speicher_fehler` | die kopierte Datei wird **best effort** wieder entfernt (s. STOPP – Rest-Risiko bei Absturz genau dazwischen bleibt) |
| (Entfernen) Für die genannte `art`/`schriftRolle` ist gar keine importierte Datei gesetzt | – (kein Fehler) | `{ ok: true }` mit der unveränderten, aufgelösten Marke – Entfernen von „nichts" ist kein Fehler |
| (Entfernen) physische Datei fehlt bereits, `marken.json`-Feld ist aber noch `importiert` | – (kein Fehler) | das Feld wird trotzdem zurückgesetzt (Reparatur, kein Blockieren) |
| (Entfernen) `fs.unlink` scheitert dauerhaft (`EBUSY`/`EPERM` unter Windows nach Retry) | `speicher_fehler` | `marken.json` wird **nicht** geändert – sonst zeigte die Marke auf eine Datei, die laut Metadaten nicht mehr existiert, aber physisch noch da ist |
| unerwartete Ausnahme | `unbekannter_fehler` | gefangen und als Hülle gemeldet, kein `throw` |

## Nicht selbst entscheiden – STOPP und fragen
- **ECHTE OFFENE FRAGE (vom TK nicht beantwortet): Wie heißt die Zieldatei, und was passiert bei
  einem Namenskonflikt?** Drei plausible Varianten, mit unterschiedlichen Folgefragen:
  1. **Rollenbasiert, deterministisch** (`headlineElegant.woff2`, `logo.png`/`.jpg`/…): Ein
     erneuter Import für dieselbe Rolle **ersetzt** automatisch die vorherige Datei – „Namenskonflikt"
     gibt es dann per Definition nicht, aber ein Rückfall der Bild-**Endung** (z. B. `logo.png` wird
     durch ein neues `logo.jpg` ersetzt) hinterlässt eine **verwaiste** `logo.png`, wenn sie nicht
     explizit vorher gelöscht wird.
  2. **Originalname, sanitisiert:** Zwei Importe mit demselben Originalnamen (z. B. zwei
     verschiedene Marken-Betreuer laden beide `logo.png` hoch) würden sich **innerhalb derselben
     Marke** nur bei einem zweiten Import für dieselbe Rolle überschneiden – dann ist die Frage
     „überschreiben oder ablehnen" dieselbe wie oben.
  3. **Neutral generiert** (`erzeugeId() + '.' + endung`): Kollisionsfrei, aber jeder erneute Import
     lässt die **alte** Datei als Waise zurück, wenn sie nicht explizit gelöscht wird – und es gibt
     (anders als bei Projekt-Medien, TK 9.4.7) **keinen** angekündigten Reconcile-Mechanismus für
     `marken-assets/`, der solche Waisen beim Start aufräumt.
  **Keine dieser drei Varianten wird hier gewählt.** Die Entscheidung bestimmt zugleich, ob überhaupt
  ein „Datei mit gleichem Namen existiert schon"-Fall eintreten kann und, falls ja, ob er als
  **Ersetzen** (kein Fehler) oder als **Konflikt** (eigener Code, den der geschlossene Fehlercode-Satz
  aus TK 9.15.5 **nicht** vorsieht) behandelt wird. **Nicht raten.**
- **ECHTE OFFENE FRAGE: Woher kommt `seitenverhaeltnis` für ein importiertes Logo?**
  `Marke.logo` verlangt `{ datei, herkunft, seitenverhaeltnis }` (TK 9.11.2). Der `media-service`
  ermittelt Bildmaße über **ffprobe** (TK 9.4.5/9.4.8), das ohnehin mitgeliefert wird (Abschnitt 3).
  Ob diese Funktion denselben Weg (ffprobe auf die kopierte Datei) geht oder eine leichtere
  Bild-Bibliothek verwendet, legt der Vertrag nicht fest – beides hat reale Kosten (ffprobe:
  zusätzlicher Prozessstart für eine reine Bildmaß-Abfrage; eine zweite Bibliothek: zweiter
  Codepfad für dieselbe Aufgabe, den `media-service` schon löst). **Nicht selbst wählen.**
- **Verbot – kein Rollback des Kopiervorgangs bei einem Absturz genau zwischen Kopieren und
  Schreiben.** Wie beim Medien-Import (TK 9.4.5: „Crash nach 3 vor 4 → eine fertige Waise ohne
  D1-Eintrag. Beides räumt der Reconcile (9.4.7) auf.") bleibt dieses Restrisiko bestehen; **anders**
  als dort gibt es für `marken-assets/` aber **keinen** angekündigten Reconcile – das ist dieselbe
  offene Frage wie oben und wird hier **nicht** durch einen selbst erfundenen Aufräum-Mechanismus
  geschlossen.
- **Verbot – keine Lizenzprüfung.** Diese Funktion kopiert; ob eine importierte Schrift lizenzrechtlich
  zulässig ist (R-07), entscheidet der Nutzer, angezeigt vom Editor (M8-24).

## Definition of Done
- [ ] Import eines gültigen `.woff2` für `schriftRolle: 'headlineElegant'` liefert eine Marke, deren
      `schriften.headlineElegant.herkunft === 'importiert'`; die kopierte Datei liegt innerhalb von
      `markenOrdner(markeId)` (Pfad über `loeseMarkenDateiPfad`, M8-14, nachweisbar)
- [ ] Nach dem Import ist die **Quelldatei** an `quellPfad` unverändert vorhanden und byte-identisch
      zur Kopie (Test vergleicht Inhalt und Existenz)
- [ ] Import einer `.ttf`-Datei für `art: 'schrift'` liefert `ungueltige_eingabe`, **kein**
      Kopiervorgang (Spy auf `fs.copyFile`/`fs.rename`: null Aufrufe)
- [ ] Import einer `.mp4`-Datei für `art: 'logo'` liefert `ungueltige_eingabe`, kein Kopiervorgang
- [ ] Import eines gültigen Bildformats (`jpg`, `jpeg`, `png`, `webp`) für `art: 'logo'` gelingt
      jeweils; die Formate kommen nachweislich aus `FORMAT_WHITELIST.bild` (#13), nicht aus einer
      hier neu geschriebenen Liste – Grep-Probe auf ein zweites Whitelist-Array
- [ ] `art: 'logo'` mit gesetztem `schriftRolle` liefert `ungueltige_eingabe`
- [ ] `art: 'schrift'` mit `schriftRolle: null` liefert `ungueltige_eingabe`
- [ ] Import mit unbekannter `markeId` liefert `marke_nicht_gefunden`, kein Kopiervorgang
- [ ] `entferneMarkenDatei` auf einer **abgeleiteten** Marke setzt das Feld über `bearbeiteMarke`
      mit `{ geerbt: true }` (Spy prüft das übergebene `teilwerte`-Objekt)
- [ ] `entferneMarkenDatei` auf einer **eigenständigen** Marke setzt das Feld über `bearbeiteMarke`
      auf den konkreten Wert aus `eingebauteMarke()` mit `herkunft: 'gebuendelt'` (Spy)
- [ ] `entferneMarkenDatei` löscht die zuvor importierte physische Datei (Test: Datei existiert nach
      dem Aufruf nicht mehr)
- [ ] `entferneMarkenDatei` für eine Rolle ohne importierte Datei liefert `{ ok: true }` mit der
      unveränderten Marke, **kein** Fehler
- [ ] Scheitert das Kopieren (Platte voll simuliert), wird `marken.json` **nicht** geändert (Spy:
      `bearbeiteMarke` nicht aufgerufen)
- [ ] Alle Fehlerpfade oben liefern den genannten Code (kein `throw` über die IPC-Grenze)
- [ ] Keine Datei außerhalb von `src/main/marken-store/dateien.ts` (+ zugehörige Testdatei) geändert
