### Issue M8-28: [marken-editor] Kontrast-Warnung zwischen Akzentfläche und Text (FA-24)

## Ziel (in einem Satz)
Der Marken-Editor zeigt **sichtbar, aber ohne die Auswahl zu verhindern**, wenn die Akzentfarbe einer
Marke zu wenig Kontrast zu ihrem eigenen Text bietet – berechnet ausschließlich über die **zwei**
geteilten Funktionen aus M8-19, die diese Datei braucht (`kontrastVerhaeltnis` und
`erreichtKontrastSchwelle`; die dritte, `waehleBesserenKontrast`, gehört M8-20), nicht durch eine
zweite, eigene Formel.

## Modul & Datei
- Modul: `marken-editor` (Renderer)
- Datei: `src/renderer/marken-editor/kontrast-warnung.tsx`
- Vertrag: Technisches Konzept **9.15.2** (Kontrast-Warnung), **9.10.10** (dieselbe Rechnung beim
  Ersatz-Logo), **9.10.9** (Akzent-Rollen) – Quelle der Wahrheit
- Prozess/Speicher: – (reine Renderer-UI; kein IPC, kein Dateisystem, kein Speicher)

## Warum das im Gesamtsystem wichtig ist
FA-24 verlangt eine sichtbare Warnung, **keine** Sperre: Seit FA-24 ist die Akzentfarbe ein freier
Hex-Wert, damit Partner-Hausfarben darstellbar sind – ein Schwellenwert, der die Auswahl verhindert,
machte genau eine echte Hausfarbe unbrauchbar (Risiko R-08). Die Restverantwortung für die Lesbarkeit
bleibt beim Nutzer; die Anwendung informiert nur.

Die teure lokale Entscheidung liegt **nicht** in der UI, sondern darin, die Rechnung **nicht ein
zweites Mal zu bauen**. M8-19 begründet das ausdrücklich: „Würde jede Stelle ihre eigene
Kontrastformel schreiben, liefe früher oder später eine Konstellation durch, bei der der Editor eine
Farbkombination als „ausreichend" durchwinkt, während dieselbe Rechnung im Canvas [beim Ersatz-Logo,
M8-20] zu einer anderen Textfarben-Entscheidung käme." Diese Datei ruft deshalb **ausschließlich**
`kontrastVerhaeltnis` und `erreichtKontrastSchwelle` aus `src/renderer/gemeinsam/kontrast.ts` auf und
berechnet nichts selbst nach. *(M8-19 exportiert **drei** Funktionen; die dritte,
`waehleBesserenKontrast`, wird hier **nicht** gebraucht – sie gehört dem Ersatz-Logo, M8-20. Diese
Datei braucht zusätzlich die **Zahl**, deshalb `kontrastVerhaeltnis` für beide Kandidaten statt nur
die Auswahl.)*

```ts
import type { Marke } from '../../shared/contracts/marke'
import { erreichtKontrastSchwelle, kontrastVerhaeltnis } from '../gemeinsam/kontrast'

export interface Kontrasthinweis {
  verhaeltnis: number    // aus kontrastVerhaeltnis(marke.farben.akzent, marke.farben.<textRolle>)
  ausreichend: boolean   // aus erreichtKontrastSchwelle(...) mit demselben Farbpaar und `schwellenwert`
}

/**
 * Reine Ableitung: liest NUR marke.farben und ruft AUSSCHLIESSLICH die beiden Funktionen aus M8-19
 * auf. Prüft die Fläche `akzent` gegen `textAufDunkel` UND gegen `textAufHell` und meldet den
 * BESSEREN der beiden Werte – dieselben zwei Kandidaten, mit denen 9.10.10 die Textfarbe des
 * Ersatz-Logos wählt (M8-20 nutzt dafür `waehleBesserenKontrast`; diese Datei braucht zusätzlich die
 * Zahl, deshalb `kontrastVerhaeltnis` für beide Kandidaten statt nur die Auswahl).
 *
 * `schwellenwert` ist PFLICHT-Parameter – GENAU wie bei `erreichtKontrastSchwelle` selbst (M8-19)
 * KEIN Vorgabewert, KEINE Konstante in dieser Datei. Der Zahlenwert ist seit TK v3.10 entschieden
 * (4,5:1, WCAG AA) und steht als KONTRAST_SCHWELLE in src/shared/contracts/konstanten.ts (M8-47);
 * gelesen und hereingereicht wird er von der Editor-Wurzel M8-48 - nicht von hier.
 */
export function ermittleKontrastHinweis(marke: Marke, schwellenwert: number): Kontrasthinweis {
  const vAufDunkel = kontrastVerhaeltnis(marke.farben.akzent, marke.farben.textAufDunkel)
  const vAufHell = kontrastVerhaeltnis(marke.farben.akzent, marke.farben.textAufHell)
  const verhaeltnis = Math.max(vAufDunkel, vAufHell)
  return {
    verhaeltnis,
    ausreichend: erreichtKontrastSchwelle(
      vAufDunkel >= vAufHell ? marke.farben.textAufDunkel : marke.farben.textAufHell,
      marke.farben.akzent,
      schwellenwert,
    ),
  }
}

export interface KontrastWarnungProps {
  marke: Marke
  schwellenwert: number   // KONTRAST_SCHWELLE (4.5), gelesen und uebergeben von M8-48 – NICHT hier
                          // festlegen, NICHT importieren, KEIN Vorgabewert
}

/**

 * nicht-blockierenden Hinweis. Es gibt KEINEN Bestätigungs-Dialog, KEINEN deaktivierten
 * Speichern-Knopf und KEINE zweite Bestätigung – „warnen, nicht blockieren" (FA-24).
 */
export function KontrastWarnung(props: KontrastWarnungProps): JSX.Element | null
```

## Eingang → Ausgang
| Eingang | Bedeutung | Grenzen/Validierung |
|---|---|---|
| `marke` (Prop) | die im Editor gerade bearbeitete, **aufgelöste** Marke (Vererbung bereits angewendet, TK 9.11.2) | keine eigene Prüfung; `farben.akzent`/`textAufDunkel`/`textAufHell` sind laut `Marke`-Vertrag **immer gesetzt** (die aufgelöste Marke ist vollständig) – **aber nicht zwingend 6-stellig**: TK 9.11.2 sagt „Hex, 6- oder 8-stellig (8 = mit Alpha)", und `kontrastVerhaeltnis` (M8-19) **wirft** bei 8-stelligen Werten. Was das für diese Datei heißt, ist eine **offene Frage**, s. STOPP |
| `schwellenwert` (Prop) | die Mindest-Kontrastschwelle – in der Anwendung immer `KONTRAST_SCHWELLE` (`4.5`, TK v3.10), gelesen und übergeben von der Editor-Wurzel **M8-48** | endliche Zahl `> 0`; diese Datei bewertet sie nicht inhaltlich (dieselbe Nicht-Prüfung wie in M8-19) und setzt **keinen** Vorgabewert |

Ausgang bei „ausreichendem" Kontrast: `KontrastWarnung` liefert `null` – keine sichtbare Änderung.
Ausgang bei unzureichendem Kontrast: `KontrastWarnung` liefert ein sichtbares Hinweis-Element; das
`verhaeltnis` aus `ermittleKontrastHinweis(marke, schwellenwert)` darf im Text angezeigt werden. Es
gibt **keinen** Fehlerausgang – diese Funktionen überqueren keine IPC-Grenze; ein für M8-19
ungültiges Hex-Format lässt `kontrastVerhaeltnis`/`erreichtKontrastSchwelle` werfen, und diese Datei
fängt das **nicht** ab. **Achtung, das ist keine theoretische Lage:** `marke.farben`-Werte sind laut
Typ Hex-Strings, laut TK 9.11.2 aber „6- **oder 8-stellig**", während M8-19 nur `#RRGGBB` annimmt.
Ein 8-stelliger Markenwert lässt diese Komponente also **werfen**, statt eine Warnung zu zeigen –
siehe den STOPP-Punkt dazu; **hier wird das weder abgefangen noch stillschweigend zurechtgeschnitten**.

## Nicht selbst entscheiden – STOPP und fragen
- **ERLEDIGT – nicht mehr melden: Der `schwellenwert` ist `4,5:1`, und er kommt weiterhin von außen.**
  Der Befund war: Weder TK 9.15.2 noch FA-24 noch R-08 nannten eine Zahl; M8-19 verweigerte sich der
  Entscheidung und benannte **dieses** Issue als den Ort, an dem sie fällt oder erfragt wird.
  **Entschieden** (Auftraggeber, 11.08.2026; im Technischen Konzept nachgezogen als **v3.10**, 9.15.2
  und 9.11.4): **4,5 : 1 – WCAG AA für Fließtext**, geführt als geteilte Konstante
  **`KONTRAST_SCHWELLE`** in `src/shared/contracts/konstanten.ts` (angelegt von **M8-47**).

  **Was das für DIESE Datei heißt – der Vertrag ändert sich NICHT:**
  `KontrastWarnungProps.schwellenwert` und der zweite Parameter von `ermittleKontrastHinweis` bleiben
  **Pflicht ohne Vorgabewert**, und **diese Datei importiert `KONTRAST_SCHWELLE` NICHT**. Geliefert
  wird der Wert von der **Wurzel-Komponente des Marken-Editors (M8-48)**, die die Konstante als
  einzige liest und als Prop hereinreicht – wörtlich dort festgelegt: „**Der Kontrast-Schwellenwert
  wird importiert, nicht geschrieben.** `KontrastWarnungProps.schwellenwert` ist ein Pflicht-Prop ohne
  Vorgabewert (M8-28) […] Diese Datei liest **ausschließlich** die Konstante aus
  `src/shared/contracts/konstanten.ts` und schreibt die Zahl **nirgends** selbst hin" (M8-48,
  ENTSCHIEDEN 7).

  **Warum durchreichen und nicht selbst importieren – gegen das Muster von M8-35 abgewogen:** M8-35
  importiert `SICHERHEITSABSTAND_BEREICH` **selbst**, weil es die Grenze **durchsetzt**: Es lehnt
  einen Wert ab, **bevor** ein IPC-Aufruf entsteht, und muss die Schranke deshalb an Ort und Stelle
  kennen. Diese Datei setzt nichts durch – sie **zeigt an** und liefert `null`, wenn nichts zu zeigen
  ist. Dazu kommt das Entscheidende: **M8-48 existiert bereits und importiert die Konstante schon.**
  Würde diese Datei sie **zusätzlich** importieren, gäbe es zwei Lesestellen für dieselbe Zahl und
  einen Prop, den niemand mehr braucht, aber jeder noch setzen muss – genau die Doppelung, die
  TK 9.15.2 mit „**Die Zahl steht an genau einer Stelle**" ausschließt. **Eine Lesestelle (M8-48),
  ein Durchreicher (diese Datei), ein Rechner (M8-19).**

  **Das Verbot bleibt deshalb wortgleich bestehen** (s. unten): kein `4.5` als Literal in dieser
  Datei, kein Vorgabewert am Prop, keine eigene Konstante.
- **ECHTE OFFENE FRAGE, von M8-19 hierher übergeben: Was geschieht bei einem 8-stelligen Hex-Wert
  (mit Alpha) in `marke.farben`?** TK 9.11.2 lässt ihn ausdrücklich zu – wörtlich:
  „`farben:      { <FarbRolle>: string }      // Hex, 6- oder 8-stellig (8 = mit Alpha)`" –, und
  M8-19 **wirft** bei genau diesen Werten. Der STOPP-Block von M8-19 sagt dazu wörtlich: „**Ob
  `aktion.akzentfarbe` je einen 8-stelligen Hex-Wert (mit Alpha) tragen darf, ist nicht
  spezifiziert** (FA-24 spricht nur von einem „freien Hex-Wert", das Datenmodell-Kommentar in TK
  9.8.2 ebenso). Diese Datei geht von 6-stelligem Hex ohne Alpha aus und **wirft** bei 8-stelligem
  Hex, statt den Alphakanal zu ignorieren oder gegen einen angenommenen Hintergrund vorzumischen –
  eine stillschweigende Annahme darüber, welcher Hintergrund „durchscheint", wäre hier erfunden."
  (M8-19). **Für die Marken-Farben ist die Frage schärfer als für `aktion.akzentfarbe`:** Dort ist
  8-stellig unspezifiziert, hier ist es vom Vertrag **erlaubt** – und der eingebaute Schattenwert
  `#0000001A` (TK 9.11.2) zeigt, dass 8-stellige Werte im Marken-Datensatz tatsächlich vorkommen.
  Drei Wege stehen offen, **keiner wird hier gewählt**: (1) M8-19 um den Alpha-Fall erweitern (dann
  muss festgelegt werden, **gegen welchen Hintergrund** vorgemischt wird – genau die Annahme, die
  M8-19 als „erfunden" ablehnt); (2) 8-stellige Werte in den **Farb-Rollen** verbieten und die
  Prüfung dort ansiedeln, wo der Wert entsteht (`bearbeiteMarke`, M8-11); (3) die Warnung in diesem
  Fall **aussetzen** statt zu werfen (dann zeigt der Editor bei einem erlaubten Wert stillschweigend
  nichts an – die schlechteste der drei, aber nicht meine Entscheidung).
  **Für dich heißt das:** Diese Datei baut **keine** eigene Behandlung – kein `try/catch`, kein
  Abschneiden der letzten zwei Zeichen, kein Vormischen, kein Ersatzwert. Sie ruft M8-19 wie oben,
  und bis die Frage entschieden ist, ist der Fall ein **gemeldeter**, kein gelöster.
- **Verbot – keinen eigenen Schwellenwert einführen, raten oder importieren.** Kein `4.5`, `3.0`,
  `7.0` oder ähnliches Literal in dieser Datei (dieselbe Grep-Probe wie in M8-19 selbst) – **und
  auch kein `import { KONTRAST_SCHWELLE }`**, obwohl die Konstante seit M8-47 existiert. Der Wert
  kommt als Prop von M8-48; zwei Lesestellen für dieselbe Zahl wären genau die Doppelung, die
  TK 9.15.2 ausschließt. Ebenso **kein** Vorgabewert am Prop (`schwellenwert = KONTRAST_SCHWELLE`
  wäre der bequeme Ausweg und macht den Prop still optional).
- **Verbot – keine eigene Formel für Fläche/Text-Kandidaten.** Es werden **immer** genau `akzent`
  gegen `textAufDunkel`/`textAufHell` geprüft – keine weiteren Farb-Rollen der Marke (z. B.
  `flaecheAkzentZart`) und keine Kombination, die 9.10.9 nicht vorsieht.
- **Echte offene Frage – wo genau im Editor-Layout erscheint der Hinweis** (direkt unter dem
  Farbwähler für `akzent`, als globaler Banner am oberen Rand des Editors, oder mit beiden
  Text-Rollen samt Einzelwerten)? TK 9.15.2 legt nur **dass** gewarnt wird fest, nicht **wo**. Das ist
  eine reine Platzierungsfrage ohne Wirkung auf Schnittstelle oder Verhalten und wird deshalb
  **nicht** mit dem Label `braucht-entscheidung` versehen; der Agent entscheidet sie selbst.
