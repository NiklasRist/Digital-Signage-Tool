### Issue M8-24: [marken-editor] Schrift-Rollen anzeigen und Schrift importieren

## Ziel (in einem Satz)
Für die geöffnete Marke ist zu jeder der vier festen Schrift-Rollen sichtbar, ob sie gebündelt oder
importiert ist, und für eine Rolle lässt sich eine eigene `.woff2`-Datei importieren.

## Modul & Datei
- Modul: `marken-editor` (Renderer)
- Datei: `src/renderer/marken-editor/schriften-bearbeiten.ts`
- Vertrag: Technisches Konzept **9.15.2** (`marken-editor`), **9.15.3** (Import-Riegel, Format
  `.woff2`, Lizenzhinweis), **9.11.2** (die vier Schrift-Rollen), **9.15.1** (`importiereMarkenDatei`)
  – Quelle der Wahrheit
- Prozess/Speicher: Renderer; V2 **nur mittelbar**. Kein Dateisystem, kein `FontFace`-Laden (das ist
  `template-canvas`, TK 9.15.3, nicht Teil dieses Issues).
- IPC-Kanäle (genutzt, **nicht** angemeldet): `marken:importiereMarkenDatei`

## Warum das im Gesamtsystem wichtig ist
Diese Datei ist der einzige Weg, mit dem eine Marke eine eigene Schrift bekommt. Zwei Dinge sind
hier teuer, wenn sie falsch entschieden werden.

**Erstens die Format-Enge.** „Nur `.woff2`, weil die gebündelten Schriften dasselbe Format haben:
ein Ladepfad statt zwei, und `FontFace` verlangt für andere Formate eigene Behandlung." (TK 9.15.3)
Ließe diese Datei ein anderes Format durch, würde `template-canvas` beim Zeichnen entweder auf eine
Fallback-Schrift zurückfallen (stiller Markenbruch, sichtbar erst am Fernseher) oder eine Schrift
laden, die es nicht laden kann. Die Prüfung liegt zwar beim Store (`importiereMarkenDatei`,
M8-15) – diese Datei darf aber nicht durch einen eigenen, laxeren Dateidialog-Filter eine Datei
anbieten, die der Store ohnehin ablehnt, denn dann bekäme der Nutzer erst nach dem Wählen eine
Fehlermeldung statt gar nicht erst die Auswahl.

**Zweitens die Lizenz-Verantwortung.** „Für **importierte** Schriften trägt der Nutzer die
Nutzungsrechte – die Anwendung brennt sie in ein Video ein, das weitergegeben und öffentlich gezeigt
wird." (Anforderungsdokument R-07) Diese Zusage hat **keine** technische Durchsetzung (es gibt keine
Lizenzprüfung im Code) – sie hängt vollständig daran, dass der Nutzer den Hinweis **sieht**, bevor er
importiert. Ohne einen dafür vorgesehenen Anzeigepunkt verschwindet sie lautlos.

## Signatur (verbindlich – NICHT ändern)
```ts
// src/renderer/marken-editor/schriften-bearbeiten.ts
import type { Ergebnis } from '../../shared/contracts/ergebnis'
import type { Marke, SchriftRolle, Schrift } from '../../shared/contracts/marke'
import { KANAELE } from '../../shared/contracts/kanaele'
import { rufeAuf } from '../ipc-client/rufe-auf'
import { uebernimmAktualisierteMarke } from './marken-uebersicht'

/** Die vier Schrift-Rollen in fester Anzeigereihenfolge (TK 9.11.2) – NICHT alphabetisch sortiert. */
export const SCHRIFT_ROLLEN: readonly SchriftRolle[] = [
  'headlineElegant', 'headlinePlakativ', 'fliesstext', 'fliesstextFett',
]

/** Reiner Lesezugriff: die Schrift EINER Rolle plus ob sie importiert (statt gebündelt) ist. */
export interface SchriftAnzeige {
  rolle: SchriftRolle
  schrift: Schrift              // vollständig, wie in `marke.schriften[rolle]`
  importiert: boolean           // === (schrift.herkunft === 'importiert')
}

/** Baut die Anzeige für alle vier Rollen einer bereits geladenen (aufgelösten) Marke. */
export function baueSchriftAnzeige(marke: Marke): readonly SchriftAnzeige[]

/**
 * LIZENZHINWEIS-TEXT (fest, TK 9.15.3 / Anforderungsdokument R-07). Exportiert, damit die
 * zeichnende Komponente ihn UNVERÄNDERT anzeigt, statt ihn selbst zu formulieren.
 */
export const LIZENZHINWEIS_IMPORT =
  'Für importierte Schriften trägst du die Nutzungsrechte. Die Anwendung brennt die Schrift in ein ' +
  'Video ein, das weitergegeben und öffentlich gezeigt wird – prüfe die Lizenz vor dem Import.'

/**
 * Importiert `quellPfad` als `.woff2` für `rolle` der Marke `markeId` und übernimmt bei Erfolg das
 * Ergebnis in die gemeinsame Sicht (M8-22). `quellPfad` stammt aus
 * oeffneMarkenDateiDialog('schrift') - M8-33; der Dialog selbst ist NICHT Teil dieses Issues.
 */
export async function importiereSchrift(
  markeId: string,
  rolle: SchriftRolle,
  quellPfad: string,
): Promise<Ergebnis<Marke, string>>
```

**ENTSCHIEDEN – der Fehlercode reist auf der Renderer-Seite als `string`** (wie M8-22/M8-23
begründet); die Union `MarkenFehlercode` wird hier **nicht** ein zweites Mal deklariert.

## ENTSCHIEDEN (lokale Festlegungen dieses Issues – kein TK-Zitat, aber verbindlich)

1. **Die Anzeige liest ausschließlich `Marke.schriften[rolle].herkunft`.** Es gibt **keine** zweite
   Quelle dafür, ob eine Schrift importiert ist – die aufgelöste Marke trägt das Feld bereits
   (TK 9.11.2: `Schrift { familie, gewicht, datei, herkunft }`). `baueSchriftAnzeige` ist eine reine
   Funktion ohne IPC-Aufruf; sie arbeitet auf der **bereits geladenen** Marke aus M8-22.
2. **`importiereSchrift` löst KEINEN Dateidialog aus.** Der native Dateidialog mit `.woff2`-Filter
   gehört – wie beim Medien-Import (`öffneMedienDialog`, TK 9.4.3: „weil der Formatfilter zum Dienst
   gehört") – demjenigen, der die Whitelist besitzt: dem `marken-store`. Diese Datei nimmt
   `quellPfad` als **fertigen** Aufrufparameter entgegen. **Er kommt aus `öffneMarkenDateiDialog`
   (M8-33)**, dem eigenen Dialog des `marken-store` mit dem `.woff2`-Filter.
3. **Der Lizenzhinweis wird von dieser Datei bereitgestellt, aber nicht selbst angezeigt.** Diese
   Datei ist `.ts` ohne JSX; `LIZENZHINWEIS_IMPORT` ist der **einzige** Text dafür (eine Formulierung,
   keine zweite an anderer Stelle). **MELDE-KLAUSEL:** Baut die zeichnende Komponente den
   Import-Dialog, ohne diesen Text vor dem Aufruf von `importiereSchrift` anzuzeigen, ist das ein
   Vertragsfehler an der Naht zu dieser Datei – melden.
4. **Kein Entfernen einer importierten Schrift in diesem Issue.** TK 9.15.1 kennt
   `entferneMarkenDatei` für `art: 'schrift'`, aber die Zuschnitt-Tabelle weist dieses Issue
   ausdrücklich nur „Schrift-Rollen anzeigen und Schrift importieren" zu (BRIEFING Abschnitt M8-24).
   Diese Datei importiert `entferneMarkenDatei` deshalb **nicht** und bietet keinen Rückweg auf die
   gebündelte Schrift an – das ist eine **Lücke des Zuschnitts**, kein Versäumnis dieser Datei
   (s. STOPP-Block).

## Eingang → Ausgang
| Eingang | Bedeutung | Grenzen/Validierung |
|---|---|---|
| `marke` (`baueSchriftAnzeige`) | die aktuell geöffnete, aufgelöste Marke | – (reine Funktion, kein Fehlerfall) |
| `markeId` | die zu ändernde Marke | nicht-leerer String |
| `rolle` | eine der vier Schrift-Rollen | Wert **muss** in `SCHRIFT_ROLLEN` stehen; der Typ `SchriftRolle` schließt andere Strings bereits zur Kompilierzeit aus |
| `quellPfad` | absoluter Pfad der `.woff2`-Datei | Format- und Existenz-Prüfung liegen beim Store (M8-15) |

Ausgang bei Erfolg: `baueSchriftAnzeige` → vier `SchriftAnzeige`-Einträge, in Reihenfolge von
`SCHRIFT_ROLLEN`; `importiereSchrift` → `Ergebnis<Marke, string>` mit der **aufgelösten** Marke nach
dem Import, unverändert an `uebernimmAktualisierteMarke` weitergereicht.
Ausgang bei Fehler: `ungueltige_eingabe` (Format außerhalb der Whitelist, ungültiger Pfad),
`marke_nicht_gefunden`, `speicher_fehler`, `unbekannter_fehler`.

## Verbindliche Invarianten (wörtlich – Verletzung = Issue nicht erfüllt)
- „**Zwei Herkünfte, eine Auflösung.** `gebuendelt` löst auf den Bundle-Pfad auf …, `importiert` auf
  `marken-assets/<markeId>/`." (TK 9.15.3) – diese Datei unterscheidet die Anzeige **ausschließlich**
  über `herkunft`, nie über einen Datei-Pfad-Vergleich.
- „**Import kopiert.** Die Quelldatei bleibt unberührt, die Kopie gehört der Marke … Format-Whitelist:
  **`.woff2`** für Schriften … *Nur `.woff2`, weil die gebündelten Schriften dasselbe Format haben:
  ein Ladepfad statt zwei*." (TK 9.15.3) – diese Datei erzwingt **keine** eigene Formatprüfung, weil
  sie den nativen Dialog nicht besitzt (s. ENTSCHIEDEN 2), verspricht aber auch **keinen** Import
  eines anderen Formats.
- „**Lizenzen:** Für importierte Schriften trägt der Nutzer die Rechte (Risiko R-07). Die Anwendung
  brennt sie in ein Video, das weitergegeben und öffentlich gezeigt wird." (TK 9.15.3)
- Die Ergebnis-Hülle (TK 9.1.1, Punkt 2), unverändert verarbeitet, kein `throw`.
- „**Nur der Main** berührt das Dateisystem; der Renderer bekommt Marken über IPC und importierte
  Dateien über das Protokoll (9.15.3)." (TK 9.15.1) – diese Datei enthält kein `fs`.

## Nicht selbst entscheiden – STOPP und fragen
- **ERLEDIGT – nicht mehr melden: `quellPfad` kommt aus M8-33.** Die gemeldete Lücke war echt und ist
  geschlossen. Der `marken-store` hat einen **eigenen** Dateidialog
  `öffneMarkenDateiDialog(art: 'logo' | 'schrift') → Ergebnis<{ pfade: string[] }>`, erreichbar über
  den Kanal `marken:öffneMarkenDateiDialog` (angemeldet in M8-31). Diese Datei ruft ihn mit
  `art: 'schrift'` und reicht den **ersten** Pfad an `importiereMarkenDatei` weiter.
  **Weiterhin verboten:** `media:öffneMedienDialog` zweckentfremden – dessen Filter kennt kein
  `.woff2`. Bricht der Nutzer den Dialog ab, liefert er `ok: true` mit **leerer** Pfadliste; dann
  passiert nichts, und das ist **kein** Fehler.
- **Verbot mit Melde-Pflicht – kein Entfernen einer importierten Schrift.** `entferneMarkenDatei`
  (M8-15) kennt `art: 'schrift'`, aber **kein** M8-Issue (22–32) ruft sie für Schriften auf (M8-25
  nutzt sie nur für `art: 'logo'`). Ein Nutzer, der eine Schrift importiert hat, kann sie über die
  Oberfläche **nicht** wieder auf „gebündelt" zurücksetzen. Baue **keinen** Ersatz dafür in dieser
  Datei (das wäre eine Erweiterung über den zugewiesenen Umfang hinaus) – melden.
- **Verbot – kein eigener Formatfilter, keine eigene `.woff2`-Prüfung.** Diese Datei liest niemals
  Dateiinhalte oder -endungen selbst; die Prüfung ist Sache von M8-15.
