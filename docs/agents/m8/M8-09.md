### Issue M8-09: [marken-store] leseMarke(markeId) – die eine aufgelöste Marke

## Ziel (in einem Satz)
Zu einer `markeId` wird die **fertig aufgelöste** Marke geliefert – die Stelle, über die **jeder**
Zeichenaufruf und **jede** Editor-Ansicht ihre Marke bekommt, statt Vererbung selbst nachzubauen.

## Modul & Datei
- Modul: `marken-store` [V2] (Main)
- Datei: `src/main/marken-store/lese-marke.ts`
- Vertrag: Technisches Konzept **9.15.1** (Operationstabelle und Invarianten – Quelle der Wahrheit),
  **9.11.2** (Ableitungsregel), **9.15.4** (wer aufruft und woher der Kontext kommt)
- Prozess/Speicher: V2 (`marken.json`), nur lesend

## Warum das im Gesamtsystem wichtig ist
Diese Funktion ist der **teuerste einzelne Baustein** des ganzen Meilensteins, gemessen an der
Anzahl der Aufrufer: „`leseMarke` hatte bis v3.3 **kein Argument**; es gab nur eine Marke. Ab v3.4
braucht jeder Aufrufer eine `markeId`. **Neunzehn** Issues holen die Marke, alle über `leseMarke`
und **keines** über `leseKonfig`: `#77`, `#112`, `#119`, `#134`, `#139`, `#140`, `#150`, `#154`,
`#164`, `#176`, `#177`, `#181`, `#196`, `#197`, `#216`, `#218`, `#221`, `#239`, `#262`." (TK 9.15.4)

Jede dieser 19 Stellen bekommt ihre Marke **fertig aufgelöst**. Baute stattdessen jede von ihnen die
Vererbung selbst nach (Parent nachschlagen, Felder zusammenführen), liefen 19 eigene
Vererbungslogiken unweigerlich auseinander – „Es gibt genau eine Auflösungsstelle." (TK 9.10.9, für
die Farb-Rollen; TK 9.11.2 zieht dieselbe Begründung für `Marke` heran). Ein Fehler in dieser einen
Funktion wirkt sich dagegen **überall gleich** aus und ist an **einer** Stelle behebbar.

**Woher die `markeId` kommt, entscheidet diese Funktion nicht.** TK 9.15.4 legt das für jeden
Aufrufer verbindlich fest: Ein Aktions-Segment übergibt `aktion.markeId`, ein Band-Hintergrund oder
die Split-Restflächen übergeben `Project.standardMarkeId` – „**Rahmen stabil, Inhalt wechselt**"
(TK 9.15.4). Diese Funktion selbst kennt weder eine Aktion noch ein Projekt; sie nimmt entgegen, was
der Aufrufer ihr gibt, und löst genau diese eine ID auf.

## Signatur (verbindlich – NICHT ändern)
```ts
// src/main/marken-store/lese-marke.ts
import type { Ergebnis } from '../../shared/contracts/ergebnis'
import type { Marke } from '../../shared/contracts/marke'
import type { MarkenFehlercode } from './fehlercodes'
import { ladeBestand } from './schreibe-marken'
import { loeseMarkeAuf } from './vererbung'

// Fremde Aufrufe – vollstaendige Signaturen, damit hier nichts geraten wird:
//   M8-03: interface MarkenEintrag { id: string; name: string; parent: string | null
//                                    eingebaut: boolean; farben: Partial<Record<FarbRolle, string>>
//                                    schriften: Partial<Record<SchriftRolle, Schrift>>
//                                    logo?: {...} | null; sicherheit?: {...}; radien?: {...}
//                                    schatten?: {...}; slogan?: {...} }
//          ladeBestand(): Promise<Ergebnis<MarkenEintrag[], MarkenFehlercode>>
//          // vollstaendiger, ROHER Bestand als TIEFE Kopie
//   M8-05: loeseMarkeAuf(eintrag: MarkenEintrag, bestand: MarkenEintrag[]): Ergebnis<Marke, MarkenFehlercode>
//   M8-02: type MarkenFehlercode =
//            'marke_referenziert' | 'marke_eingebaut' | 'marke_nicht_gefunden'
//            | 'marken_datei_fehlt' | 'speicher_fehler'

/** Liefert die AUFGELÖSTE Marke zu markeId. Kein Filtern, keine Vererbung außerhalb von loeseMarkeAuf. */
export async function leseMarke(markeId: string): Promise<Ergebnis<Marke, MarkenFehlercode>>
```

**Ablauf (verbindlich):**
1. `markeId` formal prüfen (nicht leer, String) – sonst `ungueltige_eingabe`, **ohne** zu lesen.
2. `ladeBestand()` (M8-03) aufrufen. Fehler → unverändert zurückgeben.
3. Eintrag mit `eintrag.id === markeId` im Bestand suchen. Fehlt er → `marke_nicht_gefunden`.
4. `loeseMarkeAuf(eintrag, bestand)` (M8-05) aufrufen und dessen Ergebnis **unverändert**
   zurückgeben.

## Eingang → Ausgang
| Eingang | Bedeutung | Grenzen/Validierung |
|---|---|---|
| `markeId` | ID der gesuchten Marke | nicht leerer String; **kein** UUID-Zwang – die eingebaute Marke bekommt zwar eine UUID (M8-06), aber die Funktion prüft nur „steht im Bestand", nicht die Form der ID |

Ausgang bei Erfolg: `Ergebnis<Marke>` – die vollständig aufgelöste Marke (alle Farb-/Schrift-Rollen,
Logo, Sicherheitsabstand, Radien, Schatten, Slogan gefüllt; bei `parent === null` sind das ihre
eigenen Werte, bei `parent !== null` eine Mischung aus eigenen und geerbten Werten, TK 9.11.2),
**samt `herkunftJeFeld`** (TK 9.15.1; gesetzt von `loeseMarkeAuf`, M8-05, und hier unverändert
durchgereicht).
Ausgang bei Fehler: `ungueltige_eingabe`, `marke_nicht_gefunden` (unbekannte `markeId` **oder**
verwaiste Ableitung, durchgereicht von `loeseMarkeAuf`), `speicher_fehler`, `unbekannter_fehler`.

## Verbindliche Invarianten (wörtlich – Verletzung = Issue nicht erfüllt)
- Die Operations-Zeile, wörtlich (TK 9.15.1): „`leseMarke` | `markeId` → `Ergebnis<Marke>` –
  **aufgelöst** (Vererbung angewandt, 9.11.2), samt `herkunftJeFeld`"
- **Der Herkunfts-Stempel reist mit** (TK 9.15.1, wörtlich): „**Jede Marke, die dieses Modul
  herausgibt, trägt ihren Herkunfts-Stempel** (`herkunftJeFeld`, 9.11.2)". Er wird in dieser Datei
  **nicht berechnet** – `loeseMarkeAuf` (M8-05) setzt ihn, diese Funktion gibt dessen Ergebnis
  **unverändert** zurück. **Verboten** ist jedes Nachbessern, Weglassen oder Überschreiben von
  `herkunftJeFeld` hier, ebenso ein Feld-für-Feld-Vergleich zweier Marken als Ersatz (TK 9.15.2).
- „**Die Auflösung geschieht an genau EINER Stelle:** im `marken-store`. `leseMarke(markeId)`
  liefert die **fertig aufgelöste** Marke; kein Aufrufer sieht je eine Teilmenge, keiner
  implementiert Vererbung selbst. Das ist dieselbe Begründung wie bei den Farb-Rollen (9.10.9):
  **neunzehn** Aufrufer holen die Marke (9.15.1) – neunzehn eigene Vererbungslogiken liefen
  unweigerlich auseinander." (TK 9.11.2)
- Die Kontext-Tabelle, wörtlich (TK 9.15.4):
  | Wer zeichnet | Marke |
  |---|---|
  | Aktions-Segment (Vollfläche oder Band-Abschnitt) | `aktion.markeId` – die Marke **der Aktion** |
  | Band-Hintergrund (Zone `hintergrund` der Einblendung) | `Project.standardMarkeId` |
  | Restflächen der Split-Komposition (`flaecheDunkel`) | `Project.standardMarkeId` |
  | Vorschau und Vorschaubilder | dieselbe Marke wie beim Render – nie eine andere |
  Diese Tabelle ist Sache der **Aufrufer** – diese Funktion validiert **nicht**, ob eine `markeId`
  „zur Situation passt"; sie nimmt entgegen, was übergeben wird.
- „**Ketten sind auf EINE Stufe begrenzt:** Ein Parent darf selbst keinen Parent haben." (TK 9.11.2)
  – die Prüfung dieser Regel gehört `erstelleMarke` (M8-10); `leseMarke` **erzwingt** sie nicht,
  sondern verlässt sich darauf, dass sie beim Anlegen bereits galt (s. „Nicht selbst entscheiden").
- Die Ergebnis-Hülle (TK 9.1.1, Punkt 2), wie in M8-08 zitiert. Kein `throw`.
- „**Der Main validiert jede eingehende Nutzlast** – er vertraut dem Renderer **nicht**. Ungültige
  Eingabe → `ungueltige_eingabe`, **ohne** jede Wirkung auf die Daten." (TK 9.1.1, Punkt 6)
- **Kein Zugriff auf `fs`.** Nur über `ladeBestand` (M8-03).

## Fehlerpfade (vollständig)
| Situation | Code | Verhalten |
|---|---|---|
| `markeId` ist kein String oder leer | `ungueltige_eingabe` | keine Wirkung; es wird nichts gelesen |
| `ladeBestand` meldet `speicher_fehler` | `speicher_fehler` | unverändert durchgereicht |
| kein Eintrag mit dieser `id` im Bestand | `marke_nicht_gefunden` | keine Wirkung |
| Eintrag hat `parent !== null`, Parent-`id` fehlt im Bestand (verwaiste Ableitung) | `marke_nicht_gefunden` | durchgereicht von `loeseMarkeAuf`; **kein** Rückfall auf die unaufgelöste Marke |
| unerwartete Ausnahme | `unbekannter_fehler` | gefangen und als Hülle gemeldet, kein `throw` |

## Nicht selbst entscheiden – STOPP und fragen
- **ERLEDIGT – nicht mehr melden.** Die gemeldete Lücke war echt und ist mit **TK v3.5**
  geschlossen: Die aufgelöste `Marke` trägt den Herkunfts-Stempel **`herkunftJeFeld`** als
  eigenes Feld (TK 9.11.2), gesetzt an der einen Auflösungsstelle (M8-05). **Diese Signatur
  bleibt dadurch unverändert** – der Stempel steckt im **Typ `Marke`**, nicht in einer
  zusätzlichen Rückgabeform; es gibt weiterhin **keine** zweite, unaufgelöste Leseoperation.
  Der Editor (M8-26) bekommt die Information damit an der Marke mit.
- **Verbot – keine Toleranz bei der Groß-/Kleinschreibung von `markeId`.** Der Vergleich ist der
  **exakte** String-Vergleich `eintrag.id === markeId` aus dem verbindlichen Ablauf, Schritt 3 –
  **kein** `toLowerCase()`, **kein** `localeCompare`, **kein** Trimmen. Das ist entschieden und
  keine offene Frage: UUIDs sind nach `crypto.randomUUID()` immer klein geschrieben (TK 9.11.4), und
  jede andere ID im System wird ebenfalls exakt verglichen; eine Toleranz nur für Marken wäre eine
  Sonderregel, die zwei verschieden geschriebene IDs auf denselben Eintrag abbildete.

## Definition of Done
- [ ] `leseMarke(<id der eingebauten Marke>)` liefert die eingebaute Marke vollständig (alle 12
      `FarbRolle`n, alle 4 `SchriftRolle`n gesetzt)
- [ ] Für eine abgeleitete Marke, die nur `farben.akzent` setzt, liefert `leseMarke` eine Marke, bei
      der **alle** übrigen Farben, alle Schriften, Logo, Sicherheitsabstand, Radien, Schatten und
      Slogan die Werte des Parents tragen, und `farben.akzent` den eigenen Wert
      (deckungsgleicher Test zu TK 9.11.2, Beispiel „Saison-Look setzt nur Farben")
- [ ] `leseMarke('')` und `leseMarke(123 as any)` liefern `ungueltige_eingabe`; `ladeBestand` wird
      nachweislich **nicht** aufgerufen (Spy: null Aufrufe)
- [ ] Eine unbekannte `markeId` liefert `marke_nicht_gefunden`
- [ ] Meldet `ladeBestand` `speicher_fehler`, liefert `leseMarke` genau diesen Code
- [ ] Eine abgeleitete Marke, deren `parent` im Bestand nicht existiert, liefert
      `marke_nicht_gefunden` (Test mit absichtlich manipuliertem Bestand)
- [ ] `loeseMarkeAuf` wird mit genau dem gefundenen Eintrag **und** dem vollständigen Bestand
      aufgerufen (Spy prüft beide Argumente)
- [ ] Die zurückgegebene Marke trägt ein vollständig gefülltes `herkunftJeFeld` – geprüft für eine
      eigenständige (durchgehend `'eigen'`) **und** eine abgeleitete Marke; die Werte sind
      byte-identisch mit dem, was `loeseMarkeAuf` geliefert hat (Spy vergleicht Rückgabe und Ausgabe)
- [ ] Die Datei enthält keine eigene Berechnung oder Änderung von `herkunftJeFeld` – Grep-Probe auf
      `herkunftJeFeld` findet in `lese-marke.ts` **keinen** Treffer
- [ ] Ein Aufruf mit der groß geschriebenen Fassung einer im Bestand klein geschriebenen `markeId`
      liefert `marke_nicht_gefunden` (Nachweis des exakten String-Vergleichs); Grep-Probe: kein
      `toLowerCase`, kein `toUpperCase`, kein `localeCompare`, kein `trim` in dieser Datei
- [ ] Die Datei enthält keinen `fs`-Import und keine eigene Vererbungslogik (kein Zugriff auf
      `eintrag.parent` außerhalb des Aufrufs von `loeseMarkeAuf`) – Grep-Probe
- [ ] Alle Fehlerpfade oben liefern den genannten Code (kein `throw` über die IPC-Grenze)
- [ ] Keine Datei außerhalb von `src/main/marken-store/lese-marke.ts` (+ zugehörige Testdatei)
