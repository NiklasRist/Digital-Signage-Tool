### Issue M8-30: [marken-editor] Live-Vorschau über `template-canvas`

## Ziel (in einem Satz)
Der Marken-Editor zeigt das Ergebnis einer Marke über **dieselbe** Zeichenroutine, die später das
Segment-PNG erzeugt – über eine synthetische Vorschau-Aktion, ohne einen zweiten, eigenen
Zeichenpfad.

## Modul & Datei
- Modul: `marken-editor` (Renderer)
- Datei: `src/renderer/marken-editor/live-vorschau.ts`
- Vertrag: Technisches Konzept **9.10.1** (die eine Zeichenroutine), **9.10.10** (Ersatz-Logo),
  **9.10.7** (fehlendes Motiv), **9.15.2** (Live-Vorschau des Editors) – Quelle der Wahrheit
- Prozess/Speicher: – (Renderer-Laufzeit; ruft eine reine, synchron aufrufbare Funktion aus
  `template-canvas`, kein IPC, kein Auftrag der Queue, TK 9.10.8)

## Warum das im Gesamtsystem wichtig ist
TK 9.10.1 formuliert die teuerste Zusage des ganzen Projekts wörtlich: „Es gibt **keinen zweiten
Zeichenpfad.** Anzeige und Export stammen immer aus **demselben** Aufruf – sonst driften Vorschau und
Endvideo auseinander." Ein Marken-Editor, der Farben, Schriften und Logo mit eigenem DOM/CSS
nachbaut („so sieht es ungefähr aus"), bräche genau diese Zusage an der Stelle, an der eine Marke
**entsteht** – jeder Fehler in einem solchen Nachbau würde sich erst am fertigen Video zeigen, nie im
Editor.

TK 9.15.2 verlangt deshalb ausdrücklich: „[Der Editor] stellt das Ergebnis über `template-canvas` dar
– **dieselbe** Zeichenroutine wie überall, damit die Vorschau im Editor dem späteren Segment
entspricht (9.10.1)." Das schließt insbesondere das **Ersatz-Logo** (M8-20, TK 9.10.10) ein: Wer eine
Marke ohne Logo anlegt, muss im Editor **sofort** sehen, wie ihr Markenname als Ersatz-Logo aussieht
– sonst bemerkt er erst am 85-Zoll-Fernseher, dass der gewählte Markenname zweizeilig umbricht oder
die automatisch gewählte Textfarbe unlesbar ist.

Die teure lokale Entscheidung liegt darin, **wie** eine Marke – die keiner Aktion und keinem Projekt
gehört – überhaupt an `zeichneSegment(aktion, vorlage, marke)` (TK 9.10.1) übergeben werden kann: Die
Funktion verlangt eine `Aktion`. Diese Datei baut dafür eine **synthetische** Vorschau-Aktion, die nie
gespeichert und nie gerendert wird.

## Signatur (verbindlich – NICHT ändern)
```ts
// src/renderer/marken-editor/live-vorschau.ts
import type { Marke } from '../../shared/contracts/marke'
import type { Vorlage } from '../../shared/contracts/vorlage'
import type { Aktion } from '../../shared/contracts/aktion'
import { zeichneSegment, type SegmentBild } from '../template-canvas/zeichne-segment'

/**
 * Baut eine SYNTHETISCHE Vorschau-Aktion für den Marken-Editor: feste Platzhaltertexte, KEIN Bild
 * (`bildRef: null` – eine gültige, gespeicherte Belegung laut TK 9.8.2 "Bild ist optional"; die
 * Bild-Zone folgt damit dem `wennLeer` der Vorlage, TK 9.11.1, statt einen Defekt-Platzhalter zu
 * zeigen). `akzentfarbe` ist IMMER `null`, damit die Vorschau die Farb-Rollen der MARKE zeigt und
 * nicht eine erfundene Aktions-Farbe (TK 9.10.9: "Ist aktion.akzentfarbe nicht gesetzt, gilt der
 * Markenwert"). Diese Aktion wird NIE in ein Project.aktionen-Array eingetragen und NIE gerendert.
 */
export function baueVorschauAktion(marke: Marke, vorlage: Vorlage): Aktion

/**
 * Zeichnet die Live-Vorschau EINER Marke über GENAU DENSELBEN Aufruf wie das spätere Segment.
 * SYNCHRON – wie zeichneSegment selbst (TK 9.10.1, 9.10.3 Punkt 3/4: alles Asynchrone – Schriften,
 * Motive, Logo – ist VOR diesem Aufruf erledigt; das ist NICHT Teil dieser Datei, s. STOPP).
 */
export function zeichneMarkenVorschau(marke: Marke, vorlage: Vorlage): SegmentBild {
  return zeichneSegment(baueVorschauAktion(marke, vorlage), vorlage, marke)
}
```

**Fremde Signatur, die du benutzt (abgeschrieben aus der definierenden Quelle M4-23; der umsetzende
Agent sieht M4-23 nicht – hier steht sie vollständig):**

```ts
// M4-23 – src/renderer/template-canvas/zeichne-segment.ts (DEFINIERENDE QUELLE)
export interface SegmentBild {
  canvas: HTMLCanvasElement
  breite: number
  höhe: number
}

export function zeichneSegment(aktion: Aktion, vorlage: Vorlage, marke: Marke): SegmentBild
// SYNCHRON, ohne async/await/Promise. M4-23 wörtlich: "Alles Asynchrone ist vorher erledigt: Die
// Marken-Schriften sind registriert und einsatzbereit (M4-16), die Motive des Projekts sind geladen
// und dekodiert (M4-17), das gebündelte Marken-Logo ebenso (M4-25). Diese Funktion darf deshalb
// weder auf document.fonts.ready warten noch ein Bild laden."

// #14/M1-02 – src/shared/contracts/aktion.ts (Belegung laut TK 9.8.2 – NICHT hier neu definieren)
export interface Aktion {
  id: string
  titel: string
  beschreibung: string | null
  preis: string | null
  bildRef: string | null
  cta: string | null
  standardDauer: number | null
  vorlagenId: string
  markeId: string
  akzentfarbe: string | null
}
```

**Weicht eine dieser Signaturen von der tatsächlichen Fassung ab, ist das ein Vertragsfehler: melden
und NICHT eigenmächtig anpassen.**

## Eingang → Ausgang
| Eingang | Bedeutung | Grenzen/Validierung |
|---|---|---|
| `marke` | die im Editor gerade bearbeitete, **aufgelöste** Marke (Entwurf, ggf. noch nicht gespeichert) | keine eigene Prüfung – `zeichneSegment` bekommt sie unverändert; es wird **nie** über `leseMarke` nachgeladen |
| `vorlage` | die für die Vorschau gewählte Vorlage (z. B. die eingebaute „Vollbild", die eine Logo-Zone besitzt) | keine eigene Prüfung; von der aufrufenden Editor-Oberfläche (M8-22) übergeben |

Ausgang: `SegmentBild` (Canvas + native Fläche) – **identisch** in Form und Herkunft zu jedem anderen
Aufruf von `zeichneSegment` im System. Es gibt **keinen** Fehlerausgang, weil `zeichneSegment` selbst
keinen liefert (TK 9.10.8: „kein Auftrag der Queue – eine reine, synchron aufrufbare
Renderer-Funktion").

## Verbindliche Invarianten (wörtlich – Verletzung = Issue nicht erfüllt)
- „**Invariante:** Es gibt **keinen zweiten Zeichenpfad.** Anzeige und Export stammen immer aus
  **demselben** Aufruf – sonst driften Vorschau und Endvideo auseinander." (TK 9.10.1)
- „[Der `marken-editor`] stellt das Ergebnis über `template-canvas` dar – **dieselbe**
  Zeichenroutine wie überall, damit die Vorschau im Editor dem späteren Segment entspricht (9.10.1)."
  (TK 9.15.2)
- „**Immer bei der nativen Fläche der Vorlagenart zeichnen** (1920×1080 bzw. 1920×162, s. 9.10.2);
  Skalierung geschieht **nur** zur Darstellung (CSS). **Nie** kleiner rendern und hochskalieren – das
  erzeugt ein unscharfes Segment bzw. Band im Endvideo." (TK 9.10.3, Punkt 1) – die aufrufende
  Oberfläche (M8-22) skaliert das `canvas` nur per CSS, diese Datei selbst zeichnet immer in der
  nativen Fläche.
- „Ist `aktion.bildRef` ein `fehlt`-Asset (9.4.7), zeichnet `template-canvas` einen **Platzhalter** an
  der Bildzone, damit der `action-editor` den Defekt zeigen kann (9.8.5)." (TK 9.10.7) – gilt hier
  **nicht**: `bildRef: null` ist kein `fehlt`-Asset, sondern eine gültige „kein Bild gewählt"-Belegung
  (TK 9.8.2: „Bild ist optional"); die betroffene Zone folgt ihrem `wennLeer` (TK 9.11.1).
- „**Ist `aktion.akzentfarbe` nicht gesetzt, gilt der Markenwert** der jeweiligen Rolle. Das ist der
  reguläre Rückfall und **kein** Fehler; eine Aktion ohne gewählte Akzentfarbe sieht aus wie die
  Vorlage sie vorsieht." (TK 9.10.9)

## Nicht selbst entscheiden – STOPP und fragen
- **Verbot – kein zweiter Zeichenpfad.** Diese Datei zeichnet **nichts** selbst auf ein
  `CanvasRenderingContext2D` – jede Pixelentscheidung läuft ausschließlich über `zeichneSegment`.
- **Verbot – keine eigene Platzhalter-Logik für das Bild.** `baueVorschauAktion` setzt `bildRef:
  null`; ob und wie die Bild-Zone das anzeigt, entscheidet die Vorlage über `wennLeer` (TK 9.11.1),
  nicht diese Datei.
- **Echte offene Frage, NICHT Teil dieses Issues – die Vorbereitung vor dem Zeichnen fehlt im
  M8-Zuschnitt.** `zeichneSegment` ist **synchron** und setzt voraus, dass Marken-Schriften und
  Marken-Logo **vor** dem Aufruf geladen sind (TK 9.10.3 Punkt 3/4, M4-16, M4-25). M8-17 deckt laut
  Zuschnitt nur das Laden **importierter Schriften** je Marke ab. Für das **Logo** gibt es im
  M8-Zuschnitt **kein** Issue, das `holeLogo()`/`bereiteLogoVor(marke)` (M4-25) auf mehrere,
  möglicherweise **importierte** Marken-Logos erweitert – M4-25 ist wörtlich auf „**das** [eine]
  gebündelte Marken-Logo" ausgelegt und kennt weder eine `markeId` beim Abruf noch die Herkunft
  `importiert` (TK 9.15.3). Ohne diese Erweiterung zeichnet `zeichneSegment` für jede Marke außer der
  eingebauten entweder das **falsche** Logo oder gar keins, **unabhängig** davon, ob diese Datei
  korrekt ist. **Diese Lücke wird hier nicht geschlossen** (sie liegt außerhalb von
  `src/renderer/marken-editor/`) – sie ist an den Auftraggeber zu melden, bevor M8-30 sinnvoll
  gegen echte, nicht eingebaute Marken getestet werden kann.
- **Verbot – keine eigene Vorbereitung einbauen, um die obige Lücke zu umgehen.** Insbesondere kein
  `await`, kein `document.fonts.load(...)`, kein eigenes `Image()`-Laden in dieser Datei – das wäre
  eine zweite, abweichende Vorbereitung neben M4-16/M4-25/M8-17 und liefe der „eine Stelle lädt
  vorher"-Regel zuwider (TK 9.10.3).
- **Echte offene Frage – welche Vorlage die aufrufende Oberfläche (M8-22) für die Vorschau wählt**
  (die eingebaute „Vollbild" fest, oder ein Umschalter zwischen den vorhandenen Vorlagen)? Diese
  Datei ist dagegen neutral (`vorlage` als Parameter) – die Entscheidung gehört zu M8-22, nicht
  hierher.

## Definition of Done
- [ ] `baueVorschauAktion(marke, vorlage)` liefert eine `Aktion` mit `bildRef: null`,
      `akzentfarbe: null`, `markeId: marke.id`, `vorlagenId: vorlage.id` und einem nicht-leeren
      `titel`
- [ ] `zeichneMarkenVorschau(marke, vorlage)` ruft `zeichneSegment` **genau einmal** auf, mit
      `(baueVorschauAktion(marke, vorlage), vorlage, marke)` in dieser Reihenfolge (Test mit Spy auf
      `zeichneSegment`) und liefert dessen Rückgabewert **unverändert** zurück
- [ ] `zeichneMarkenVorschau` ist **synchron** (kein `async`, kein `Promise` im Rückgabetyp;
      Typecheck-Probe)
- [ ] Grep-Probe: Diese Datei enthält **kein** `CanvasRenderingContext2D`, kein
      `getContext('2d')`, kein `new Image()`, kein `document.fonts` – jede Pixelentscheidung liegt in
      `zeichneSegment`
- [ ] Ruft `baueVorschauAktion` mit zwei verschiedenen `Marke`-Objekten auf: Das Ergebnis unterscheidet
      sich **nur** in `markeId`; `bildRef`, `akzentfarbe` bleiben in beiden Fällen `null`
- [ ] Keine Datei außerhalb von `src/renderer/marken-editor/live-vorschau.ts` (+ zugehörige
      Testdatei) geändert
