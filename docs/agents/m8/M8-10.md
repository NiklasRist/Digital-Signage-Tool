### Issue M8-10: [marken-store] erstelleMarke(name, parentId?) – neue eigenständige oder abgeleitete Marke

## Ziel (in einem Satz)
Der Nutzer legt eine neue Marke an – **eigenständig** (Partner-/Fremdwerbung) oder, mit `parentId`,
**abgeleitet** (Saison-/Kampagnen-Look) –, wobei eine Ableitungskette **nie** länger als eine Stufe
werden kann.

## Modul & Datei
- Modul: `marken-store` [V2] (Main)
- Datei: `src/main/marken-store/erstelle-marke.ts`
- Vertrag: Technisches Konzept **9.15.1** (Operationstabelle, Sperre für Ketten), **9.11.2**
  (Ableitungsregel, Kettentiefe), **9.11.4** (ID-Schema) – Quelle der Wahrheit
- Prozess/Speicher: V2 (`marken.json`)

## Warum das im Gesamtsystem wichtig ist
Diese Funktion ist der einzige Ort, an dem eine **Ableitungskette** entstehen kann – und damit der
einzige Ort, an dem sie **begrenzt** werden muss: „**Ketten sind auf EINE Stufe begrenzt:** Ein
Parent darf selbst keinen Parent haben. Sonst müsste die Auflösung beliebig tief laufen und die
Referenzprüfung beim Löschen (9.15.1) rekursiv über einen Baum statt über eine Liste – beides ohne
fachlichen Gewinn, denn zwei Stufen decken „Marke + Look" ab." (TK 9.11.2) Lässt diese Funktion eine
Kette aus drei Marken zu, bricht **jede** nachgelagerte Annahme: `loeseMarkeAuf` (M8-05) löst nur eine
Stufe auf, `pruefeMarkenReferenzen` (M8-12) durchsucht die abgeleiteten Marken als flache Liste, und
`löscheMarke` (M8-13) geht von genau zwei Ebenen aus.

Die zweite teure Entscheidung betrifft **neue eigenständige** Marken: Ohne `parentId` gibt es keinen
Parent, von dem geerbt werden könnte – die neue Marke muss deshalb selbst **vollständig** befüllt
sein (jede `FarbRolle`, jede `SchriftRolle`, Sicherheitsabstand, Radien, Schatten, Slogan), sonst
liefert `leseMarke` (M8-09) für sie kein vollständiges Ergebnis, sondern eine Marke mit Lücken.
**`logo` ist die einzige Ausnahme von dieser Vollständigkeit – und sie ist ENTSCHIEDEN: `logo: null`**
(Auftraggeber, 11.08.2026). Das Feld ist
laut TK 9.11.2 ausdrücklich `| null`-fähig (dort wörtlich:
`logo: { datei, herkunft, seitenverhaeltnis } | null` mit dem Kommentar „null -> Ersatz-Logo
(9.10.10)"), eine Marke ohne Logo ist also **kein** Lückenfall, sondern ein
im Vertrag vorgesehener Zustand – **der Normalfall** sogar: „bei Werbepartnern der Normalfall"
(TK 9.10.10). Eine neu angelegte eigenständige Marke trägt damit **nie** ein fremdes Bildzeichen,
sondern von Anfang an ihren **eigenen** Namen auf ihrer **eigenen** Akzentfläche.

## Signatur (verbindlich – NICHT ändern)
```ts
// src/main/marken-store/erstelle-marke.ts
import type { Ergebnis } from '../../shared/contracts/ergebnis'
import type { Marke } from '../../shared/contracts/marke'
import type { MarkenFehlercode } from './fehlercodes'
import { aendereBestand } from './schreibe-marken'
import { eingebauteMarke } from './anfangsbestand'
import { loeseMarkeAuf } from './vererbung'
import { erzeugeId } from '../../shared/contracts/id'

// Fremde Aufrufe – vollstaendige Signaturen, damit hier nichts geraten wird:
//   M8-03: interface MarkenEintrag { id: string; name: string; parent: string | null
//                                    eingebaut: boolean; farben: Partial<Record<FarbRolle, string>>
//                                    schriften: Partial<Record<SchriftRolle, Schrift>>
//                                    logo?: {...} | null; sicherheit?: {...}; radien?: {...}
//                                    schatten?: {...}; slogan?: {...} }
//          aendereBestand<T>(
//            aenderung: (bestand: MarkenEintrag[]) =>
//              Ergebnis<{ bestand: MarkenEintrag[]; wert: T }, MarkenFehlercode>,
//            schreibart: 'sofort' | 'entprellt',
//          ): Promise<Ergebnis<T, MarkenFehlercode>>
//          // `aenderung` ist SYNCHRON und bekommt eine tiefe Kopie des Bestands
//   M8-06: eingebauteMarke(): MarkenEintrag   // frische TIEFE Kopie der Fitnessworld24-Marke,
//          // VOLLSTÄNDIG befüllt (alle Rollen, Logo, Sicherheit, Radien, Schatten, Slogan)
//   M8-05: loeseMarkeAuf(eintrag: MarkenEintrag, bestand: MarkenEintrag[]): Ergebnis<Marke, MarkenFehlercode>
//   #20:   erzeugeId(): string   // UUID v4
//   M8-02: type MarkenFehlercode =
//            'marke_referenziert' | 'marke_eingebaut' | 'marke_nicht_gefunden'
//            | 'marken_datei_fehlt' | 'speicher_fehler'

export async function erstelleMarke(
  name: string,
  parentId: string | null,
): Promise<Ergebnis<Marke, MarkenFehlercode>>
```

**Warum `parentId` ein Pflichtparameter mit `| null` ist und nicht optional.** Die Vertragstabelle
schreibt `erstelleMarke | name, parentId? → Ergebnis<Marke>` (TK 9.15.1). Ein echtes optionales
zweites Argument wäre in TypeScript zulässig, würde aber zwischen „Aufrufer hat `undefined`
übergeben" und „Aufrufer hat bewusst `null` (keine Ableitung) übergeben" nicht unterscheidbar sein –
beide sähen im Funktionskörper gleich aus. Mit `string | null` muss der Aufrufer sich für eine
eigenständige Marke **ausdrücklich** für `null` entscheiden (dieselbe Begründung wie in M4-06 für
`höhe` bei `erstelleVorlage`).

**Ablauf (verbindlich):**
1. **Validieren, bevor irgendetwas passiert** (TK 9.1.1, Punkt 6):
   - `name`: String, nach `trim()` nicht leer, höchstens 80 Zeichen. Gespeichert wird der
     **getrimmte** Name.
   - `parentId`, falls nicht `null`: muss ein nicht leerer String sein.
2. Ist `parentId !== null`: `ladeBestand()` (über `aendereBestand`s Lesezugriff, s. u.) und darin die
   Parent-Marke suchen.
   - Parent nicht gefunden → `marke_nicht_gefunden`.
   - Parent hat selbst `parent !== null` → `ungueltige_eingabe` (**Kettensperre**, s. Invarianten).
3. `id` über `erzeugeId()` (#20) erzeugen.
4. Den neuen Eintrag bilden:
   - **abgeleitet** (`parentId !== null`): `{ id, name: <getrimmt>, parent: parentId,
     eingebaut: false, farben: {}, schriften: {}, sicherheit: undefined, radien: undefined,
     schatten: undefined, slogan: undefined, logo: undefined }` – **kein** Feld außer `id`, `name`,
     `parent`, `eingebaut` wird gesetzt; alles andere bleibt vollständig geerbt.
   - **eigenständig** (`parentId === null`): `{ id, name: <getrimmt>, parent: null,
     eingebaut: false, ...<die Werte-Felder `farben`, `schriften`, `sicherheit`, `radien`,
     `schatten`, `slogan` aus `eingebauteMarke()`>, logo: null }` – eine **tiefe Kopie** der **sechs**
     Werte-Felder der eingebauten Fitnessworld24-Marke, **`logo` dagegen ausdrücklich `null`**
     (s. „ENTSCHIEDEN" unten). `logo` wird also **gesetzt**, und zwar auf `null` – **nicht**
     weggelassen und **nicht** auf `undefined` gelassen: Bei `parent === null` gibt es niemanden, von
     dem geerbt werden könnte, und `null` ist der im Vertrag vorgesehene Wert („null -> Ersatz-Logo
     (9.10.10)", TK 9.11.2). **Verboten ist, das `logo` aus `eingebauteMarke()` mitzukopieren** –
     auch nicht „vorläufig, der Nutzer entfernt es ja".
5. Über `aendereBestand(…, 'sofort')` an den Bestand **anhängen**.
6. Den neuen Eintrag mit `loeseMarkeAuf(eintrag, bestand)` (M8-05) auflösen und zurückgeben.

## Eingang → Ausgang
| Eingang | Bedeutung | Grenzen/Validierung |
|---|---|---|
| `name` | Anzeigename | String, nach `trim()` nicht leer, höchstens 80 Zeichen; **Doppelte erlaubt** – die Identität ist die `id` (TK 9.11.4) |
| `parentId` | `null` = eigenständige Marke; sonst ID der Marke, von der abgeleitet wird | falls gesetzt: muss im Bestand stehen **und** selbst `parent === null` haben (Kettensperre) |

Ausgang bei Erfolg: `Ergebnis<Marke>` mit der neuen, **aufgelösten** Marke (`eingebaut: false`).
Ausgang bei Fehler: `ungueltige_eingabe` (Validierung, leerer Name, Kettensperre),
`marke_nicht_gefunden` (`parentId` unbekannt), `speicher_fehler`, `unbekannter_fehler`.

## Verbindliche Invarianten (wörtlich – Verletzung = Issue nicht erfüllt)
- Die Operations-Zeile, wörtlich (TK 9.15.1): „`erstelleMarke` | `name`, `parentId?` →
  `Ergebnis<Marke>` (`parentId` gesetzt → abgeleitet)"
- „**Ableitungsketten sind auf eine Stufe begrenzt** (9.11.2): `erstelleMarke` mit einer `parentId`,
  deren Marke selbst einen Parent hat, wird mit `ungueltige_eingabe` abgewiesen." (TK 9.15.1)
- „**Ketten sind auf EINE Stufe begrenzt:** Ein Parent darf selbst keinen Parent haben." (TK 9.11.2)
- „**Ableitung über `parent`** – feldweise Vererbung, **eine** Stufe tief." (Entscheidung 3 des
  Auftraggebers, BRIEFING Abschnitt 3)
- „**Alle IDs sind UUIDs** … **Keine** fortlaufenden Zähler … **Keine** aus Namen abgeleiteten IDs …
  **IDs werden nie wiederverwendet**, auch nicht nach dem Löschen." (TK 9.11.4)
- „Das gilt für **jedes** Feld außer `id`, `name`, `parent` und `eingebaut`." (TK 9.11.2) – genau
  diese vier Felder setzt diese Funktion für eine abgeleitete Marke; alle übrigen bleiben leer.
- „Der Main validiert jede eingehende Nutzlast – er vertraut dem Renderer **nicht**. Ungültige
  Eingabe → `ungueltige_eingabe`, **ohne** jede Wirkung auf die Daten." (TK 9.1.1, Punkt 6)
- Die neue Marke trägt **`eingebaut: false`** – nur die Fitnessworld24-Marke aus M8-06 ist eingebaut;
  dieses Feld ist das Kennzeichen, an dem die Lösch-Sperre (M8-13) hängt.
- Warum eine neue eigenständige Marke **ohne** Logo entsteht, wörtlich (TK 9.10.10): „`Marke.logo`
  ist seit v3.4 `| null` – bei Werbepartnern der Normalfall. Ist es `null`, zeichnet
  `template-canvas` in **jeder** Zone mit `bindung: logo` einen **Ersatz**: den **Markennamen**
  (`marke.name`) auf einer Fläche in der **Akzentfarbe der Marke**. Kein leerer Bereich, und
  **kein** fremdes Logo an dieser Stelle – eine geliehene Marke wäre schlimmer als gar keine."
  → Diese Funktion setzt `logo: null` und stellt damit genau diesen Zustand her.

**ENTSCHIEDEN – womit eine neue EIGENSTÄNDIGE Marke vorbelegt wird (sechs Felder als tiefe Kopie,
`logo: null`).** Der Vertrag sagt nicht, welche Werte eine Marke ohne `parentId`
bekommt – es gibt keinen Parent, von dem geerbt werden könnte, und die aufgelöste `Marke` (M8-09)
verlangt **alle** Felder gefüllt. Diese Funktion befüllt **`farben`, `schriften`, `sicherheit`,
`radien`, `schatten` und `slogan`** mit einer **tiefen Kopie** der Werte der eingebauten
Fitnessworld24-Marke (`eingebauteMarke()`, M8-06); `id`, `name`, `parent` und `eingebaut` setzt sie
selbst. Begründung: Die Fitnessworld24-Marke ist das einzige im TK belegte, vollständige Werteset
(9.11.2) und damit der einzige nicht erfundene Ausgangspunkt; eine neue Marke ohne jede
Farbe/Schrift wäre nicht darstellbar (Scrim, Pillen, Sicherheitslinie usw. bräuchten dann eigene
„was, wenn leer"-Regeln, die der Vertrag nicht kennt). Der Nutzer überschreibt danach frei über
`bearbeiteMarke` (M8-11) – **dieselbe** Situation wie bei `erstelleVorlage` (M4-06), die die festen
Zonen aus der eingebauten Vorlage kopiert, statt sie neu zu erfinden.

**Warum die Kopie bei diesen sechs Feldern unstrittig ist:** Farben, Schriften, Sicherheitsabstand,
Radien und Schatten sind reine **Gestaltungsparameter** – sie tragen keinen fremden Namen, sind ohne
Vorbelegung nicht darstellbar, und der Nutzer überschreibt sie im Editor Feld für Feld. Beim
`slogan` ist die Kopie ebenfalls entschieden, weil er ein **frei editierbares Textfeld mit eigenem
Schalter** (`{ text, aktiv }`) ist: Er lässt sich in einem Zug überschreiben oder abschalten und
hinterlässt danach keine Spur. **`logo` ist ein anderer Fall** – es ist kein Wert, sondern eine
**Dateireferenz mit Herkunft** (`{ datei, herkunft, seitenverhaeltnis }`), und sie zeigt das
Bildzeichen eines fremden Unternehmens.

**ENTSCHIEDEN (Auftraggeber, 11.08.2026) – `logo: null`.** Eine neu angelegte **eigenständige** Marke
bekommt das Logo der eingebauten Marke **nicht** mitkopiert; die anderen sechs Felder bleiben die
oben entschiedene tiefe Kopie. **Zwei Gründe, beide sichtbar:**
1. **Es ist der vom Vertrag beschriebene Normalfall.** TK 9.10.10 nennt eine Marke ohne Logo
   ausdrücklich „bei Werbepartnern der Normalfall" – und Partner-/Fremdwerbung ist der erste der
   beiden Zwecke, für die es die Marken überhaupt gibt (Entscheidung 1 des Auftraggebers,
   BRIEFING Abschnitt 3). Die neue Marke zeigt damit ab dem ersten Moment ihren **eigenen** Namen auf
   ihrer **eigenen** Akzentfläche, statt ein fremdes Bildzeichen zu tragen, das der Nutzer erst aktiv
   entfernen müsste. Übersähe er das, brennte er fremdes Logo und Partner-Farben in **dasselbe**
   Segment – ein Fehler, der erst am 85-Zoll-Fernseher auffällt.
2. **Nur so wird der Ersatz-Logo-Pfad überhaupt je ausgelöst.** Mit mitkopiertem Logo wäre `logo` bei
   eigenständigen Marken **nie** `null`; der Zweig aus TK 9.10.10, den **M8-20** baut, wäre gebaut,
   geprüft, grün – und **strukturell tot**. Er entstünde nur noch, wenn ein Nutzer das Logo von Hand
   entfernt (`entferneMarkenDatei`, M8-15) – ein Weg, den er kennen müsste.

*Der Preis ist benannt und in Kauf genommen:* Die Marke sieht direkt nach dem Anlegen **weniger
fertig** aus (ein Schriftzug statt eines Bildzeichens). Wer eine Fitnessworld24-Variante **mit** Logo
will, nimmt die **Ableitung** über `parentId` – die erbt das Logo, und genau dafür ist sie da.

## Fehlerpfade (vollständig)
| Situation | Code | Verhalten |
|---|---|---|
| `name` ist kein String, nach `trim()` leer oder länger als 80 Zeichen | `ungueltige_eingabe` | keine Wirkung |
| `parentId` ist weder `null` noch ein nicht leerer String | `ungueltige_eingabe` | keine Wirkung |
| `parentId` gesetzt, aber keine Marke mit dieser `id` im Bestand | `marke_nicht_gefunden` | keine Wirkung |
| `parentId` gesetzt, gefundene Marke hat selbst `parent !== null` (Kettensperre) | `ungueltige_eingabe` | keine Wirkung; Meldung nennt, dass Ketten nur eine Stufe tief sein dürfen |
| `aendereBestand` meldet `speicher_fehler` | `speicher_fehler` | unverändert durchgereicht; die Marke entsteht **nicht** |
| unerwartete Ausnahme | `unbekannter_fehler` | gefangen und als Hülle gemeldet, kein `throw`, nichts geschrieben |

## Nicht selbst entscheiden – STOPP und fragen
- **ERLEDIGT – nicht mehr melden, hier ist die Entscheidung: Eine neue EIGENSTÄNDIGE Marke bekommt
  `logo: null`** (Auftraggeber, 11.08.2026). Der Befund war: Die anderen sechs Werte-Felder waren
  entschieden (Farben, Schriften, Sicherheit, Radien, Schatten, Slogan als tiefe Kopie); **nur**
  `logo` stand offen – und die Antwort ist in **jedem** Fall sichtbar, weil das
  Logo in jeder Zone mit `bindung: logo` gezeichnet wird. **Entschieden ist Möglichkeit (b)** – die
  Begründung steht ausgeschrieben im ENTSCHIEDEN-Block oben, der Wert in Ablaufpunkt 4, die Probe in
  der DoD. Die Abwägung bleibt hier stehen, damit nachvollziehbar ist, **wogegen** entschieden wurde:

  **Was der Vertrag dazu sagt** – wörtlich (TK 9.10.10): „`Marke.logo` ist seit v3.4 `| null` – bei
  Werbepartnern der Normalfall. Ist es `null`, zeichnet `template-canvas` in **jeder** Zone mit
  `bindung: logo` einen **Ersatz**: den **Markennamen** (`marke.name`) auf einer Fläche in der
  **Akzentfarbe der Marke**. Kein leerer Bereich, und **kein** fremdes Logo an dieser Stelle – eine
  geliehene Marke wäre schlimmer als gar keine." Dazu die Entscheidungen 10 und 11 des Auftraggebers
  (BRIEFING Abschnitt 3): „**Marke ohne Logo → Ersatz-Logo:** Markenname auf Akzentfarbe,
  Standardschrift." und „**Dessen Akzentfarbe ist die der MARKE**, nicht die der Aktion – stabil wie
  ein echtes Logo."

  **Möglichkeit (a) – `logo` mitkopieren – VERWORFEN:** Die neue Marke ist ab
  Sekunde eins **vollständig** und sieht im Editor „fertig" aus; keine Zone bleibt ohne Bild, und
  wer nur die Farben ändern will, ist mit einem Klick fertig. *Preis:* **Jede** neu angelegte
  Partner-Marke trägt zunächst das **Fitnessworld24-Logo**. Wer das übersieht, brennt fremdes Logo
  und fremde Farben in dasselbe Segment – der Fehler fällt erst am 85-Zoll-Fernseher auf. Und
  strukturell schwerer: Der Ersatz-Logo-Pfad wird für eigenständige Marken **nie** ausgelöst, weil
  `logo` nie `null` ist; das Verhalten, das TK 9.10.10 als Normalfall für Werbepartner beschreibt,
  entstünde nur, wenn der Nutzer das Logo aktiv **entfernt** (`entferneMarkenDatei`, M8-15) – ein
  Weg, den er kennen muss.
  **Möglichkeit (b) – `logo: null` setzen – GEWÄHLT:** Die neue Marke zeigt sofort das **Ersatz-Logo** mit
  **ihrem eigenen Namen** in **ihrer** Akzentfarbe. Kein fremdes Zeichen, keine Aufräumarbeit, und
  der von TK 9.10.10 beschriebene Normalfall greift ohne Zutun. *Preis:* Die Marke sieht direkt nach
  dem Anlegen **weniger fertig** aus (ein Schriftzug statt eines Bildzeichens), und wer tatsächlich
  eine Fitnessworld24-Variante als **eigenständige** Marke bauen will, muss das Logo importieren –
  wobei für genau diesen Zweck die **Ableitung** über `parentId` gedacht ist, die das Logo erbt.

  **Für die abgeleitete Marke ändert die Entscheidung nichts:** Dort bleibt `logo` **ungesetzt**
  (`undefined`) und wird feldweise vom Parent geerbt – so verlangt es TK 9.11.2 („Das gilt für
  **jedes** Feld außer `id`, `name`, `parent` und `eingebaut`."). Sie betrifft
  **ausschließlich** den Zweig `parentId === null`.

  **Die Entscheidung setzt auch den Herkunfts-Stempel – ohne dass du dafür etwas tust.** `M8-05`
  setzt ihn beim Auflösen: „Bei einem **eigenständigen** Eintrag (`parent === null`) ist **jeder**
  Wert in
  `herkunftJeFeld` `"eigen"` – Ausnahme `logo`, das `"keins"` trägt, wenn die aufgelöste `logo`
  `null` ist" (M8-05, DoD). Weil hier `logo: null` gesetzt wird, meldet die zurückgegebene Marke
  also **`herkunftJeFeld.logo === 'keins'`** – und damit greift, was TK 9.11.2 dazu vermerkt:
  „keins = weder
  eigen noch geerbt gesetzt -> Ersatz-Logo greift (9.10.10)". Der Marken-Editor zeigt diesen Stempel
  an (M8-26), die Entscheidung ist also auch **im Editor sichtbar**, nicht nur auf dem Segment.
  **Du setzt den Stempel NICHT selbst** – er entsteht in `loeseMarkeAuf` (M8-05, Ablaufpunkt 6);
  diese Funktion setzt nur den **Wert** `logo: null`.

  **Gegengeprüft an M8-05 (11.08.):** Dessen Kopfkommentar sagt, bei `eintrag.parent === null` werde
  der Eintrag „unveraendert (reshaped) als `Marke` zurueckgegeben" und die Systeminvariante der
  Vollständigkeit sei „durch M8-06/M8-10 strukturell erzwungen". Das bleibt mit `logo: null`
  richtig: `null` **ist** der vollständige Wert dieses Feldes (TK 9.11.2:
  `logo: … | null`), keine Lücke. Gerade **weil** `logo` gesetzt wird, kann in der aufgelösten
  `Marke` niemals `undefined` stehen – und genau darauf verlässt sich die `'keins'`-Regel, die auf
  `=== null` prüft, nicht auf „fehlt".
- **Was passiert mit `parentId`, wenn die gefundene Marke die EINGEBAUTE ist?** Die eingebaute
  Fitnessworld24-Marke hat `parent === null` (M8-06) – ein Saison-Look davon abzuleiten ist also nach
  der Kettensperre **zulässig** und ist sogar der in AD 4.8 beschriebene Regelfall („Saison- und
  Kampagnen-Looks. Dieselbe Fitnessworld24-Marke in einer abweichenden Anmutung"). Das ist **keine**
  offene Frage, sondern hier zur Klarstellung festgehalten, damit niemand fälschlich `eingebaut:
  true` als zusätzliche Sperre einbaut, die der Vertrag nicht kennt.
- **ECHTE OFFENE FRAGE: Existenzprüfung des Parents unter Nebenläufigkeit.** Zwischen dem Lesen des
  Bestands (Schritt 2) und dem Schreiben (Schritt 5) kann der Parent durch eine andere, gleichzeitig
  laufende Operation gelöscht worden sein (`aendereBestand` verkettet nur **innerhalb** dieser Datei,
  nicht über Aufrufe hinweg mit einem eigenen `await` dazwischen). Ob die Prüfung deshalb **innerhalb**
  der synchronen Änderungsfunktion von `aendereBestand` wiederholt werden muss (wie in M4-13 für
  `löscheVorlage` vorgemacht) oder ob das Zeitfenster hier – anders als beim Löschen – hingenommen
  wird, weil das schlimmste Ergebnis eine Marke mit einer kurzzeitig verwaisten Ableitung wäre (die
  `leseMarke`/`listeMarken` ohnehin mit `marke_nicht_gefunden` melden), ist **nicht** entschieden.
  **Nicht raten** – falls im Zweifel: dieselbe Antwort wie in M8-13 verwenden, sobald dort entschieden.

## Definition of Done
- [ ] `erstelleMarke('Partner GmbH', null)` liefert eine Marke mit UUID-`id`, `parent: null`,
      `eingebaut: false` und **allen** Farb-/Schrift-Rollen sowie Sicherheit, Radien, Schatten und
      Slogan identisch zur eingebauten Marke – als **tiefe Kopie** (Änderung an
      `neu.farben.akzent` verändert die eingebaute Marke nicht, Test)
- [ ] Dieselbe Marke hat **`logo === null`** – der `MarkenEintrag` im geschriebenen Bestand trägt das
      Feld **gesetzt** mit dem Wert `null` (Nachweis über `'logo' in eintrag` **und**
      `eintrag.logo === null`, nicht nur über `== null`); das Logo der eingebauten Marke ist
      **nicht** mitkopiert (Test: `eingebauteMarke().logo` ist gesetzt, die neue Marke trotzdem
      `null`)
- [ ] Die zurückgegebene, **aufgelöste** Marke meldet **`herkunftJeFeld.logo === 'keins'`** – nicht
      `'eigen'`. Diesen Stempel setzt `loeseMarkeAuf` (M8-05); die Zeile prüft, dass der hier
