### Issue M8-33: [marken-store] `öffneMarkenDateiDialog` – der Dateidialog für `.woff2` und Logo-Bilder

## Ziel (in einem Satz)
Der Nutzer kann über den nativen Datei-Dialog **eine** Schriftdatei (`.woff2`) oder **ein** Logo-Bild
auswählen, und der Main liefert deren absoluten Pfad zurück – der Filter kommt aus **derselben**
Konstante, die der Import (M8-15) danach prüft, und ein Abbruch ist ein normales, erfolgreiches
Ergebnis.

## Modul & Datei
- Modul: `marken-store` [V2] (Main)
- Datei: `src/main/marken-store/dialog.ts`
- Vertrag: Technisches Konzept **9.15.3** (Format-Whitelist `.woff2` bzw. Bild-Whitelist – Quelle der
  Wahrheit für die Formate), **9.4.2** (die Invariante „ein konstanter Wert für Dialog **und**
  Import"), **9.4.3** (`öffneMedienDialog` – das **Bauvorbild**, dessen Abbruch-Regel hier
  übernommen wird), **9.3.2** (Instant statt Auftrag), **9.1.1** (Ergebnis-Hülle)
- Prozess/Speicher: V2; **kein** Speicherzugriff, **kein** Lesen oder Schreiben von Dateien – der
  Dialog liefert nur Pfade

**WICHTIG – diese Operation steht NICHT in der Operationstabelle des TK.** TK 9.15.1 führt für den
`marken-store` acht Operationen (`listeMarken`, `leseMarke`, `erstelleMarke`, `bearbeiteMarke`,
`importiereMarkenDatei`, `entferneMarkenDatei`, `löscheMarke`, `pruefeMarkenReferenzen`) – ein
Dateidialog ist **nicht** darunter. Sie entstand beim Zuschnitt von M8, weil `importiereMarkenDatei`
einen `quellPfad` verlangt, den sonst **niemand** beschafft. Ihr Vorbild ist deshalb der Dialog des
`media-service` (TK 9.4.3, gebaut in **#81**, verdrahtet in **#93**), und alle Zitate unten stammen
entweder von dort oder aus 9.15.3. **Erfinde daraus keine weiteren Operationen** – was das TK für
den `marken-store` vorsieht, ist abschließend, diese eine Ergänzung ist bewusst und begründet.

## Warum das im Gesamtsystem wichtig ist
`importiereMarkenDatei(markeId, art, schriftRolle, quellPfad)` (M8-15) nimmt einen fertigen
absoluten Pfad entgegen. Die beiden Aufrufer im `marken-editor` – M8-24 (Schrift importieren) und
M8-25 (Logo importieren) – bringen ihn ausdrücklich **nicht** selbst bei: Beide halten fest, dass
der native Dialog nicht in ihre Datei gehört. Ohne dieses Issue gibt es also **keinen Weg**, aus der
Oberfläche überhaupt eine Datei auszuwählen, und **FA-24** („Marken-Editor … sowie **Import** von
Logo und Schriftdateien", Muss) bliebe unerfüllbar. Genau dieses Muster – eine fertige Funktion,
deren Eingang niemand beschafft – war in **fünf** Meilensteinen der häufigste kritische Befund.

Zwei lokale Fehlentscheidungen sind hier teuer:

**Erstens der Filter.** Er muss aus derselben Konstante kommen wie die Prüfung beim Import. Zeigt der
Dialog Formate, die M8-15 danach ablehnt, führt die Anwendung den Nutzer in eine Sackgasse: Er darf
`schrift.ttf` auswählen und bekommt danach `ungueltige_eingabe`. Der umgekehrte Fehler – ein zu
enger Filter – versteckt Dateien, die importierbar wären. Besonders heikel ist das bei Schriften,
weil `.ttf` und `.otf` die auf Rechnern **üblichen** Formate sind und `.woff2` die Ausnahme: Ein
Dialog, der beides anzeigt, produziert den Sackgassen-Fall als **Regelfall**, nicht als Randfall.

**Zweitens der Abbruch.** Klickt der Nutzer „Abbrechen", ist das kein Fehler, sondern der häufigste
Ausgang überhaupt. Wird er als Fehler gemeldet, zeigt der Marken-Editor bei jedem versehentlich
geöffneten Dialog eine Fehlermeldung – und ein Aufrufer, der Fehler protokolliert oder einen
Wiederholungsversuch anbietet, tut das dann für einen Vorgang, den der Nutzer bewusst abgebrochen
hat. M8-24 und M8-25 verlassen sich beide wörtlich darauf: „Bricht der Nutzer den Dialog ab, liefert
er `ok: true` mit **leerer** Pfadliste; dann passiert nichts, und das ist **kein** Fehler." (M8-24)

## Signatur (verbindlich – NICHT ändern)
```ts
// src/main/marken-store/dialog.ts
import { dialog } from 'electron'
import { FORMAT_WHITELIST } from '../../shared/contracts/asset'
import { MARKEN_SCHRIFT_ENDUNG } from './dateien'
import type { Ergebnis } from '../../shared/contracts/ergebnis'

export async function öffneMarkenDateiDialog(
  art: 'logo' | 'schrift',
): Promise<Ergebnis<{ pfade: string[] }>>
```

**Der Funktionsname trägt den Umlaut.** Er wird hier genauso geschrieben wie `öffneMedienDialog` in
**#81** (`src/main/media-service/dialog.ts`) – ein `oe` wäre eine zweite Schreibweise für dieselbe
Sache. **Nur** der Objektschlüssel in der Kanal-Registry bleibt ASCII, und der entsteht nicht hier,
sondern in M8-31.

**Kein zweiter Fehlercode-Typparameter.** `Ergebnis<{ pfade: string[] }>` steht **ohne** zweites
Typargument. Diese Operation kann keinen **fachlichen** Fehler des `marken-store` erzeugen: Sie fasst
keine Marke an, liest kein `marken.json`, kopiert nichts. Möglich sind allein die generischen Codes
aus `Ergebnis<T>` (Default-Typparameter). Insbesondere ist `MarkenFehlercode` (M8-02) hier **nicht**
zu importieren – weder `marke_nicht_gefunden` noch `speicher_fehler` noch `marken_datei_fehlt`
können hier entstehen.

**Fremde Werte und fremde APIs, die du benutzt, vollständig ausgeschrieben** (der umsetzende Agent
sieht die anderen Issues **nicht**):

```ts
// #13 – src/shared/contracts/asset.ts, bereits angelegt. DIE EINZIGE Quelle für Bild-Endungen:
export const FORMAT_WHITELIST = {
  video: ['mp4'] as const,
  bild: ['jpg', 'jpeg', 'png', 'webp'] as const,
} as const

// M8-15 – src/main/marken-store/dateien.ts, DIE EINZIGE Quelle für die Schrift-Endung.
// Wörtlich von dort abgeschrieben, samt Kommentar:
/** Nur .woff2 – "ein Ladepfad statt zwei" (TK 9.15.3). Modul-lokal: KEINE Bild-/Video-Endung, also
 *  keine Erweiterung von FORMAT_WHITELIST (#13), die ausschließlich Projekt-Assets beschreibt. */
export const MARKEN_SCHRIFT_ENDUNG = 'woff2'
// (ohne führenden Punkt – genau die Form, die Electron in `extensions` erwartet)

// #22 – src/shared/contracts/ergebnis.ts:
export type Ergebnis<T, F extends string = GenerischerFehlercode> =
  | { ok: true; wert: T }
  | { ok: false; fehler: { code: F | GenerischerFehlercode; meldung: string; daten?: unknown } }
// GenerischerFehlercode = 'ungueltige_eingabe' | 'nicht_gefunden' | 'unbekannter_fehler'
// `daten` trägt strukturierte Fehlerdaten, deren Form je Fehlercode festgelegt ist (TK 9.1.1).
// KEINER der hier möglichen Codes hat solche Daten – das Feld bleibt in dieser Datei ungesetzt.

// Electron (externe Bibliothek), die verwendete Überladung OHNE Elternfenster:
dialog.showOpenDialog(options: {
  title?: string
  properties?: Array<'openFile' | 'multiSelections' | ...>
  filters?: Array<{ name: string; extensions: string[] }>   // extensions OHNE führenden Punkt
}): Promise<{ canceled: boolean; filePaths: string[] }>
```

**Weicht die tatsächliche Signatur oder der tatsächliche Wert einer dieser fremden Stellen von der
hier ausgeschriebenen Fassung ab, ist das ein Vertragsfehler: melden und NICHT eigenmächtig
anpassen.** Insbesondere wird `MARKEN_SCHRIFT_ENDUNG` **nicht** durch ein hier getipptes `'woff2'`
ersetzt, wenn der Import es einmal umbenennen sollte.

**Der Ablauf, verbindlich:**

1. `art` auf die zwei bekannten Werte abbilden. Die Zuordnung ist **erschöpfend** und erzeugt
   **genau einen** Filtereintrag je Art:
   - `art === 'schrift'` → `[{ name: 'Schriften (WOFF2)', extensions: [MARKEN_SCHRIFT_ENDUNG] }]`
   - `art === 'logo'` → `[{ name: 'Bilder', extensions: [...FORMAT_WHITELIST.bild] }]`

   Die `name`-Felder sind reine Anzeigetexte; die Endungen stehen **ohne** führenden Punkt, so
   erwartet es Electron.
2. Ein Wert außerhalb der Union (nur über eine defekte Verdrahtung erreichbar) → sofort
   `{ ok: false, fehler: { code: 'ungueltige_eingabe', meldung } }`, **ohne** einen Dialog zu
   öffnen.
3. `properties: ['openFile']` – **kein** `'multiSelections'`, **kein** `'openDirectory'`, **kein**
   `'promptToCreate'`.
4. `dialog.showOpenDialog(…)` **await**en.
5. `canceled === true` **oder** `filePaths` leer → `{ ok: true, wert: { pfade: [] } }`. Beides ist
   Erfolg, kein Fehler.
6. Sonst → `{ ok: true, wert: { pfade: filePaths } }`, **unverändert** durchgereicht: nicht
   sortiert, nicht dedupliziert, nicht normalisiert, nicht auf Existenz geprüft, nicht auf die
   Endung nachgeprüft.
7. Wirft der Aufruf wider Erwarten (z. B. weil noch kein Fenster bereit ist), wird die Ausnahme
   **hier** gefangen und als `{ ok: false, fehler: { code: 'unbekannter_fehler', meldung } }`
   zurückgegeben. Die Meldung enthält **keinen** Stacktrace.

**ENTSCHIEDEN – genau EIN Filtereintrag je Art, kein „Alle Dateien"-Eintrag daneben.** Der
Medien-Dialog (#81) hat drei Einträge, weil dort Videos **und** Bilder in einem Zug ausgewählt
werden sollen; hier gibt es je Art **eine** zulässige Menge. Ein zusätzlicher weiter Eintrag („Alle
Dateien") wäre genau die Sackgasse aus TK 9.4.2: Der Nutzer wählt `schrift.otf`, und M8-15 lehnt
ab. Dass der Filter dadurch nicht **erzwungen** ist, bleibt richtig und ist unten als Invariante
festgehalten – die verbindliche Prüfung liegt in M8-15, nicht hier.

**ENTSCHIEDEN – Einfachauswahl, obwohl der Rückgabetyp ein Array ist.** `properties` enthält
**kein** `'multiSelections'`. *Begründung:* Eine Marke hat **ein** Logo, und je Schrift-Rolle **eine**
Datei; `importiereMarkenDatei` nimmt genau **einen** `quellPfad`. Beide Aufrufer (M8-24, M8-25)
verwenden ausdrücklich den **ersten** Pfad. Erlaubte Mehrfachauswahl hieße: Der Nutzer markiert vier
Schriften, sieht den Dialog schließen und glaubt, vier Schriften importiert zu haben – tatsächlich
verschwinden drei davon **lautlos**. Der **Rückgabetyp bleibt trotzdem das Array**, weil er
verbindlich vorgegeben ist und weil der Abbruch damit denselben, bereits eingeführten Ausdruck hat
wie beim Medien-Dialog (leere Liste statt eines zweiten „nichts"-Wertes). Praktische Folge: Bei
Erfolg enthält `pfade` genau **einen** Eintrag; die Funktion **erzwingt** das aber nicht durch
Abschneiden – sie reicht durch, was das Betriebssystem liefert (s. Verbote).

**ENTSCHIEDEN – der Dialog wird ohne Elternfenster geöffnet.** Die Signatur nimmt kein
`BrowserWindow` entgegen, und der `marken-store` soll die Fensterverwaltung nicht kennen; ein
`BrowserWindow.getFocusedWindow()`-Griff aus diesem Modul wäre eine zusätzliche Abhängigkeit vom
Renderer-Lebenszyklus. Dasselbe hat #81 für den Medien-Dialog entschieden. Praktische Folge: Der
Dialog ist nicht als Sheet am Fenster angeheftet – ein bewusst in Kauf genommener kosmetischer
Nachteil, kein Versehen.

**ENTSCHIEDEN – kein `title`, kein `defaultPath`, kein Merken des zuletzt benutzten Ordners.** Der
`config-store` (D3) hält das zuletzt benutzte **Export**-Ziel, kein Schrift- oder Bildverzeichnis;
ein neues Feld dort wäre eine fremde Datei und eine Erweiterung des Konfigurationsvertrags. Das
Betriebssystem merkt sich den zuletzt benutzten Ordner ohnehin selbst. Auf einen `title` wird
verzichtet, weil Anzeigetexte in die Oberfläche gehören und der Filtername („Bilder" bzw.
„Schriften (WOFF2)") die Art bereits benennt; #81 setzt aus demselben Grund keinen.

**ENTSCHIEDEN – die Schrift-Endung wird aus `./dateien` importiert, nicht neu hingeschrieben.** Sie
steht schon in `src/main/marken-store/dateien.ts` (M8-15). Sie dort **auszulagern** wäre eine
Änderung an einer fremden Datei (Regel E); sie hier ein zweites Mal zu tippen wäre die zweite
Quelle, die TK 9.4.2 ausdrücklich ausschließt. Also: importieren. Dass dieser Import den Dialog an
das Import-Modul bindet, ist gewollt – genau diese Bindung ist die Invariante.

## Eingang → Ausgang
| Eingang | Bedeutung | Grenzen/Validierung |
|---|---|---|
| `art` | steuert **allein** den Formatfilter: `'schrift'` → `.woff2`, `'logo'` → Bild-Whitelist | genau einer der zwei Werte; ein anderer Wert kann nur über eine defekte Verdrahtung ankommen und liefert `ungueltige_eingabe` **ohne** Dialog. Die Nutzlast-Prüfung an der IPC-Grenze macht **M8-31**, nicht diese Datei |
| – (sonst) | der eigentliche „Eingang" ist die Nutzeraktion im Dialog | die zurückgegebenen Pfade werden **nicht** validiert – Format, Existenz und Lesbarkeit prüft der Import (M8-15) |

Ausgang bei Erfolg: `{ ok: true, wert: { pfade } }` – `pfade` ist ein Array absoluter Quellpfade,
bei Abbruch **leer**, sonst mit **einem** Eintrag.
Ausgang bei Fehler: `ungueltige_eingabe` (unbekannte `art`) und `unbekannter_fehler` (unerwartete
Ausnahme). **Ein Abbruch ist kein Fehler.** Kein fachlicher `marken-store`-Code ist hier möglich.

## Verbindliche Invarianten (wörtlich – Verletzung = Issue nicht erfüllt)
- Die Formate, wörtlich (TK 9.15.3): „**Import kopiert.** Die Quelldatei bleibt unberührt, die Kopie
  gehört der Marke – wie beim Medien-Import (9.4.5). Format-Whitelist: **`.woff2`** für Schriften,
  die Bild-Whitelist (9.4.2) für Logos."
- Warum ausgerechnet `.woff2` und nichts sonst, wörtlich (TK 9.15.3): „*Nur `.woff2`, weil die
  gebündelten Schriften dasselbe Format haben: ein Ladepfad statt zwei, und `FontFace` verlangt für
  andere Formate eigene Behandlung.*"
- Die Bild-Whitelist, wörtlich (TK 9.4.2): „| `bild` | JPG, PNG, WebP |" – bezogen aus
  `FORMAT_WHITELIST.bild` (#13), **nicht** neu geschrieben.
- **Die Ein-Quellen-Invariante, wörtlich (TK 9.4.2):** „**Invariante:** Der Formatfilter des Dialogs
  (9.4.3) und die Prüfung beim Import lesen **denselben** konstanten Wert aus `contracts/types` —
  sie dürfen nie auseinanderlaufen."
  → **In dieser Datei steht kein einziges Endungs-Literal.** Der Filter entsteht aus
  `FORMAT_WHITELIST.bild` (#13) und `MARKEN_SCHRIFT_ENDUNG` (M8-15). *(Der Satz nennt
  `contracts/types` als Ort; für die Schrift-Endung ist das nachweislich nicht möglich – sie ist
  modul-lokal in `dateien.ts` festgelegt, mit der dortigen Begründung „**KEINE** Bild-/Video-Endung,
  also keine Erweiterung von `FORMAT_WHITELIST` (#13), die ausschließlich Projekt-Assets
  beschreibt". Der **Kern** der Invariante – ein einziger konstanter Wert für Dialog und Prüfung –
  gilt unverändert und wird hier eingehalten.)*
- Die Abbruch-Regel, wörtlich aus dem Bauvorbild (TK 9.4.3): „| Nutzer bricht ab | `ok: true` mit
  `pfade = []` – Abbruch ist **kein** Fehler |" und „| Nutzer wählt Dateien | `pfade` = Array
  absoluter Quellpfade |". Diese Funktion übernimmt beide Zeilen unverändert.
- **Dies ist eine Instant-Operation, kein Auftrag** (TK 9.3.2): „**Nicht** über die Queue laufen
  **Instant-Operationen** (Millisekunden, reine D1-Schreibvorgänge): Aktion anlegen/bearbeiten,
  Liste umsortieren, Trim setzen, **Aktion** löschen, Datei-Dialog öffnen." Sie trägt deshalb die
  Ergebnis-Hülle: „**Nur Instant-Aufrufe tragen die Hülle.**" (TK 9.1.1) Sie ruft **nicht**
  `reiheEin`, erzeugt **keinen** `Auftrag` und erscheint **nicht** im `queue-panel`.
- Die Hülle, wörtlich (TK 9.1.1, Punkt 2):
  ```
  Ergebnis<T> =
    | { ok: true,  wert: T }
    | { ok: false, fehler: { code: Fehlercode, meldung: string, daten?: Fehlerdaten } }
  ```
  (Im tatsächlichen Typ, `src/shared/contracts/ergebnis.ts` aus #12/#22, heißt das Feld
  `daten?: unknown`.)
- **Niemals `throw` über die Prozessgrenze** (TK 9.1.1, Punkt 2). Grund wörtlich: „**Fehlerklasse
  und eigene Felder wie `code` sind verloren** – übrig ist Text."
- Fehlercodes werden nicht erfunden (TK 9.1.1, Punkt 3): „**Fehlercodes sind ein geschlossener,
  typisierter Satz** … **Eine rohe Exception-Meldung wird nie zum Code.**"
- **Der Filter ist eine Bequemlichkeit, keine Garantie.** Auf beiden Betriebssystemen kann der
  Nutzer ihn umgehen (Dateinamen tippen, „Alle Dateien" im System-Dialog wählen, per Automatisierung
  aufrufen). Die verbindliche Prüfung ist die Whitelist-Prüfung in `importiereMarkenDatei` (M8-15).
  Diese Datei prüft **nicht** selbst und filtert die Rückgabe **nicht** nach.
- **Keine Lizenzprüfung, kein Lizenzhinweis** (Risiko R-07, TK 9.15.3: „**Lizenzen:** Für importierte
  Schriften trägt der Nutzer die Rechte (Risiko R-07)."). Der sichtbare Hinweis vor dem Import ist
  Sache des Editors (M8-24); diese Datei zeigt **keinen** eigenen Text.
- **Diese Datei registriert keinen IPC-Kanal.** Die Verdrahtung (Kanalname
  `marken:öffneMarkenDateiDialog`, Validierung, `registriereHandler`) geschieht in **M8-31**;
  `src/shared/contracts/kanaele.ts` (#25) wird hier **nicht** angefasst. Grund: Kanalnamen und
  Validierung liegen gebündelt an **einer** Stelle je Modul, sonst registriert später ein zweites
  Issue denselben Kanal ein zweites Mal.
