### Issue M8-11: [marken-store] bearbeiteMarke(markeId, teilwerte) – Werte setzen oder an den Parent zurückgeben

## Ziel (in einem Satz)
Der Nutzer ändert einzelne Felder einer Marke; bei einer abgeleiteten Marke kann er ein Feld
entweder **eigen** setzen (löst sich von der Vererbung) oder ausdrücklich **an den Parent
zurückgeben** (folgt wieder dessen künftigen Änderungen) – die Auto-Speicherung übernimmt das
entprellt.

## Modul & Datei
- Modul: `marken-store` [V2] (Main)
- Datei: `src/main/marken-store/bearbeite-marke.ts`
- Vertrag: Technisches Konzept **9.15.1** (Operationstabelle), **9.11.2** (Ableitungsregel),
  **9.15.2** (geerbt/eigen sichtbar, Auto-Speichern trifft die Marke), **9.5.4** (Entprell-Regeln,
  Instant-Op vs. Speichern) – Quelle der Wahrheit
- Prozess/Speicher: V2 (`marken.json`)

## Warum das im Gesamtsystem wichtig ist
Diese Funktion trägt eine Unterscheidung, die in keiner anderen Store-Operation des Projekts
vorkommt: Ein Feld kann nicht nur „gesetzt" oder „unverändert" sein, sondern bei einer abgeleiteten
Marke ausdrücklich **wieder auf geerbt zurückgesetzt** werden. TK 9.15.2 verlangt genau das: „Ein
Wert, den der Nutzer nicht setzt, bleibt geerbt und folgt künftigen Änderungen des Parents; ein
gesetzter Wert löst sich davon." Eine `teilwerte`-Form, die nur zwischen „Feld im Objekt vorhanden"
und „Feld fehlt" unterscheidet (ein gewöhnliches `Partial<Marke>`), kann „zurück auf geerbt" **nicht**
ausdrücken – „fehlt" bedeutet dort immer „unverändert lassen", nie „lösche den eigenen Wert". Ohne
eine dritte Form bliebe ein einmal gesetzter eigener Wert für immer eigen, selbst wenn der Nutzer ihn
im Editor wieder auf „geerbt" stellt – künftige Logo- oder Farbänderungen der Fitnessworld24-Marke
kämen dann in diesem Look **nie mehr** an, obwohl TK 9.11.2 genau das als Zweck der Ableitung
beschreibt („Ändert Fitnessworld24 sein Erscheinungsbild, soll das … in allen abgeleiteten Looks
wirken", TK 9.15.1).

## Signatur (verbindlich – NICHT ändern)
```ts
// src/main/marken-store/bearbeite-marke.ts
import type { Ergebnis } from '../../shared/contracts/ergebnis'
import type { Marke, FarbRolle, SchriftRolle, Schrift, Herkunft } from '../../shared/contracts/marke'
import type { MarkenFehlercode } from './fehlercodes'
import { aendereBestand } from './schreibe-marken'
import { loeseMarkeAuf } from './vererbung'

// Fremde Aufrufe – vollstaendige Signaturen, damit hier nichts geraten wird:
//   M8-03: interface MarkenEintrag { id: string; name: string; parent: string | null
//                                    eingebaut: boolean; farben: Partial<Record<FarbRolle, string>>
//                                    schriften: Partial<Record<SchriftRolle, Schrift>>
//                                    logo?: {...} | null; sicherheit?: {...}; radien?: {...}
//                                    schatten?: {...}; slogan?: {...} }
//          aendereBestand<T>(
//            aenderung: (bestand: MarkenEintrag[]) =>
//              Ergebnis<{ bestand: MarkenEintrag[]; wert: T }, MarkenFehlercode>,
//            schreibart: 'sofort' | 'entprellt',
//          ): Promise<Ergebnis<T, MarkenFehlercode>>
//   M8-05: loeseMarkeAuf(eintrag: MarkenEintrag, bestand: MarkenEintrag[]): Ergebnis<Marke, MarkenFehlercode>
//   M8-02: type MarkenFehlercode =
//            'marke_referenziert' | 'marke_eingebaut' | 'marke_nicht_gefunden'
//            | 'marken_datei_fehlt' | 'speicher_fehler'

/**
 * Sentinel für „diesen Wert an den Parent zurückgeben". Nur zulässig, wenn die bearbeitete Marke
 * `parent !== null` hat; bei einer eigenständigen oder eingebauten Marke gibt es nichts, an das
 * zurückgegeben werden könnte.
 */
export interface MarkenWertGeerbt { geerbt: true }

/** Ein Feld ist entweder EIGEN GESETZT (der Wert), GEERBT (Sentinel) oder – als fehlender Schlüssel
 *  im umgebenden Objekt – UNVERÄNDERT. Diese drei Zustände sind mit einem gewöhnlichen
 *  `Partial<Marke>` NICHT ausdrückbar (der hat nur zwei: vorhanden/fehlend). */
export type MarkenFeld<T> = T | MarkenWertGeerbt

export interface MarkenTeilwerte {
  name?:       string                                          // NIE geerbt (TK 9.11.2: name bleibt eigen)
  farben?:     Partial<Record<FarbRolle, MarkenFeld<string>>>
  schriften?:  Partial<Record<SchriftRolle, MarkenFeld<Schrift>>>
  logo?:       MarkenFeld<{ datei: string; herkunft: Herkunft; seitenverhaeltnis: number } | null>
  sicherheit?: MarkenFeld<{ horizontal: number; vertikal: number }>
  radien?:     MarkenFeld<{ pille: number; karte: number; klein: number }>
  schatten?:   MarkenFeld<{ versatzY: number; weichzeichnen: number; farbe: string }>
  slogan?:     MarkenFeld<{ text: string; aktiv: boolean }>
}

export async function bearbeiteMarke(
  markeId: string,
  teilwerte: MarkenTeilwerte,
): Promise<Ergebnis<Marke, MarkenFehlercode>>
```

**Warum `{ geerbt: true }` statt `null` als Sentinel.** Bei `logo` ist der reale Wertebereich bereits
`T | null` (`null` heißt „kein eigenes Logo, Ersatz-Logo greift", TK 9.10.10) – ein `null` als
„zurück auf geerbt" wäre mit einem echten, gewollten `null`-Logo **nicht unterscheidbar**. Ein
eigenes Objekt `{ geerbt: true }` ist von jedem denkbaren Fachwert (auch `null`) klar unterscheidbar
und macht die Absicht im Code lesbar, statt sich auf einen überladenen Spezialwert zu verlassen.

**Ablauf (verbindlich):**
1. **Validieren, bevor irgendetwas passiert** (TK 9.1.1, Punkt 6): `markeId` nicht leer;
   `teilwerte` ein Objekt; `name`, falls gesetzt, nach `trim()` nicht leer und höchstens 80 Zeichen;
   jede `FarbRolle` in `farben` ist ein bekannter Rollen-Name (s. Fehlerpfade); jede `SchriftRolle`
   in `schriften` ebenso.
2. `aendereBestand(aenderung, 'entprellt')` (M8-03) – **entprellt**, s. Invarianten. Die
   Änderungsfunktion:
   a) Eintrag mit `markeId` suchen. Fehlt er → `marke_nicht_gefunden`.
   b) Für jedes in `teilwerte` **vorhandene** Feld:
      - Wert ist `{ geerbt: true }` **und** `eintrag.parent === null` → `ungueltige_eingabe`
        (nichts, an das zurückgegeben werden könnte).
      - Wert ist `{ geerbt: true }` **und** `eintrag.parent !== null` → das Feld (bzw. bei
        `farben`/`schriften` die einzelne Rolle) wird aus `eintrag` **entfernt** (`delete`), nicht
        auf `undefined` gesetzt – ein Schlüssel mit dem Wert `undefined` sähe für `loeseMarkeAuf`
        (M8-05) anders aus als ein fehlender Schlüssel, falls dessen Prüfung `in` statt eines
        Truthy-Checks verwendet.
      - Wert ist ein Fachwert → er wird **eigen** übernommen (bei `farben`/`schriften`: nur die
        genannte Rolle, die übrigen Rollen des Objekts bleiben unangetastet).
      - `name` folgt keiner dieser Regeln: ein gesetzter `name` wird **immer** eigen übernommen
        (getrimmt); es gibt für `name` **kein** `{ geerbt: true }` (TK 9.11.2: „außer `id`, `name`,
        `parent` und `eingebaut`").
   c) Geänderten Eintrag zurückgeben.
3. `loeseMarkeAuf(eintrag, bestand)` (M8-05) auf den **geänderten** Eintrag anwenden und das Ergebnis
   zurückgeben.

## Eingang → Ausgang
| Eingang | Bedeutung | Grenzen/Validierung |
|---|---|---|
| `markeId` | zu ändernde Marke | nicht leerer String; muss im Bestand stehen |
| `teilwerte` | die zu ändernden Felder, s. Signatur | jedes vorhandene Feld muss zu Rollen-Namen bzw. Objektform passen; `{ geerbt: true }` nur bei `parent !== null` zulässig |

Ausgang bei Erfolg: `Ergebnis<Marke>` – die **aufgelöste** Marke nach der Änderung.
Ausgang bei Fehler: `ungueltige_eingabe`, `marke_nicht_gefunden`, `speicher_fehler`,
`unbekannter_fehler`.

## Verbindliche Invarianten (wörtlich – Verletzung = Issue nicht erfüllt)
- Die Operations-Zeile, wörtlich (TK 9.15.1): „`bearbeiteMarke` | `markeId`, `teilwerte` →
  `Ergebnis<Marke>` – **Auto-Speichern** während des Bearbeitens"
- „**Bei einer abgeleiteten Marke ist sichtbar, was geerbt und was eigen ist.** Ein Wert, den der
  Nutzer nicht setzt, bleibt geerbt und folgt künftigen Änderungen des Parents; ein gesetzter Wert
  löst sich davon." (TK 9.15.2)
- „Das gilt für **jedes** Feld außer `id`, `name`, `parent` und `eingebaut`." (TK 9.11.2)
- „**Instant-Op vs. Speichern getrennt:** Eine Instant-Operation (9.5.2) validiert und wendet **im
  Speicher** an, *bevor* sie „ok" meldet – ihr Erfolg bedeutet „gültig übernommen", **nicht** „schon
  auf Platte". Die Platten-Schreibung ist die entprellte Auto-Speicherung." (TK 9.5.4) – diese
  Funktion meldet Erfolg, sobald `aendereBestand(…, 'entprellt')` die Änderung **im Speicher**
  übernommen hat.
- „**Entprellt 3–5 s** nach der letzten Änderung (kein Platten-Hämmern beim Slider-Ziehen)."
  (TK 9.5.4) – die konkrete Zahl (analog M4-04: 4000 ms) legt M8-03 fest, nicht diese Datei.
- „**Kein Undo für den Marken-Bestand in v1.** … Stattdessen gilt hier der `.bak`-Schutz des
  Stores." (TK 9.15.2) – diese Funktion legt **keinen** Schnappschuss an und ruft keine
  Undo-Infrastruktur.
- „Der Main validiert jede eingehende Nutzlast – er vertraut dem Renderer **nicht**." (TK 9.1.1,
  Punkt 6)
- Die eingebaute Marke ist „**bearbeitbar**" (TK 9.15.1) – diese Funktion sperrt sie **nicht**
  zusätzlich; die einzige Sperre der eingebauten Marke betrifft das **Löschen** (M8-13), nicht das
  Bearbeiten.

## Fehlerpfade (vollständig)
| Situation | Code | Verhalten |
|---|---|---|
| `markeId` ist kein String oder leer | `ungueltige_eingabe` | keine Wirkung |
| `teilwerte` ist kein Objekt oder `null` | `ungueltige_eingabe` | keine Wirkung |
| `name` gesetzt, aber nach `trim()` leer oder länger als 80 Zeichen | `ungueltige_eingabe` | keine Wirkung |
| ein Schlüssel in `farben` ist keine bekannte `FarbRolle` | `ungueltige_eingabe` | keine Wirkung; Meldung nennt den unbekannten Schlüssel |
| ein Schlüssel in `schriften` ist keine bekannte `SchriftRolle` | `ungueltige_eingabe` | keine Wirkung |
| `{ geerbt: true }` für ein Feld, obwohl `eintrag.parent === null` | `ungueltige_eingabe` | keine Wirkung; Meldung nennt, dass eine eigenständige Marke nichts erbt |
| keine Marke mit dieser `markeId` im Bestand | `marke_nicht_gefunden` | keine Wirkung |
| `aendereBestand` meldet `speicher_fehler` (beim entprellten Schreiben) | `speicher_fehler` | die Änderung **bleibt im Speicher** gültig (TK 9.5.4: kein Rollback); der Fehler geht zusätzlich über `marken:autoSpeichernStatus` (M8-04) hinaus – diese Funktion selbst liefert ihn nur, wenn der Aufruf **sofort** scheitert (z. B. das Laden vor der ersten Änderung) |
| unerwartete Ausnahme | `unbekannter_fehler` | gefangen und als Hülle gemeldet, kein `throw` |

## Nicht selbst entscheiden – STOPP und fragen
- **ECHTE OFFENE FRAGE: Was liefert diese Funktion zurück, wenn `aendereBestand(…, 'entprellt')` die
  Änderung im Speicher übernimmt, aber die Platte erst Sekunden später (oder mit Fehler)
  beschrieben wird?** Analog zu M4-04/M4-08 des `vorlagen-store` gibt es keine Antwort, an die sich
  ein späterer Schreibfehler hängen könnte – er läuft über `marken:autoSpeichernStatus` (M8-04). Ob
  diese Funktion überhaupt etwas anderes als den **sofort im Speicher** übernommenen Stand
  zurückgeben kann, oder ob `Ergebnis<Marke>` hier strukturell **immer** einen Erfolg mit der neuen
  Marke bedeutet (solange die Validierung und das Auffinden der `markeId` gelingen), ist **nicht**
  spezifiziert. **Nicht selbst festlegen** – dieselbe Frage stellt sich in M8-04 (Auto-Speichern) und
  sollte dort einheitlich beantwortet werden.
- **Reihenfolge mehrerer Felder in einem Aufruf, die sich gegenseitig beeinflussen könnten:** Wird
  z. B. `farben` und `name` im selben `teilwerte`-Objekt geändert, ist die Reihenfolge der Anwendung
  (b) oben unkritisch, weil die Felder unabhängig sind. Sollte künftig ein Feld eingeführt werden,
  das von einem anderen Feld desselben Aufrufs abhängt, ist die Reihenfolge zu klären – **aktuell
  keine offene Frage**, hier nur als Warnung für eine spätere Erweiterung vermerkt.
- **Was zählt als „gültiger Fachwert" für `farben[rolle]`?** Ist ein beliebiger String zulässig (auch
  kein Hex-Format), oder wird das Hex-Format (6-/8-stellig) hier geprüft? TK 9.11.2 sagt für den
  gespeicherten Typ nur „Hex, 6- oder 8-stellig", ohne zu sagen, **wo** das erzwungen wird. **Nicht
  raten** – analog zur Akzentfarbe der Aktion, die laut Entscheidung 4 des Auftraggebers „ein FREIER
  Hex-Wert" ist, aber ebenfalls nicht sagt, wer das Hex-Format prüft.

## Definition of Done
- [ ] Ein eigenständiges Feld (`farben.akzent = '#112233'`) auf einer eigenständigen Marke wird
      übernommen und erscheint in der aufgelösten Rückgabe
- [ ] `{ farben: { akzent: '#112233' } }` auf einer **abgeleiteten** Marke setzt genau diese Rolle
      eigen; alle übrigen Rollen bleiben geerbt (Test: `MarkenEintrag.farben` enthält nur `akzent`)
- [ ] `{ farben: { akzent: { geerbt: true } } }` auf einer abgeleiteten Marke, deren `akzent` zuvor
      eigen gesetzt war, entfernt den Schlüssel `akzent` aus `MarkenEintrag.farben` (Test prüft
      `'akzent' in eintrag.farben === false`, nicht nur `undefined`) und die aufgelöste Rückgabe
      trägt danach wieder den Wert des Parents
- [ ] `{ farben: { akzent: { geerbt: true } } }` auf einer **eigenständigen** Marke (`parent ===
      null`) ergibt `ungueltige_eingabe`, nichts wird geändert
- [ ] `{ logo: null }` (echtes, eigenes „kein Logo") und `{ logo: { geerbt: true } }` (zurück auf den
      Parent) ergeben **unterscheidbare** Ergebnisse: Ersteres setzt `eintrag.logo = null` eigen,
      Zweiteres entfernt den Schlüssel `logo` (Test, der beide Fälle gegenüberstellt)
- [ ] Ein unbekannter Schlüssel in `farben` (`{ farben: { nichtVorhandeneRolle: '#fff' } }`) ergibt
      `ungueltige_eingabe`
- [ ] `name` wird **immer** eigen übernommen, auch auf einer abgeleiteten Marke, und kennt keinen
      `{ geerbt: true }`-Zustand (Typtest: `MarkenTeilwerte['name']` ist `string | undefined`, kein
      `MarkenFeld<string>`)
- [ ] Eine unbekannte `markeId` ergibt `marke_nicht_gefunden`
- [ ] `aendereBestand` wird mit `schreibart === 'entprellt'` aufgerufen (Spy) – **nicht** `'sofort'`
- [ ] Die Datei enthält keinen `fs`-Import und keine eigene Undo-/Schnappschuss-Logik – Grep-Probe
- [ ] Alle Fehlerpfade oben liefern den genannten Code (kein `throw` über die IPC-Grenze)
- [ ] Keine Datei außerhalb von `src/main/marken-store/bearbeite-marke.ts` (+ zugehörige Testdatei)
      geändert
