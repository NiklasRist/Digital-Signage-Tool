### Issue M8-17: [template-canvas] Importierte Schriften je Marke laden

## Ziel (in einem Satz)
Vor dem ersten Zeichenaufruf mit einer bestimmten Marke steht nachweislich fest, dass **alle**
importierten Schriften dieser Marke geladen und registriert sind – belegt über
`document.fonts.check()` –, damit der Canvas nie lautlos auf eine Ersatzschrift zurückfällt.

## Modul & Datei
- Modul: `template-canvas` (Renderer, geteilt)
- Datei: `src/renderer/template-canvas/marken-schriften.ts`
- Vertrag: Technisches Konzept **9.10.4** (Satz 2, seit v3.4), **9.15.3** (Determinismus muss neu
  erfüllt werden), **9.10.3** Punkt 3 (Determinismus-Invariante) – Quelle der Wahrheit
- Prozess/Speicher: P2, P3, P4, P5 (jeder Zeichenaufruf, der eine Marke mit importierten Schriften
  benutzt); kein Dateisystem-Zugriff (liest über das Protokoll aus M8-16)

## Warum das im Gesamtsystem wichtig ist
Die vier **gebündelten** Marken-Schriften lädt `stelleSchriftenBereit()` (#8/M4-16) beim Start – das
bleibt unverändert und wird von dieser Datei **nicht** angefasst. Seit FA-24 kann eine Marke
zusätzlich **eigene** Schrift-Dateien mitbringen (`herkunft: "importiert"`, 9.15.3). Ohne diese Datei
gäbe es für genau diesen Fall **keinen** Ladeweg – `zeichneSegment` würde eine importierte
`SchriftRolle` mit der zuvor gesetzten Canvas-Schrift zeichnen, ohne dass irgendwo ein Fehler
entsteht. Das Ergebnis "funktioniert" augenscheinlich, aber Textbreiten, Umbrüche und die
Überlauf-Kaskade (M4-19) messen mit der falschen Schrift – Vorschau und Endvideo laufen lautlos
auseinander, und der Markenbruch (eine fremde Schrift statt der importierten) fällt frühestens auf
dem 85-Zoll-Fernseher im Studio auf.

Wörtlich aus dem Technischen Konzept (Fassung **v3.9** – der Satz über den frühen Render-Abbruch ist
seit v3.8 **zurückgenommen**, s. Klammer im Zitat): „**Playfair Display ist auf Windows/macOS nicht
vorinstalliert.** Die Marken-Schriften werden daher als **Dateien mit der App gebündelt** und
explizit registriert/geladen (`FontFace`), bevor gezeichnet wird. **Seit v3.4 gilt dasselbe für
importierte Schriften** (FA-24): Sie werden **je Marke** registriert und geladen, **bevor** die
erste Zone gezeichnet wird, und der Nachweis unten gilt für sie mit (9.15.3). Fehlt eine importierte
Datei, **entsteht gar kein Segment-PNG** – die Prüfung sitzt im **Renderer, vor dem Zeichnen**
(9.15.3); ein Rückfall auf die gebündelte Schrift wäre genau der stille Markenbruch, den dieser
Abschnitt verhindert. *(Bis v3.8 stand hier „bricht der Render früh ab (`marken_datei_fehlt`)" – der
`render-service` sieht bei Variante A nie eine Marken-Datei, s. 9.2.3.)* Andernfalls rendert der
Canvas still auf eine Fallback-Schrift → Vorschau ≠ Endvideo **und** Markenbruch." (TK 9.10.4)

## Signatur (verbindlich – NICHT ändern)
```ts
// src/renderer/template-canvas/marken-schriften.ts
import type { Marke, Schrift } from '../../shared/contracts/marke'

/**
 * Lädt und registriert ALLE Schriften mit herkunft: "importiert" der übergebenen Marke.
 * Idempotent je markeId: merkt sich das Promise dieser Marke in einem modul-globalen Bestand
 * (Map<string, Promise<void>>) und gibt es bei jedem weiteren Aufruf mit derselben markeId
 * unverändert zurück. Ein abgelehntes Promise wird NICHT gemerkt – der nächste Aufruf für dieselbe
 * markeId versucht es erneut. Hat die Marke KEINE importierte Schrift, löst die Funktion sofort auf,
 * ohne irgendetwas zu registrieren.
 */
export async function stelleMarkenSchriftenBereit(marke: Marke): Promise<void>

/**
 * Synchron. Liefert true NUR, wenn für JEDE importierte Schrift dieser Marke
 * document.fonts.check(schriftKurzform(schrift, 16)) true liefert. Eine Marke ohne importierte
 * Schrift liefert immer true (nichts zu prüfen). Existiert kein vorheriger Aufruf von
 * stelleMarkenSchriftenBereit(marke) für diese markeId, liefert die Funktion false.
 * zeichneSegment (M4-23) ruft diese Abfrage vor dem Zeichnen ab und wirft, wenn sie false liefert
 * (s. STOPP – der genaue Ablaufschritt ist NICHT Teil dieses Issues).
 */
export function sindMarkenSchriftenBereit(marke: Marke): boolean

/** Verwirft den gesamten Bestand. Gerufen wird sie an GENAU EINER Stelle: leereMarkenBestand()
 *  (M8-39, src/renderer/gemeinsam/marken-bereitstellung.ts) ruft sie nach JEDER Änderung am
 *  Marken-Bestand mit, damit eine ausgetauschte Schrift-Datei nicht als "bereit" durchgeht,
 *  obwohl sie sich geändert hat. Diese Datei sucht sich KEINE eigenen Aufrufer. */
export function leereMarkenSchriftBestand(): void
```

## Fremde Funktionen, die du aufrufst
```ts
// M4-16 – src/renderer/template-canvas/schriften.ts (bestehend, NICHT verändert)
export function schriftKurzform(schrift: Schrift, größePx: number): string
// `${schrift.gewicht} ${größePx}px "${schrift.familie}"` – dieselbe Kurzform, dieselbe Funktion für
// gebündelte UND importierte Schriften. Diese Datei baut KEINE zweite Kurzform-Funktion.

// #52 – src/shared/contracts/marke.ts (Ausschnitt, mit v3.4 ergänzt)
export interface Schrift { familie: string; gewicht: number; datei: string; herkunft: Herkunft }
export type Herkunft = 'gebuendelt' | 'importiert'
export interface Marke {
  id: string
  schriften: Record<SchriftRolle, Schrift>
  // …
}
```

**`FontFace` wird mit einer `marken://`-URL geladen, NICHT mit einer `media://`-URL:**
```ts
new FontFace(
  schrift.familie,
  `url(marken://${marke.id}/${schrift.datei})`,
  { weight: String(schrift.gewicht) },
)
```
Die URL wird von M8-16 (`behandleMarkenAssetAnfrage`) bedient. Diese Datei ruft den Handler **nicht**
direkt auf – sie erzeugt nur die URL, exakt wie M4-17 es für `media://` vormacht.

**Weicht die tatsächliche Signatur einer der genannten Fremdfunktionen ab, ist das ein
Vertragsfehler: melden und NICHT eigenmächtig anpassen.**

## Eingang → Ausgang
| Eingang | Bedeutung | Grenzen/Validierung |
|---|---|---|
| `marke` (beide Funktionen) | die **aufgelöste** Marke aus `leseMarke(markeId)` (M8-09) | `marke.id` nicht leer; `marke.schriften` vollständig (alle vier Rollen, TK 9.11.2) |

Ausgang bei Erfolg: `stelleMarkenSchriftenBereit(marke)` löst erst auf, wenn alle importierten
Schriften dieser Marke einsatzbereit sind; danach liefert `sindMarkenSchriftenBereit(marke)` `true`.
Ausgang bei Fehler: `stelleMarkenSchriftenBereit` reicht die Ausnahme aus `FontFace.load()`
unverändert weiter (Datei fehlt hinter `marken://`, Format ungültig); `sindMarkenSchriftenBereit`
bleibt `false`. **Keine** `Ergebnis<T>`-Hülle (dieselbe Begründung wie M4-16: die Funktion überschreitet
keine IPC-Grenze).

## Verbindliche Invarianten (wörtlich – Verletzung = Issue nicht erfüllt)
- „**Seit v3.4 gilt dasselbe für importierte Schriften** (FA-24): Sie werden **je Marke** registriert
  und geladen, **bevor** die erste Zone gezeichnet wird, und der Nachweis unten gilt für sie mit
  (9.15.3)." (TK 9.10.4)
- „**Determinismus muss neu erfüllt werden.** 9.10.3 verlangt, dass Schriften **vor** dem Zeichnen
  geladen sind; für die gebündelten erledigt das der Start. Für importierte gilt: Sie werden **je
  Marke** registriert und geladen, **bevor** die erste Zone gezeichnet wird, und der Nachweis aus
  9.10.4 (alle Familien über `document.fonts.check()` verfügbar) gilt für sie mit. Ohne das rendert
  der Canvas still auf eine Fallback-Schrift → **Vorschau ≠ Endvideo und Markenbruch**." (TK 9.15.3)
- „**Fehlt eine importierte Datei, wird gar nicht erst gezeichnet – die Prüfung sitzt im RENDERER,
  vor dem Zeichnen (v3.7, geschärft).** […] Schlägt das Laden fehl, **entsteht kein Segment-PNG**;
  der `composer` behandelt das wie jede andere ins Leere zeigende Referenz und führt in den
  **geführten Reparatur-Modus** (FA-19, 9.7.5) – und dort gilt: **Render erst frei, wenn alles
  behoben ist.** Der fehlerhafte Auftrag wird also **gar nicht erst eingereiht**. Ein stiller
  Rückfall auf die gebündelte Schrift bleibt verboten (er zeigte den Markenbruch erst am
  Fernseher)." (TK 9.15.3, Fassung v3.9) – diese Datei liefert dafür die Renderer-seitige Grundlage
  (Ladeweg + Nachweis); **sie ist damit auch die Stelle, an der das Fehlen auffällt** – ein früherer
  Abbruch im `render-service` ist zurückgenommen (er sieht nie eine Marken-Datei). *(Die frühere
  Fassung dieses Zitats – „bricht der Render FRÜH ab, vor dem ersten `ffmpeg`-Aufruf, mit dem
  Fehlercode `marken_datei_fehlt`" – stammt aus TK ≤ v3.6 und darf nicht mehr zitiert werden.)*
- „**Schriften sind vor dem Zeichnen geladen.** Der Aufruf wartet, bis alle benötigten Fonts
  einsatzbereit sind. Zeichnen mit Fallback-Schrift ist ein **Vertragsbruch** (lautloser Drift
  zwischen Vorschau und Endvideo)." (TK 9.10.3, Punkt 3)
- „Kennt **keine** Dateisystem-Pfade – Motive kommen ausschließlich über `media://` (9.5.7)." (TK
  9.10.8) – für importierte Marken-Dateien gilt dasselbe Prinzip mit `marken://` (M8-16).

## Nicht selbst entscheiden – STOPP und fragen
- **ERLEDIGT – nicht mehr melden: der Aufruf in Ablaufschritt 0 gehört M8-21.** Der Befund war
  richtig: `zeichneSegment` (M4-23) prüft heute nur `sindSchriftenBereit()` der VIER gebündelten
  Schriften, nicht die importierten dieser Datei. **M8-21 besitzt `zeichne-segment.ts` und trägt es
  ein** – dort steht verbindlich: `sindMarkenSchriftenBereit(marke)` immer, und
  `sindMarkenSchriftenBereit(rahmenMarke)` genau dann, wenn die Rahmen-Marke in diesem Aufruf
  gezeichnet wird (`vorlage.art === 'einblendung'`, `rahmenMarke !== marke`, Zone `id: 'hintergrund'`
  vorhanden); liefert eine der Prüfungen `false`, **wirft** `zeichneSegment`, bevor ein Canvas
  erzeugt wird. **Für dich ändert das nichts** – diese Datei bleibt eine reine Abfrage und trägt
  nichts in `zeichne-segment.ts` ein.
- **ERLEDIGT – nicht mehr melden: Aufrufer und Zeitpunkt von `stelleMarkenSchriftenBereit(marke)`
  stehen fest (M8-39 und M8-40).** Für die **gebündelten** Schriften erledigt das weiterhin der
  App-Start (`stelleSchriftenBereit()`, #8/M4-16 – einmalig, vier Schriften, feststehend). Für die
  **importierten** Schriften ist der Aufrufer `stelleMarkeBereit` in
  `src/renderer/gemeinsam/marken-bereitstellung.ts` (M8-39):

  ```ts
  export async function stelleMarkeBereit(markeId: string): Promise<Ergebnis<Marke, string>>
  ```

  In dessen verbindlichem Ablauf ist es Schritt 5: „**`await stelleMarkenSchriftenBereit(marke)`**
  (M8-17). Diese Funktion **wirft**, wenn eine importierte Schrift-Datei hinter `marken://` fehlt
  oder ihr Format ungültig ist. Der Wurf wird **hier gefangen** und zu
  `{ ok: false, fehler: { code: MARKEN_DATEI_FEHLT, … } }`" (M8-39). Der **Zeitpunkt** ist
  **gebündelt und im Voraus**, nicht je Zeichenaufruf: `bereiteZeichnenVor(projekt)` (#154, durch
  M8-40 geändert) stellt vor dem ersten Thumbnail „**alle** `aktion.markeId` aus `projekt.aktionen`
  **plus** `projekt.standardMarkeId` – entdoppelt" bereit und ruft dafür je `markeId`
  `stelleMarkeBereit(markeId)`; laut Signaturkommentar dort: „Muss abgeschlossen sein, BEVOR ein
  Thumbnail, eine Vorschau oder ein Render entsteht. Erneut aufrufen nach jedem abgeschlossenen
  Import und bei jedem Projektwechsel." (M8-40). Die befürchtete sichtbar wartende erste Vorschau
  einer neuen Marke tritt damit **nicht** ein. **Für dich ändert das nichts** – diese Datei ruft
  weder `stelleMarkeBereit` noch `bereiteZeichnenVor` und trägt in keine der beiden Dateien etwas
  ein.
  *Bis zum 11.08.2026 stand hier eine offene Frage: ob der Aufruf beim Öffnen eines Projekts für
  alle im Projekt verwendeten Marken gebündelt geschieht oder erst unmittelbar vor dem jeweiligen
  Zeichenaufruf – „dieselbe Klasse offener Fragen wie beim Aufwärm-Zeitpunkt der gebündelten
  Schriften in M4-16".*
- **Timeout beim Laden.** Wie in M4-16: kein eigener Timeout in dieser Datei; falls das Bündelungs-
  Gegenstück je einen einführt, gilt derselbe Wert hier gleichlautend – nicht selbst erfinden.
- **`document.fonts.check()` bei Canvas-Text.** M4-16 hält ausdrücklich fest, dass `document.fonts
  .ready` bei Canvas-2D-Text zu früh auflösen kann. `document.fonts.check()` ist die vom TK
  ausdrücklich verlangte Nachweis-Methode (9.10.4) und wird deshalb hier verwendet – ob sie in jeder
  Zielumgebung zuverlässig ist, ist dieselbe empirische Frage wie in M4-16 und wird hier **nicht**
  erneut durch eine eigene Zusatzabsicherung (Aufwärm-Zeichnen, `setTimeout`) ersetzt.
