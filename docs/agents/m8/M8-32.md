### Issue M8-32: [app-shell] Zugang zur gemeinsamen Marken-Sicht bereitstellen

## Ziel (in einem Satz)
Die Marken-Übersicht (M8-22, bereits geschrieben) entsteht **einmal je Fenster** an einer einzigen
Stelle, und jedes Renderer-Modul, das sie braucht (`action-editor`, `composer`, `template-canvas`),
bekommt seinen Zugang darauf als **Parameter** übergeben – nach demselben Muster, das `sichten.ts`
(M7-04) für die Projekt- und die Vorlagen-Sicht bereits festlegt.

**Ausdrücklich NICHT Ziel dieses Issues:** die Bedienfläche zu bauen, über die der Nutzer den
Marken-Editor öffnet. **Sie ist entschieden** – ein **fünfter Reiter [Marken]** (TK 9.14.1, seit
v3.6) – und sie wird von **M8-41** angelegt, nicht hier. Diese Datei liefert allein den Zugang zur
gemeinsamen Marken-Sicht.

## Warum das im Gesamtsystem wichtig ist
Das ist **dieselbe Stelle und dasselbe Muster**, das M7-04 für Projekt- und Vorlagen-Sicht bereits
umsetzt und wörtlich begründet:

> „Module **außerhalb** dieses Ordners importieren die Sicht **nicht** direkt; sie bekommen die
> Aktualisierungsfunktion als **Parameter** übergeben. Wer sie beim Aufbau der Oberfläche
> durchreicht, ist Sache der `app-shell` (M7) und ausdrücklich **nicht** Teil von M5." (#155,
> ENTSCHIEDEN 1, zitiert in M7-04)

M8-22 (die Marken-Übersicht selbst) benennt dieses Issue bereits **namentlich** als den vorgesehenen
Ort dieser Verteilung: „Module **außerhalb** dieses Ordners (etwa `app-shell`, M8-32) importieren
diese Sicht **nicht** direkt; sie bekommen die Aktualisierungsfunktionen als **Parameter**
übergeben." (M8-22, ENTSCHIEDEN 1)

Ohne diese Datei importiert jedes Modul, das eine Marke zeichnen will (`action-editor` für die
Live-Vorschau einer Aktion, `composer` für Thumbnails, `template-canvas` für den Segment-Render),
den Marken-Bestand **selbst** – mit demselben Risiko, das M7-04 für Projekt/Vorlagen bereits
ausformuliert hat: „Dann gibt es **zwei** Wahrheiten darüber, welches Projekt offen ist … Genau diese
Klasse Fehler ist im M5-Prüflauf fünfmal an den **Nähten** aufgetreten und nie innerhalb eines
Issues." Für Marken ist der Schaden konkret: Löscht der Nutzer im Marken-Editor eine Farbe einer
abgeleiteten Marke, während der `composer` noch den alten Bestand zeigt, weicht das Thumbnail von der
gerade bearbeiteten Marke ab, bis der Nutzer zufällig neu lädt.

**Warum es kein Ereignis über IPC gibt.** M8-22 legt bereits fest: „Sie wird **nicht** über
IPC-Ereignisse aktuell gehalten: `marken-editor` ist der einzige Renderer-Nutzer der
Marken-Bearbeitung, und der `marken-store` hat für Änderungen aus der eigenen Sitzung **kein**
Ereignis vorgesehen – `marken:autoSpeichernStatus` (M8-04) meldet ausschließlich einen
**fehlgeschlagenen** Schreibvorgang, nicht den Inhalt." (M8-22) Der Ausgleich ist derselbe wie bei
Projekt/Vorlagen: Jede Operation des Marken-Editors liefert den neuen Stand zurück, der
Marken-Editor selbst hält ihn (`marken-uebersicht.ts`, M8-22) und meldet ihn seinen Abonnenten; diese
Datei **verteilt nur den Zugang**.

## Signatur (verbindlich – NICHT ändern)
```ts
// src/renderer/app-shell/marken-zugang.ts
import type { Marke } from '../../shared/contracts/marke'
import type { Ergebnis } from '../../shared/contracts/ergebnis'
import {
  type MarkenUebersicht, ladeUebersicht, holeUebersicht, aufUebersichtGeaendert,
} from '../marken-editor/marken-uebersicht'

/** Zugang zur gemeinsamen Marken-Übersicht (M8-22). Reine Weiterreichung, keine eigene Logik –
 *  dasselbe Muster wie `VorlagenZugang` in M7-04. Bewusst NUR die Listen-Sicht: `oeffneMarke`/
 *  `holeGeoeffneteMarke` aus M8-22 sind editor-interne Konzepte ("welche Marke wird GERADE
 *  bearbeitet") und werden NICHT weitergereicht – Module außerhalb des Editors brauchen eine
 *  beliebige Marke per ID aus dem Bestand, nicht "die gerade offene". */
export interface MarkenZugang {
  /** (Erneutes) Laden über marken:listeMarken (M8-31, aufgerufen von M8-22). */
  lade: () => Promise<Ergebnis<MarkenUebersicht, string>>
  /** Momentaufnahme; null, solange nie erfolgreich geladen wurde. */
  hole: () => MarkenUebersicht | null
  aufGeaendert: (hoerer: (uebersicht: MarkenUebersicht) => void) => () => void
}

/**
 * Baut den Zugang EINMAL auf und lädt die Übersicht einmalig nach. Liefert entweder einen
 * vollständigen Zugang mit gefüllter Übersicht oder einen benannten Fehler – NIE einen Zugang mit
 * `hole() === null` im Erfolgsfall.
 */
export async function baueMarkenZugang(): Promise<Ergebnis<MarkenZugang, string>>
```

**Der Fehlercode reist auf der Renderer-Seite als `string`** – dieselbe Begründung wie in M7-04 und
bereits in M8-22 entschieden: „Die fachliche Union `MarkenFehlercode` liegt in
`src/main/marken-store/fehlercodes.ts` (M8-02); der Renderer darf wegen der getrennten tsconfigs (#1)
**nicht** aus `src/main/**` importieren. … **Deklariere die Union NICHT ein zweites Mal** in
`src/renderer/**`." (M8-22)

**Fremde Signaturen, die du benutzt (abgeschrieben aus der bereits bestehenden Quelle M8-22; weicht
die tatsächliche Fassung ab, ist das ein Vertragsfehler: melden und NICHT eigenmächtig anpassen):**

```ts
// M8-22 – src/renderer/marken-editor/marken-uebersicht.ts (DEFINIERENDE QUELLE, bereits geschrieben)

  marken: readonly Marke[]   // ALLE Marken, AUFGELÖST, in Bestandsreihenfolge, NICHT sortiert
}

export function aufUebersichtGeaendert(hoerer: (u: MarkenUebersicht) => void): () => void
// NICHT übernommen in MarkenZugang (editor-intern, s. Signatur oben):
//   oeffneMarke, holeGeoeffneteMarke, aufGeoeffneteMarkeGeaendert, uebernimmAktualisierteMarke,
//   erstelleEigenstaendigeMarke   // legt eine neue eigenständige Marke an (M8-22); sie wird von
//                                 // der Editor-Wurzel (M8-48) direkt beim Nachbarn geholt, weil sie
//                                 // eine Handlung DES EDITORS ist. Module außerhalb des Editors

```

## Der Ablauf (verbindlich)
`baueMarkenZugang` führt genau diese Schritte **streng nacheinander** aus:

1. **`await ladeUebersicht()`** (M8-22). `ok: false` → Code **unverändert** zurückgeben.
2. Den Zugang zusammensetzen (`lade`, `hole`, `aufGeaendert` reichen die drei importierten Funktionen
   **unverändert** durch – keine Umbenennung außer der reinen Weiterreichung) und
   `{ ok: true, wert: zugang }` liefern.

**`baueMarkenZugang` darf mehrfach gerufen werden** – dieselbe Begründung wie in M7-04
(„Ein zweiter Aufruf … würde eine Wiederholung nach einem behobenen Lesefehler verhindern"): ein
zweiter Aufruf lädt die Übersicht erneut; die Funktionen des Zugangs zeigen weiterhin auf dasselbe
`marken-editor`-Modul, es entsteht also keine zweite Sicht.

## Eingang → Ausgang
| Eingang | Bedeutung | Grenzen/Validierung |
|---|---|---|
| – (`baueMarkenZugang` hat kein Argument) | einmaliger Aufbau, vom Renderer-Bootstrap gerufen (die Verdrahtung leistet **M8-38**) | – |

Ausgang bei Erfolg: `{ ok: true, wert: MarkenZugang }`, mit `zugang.hole()` bereits gefüllt (nie
`null` im Erfolgsfall dieser Funktion – erst ein **späterer** Lesefehler nach erneutem `lade()` könnte
den zuletzt bekannten Stand unverändert lassen, s. Fehlerpfade).
Ausgang bei Fehler: Code **unverändert** aus `ladeUebersicht()` als `string`.
