### Issue M4-01: [contracts] Typen Vorlage und Zone definieren

## Ziel (in einem Satz)
Das Layout-Datenmodell des Systems – `Vorlage` mit ihren `Zone`n – existiert als geteilter,
typisierter Datensatz, sodass eigene Vorlagen (FA-13) reine Daten bleiben und `template-canvas`,
`vorlagen-store` und `vorlagen-editor` über dieselbe Struktur reden.

## Modul & Datei
- Modul: `contracts/types` (geteilt)
- Datei: `src/shared/contracts/vorlage.ts`
- Vertrag: Technisches Konzept **9.11.1** (Quelle der Wahrheit), ergänzend **9.11.1.1** (Ablage und
  Lebenszyklus), **9.12.1** (Invarianten des besitzenden Moduls), **9.11.2** (die Rollen, auf die
  verwiesen wird)
- Prozess/Speicher: V1 (`vorlagen.json`, app-weit); geteilt zwischen Main und Renderer

## Warum das im Gesamtsystem wichtig ist
Dieser Typ ist das **Layout-Programm** des Systems. `template-canvas` (M4-16 bis M4-24) liest nichts
anderes: Es bekommt `(Aktion, Vorlage, Marke)` und zeichnet daraus das Bild, das gleichzeitig in die
Vorschau, in die Thumbnails, in die Live-Vorschau des Aktions-Editors **und** als PNG in den finalen
Render geht. Alles, was dieser Typ nicht ausdrücken kann, muss der Zeichencode erraten – und jedes
Erraten ist ein zweiter Zeichenpfad, der lautlos zwischen Vorschau und Endvideo driftet.

Drei Modellierungsfehler sind hier besonders teuer und alle drei sind **still**:

1. **Prozentwerte statt absoluter Pixel.** Wer `rahmen` als `0..1`-Anteile modelliert, verschiebt die
   Rundung in den Zeichencode. Zwei Zonen, die auf dem Papier bündig sind, stehen dann je nach
   Rundung 1 px auseinander – im Endvideo sichtbar, im verkleinerten Vorschaubild nicht.
2. **Hex-Werte oder Schriftnamen in der Zone.** Dann ist ein Marken-Wechsel keine Datenänderung mehr,
   sondern eine Wanderung durch alle Vorlagen; und eine Vorlage kann eine Farbe tragen, die es in der
   `Marke` gar nicht gibt, ohne dass der Compiler es merkt.
3. **Ein `zIndex`- oder `position`-Feld neben der Array-Reihenfolge.** Zwei Quellen für dieselbe
   Information laufen unweigerlich auseinander; die Überlagerung ist dann nicht mehr reproduzierbar.

## Signatur (verbindlich – NICHT ändern)
```ts
// src/shared/contracts/vorlage.ts
import type { FarbRolle, SchriftRolle } from './marke'
// #52 – src/shared/contracts/marke.ts, bereits angelegt:
//   export type FarbRolle =
//     | 'akzent' | 'akzentKraeftig' | 'akzentTief'
//     | 'flaecheDunkel' | 'flaecheSehrDunkel' | 'flaecheHell' | 'flaecheAkzentZart'
//     | 'textAufDunkel' | 'textAufHell' | 'textSekundaer'
//     | 'linie' | 'scrimStart' | 'scrimEnde'
//   export type SchriftRolle = 'headlineElegant' | 'headlinePlakativ' | 'fliesstext' | 'fliesstextFett'

/** Flaeche UND Kompositionsart einer Vorlage (TK 9.11.1 Punkt 0). Nach dem Anlegen unveraenderlich. */
export type VorlagenArt = 'vollflaeche' | 'split' | 'einblendung'

/** Deklarative Verknuepfung Zone <-> Inhaltsfeld. null = dekorative/statische Zone. */
export type Bindung =
  | 'titel' | 'beschreibung' | 'preis' | 'cta' | 'bild' | 'logo' | 'slogan'

/** fest = Markenrahmen (FA-11), im Editor unveraenderlich. frei = gestaltbar (FA-12). */
export type ZonenRolle = 'fest' | 'frei'

/** Verhalten bei leerem gebundenem Feld. Default beim Anlegen einer Zone: 'leer'. */
export type WennLeer = 'leer' | 'ausblenden'

export type Einpassung = 'contain' | 'cover'

export type VerlaufRichtung = 'oben' | 'unten' | 'links' | 'rechts'

/** ABSOLUTE Pixel in der Flaeche der jeweiligen Vorlagenart – niemals Prozente. */
export interface Rahmen {
  x: number
  y: number
  breite: number
  höhe: number
}

export interface Ausrichtung {
  horizontal: 'links' | 'mitte' | 'rechts'
  vertikal: 'oben' | 'mitte' | 'unten'
}

/** Text-Parameter einer Zone – speisen die Ueberlauf-Kaskade (TK 9.10.6). */
export interface ZonenText {
  schriftRolle: SchriftRolle      // Rollen-Verweis in die Marke – NIE ein Font-Name
  farbRolle: FarbRolle            // Rollen-Verweis in die Marke – NIE ein Hex-Wert
  größeMax: number                // px, Startgroesse (Stufe 2 der Kaskade beginnt hier)
  größeMin: number                // px, Untergrenze des Verkleinerns
  maxZeilen: number               // Stufe 1 der Kaskade (Umbruch)
}

export interface ZonenBild {
  einpassung: Einpassung
}

export interface ZonenDeko {
  füllungFarbRolle?: FarbRolle
  radius?: number                 // Eckenradius in px
  statischerText?: string         // fester Text ohne Bindung; benoetigt zusaetzlich `text`
  verlauf?: {
    vonFarbRolle: FarbRolle
    bisFarbRolle: FarbRolle
    richtung: VerlaufRichtung
  }
}

export interface Zone {
  id: string                      // "ueberschrift" | "motiv" | "preis" | "logo" …
  rolle: ZonenRolle
  bindung: Bindung | null
  rahmen: Rahmen
  ausrichtung: Ausrichtung
  wennLeer: WennLeer
  text?: ZonenText
  bild?: ZonenBild
  deko?: ZonenDeko
}

export interface Vorlage {
  id: string                      // "vollbild" | "split" | "band-standard" | <uuid> bei eigenen
  name: string                    // Anzeigename
  art: VorlagenArt
  höhe: number | null             // nur bei "split"/"einblendung": Bandhoehe in px; sonst null
  parent: string | null           // != null -> ARBEITSKOPIE; == null -> nutzbare Vorlage
  eingebaut: boolean              // true = mitgeliefert; false = eigene (FA-13)
  zonen: Zone[]                   // Zeichenreihenfolge = Array-Reihenfolge (spaeter = darueber)
}

/** Ein Fundort einer Vorlagen-Referenz (ein Treffer der Referenzpruefung, M4-12). */
export interface VorlagenReferenz {
  projektId: string               // Project.id
  projektName: string             // Project.name – fuer die Meldung "in 2 Projekten"
  id: string                      // Aktions-ID bzw. Listenelement-ID des Treffers
}

/** Das vollstaendige Pruefergebnis: beide Trefferlisten, je mit Projekt. */
export interface Vorlagennutzung {
  aktionen: VorlagenReferenz[]         // Treffer ueber aktion.vorlagenId
  listenelemente: VorlagenReferenz[]   // Treffer ueber listenelement.einblendung.bandVorlageId
}
```

**Die oben mitzitierten Rollen-Unionen stammen aus #52 und sind fremder Vertrag.** Weicht die
tatsächliche Signatur von der hier ausgeschriebenen ab, ist das ein **Vertragsfehler**: **melden und
NICHT eigenmächtig anpassen.**

**ENTSCHIEDEN – `VorlagenReferenz` und `Vorlagennutzung` gehören hierher, nicht in den
`vorlagen-store`.** Sie sind das Ergebnis der Referenzprüfung (M4-12) und reisen zugleich als
`fehler.daten` einer abgelehnten Löschung (M4-13, Code `vorlage_referenziert`) **über die
IPC-Grenze** in den Renderer. Der Renderer kann nach der Ordner- und tsconfig-Trennung aus #1
**nicht** aus `src/main/**` importieren; lägen die Typen dort, müsste die Oberfläche die Trefferliste
als `unknown` auspacken und ihre Felder erraten – und ein Tippfehler in `projektName` fiele erst auf,
wenn ein Nutzer eine benutzte Vorlage zu löschen versucht. M4-12 und M4-13 **importieren** beide
Typen von hier und deklarieren sie **nicht** erneut.

**Diese Datei enthaelt ausschliesslich Typen** – keine Laufzeit-Werte, keine Konstanten, keine
Hilfsfunktionen, keine Validierung. Die drei eingebauten Vorlagen sind **Daten des
`vorlagen-store`** (M4-02, `src/main/vorlagen-store/eingebaute-vorlagen.ts`) und stehen bewusst
**nicht** hier: Nur der Store legt sie an, der Renderer bekommt sie über `listeVorlagen` und erkennt
sie am Feld `eingebaut`. So liegen die Daten nicht doppelt im Bundle.

## Verbindliche Invarianten (wörtlich – Verletzung = Issue nicht erfüllt)
- Das Modell steht wörtlich in TK 9.11.1:
  ```
  Vorlage {
    id:        string        // "vollbild" | "split" | "band-standard" | <uuid> bei eigenen
    name:      string        // Anzeigename
    art:       "vollflaeche" | "split" | "einblendung"   // Fläche + Kompositionsart (s. u.)
    höhe:      number | null // nur bei "split"/"einblendung": Bandhöhe in px, GERADZAHLIG (Punkt 8);
                             //   bei "vollflaeche" null
    parent:    string | null // Herkunft: ID der Vorlage, von der diese abgeleitet wurde.
                             //   ≠ null → ARBEITSKOPIE (in Bearbeitung, nicht auswählbar)
                             //   = null → eigenständige, nutzbare Vorlage
    eingebaut: boolean       // true = mitgeliefert; false = eigene (FA-13)
    zonen:     Zone[]        // Zeichenreihenfolge = Array-Reihenfolge (später = darüber)
  }

  Zone {
    id:          string                  // "ueberschrift" | "motiv" | "preis" | "logo" …
    rolle:       "fest" | "frei"         // fest = Markenrahmen (FA-11), im Editor unveränderlich
    bindung:     Bindung | null          // null = dekorative/statische Zone
    rahmen:      { x, y, breite, höhe }  // ABSOLUTE Pixel im 1920×1080-Raster
    ausrichtung: { horizontal: "links"|"mitte"|"rechts", vertikal: "oben"|"mitte"|"unten" }
    wennLeer:    "leer" | "ausblenden"   // Verhalten bei leerem gebundenem Feld (Default: "leer")
    text?: { schriftRolle, farbRolle, größeMax, größeMin, maxZeilen }
    bild?: { einpassung: "contain" | "cover" }
    deko?: { füllungFarbRolle?, radius?, statischerText?,
             verlauf?: { vonFarbRolle, bisFarbRolle, richtung: "oben"|"unten"|"links"|"rechts" } }
  }

  Bindung = "titel" | "beschreibung" | "preis" | "cta" | "bild" | "logo" | "slogan"
  ```
  (TK 9.11.1, wörtlich übernommen)
- „**`art` bestimmt Zeichenfläche *und* Kompositionsart** (gewählt bei der Vorlagenerstellung,
  FA-13)" (TK 9.11.1, Punkt 0). Die zugehörige Tabelle lautet wörtlich:

  | `art` | Zeichenfläche | Deckkraft | Video | Komposition (9.2.8) |
  |---|---|---|---|---|
  | `"vollflaeche"` | 1920 × 1080 | deckend | – | eigenständiges Segment (sequenziell) |
  | `"split"` | 1920 × `höhe` | deckend | **verkleinert** auf 1080 − `höhe` | `vstack` (Band **unter** dem Video) |
  | `"einblendung"` | 1920 × `höhe` | **mit Alpha** | bleibt **vollflächig** | `overlay` (Band **über** dem Video, unten) |

  Und: „Alle `rahmen`-Werte einer Zone beziehen sich auf die Fläche **ihrer** Vorlagenart. Die Arten
  sind **nicht** austauschbar: `composer` und `action-editor` bieten jeweils nur die passende Art an
  (vollflächig für eigenständige Segmente, `split`/`einblendung` für parallele Bänder)." (TK 9.11.1)
  **Folge für diesen Typ:** `Rahmen` bekommt **keinen** Hinweis auf 1920×1080; die Bezugsfläche
  ergibt sich aus `art` + `höhe` derselben `Vorlage`. Wer in den Typ eine feste Höhe schreibt
  (`höhe: 1080`), macht Bänder unmodellierbar.
- „**Absolute Pixel** im Raster der Vorlagenart – keine Prozentwerte. Eindeutig, keine Rundungsdrift,
  deckungsgleich mit der Canvas-Auflösung (9.10.2)." (TK 9.11.1, Punkt 1) – `x`, `y`, `breite`,
  `höhe` sind Pixel. **Keine** Normalisierung auf `0..1`, **keine** Prozent-Strings, **keine**
  CSS-Einheiten.
- „**Zeichenreihenfolge = Array-Reihenfolge** (später gezeichnete Zone liegt oben). **Kein**
  implizites Sortieren – sonst ist die Überlagerung nicht reproduzierbar." (TK 9.11.1, Punkt 2) –
  deshalb hat `Zone` **kein** `zIndex`-, **kein** `ebene`- und **kein** `position`-Feld. Dieselbe
  Regel gilt schon bei `Project.liste`: „Die Reihenfolge ist die Array-Reihenfolge von `liste` – es
  gibt **kein** separates `position`-Feld. Zwei Quellen für dieselbe Information würden unweigerlich
  auseinanderlaufen." (TK 9.11.3)
- „**`bindung`** verknüpft Zone ↔ Aktions-Feld **deklarativ**. **`wennLeer`** bestimmt das Verhalten
  bei leerem Feld:
  - **`"leer"`** *(Default)*: Zone bleibt leer, Layout unverändert.
  - **`"ausblenden"`**: Zone wird **gar nicht** gezeichnet – **inklusive Dekoration** (verhindert
    z. B. eine leere rote Preis-Pille)." (TK 9.11.1, Punkt 3)
- „**Invariante:** *Keine* der beiden Varianten verschiebt oder skaliert andere Zonen. Es gibt
  **kein automatisches Umlayouten** – sonst erfindet jeder Agent eine eigene Layout-Logik und das
  Ergebnis wird unvorhersehbar." (TK 9.11.1, Punkt 3) – **Folge für diesen Typ:** Es gibt **kein**
  Feld, das ein Umlayouten steuern könnte (kein `flow`, kein `stack`, kein `abstand`, kein
  `autoHeight`). Wer so ein Feld ergänzt, macht das Verbot unmöglich durchzusetzen.
- „**Feste Zonen sind Teil der Vorlage**, nicht hartkodiert – dadurch bleibt FA-13 ein reiner
  Datensatz. Der Editor darf Zonen mit `rolle: "fest"` **nicht** ändern, verschieben oder entfernen
  (Markenrahmen erzwungen, FA-11)." (TK 9.11.1, Punkt 4)
- „**Eigene Vorlagen dürfen freie Zonen hinzufügen, ändern, umordnen und entfernen** – auch
  **dekorative** Zonen (`bindung: null`) mit eigener Füllung, Radius oder statischem Text. So lässt
  sich Neues ergänzen, **ohne** das `Aktion`-Datenmodell zu erweitern. Ebenso ist `wennLeer` je Zone
  frei wählbar." (TK 9.11.1, Punkt 5)
- „**`text.*` speist die Überlauf-Kaskade** (9.10.6): `maxZeilen` = Stufe 1 (Umbruch),
  `größeMax`→`größeMin` = Stufe 2 (Verkleinern), danach Stufe 3 („…")." (TK 9.11.1, Punkt 6) – die
  drei Zahlen gehören deshalb **zur Zone**, nicht in den Zeichencode.
- „**Farben und Schriften sind Rollen-Verweise in die `Marke`** (z. B. `farbRolle: "akzent"`,
  `schriftRolle: "headlineDisplay"`), **keine** Hex-Werte oder Font-Namen. So bleibt ein
  Marken-Wechsel ein Datenwert und keine Vorlagen-Änderung." (TK 9.11.1, Punkt 7) – deshalb sind
  `farbRolle`, `schriftRolle`, `füllungFarbRolle`, `vonFarbRolle`, `bisFarbRolle` als `FarbRolle`
  bzw. `SchriftRolle` aus #52 typisiert und **nicht** als `string`.
- „**`Vorlage` und `Marke` liegen NICHT im Projekt** – sie sind app-weit (9.11.1.1, 9.5.6). Das
  Projekt hält nur **Referenzen** (`vorlagenId`, `bandVorlageId`)." (TK 9.11.3) – dieser Typ trägt
  deshalb **keine** `projektId` und **keine** Rückreferenz auf Aktionen oder Listenelemente.
- „**Eingebaute Vorlagen sind unlöschbar und eingefroren:** Layout-Änderungen an einer eingebauten
  Vorlage werden **nicht in-place** vorgenommen, sondern als **neue Vorlagen-ID** ausgeliefert. Sonst
  sähen Aktionen in bestehenden Projekten nach einem App-Update plötzlich anders aus."
  (TK 9.11.1.1) – `eingebaut: boolean` ist genau das Kennzeichen, an dem diese Sperre hängt.
- „**`art` ist nach dem Anlegen unveränderlich** – auch über die Arbeitskopie. Ein Wechsel würde alle
  Zonen-Rahmen ungültig machen (andere Fläche); stattdessen neu anlegen." (TK 9.12.1) – die
  Durchsetzung sitzt im Store (M4-08), **nicht** im Typ; `art` wird hier trotzdem **nicht** als
  optional oder änderbar modelliert.
- „**`höhe` nur bei `split`/`einblendung`**, Wertebereich > 0 und < 1080 **und geradzahlig**
  (9.11.1 Punkt 8, Begründung `yuv420p` in 9.2.8). Bei `vollflaeche` immer `null`. Der Store weist
  eine ungerade Höhe ab – auf **jedem** Weg, der sie setzen kann (`erstelleVorlage`,
  `speichereArbeitskopie`, `uebernehmeInParent`); der Editor sperrt sie bereits vorher (9.12.2)."
  (TK 9.12.1) – der Typ drückt das als `number | null` aus; die Prüfung von Wertebereich **und**
  Geradzahligkeit ist Laufzeit-Sache des Stores (M4-06/M4-08), **nicht** dieses Typs: `number` kann eine
  gerade Zahl nicht erzwingen.

**ENTSCHIEDEN – Feldnamen mit Umlaut bleiben wie im Vertrag.** `höhe`, `größeMax`, `größeMin`,
`füllungFarbRolle` werden **genau so** geschrieben, mit Umlaut und `ß`. Zwei Gründe: (a) Diese Namen
sind **JSON-Schlüssel** in `vorlagen.json` – eine Umschrift wäre eine stille Abweichung vom Vertrag,
die niemand mehr zurückverfolgen kann; (b) der bereits angelegte Typ `Asset` (#13) führt aus demselben
Grund `maße: { breite: number; höhe: number }`. Dass `RenderProfile` (#18) `hoehe` schreibt, ist
**kein** Gegenbeispiel: Das ist ein reines Laufzeit-Konfigurationsobjekt, das nie als Fachdatei
persistiert wird. **Verboten** ist hier jede ASCII-Umschrift (`hoehe`, `groesseMax`,
`fuellungFarbRolle`).

**ENTSCHIEDEN – die Schrift-Rolle `headlineDisplay` aus dem TK-Beispiel gibt es nicht.** TK 9.11.1
Punkt 7 nennt beispielhaft `schriftRolle: "headlineDisplay"`; die verbindliche Rollen-Liste steht
aber in TK 9.11.2 und lautet `headlineElegant`, `headlinePlakativ`, `fliesstext`, `fliesstextFett`
(so auch in #52 umgesetzt). Das Beispiel ist ein **veralteter Name im Fliesstext**, keine zusätzliche
Rolle. Deshalb: `SchriftRolle` aus #52 importieren, **nichts** ergänzen, **kein** `headlineDisplay`
anlegen. Wäre `schriftRolle` hier ein freier `string`, würde genau dieser Tippfehler erst beim
Zeichnen als Fallback-Schrift auffallen – und Fallback-Schriften sind laut TK 9.10.3 Punkt 3 ein
Vertragsbruch („Zeichnen mit Fallback-Schrift ist ein **Vertragsbruch**").

**ENTSCHIEDEN – wohin die sieben Bindungen zeigen** (gehört als Kommentar in die Datei, damit
M4-20/M4-21 nicht raten): `titel`, `beschreibung`, `preis`, `cta` zeigen auf die gleichnamigen Felder
der `Aktion` (#14); `bild` zeigt auf `aktion.bildRef`; `logo` und `slogan` zeigen **nicht** auf die
Aktion, sondern auf die `Marke` (#52: `marke.logo`, `marke.slogan`) – die `Aktion` hat diese Felder
gar nicht. Das ist der Grund, warum `Bindung` eine **eigene** Union ist und nicht `keyof Aktion`:
Zwei der sieben Bindungen kommen aus einer anderen Quelle.

## Nicht selbst entscheiden – STOPP und fragen
- **Verbot – keine Laufzeit-Werte in dieser Datei.** Kein `const`, keine `function`, keine
  Default-Objekte, keine Zod-/Schema-Objekte, keine Validierungshelfer. Insbesondere **nicht** die
  drei eingebauten Vorlagen – die sind Daten des `vorlagen-store` (M4-02) und liegen dort, damit sie
  nicht doppelt im Bundle landen.
- **Verbot – kein zusätzliches Feld, das ein Layout-Verhalten ausdrückt.** Kein `zIndex`, kein
  `ebene`, kein `position`, kein `sichtbar`, kein `flow`, kein `abstand`, kein `autoHeight`, kein
  `minHöhe`. Die Überlagerung ist die Array-Reihenfolge, die Sichtbarkeit ist `wennLeer`, und
  Umlayouten gibt es nicht. Jedes dieser Felder würde eine Invariante aus TK 9.11.1 unterlaufen.
- **Verbot – `farbRolle`/`schriftRolle` niemals als `string` oder `string | FarbRolle` öffnen**,
  auch nicht „für eigene Vorlagen". Eine eigene Vorlage darf freie Zonen ergänzen, aber keine neuen
  Farben erfinden (TK 9.11.1 Punkt 5 nennt ausdrücklich nur Zonen, nicht Farbwerte).
- **Verbot – `src/shared/contracts/marke.ts` (#52) wird nicht angefasst**, auch nicht „nur um
  `headlineDisplay` zu ergänzen" oder um die Rollen hierher zu verschieben. Importieren, nichts
  ändern.
- **Verbot – keine Vermischung mit `Aktion` (#14).** Kein `keyof Aktion`, kein gemeinsamer Typ, keine
  Rückreferenz von der Vorlage auf Aktionen. Die Vorlage weiss nicht, wer sie benutzt; das
  herauszufinden ist Aufgabe der Referenzprüfung (M4-12).
