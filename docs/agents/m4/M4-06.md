### Issue M4-06: [vorlagen-store] erstelleVorlage implementieren

## Ziel (in einem Satz)
Der Nutzer kann eine eigene Vorlage anlegen (FA-13): Er wählt die Art, bei Bändern die Höhe und einen
Namen, und bekommt eine nutzbare Vorlage zurück, in der der feste Markenrahmen bereits enthalten ist.

## Modul & Datei
- Modul: `vorlagen-store` (Main)
- Datei: `src/main/vorlagen-store/erstelle-vorlage.ts`
- Vertrag: Technisches Konzept **9.12.1** (Operations-Tabelle und Invarianten), **9.11.1**
  (Datenmodell und feste Zonen), **9.11.4** (ID-Schema) – Quelle der Wahrheit
- Prozess/Speicher: V1 (`vorlagen.json`)

## Warum das im Gesamtsystem wichtig ist
Diese Funktion ist der Einstieg in FA-13 („Vorlagen erstellen & bearbeiten", **Muss**). Sie
entscheidet über drei Dinge, die sich später nicht mehr korrigieren lassen:

**Die `art` ist ab hier unveränderlich** (TK 9.12.1). Wer sie falsch setzt oder aus der `höhe`
errät, zwingt den Nutzer, die Vorlage wegzuwerfen und neu anzulegen – alle Zonen-Rahmen wären
ungültig, weil sie sich auf eine andere Fläche beziehen.

**Der feste Markenrahmen entsteht hier.** FA-11 verlangt ein einheitliches Grundlayout, das
„nicht abschaltbar" ist; FA-13 sagt, eine eigene Vorlage „arrangiert nur die **freien Zonen** […]
innerhalb des **festen Markenrahmens** (Logo, Sicherheitsabstände)". Legt diese Funktion eine Vorlage
**ohne** feste Zonen an, gibt es diesen Rahmen für alle eigenen Vorlagen nicht mehr – und weil der
Editor feste Zonen nicht hinzufügen kann (er darf sie nur nicht ändern), lässt er sich auch nicht
nachträglich herstellen. Besonders fatal ist das Fehlen der `hintergrund`-Zone: Ohne sie rendert eine
Aktion ohne Motiv **schwarz** statt markenkonform.

**Die ID ist eine UUID und wird nie wiederverwendet.** Eine aus dem Namen abgeleitete oder
fortlaufende ID würde beim Umbenennen bzw. nach Löschen und Neuanlegen Referenzen in fremden
Projekten brechen – und zwar still, weil die Vorlage ja existiert, nur die falsche.

## Signatur (verbindlich – NICHT ändern)
```ts
// src/main/vorlagen-store/erstelle-vorlage.ts
import type { Ergebnis } from '../../shared/contracts/ergebnis'
import type { Vorlage, VorlagenArt, Zone } from '../../shared/contracts/vorlage'
import type { VorlagenFehlercode } from './fehlercodes'
import { aendereBestand } from './schreibe-vorlagen'
import { eingebauteVorlagen } from './eingebaute-vorlagen'
import { erzeugeId } from '../../shared/contracts/id'

// Fremde Aufrufe – vollstaendige Signaturen, damit hier nichts geraten wird:
//   M4-04: aendereBestand<T>(
//            aenderung: (bestand: Vorlage[]) =>
//              Ergebnis<{ bestand: Vorlage[]; wert: T }, VorlagenFehlercode>,
//            schreibart: 'sofort' | 'entprellt',
//          ): Promise<Ergebnis<T, VorlagenFehlercode>>
//          // `aenderung` ist SYNCHRON und bekommt eine tiefe Kopie des Bestands.
//   M4-02: eingebauteVorlagen(): Vorlage[]   // frische TIEFE Kopie der drei Mitgelieferten
//   #20:   erzeugeId(): string               // UUID v4
//   M4-03: type VorlagenFehlercode = 'vorlage_referenziert' | 'parent_eingebaut' | 'speicher_fehler'
//   M4-01: type VorlagenArt = 'vollflaeche' | 'split' | 'einblendung'
//          interface Zone { id: string; rolle: 'fest'|'frei'; bindung: Bindung | null
//                           rahmen: { x: number; y: number; breite: number; höhe: number }
//                           ausrichtung: { horizontal: 'links'|'mitte'|'rechts'
//                                          vertikal: 'oben'|'mitte'|'unten' }
//                           wennLeer: 'leer'|'ausblenden'
//                           text?: ZonenText; bild?: ZonenBild; deko?: ZonenDeko }
//          interface Vorlage { id: string; name: string; art: VorlagenArt; höhe: number | null
//                              parent: string | null; eingebaut: boolean; zonen: Zone[] }

export async function erstelleVorlage(
  art: VorlagenArt,
  höhe: number | null,
  name: string,
): Promise<Ergebnis<Vorlage, VorlagenFehlercode>>
```

**Die oben ausgeschriebenen fremden Signaturen (M4-04, M4-02, #20, M4-03, M4-01) sind fremder
Vertrag.** Weicht die tatsächliche Signatur von der hier ausgeschriebenen ab, ist das ein
**Vertragsfehler**: **melden und NICHT eigenmächtig anpassen.**

**Warum `höhe` ein Pflichtparameter mit `| null` ist und nicht optional.** Die Vertragstabelle
schreibt `erstelleVorlage | art, höhe?, name` (TK 9.12.1). Ein optionaler Parameter **in der Mitte**
ist in TypeScript nicht ausdrückbar, und eine Umsortierung der Parameter würde von der Tabelle
abweichen. Mit `number | null` bleibt die Reihenfolge erhalten, und der Aufrufer muss bei einer
vollflächigen Vorlage ausdrücklich `null` übergeben statt das Feld zu vergessen – ein vergessenes
`undefined` sähe sonst genauso aus wie eine bewusste Entscheidung.

**Ablauf (verbindlich):**

1. **Validieren, bevor irgendetwas passiert** (TK 9.1.1 Punkt 6). Bei jedem Verstoss
   `ungueltige_eingabe` und **keine** Wirkung auf den Bestand:
   - `art` ist einer der drei Werte.
   - `name` ist ein String; nach `trim()` nicht leer und höchstens 80 Zeichen lang. Gespeichert wird
     der **getrimmte** Name.
   - `art === 'vollflaeche'` → `höhe` **muss** `null` sein.
   - `art === 'split'` oder `'einblendung'` → `höhe` **muss** eine **gerade** ganze Zahl `> 0` und
     `< 1080` sein. Die Geradzahligkeit steht in TK 9.11.1 Punkt 8: Das Ausgabe-Profil `yuv420p`
     (9.2.4) verlangt gerade Höhen und gerade Versätze; eine ungerade Höhe wird **hier**
     abgewiesen, nicht erst beim Render.
2. `id` über `erzeugeId()` (#20) erzeugen.
3. Feste Zonen der Art vorbelegen (s. unten).
4. Die Vorlage `{ id, name: <getrimmt>, art, höhe, parent: null, eingebaut: false, zonen }` über
   `aendereBestand(…, 'sofort')` an den Bestand **anhängen** und zurückgeben.

**Vorbelegte feste Zonen – der entschiedene Teil:**

- **`art: 'vollflaeche'`** → eine **tiefe Kopie** der beiden Zonen mit den `id`s **`hintergrund`** und
  **`logo`** aus der eingebauten Vorlage mit der `id` **`'vollbild'`** (`eingebauteVorlagen()`,
  M4-02), in deren Reihenfolge: `hintergrund` (0, 0, 1920, 1080, Füllung `flaecheDunkel`) und `logo`
  (96, 54, 420, 120, `contain`). Die dritte feste Zone von `'vollbild'`, **`scrim`**, wird
  **ausdrücklich nicht** kopiert.
  **Warum namentlich und nicht „alle Zonen mit `rolle: 'fest'`":** `'vollbild'` führt drei feste
  Zonen. Der Scrim ist kein Bestandteil des Markenrahmens, sondern ein Lesbarkeits-Hilfsmittel für
  eine formatfüllende Fotofläche – eine neue Vorlage muss keine haben, und ein unerwarteter dunkler
  Verlauf über der unteren Bildhälfte wäre für den Nutzer nicht erklärbar.
  **Warum aus `'vollbild'` und nicht aus `'split'`:** Die eingebaute Vorlage `'split'` ist zwar
  ebenfalls vollflächig, setzt ihr Logo aber nach **rechts** (x = 1056), weil dort die Textspalte
  beginnt. Der Markenrahmen verlangt „**Logo 420×120**, **oben links**" (TK 9.11.1) – nur
  `'vollbild'` trägt es an dieser Stelle. **Warum kopiert und nicht neu geschrieben:** So stehen die
  Zahlen 1920/1080/96/54/420/120 an genau **einer** Stelle (M4-02); eine zweite Niederschrift hier
  würde beim ersten Nachjustieren auseinanderlaufen.
- **`art: 'split'` mit `höhe === 162`** → eine **tiefe Kopie** der beiden Zonen mit den `id`s
  **`hintergrund`** und **`logo`** aus der eingebauten Vorlage `'band-standard'`: `hintergrund`
  (0, 0, 1920, 162, `flaecheDunkel`) und `logo` (96, 20, 240, 69, `contain`). Andere feste Zonen hat
  diese Vorlage nicht.
- **Alle übrigen Fälle** (`art: 'split'` mit einer anderen Höhe, `art: 'einblendung'` mit jeder Höhe)
  sind **nicht entschieden** – s. „Nicht selbst entscheiden". Diesen Zweig **nicht raten und nicht
  vorläufig ausfüllen**.

Die kopierten Zonen behalten ihre `id` (`hintergrund`, `logo`), ihre `rolle: 'fest'` und ihre
`bindung`. Es entstehen **keine** freien Zonen: Die legt der Nutzer im Editor an.

## Eingang → Ausgang
| Eingang | Bedeutung | Grenzen/Validierung |
|---|---|---|
| `art` | Fläche **und** Kompositionsart der neuen Vorlage; nach dem Anlegen unveränderlich | genau einer der drei Werte `'vollflaeche' \| 'split' \| 'einblendung'` |
| `höhe` | Bandhöhe in px; bei `vollflaeche` `null` | bei `vollflaeche` **muss** `null` sein; sonst **gerade** ganze Zahl `> 0` und `< 1080` (TK 9.11.1 Punkt 8) |
| `name` | Anzeigename | String, nach `trim()` nicht leer, höchstens 80 Zeichen; **Doppelte sind erlaubt** – die Identität ist die `id`, nicht der Name (TK 9.11.4: „**Keine** aus Namen abgeleiteten IDs: ein Umbenennen darf niemals Referenzen brechen") |

Ausgang bei Erfolg: `Ergebnis<Vorlage, VorlagenFehlercode>` mit der neu angelegten Vorlage
(`parent: null`, `eingebaut: false`, feste Zonen vorbelegt). Sie steht danach in `vorlagen.json` und
erscheint in `listeVorlagen` (M4-05).
Ausgang bei Fehler: `ungueltige_eingabe` (Validierung) oder `speicher_fehler` (durchgereicht von
`aendereBestand`); ausserdem `unbekannter_fehler` aus dem generischen Satz (#12).

## Verbindliche Invarianten (wörtlich – Verletzung = Issue nicht erfüllt)
- Die Operations-Zeile, wörtlich (TK 9.12.1): „`erstelleVorlage` | `art`, `höhe?`, `name` →
  `Ergebnis<Vorlage>` mit `parent = null` (feste Zonen der Art vorbelegt)"
- „**`art` ist nach dem Anlegen unveränderlich** – auch über die Arbeitskopie. Ein Wechsel würde alle
  Zonen-Rahmen ungültig machen (andere Fläche); stattdessen neu anlegen." (TK 9.12.1) – deshalb ist
  `art` hier ein Pflichtparameter und wird **nicht** aus `höhe` abgeleitet („höhe gesetzt, also
  wohl ein Band").
- „**`höhe` nur bei `split`/`einblendung`**, Wertebereich > 0 und < 1080 **und geradzahlig**
  (9.11.1 Punkt 8, Begründung `yuv420p` in 9.2.8). Bei `vollflaeche` immer `null`. Der Store weist
  eine ungerade Höhe ab – auf **jedem** Weg, der sie setzen kann (`erstelleVorlage`,
  `speichereArbeitskopie`, `uebernehmeInParent`); der Editor sperrt sie bereits vorher (9.12.2)."
  (TK 9.12.1) – `erstelleVorlage` ist der **erste** dieser drei Wege; die Abweisung passiert hier.
- „**Feste Zonen sind Teil der Vorlage**, nicht hartkodiert – dadurch bleibt FA-13 ein reiner
  Datensatz. Der Editor darf Zonen mit `rolle: "fest"` **nicht** ändern, verschieben oder entfernen
  (Markenrahmen erzwungen, FA-11)." (TK 9.11.1, Punkt 4) – deshalb müssen sie **hier** entstehen; der
  Editor kann sie nicht nachliefern.
- „Die Zone **`hintergrund`** (fest, dekorativ, Markenfarbe) wird **als erstes** gezeichnet. Grund:
  das Bild einer Aktion ist **optional** (FA-02) – ohne diese Zone würde eine Aktion ohne Motiv
  **schwarz** rendern statt markenkonform." (TK 9.11.1) – `hintergrund` ist deshalb die **erste**
  Zone der neuen Vorlage.
- „**Logo 420×120**, **oben links**" (TK 9.11.1) – für vollflächige Vorlagen; im Band gilt der Wert
  aus der Band-Tabelle (240×69 bei 96/20).
- „**Alle IDs sind UUIDs** – `Project`, `Asset`, `Aktion`, `Listenelement`, `Vorlage`, `Auftrag`.
  **Keine** fortlaufenden Zähler: die kollidieren nach Löschen/Neu-Anlegen und beim Duplizieren von
  Projekten. **Keine** aus Namen abgeleiteten IDs: ein Umbenennen darf niemals Referenzen brechen."
  (TK 9.11.4) – die `id` kommt aus `erzeugeId()` (#20), nicht aus einem Zähler, nicht aus dem Namen,
  nicht aus einem Zeitstempel.
- „**IDs werden nie wiederverwendet**, auch nicht nach dem Löschen." (TK 9.11.4)
- „Der Main validiert jede eingehende Nutzlast – er vertraut dem Renderer **nicht**. Ungültige
  Eingabe → `ungueltige_eingabe`, **ohne** jede Wirkung auf die Daten. Ein Fehler im Renderer darf D1
  niemals beschädigen." (TK 9.1.1, Punkt 6) – die Validierung läuft **vollständig vor** dem Aufruf
  von `aendereBestand`, damit kein halb geprüfter Datensatz in den Bestand gerät.
- „**Zeichenreihenfolge = Array-Reihenfolge** (später gezeichnete Zone liegt oben). **Kein**
  implizites Sortieren" (TK 9.11.1, Punkt 2) – die kopierten festen Zonen behalten ihre Reihenfolge.
- Die neue Vorlage trägt **`eingebaut: false`**. Nur die drei aus M4-02 sind eingebaut; das Feld ist
  das Kennzeichen, an dem die Sperren gegen Löschen und gegen `uebernehmeInParent` hängen
  (TK 9.11.1.1).
- Die neue Vorlage trägt **`parent: null`** und ist damit sofort nutzbar. Sie ist **keine**
  Arbeitskopie – „Bearbeitet wird immer eine Arbeitskopie" (TK 9.12.2) betrifft das **Bearbeiten**
  (M4-07), nicht das Anlegen.
- **Angehängt wird hinten.** Die neue Vorlage kommt ans **Ende** des Bestands, damit die Reihenfolge
  bestehender Einträge unverändert bleibt (M4-05 liefert Bestandsreihenfolge; ein Einfügen vorn würde
  die Liste des Nutzers bei jedem Anlegen umsortieren).
- **Ganzzahlige Höhe.** `höhe` muss ganzzahlig sein. Begründung: Sie ist zugleich die **Höhe der
  Canvas-Fläche** (TK 9.10.2: „`art: "split"` bzw. `"einblendung"` → **1920 × `höhe`**"); eine
  gebrochene Backing-Grösse führt zu einer gerundeten Fläche, und ab da stimmen die absoluten
  Zonen-Pixel nicht mehr mit dem gezeichneten Bild überein. Das TK nennt den Wertebereich `> 0` und
  `< 1080`; die Ganzzahligkeit folgt aus der Canvas-Fläche und wird deshalb hier festgelegt, nicht
  offengelassen.
- **Gerade Höhe – vom Vertrag vorgegeben, nicht von diesem Issue.** Zusätzlich zur Ganzzahligkeit
  verlangt TK 9.11.1 Punkt 8 eine **gerade** Bandhöhe: „Bei ungerader Höhe ist die Videofläche
  `1080 − höhe` (bei `split`) bzw. der Overlay-Versatz `y = 1080 − höhe` (bei `einblendung`)
  ungerade – **beide** Kompositionsarten aus 9.2.8 brechen." Das ist **keine** eigene Festlegung
  dieses Issues und darf auch nicht wegdiskutiert werden: `erstelleVorlage` ist die Stelle, an der
  die Höhe entsteht, und der Nutzer soll den Fehler hier erfahren – nicht erst beim Render.

## Fehlerpfade (vollständig)
| Situation | Code | Verhalten |
|---|---|---|
| `art` ist kein Wert der Union | `ungueltige_eingabe` | keine Wirkung, nichts geschrieben |
| `name` ist kein String, nach `trim()` leer oder länger als 80 Zeichen | `ungueltige_eingabe` | keine Wirkung |
| `art === 'vollflaeche'` und `höhe !== null` | `ungueltige_eingabe` | keine Wirkung; Meldung nennt, dass eine vollflächige Vorlage keine Höhe hat |
| `art` ist `'split'`/`'einblendung'` und `höhe` ist `null`, keine Zahl, nicht ganzzahlig, `<= 0` oder `>= 1080` | `ungueltige_eingabe` | keine Wirkung; Meldung nennt den zulässigen Bereich |
| `art` ist `'split'`/`'einblendung'` und `höhe` ist **ungerade** (z. B. 161) | `ungueltige_eingabe` | keine Wirkung; Meldung nennt, dass die Bandhöhe gerade sein muss (TK 9.11.1 Punkt 8) |

| unerwartete Ausnahme | `unbekannter_fehler` | gefangen und als Hülle gemeldet, kein `throw`, nichts geschrieben |

## Nicht selbst entscheiden – STOPP und fragen
- **Welche festen Zonen bekommt ein Band, das nicht 162 px hoch ist – und welche eine Vorlage der
  Art `einblendung`?** Das ist die einzige echte Lücke dieses Issues, und sie hat zwei Teile:
  1. **Logo-Geometrie bei beliebiger Bandhöhe.** Die Werte der eingebauten Band-Vorlage (Logo
     96, 20, 240, 69) sind auf `höhe = 162` zugeschnitten: „Sicher nutzbar sind damit nur die oberen
     **108 px** des Bandes (9.11.2). Inhalt tiefer als Band-y 108 kann am TV abgeschnitten werden."
     (TK 9.11.1) Bei einem 120 px hohen Band bleiben nur 66 sichere Pixel – das 69 px hohe Logo passt
     nicht mehr. Ob es mitskaliert (und wie: proportional? auf welche Mindestgrösse?), ob es an eine
     andere Position rutscht oder ob Bandhöhen unter einem Mindestwert gar nicht erlaubt sind, sagt
     der Vertrag **nirgends**. Eine erfundene Skalierungsregel wäre genau das „automatische
     Umlayouten", das TK 9.11.1 Punkt 3 verbietet.
  2. **Hintergrund einer `einblendung`.** „**Deckkraft folgt der Vorlagenart:** `split`-Bänder sind
     **deckend** (echter Split, keine Überdeckung); `einblendung`-Bänder tragen **Alpha** (sie
     überlagern das Video)." (TK 9.2.8) Ein `hintergrund` mit `füllungFarbRolle: 'flaecheDunkel'`
     wäre vollständig deckend und würde den Sinn der Einblendung aufheben; welche Farbrolle oder
     welcher Verlauf stattdessen vorbelegt wird (`scrimStart`/`scrimEnde`? gar keine
     Hintergrundzone?), legt der Vertrag nicht fest. Und es gibt **keine** eingebaute
     `einblendung`-Vorlage, aus der sich die Antwort ablesen liesse.

  **Nicht raten, nicht „vorläufig wie beim Band" ausfüllen, keinen Platzhalter einbauen.** Die
  Antwort bestimmt, wie jede künftige eigene Band-Vorlage aussieht.
- **Verbot – die festen Zonen nicht neu hinschreiben.** Sie werden aus `eingebauteVorlagen()`
  kopiert. Wer die Zahlen hier noch einmal tippt, erzeugt eine zweite Quelle für den Markenrahmen.
- **Verbot – keine freien Zonen vorbelegen.** Keine leere Überschrift, kein Motiv-Platzhalter, keine
  „Standard-Zonen zum Loslegen". FA-13 sagt: die eigene Vorlage „arrangiert nur die **freien
  Zonen**" – das tut der Nutzer im Editor.
- **Verbot – keine Arbeitskopie anlegen.** Diese Funktion erzeugt eine Vorlage mit `parent: null`.
  Wer sie direkt bearbeiten will, ruft danach `oeffneZurBearbeitung` (M4-07).
- **Verbot – keine Namensprüfung auf Eindeutigkeit** und kein automatisches Anhängen von „(2)". Zwei
  Vorlagen dürfen gleich heissen; die `id` unterscheidet sie.
- **Verbot – kein direkter Dateizugriff.** Kein `fs`, kein `ermittleDatenOrt()`. Der Bestand wird
  ausschliesslich über `aendereBestand` (M4-04) geändert.
