### Issue M4-07: [vorlagen-store] oeffneZurBearbeitung implementieren

## Ziel (in einem Satz)
Das Bearbeiten einer Vorlage beginnt immer auf einer **Arbeitskopie**, von der es pro Vorlage
höchstens eine gibt – wird eine bereits vorhandene geöffnet, wird sie fortgesetzt statt eine zweite
anzulegen.

## Modul & Datei
- Modul: `vorlagen-store` (Main)
- Datei: `src/main/vorlagen-store/oeffne-zur-bearbeitung.ts`
- Vertrag: Technisches Konzept **9.12.1** (Arbeitskopie-Fluss und Invarianten), **9.11.1.1**
  (eingebaute sind eingefroren) – Quelle der Wahrheit
- Prozess/Speicher: V1 (`vorlagen.json`)

## Warum das im Gesamtsystem wichtig ist
Diese Funktion ist der **Schutzwall vor der laufenden Werbung**. Vorlagen sind app-weit: Dieselbe
Vorlage kann in mehreren Projekten von vielen Aktionen benutzt werden. Würde der Editor direkt auf
der genutzten Vorlage arbeiten, verändert jedes Verschieben einer Zone sofort das Aussehen aller
dieser Aktionen – auch derjenigen in Projekten, die der Nutzer gerade gar nicht offen hat. Die
Arbeitskopie trennt Experimentieren vom Veröffentlichen; das Übernehmen ist eine **eigene**,
ausdrückliche Handlung (M4-09/M4-10).

Der zweite Zweck ist konstruktiver Natur: **Höchstens eine Arbeitskopie je Parent** ist der Grund,
warum es im ganzen System keine Konfliktauflösung braucht. Existierten zwei Arbeitskopien derselben
Vorlage, wollten beide dieselbe Vorlage überschreiben, und irgendwer müsste entscheiden, welche
gewinnt. Wer hier bei jedem Öffnen eine neue Kopie anlegt, führt genau dieses Problem ein – und es
zeigt sich erst Wochen später, wenn ein Nutzer eine mühsam gebaute Änderung wieder verschwinden
sieht.

## Signatur (verbindlich – NICHT ändern)
```ts
// src/main/vorlagen-store/oeffne-zur-bearbeitung.ts
import type { Ergebnis } from '../../shared/contracts/ergebnis'
import type { Vorlage } from '../../shared/contracts/vorlage'
import type { VorlagenFehlercode } from './fehlercodes'
import { aendereBestand } from './schreibe-vorlagen'
import { erzeugeId } from '../../shared/contracts/id'

// Fremde Aufrufe – vollstaendige Signaturen, damit hier nichts geraten wird:
//   M4-04: aendereBestand<T>(
//            aenderung: (bestand: Vorlage[]) =>
//              Ergebnis<{ bestand: Vorlage[]; wert: T }, VorlagenFehlercode>,
//            schreibart: 'sofort' | 'entprellt',
//          ): Promise<Ergebnis<T, VorlagenFehlercode>>
//          // `aenderung` ist SYNCHRON und bekommt eine tiefe Kopie des Bestands.
//   #20:   erzeugeId(): string    // UUID v4
//   M4-03: type VorlagenFehlercode = 'vorlage_referenziert' | 'parent_eingebaut' | 'speicher_fehler'
//   M4-01: interface Vorlage { id: string; name: string; art: VorlagenArt; höhe: number | null
//                              parent: string | null; eingebaut: boolean; zonen: Zone[] }

/**
 * Liefert die Arbeitskopie, auf der bearbeitet wird.
 * Existiert bereits eine mit parent === id, wird GENAU DIESE zurueckgegeben (fortsetzen);
 * sonst wird eine neue angelegt.
 */
export async function oeffneZurBearbeitung(id: string): Promise<Ergebnis<Vorlage, VorlagenFehlercode>>
```

**Die oben ausgeschriebenen fremden Signaturen (M4-04, #20, M4-03, M4-01) sind fremder Vertrag.**
Weicht die tatsächliche Signatur von der hier ausgeschriebenen ab, ist das ein **Vertragsfehler**:
**melden und NICHT eigenmächtig anpassen.**

**Ablauf (verbindlich), vollständig innerhalb **einer** `aendereBestand(…, 'sofort')`-Einheit:**

1. `id` prüfen: nicht-leerer String, sonst `ungueltige_eingabe` **ohne** jeden Bestandszugriff.
2. Eintrag mit dieser `id` im Bestand suchen. Nicht vorhanden → `nicht_gefunden`.
3. Der gefundene Eintrag muss `parent === null` haben. Ist er selbst eine Arbeitskopie →
   `ungueltige_eingabe` (s. Invariante „keine Kette").
4. Im Bestand nach einem Eintrag mit `parent === id` suchen.
   - **Gefunden** → **genau diesen** zurückgeben. Der Bestand wird dabei **nicht verändert**.
   - **Nicht gefunden** → neue Arbeitskopie bauen und **hinten** an den Bestand anhängen:
     | Feld | Wert |
     |---|---|
     | `id` | neue UUID über `erzeugeId()` (#20) |
     | `name` | **unverändert** der Name des Parents |
     | `art` | unverändert vom Parent |
     | `höhe` | unverändert vom Parent |
     | `parent` | die übergebene `id` |
     | `eingebaut` | **immer `false`** – auch wenn der Parent eingebaut ist |
     | `zonen` | **tiefe Kopie** der Zonen des Parents, Reihenfolge unverändert |
5. Die Arbeitskopie zurückgeben.

**ENTSCHIEDEN – im Fortsetzen-Fall wird trotzdem geschrieben.** `aendereBestand` schreibt immer;
inhaltlich ändert sich in diesem Fall nichts, die Datei bekommt denselben Inhalt erneut. Das ist
bewusst in Kauf genommen: Die Alternative wäre, den Bestand **vor** der Änderungs-Einheit zu lesen
und nur bei Bedarf zu ändern – und genau das öffnet die Verschränkungslücke wieder, die M4-04
schliesst (zwischen Lesen und Schreiben könnte eine andere Operation eine zweite Arbeitskopie
anlegen). Das Öffnen des Editors ist eine seltene, vom Nutzer ausgelöste Handlung; ein zusätzlicher
Schreibvorgang von wenigen Kilobyte kostet nichts.

**ENTSCHIEDEN – die Arbeitskopie übernimmt den Namen des Parents unverändert.** Kein Zusatz wie
„(Kopie)" oder „Arbeitskopie von …". Zwei Gründe: (a) Der Editor zeigt den Zustand ohnehin selbst –
„Der Editor zeigt durchgehend, **ob** er auf einer Arbeitskopie sitzt und **welcher Parent**
dahintersteht" (TK 9.12.2); (b) bei `alsEigenstaendige` (M4-10) gibt der Nutzer einen neuen Namen an,
und ein hier angehängter Zusatz müsste dort wieder entfernt werden – eine Zeichenketten-Operation,
die bei einem Namen, der zufällig selbst „(Kopie)" enthält, das Falsche tut.

## Eingang → Ausgang
| Eingang | Bedeutung | Grenzen/Validierung |
|---|---|---|
| `id` | ID der zu bearbeitenden, **nutzbaren** Vorlage (eingebaut oder eigen) | nicht-leerer String; muss im Bestand existieren; der Eintrag muss `parent === null` haben |

Ausgang bei Erfolg: `Ergebnis<Vorlage, VorlagenFehlercode>` mit der Arbeitskopie (`parent === id`,
`eingebaut === false`). Sie erscheint danach in `listeArbeitskopien` (M4-05) und **nicht** in
`listeVorlagen`.
Ausgang bei Fehler: `nicht_gefunden` (unbekannte `id`), `ungueltige_eingabe` (leere `id` oder die
`id` gehört zu einer Arbeitskopie), `speicher_fehler` (durchgereicht von `aendereBestand`), sowie
`unbekannter_fehler` aus dem generischen Satz (#12).

## Verbindliche Invarianten (wörtlich – Verletzung = Issue nicht erfüllt)
- Die Operations-Zeile, wörtlich (TK 9.12.1): „`oeffneZurBearbeitung` | `id` → `Ergebnis<Vorlage>` –
  legt eine **Arbeitskopie** mit `parent = id` an und gibt sie zurück"
- „**Höchstens eine Arbeitskopie pro Parent.** Wird eine Vorlage geöffnet, für die bereits eine
  Arbeitskopie existiert, wird **diese fortgesetzt** statt eine zweite anzulegen. So kann es
  strukturell **keinen** Merge-Konflikt geben (zwei Kopien, die denselben Parent überschreiben
  wollen)." (TK 9.12.1) – **das ist die Kernzusage dieses Issues.**
- „**Auto-Speichern trifft nur die Arbeitskopie.** Während des Bearbeitens wird entprellt gesichert
  (3–5 s, wie 9.5.4) – aber **ausschließlich** in die Arbeitskopie. Die genutzte Vorlage ändert sich
  **erst** beim expliziten `uebernehmeInParent` bzw. `alsEigenstaendige`. So kann Experimentieren
  **nie** laufende Werbung in anderen Projekten verändern." (TK 9.12.1) – **Folge hier:** Der Parent
  wird von dieser Funktion **in keiner Weise** angefasst – nicht sein `name`, nicht seine `zonen`,
  kein Merkfeld „wird gerade bearbeitet".
- „**Zweck des `parent`-Feldes (und warum es genullt wird):** Das Feld `parent` ist **die
  Merge-Beziehung** – es sagt „diese Vorlage stammt von X und kann in X zurückgeschrieben werden"."
  (TK 9.12.1)
- „**Arbeitskopien (`parent ≠ null`) sind nicht auswählbar.** `composer` und `action-editor` bekommen
  sie nicht angeboten – halbfertige Vorlagen können nicht in einen Render geraten." (TK 9.12.1) –
  deshalb erhält die Arbeitskopie eine **eigene** UUID und behält **nicht** die `id` des Parents.
  Behielte sie sie, wäre der Parent aus dem Bestand verdrängt und alle Referenzen zeigten auf ein
  halbfertiges Layout.
- „**Eingebaute Vorlagen sind unlöschbar und eingefroren:** Layout-Änderungen an einer eingebauten
  Vorlage werden **nicht in-place** vorgenommen, sondern als **neue Vorlagen-ID** ausgeliefert."
  (TK 9.11.1.1) – **eine eingebaute Vorlage darf trotzdem geöffnet werden.** Der Vertrag sagt dazu:
  „**`uebernehmeInParent` ist gesperrt, wenn der Parent eingebaut ist.** Eingebaute Vorlagen bleiben
  unveränderlich (9.11.1.1); dort bleibt nur `alsEigenstaendige`." (TK 9.12.1) Gesperrt ist also das
  **Übernehmen** (M4-09), nicht das Öffnen. Das Öffnen einer eingebauten Vorlage ist im Gegenteil der
  vorgesehene Weg, aus ihr eine eigene abzuleiten. Diese Funktion gibt deshalb **nie**
  `parent_eingebaut` zurück.
- **Die Arbeitskopie ist nie `eingebaut`.** Sie trägt `eingebaut: false`, auch wenn der Parent
  eingebaut ist. Andernfalls wäre die Arbeitskopie selbst unlöschbar und eingefroren – sie liesse
  sich weder verwerfen noch bearbeiten, und der Nutzer säße in einer Sackgasse.
- **Keine Kette von Arbeitskopien.** Der Parameter `id` muss auf eine Vorlage mit `parent === null`
  zeigen. Eine Arbeitskopie einer Arbeitskopie ergäbe eine Kette, für die es weder ein Übernehmen
  noch ein Verwerfen gibt: „Merge ist ein vollständiges Ersetzen, kein Feld-Abgleich."
  (TK 9.12.1) beschreibt genau **einen** Schritt in **einen** Parent. Wer eine Arbeitskopie
  weiterbearbeiten will, benutzt sie direkt – `listeArbeitskopien` (M4-05) liefert sie.
- „**Alle IDs sind UUIDs** […] **Keine** fortlaufenden Zähler […] **Keine** aus Namen abgeleiteten
  IDs" und „**IDs werden nie wiederverwendet**, auch nicht nach dem Löschen." (TK 9.11.4) – die `id`
  der Arbeitskopie kommt aus `erzeugeId()` (#20). Insbesondere **nicht** `parent + '-arbeitskopie'`:
  Solche abgeleiteten IDs kollidieren nach Verwerfen und erneutem Öffnen.
- „Der Main validiert jede eingehende Nutzlast – er vertraut dem Renderer **nicht**. Ungültige
  Eingabe → `ungueltige_eingabe`, **ohne** jede Wirkung auf die Daten." (TK 9.1.1, Punkt 6)
- **Die Zonen werden tief kopiert.** Ein flacher Spread (`zonen: [...parent.zonen]`) würde `rahmen`-,
  `text`- und `deko`-Objekte weiterhin **teilen**: Das erste Verschieben einer Zone in der
  Arbeitskopie veränderte damit den Parent im Speicher – genau das, was die Arbeitskopie verhindern
  soll, und es fiele erst beim nächsten Schreibvorgang auf.

## Fehlerpfade (vollständig)
| Situation | Code | Verhalten |
|---|---|---|
| `id` ist kein String oder leer | `ungueltige_eingabe` | keine Wirkung, kein Bestandszugriff |
| keine Vorlage mit dieser `id` im Bestand | `nicht_gefunden` | keine Wirkung, nichts angelegt |
| die `id` gehört zu einer Arbeitskopie (`parent !== null`) | `ungueltige_eingabe` | keine Wirkung; Meldung nennt, dass Arbeitskopien direkt bearbeitet werden |
| es existiert bereits eine Arbeitskopie mit `parent === id` | – | **kein Fehler**: die vorhandene wird zurückgegeben, keine zweite angelegt |
| die `id` gehört zu einer **eingebauten** Vorlage | – | **kein Fehler**: Arbeitskopie wird angelegt (die Sperre sitzt in M4-09, nicht hier) |
| `aendereBestand` meldet `speicher_fehler` | `speicher_fehler` | durchgereicht; die Arbeitskopie existiert danach **nicht** |
| unerwartete Ausnahme | `unbekannter_fehler` | gefangen und als Hülle gemeldet, kein `throw`, nichts geschrieben |

## Nicht selbst entscheiden – STOPP und fragen
- **Verbot – den Parent nicht anfassen.** Kein Umbenennen, kein Zeitstempel, kein Merkfeld „in
  Bearbeitung", keine Sperre auf dem Parent. Der Bestand darf sich in dieser Operation **ausser** um
  den einen neuen Eintrag nicht verändern.
- **Verbot – kein zweiter Vergleich beim Fortsetzen.** Wird eine vorhandene Arbeitskopie gefunden,
  wird sie **unverändert** zurückgegeben. Insbesondere wird sie **nicht** mit dem aktuellen Stand des
  Parents abgeglichen, aufgefrischt oder um neu hinzugekommene feste Zonen ergänzt. Das wäre ein
  Feld-Abgleich, und den schliesst TK 9.12.1 ausdrücklich aus: „**Merge ist ein vollständiges
  Ersetzen, kein Feld-Abgleich.**"
- **Verbot – keine Arbeitskopie automatisch aufräumen.** Findet sich eine Arbeitskopie mit einem
  `parent`, den es nicht mehr gibt, bleibt sie unberührt; das Nullen verwaister `parent`-Verweise
  gehört ausschliesslich M4-14.
- **Verbot – kein direkter Dateizugriff.** Kein `fs`, kein `ermittleDatenOrt()`, kein zweites Lesen
  des Bestands ausserhalb der `aendereBestand`-Einheit.
- **Verbot – keine eigene UUID-Erzeugung.** `erzeugeId()` (#20), nichts anderes.

## Definition of Done
- [ ] `oeffneZurBearbeitung(<id einer nutzbaren Vorlage>)` liefert eine Vorlage mit
      `parent === <id>`, einer **neuen** UUID, `eingebaut === false` und denselben `art`, `höhe`,
      `name` wie der Parent
- [ ] Die Zonen der Arbeitskopie sind inhaltsgleich zu denen des Parents, aber **tiefe Kopien**:
      Eine Änderung an `kopie.zonen[0].rahmen.x` verändert den Parent im Bestand nicht (Test lädt den
      Bestand danach erneut)
- [ ] Zweimaliges Aufrufen mit derselben `id` liefert **dieselbe** Arbeitskopie (gleiche `id`) und
      der Bestand enthält danach genau **eine** Vorlage mit `parent === <id>` (eigener Test)
- [ ] Der Parent ist nach dem Öffnen byte-identisch zu vorher (Test vergleicht den Eintrag)
- [ ] `oeffneZurBearbeitung('vollbild')` gelingt und liefert eine Arbeitskopie mit
      `eingebaut === false` – **kein** `parent_eingebaut`
- [ ] `oeffneZurBearbeitung(<id einer Arbeitskopie>)` ergibt `ungueltige_eingabe` und legt nichts an
- [ ] `oeffneZurBearbeitung('gibt-es-nicht')` ergibt `nicht_gefunden`
- [ ] `oeffneZurBearbeitung('')` ergibt `ungueltige_eingabe`
- [ ] Die neue Arbeitskopie erscheint in `listeArbeitskopien` und **nicht** in `listeVorlagen`
      (Integrationstest über M4-05)
- [ ] Meldet `aendereBestand` `speicher_fehler`, gibt die Funktion genau diesen Code zurück und der
      Bestand enthält danach keine Arbeitskopie
- [ ] Die Datei enthält keinen `fs`-Import und keinen eigenen UUID-Erzeuger – Grep-Probe auf `fs`,
      `randomUUID`
- [ ] Alle Fehlerpfade oben liefern den genannten Code (kein `throw` über die IPC-Grenze)
- [ ] Keine Datei außerhalb von `src/main/vorlagen-store/oeffne-zur-bearbeitung.ts` (+ zugehörige
      Testdatei) geändert
