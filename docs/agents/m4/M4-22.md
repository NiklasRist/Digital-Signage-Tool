### Issue M4-22: [template-canvas] Eine dekorative Zone zeichnen

## Ziel (in einem Satz)
Die gestalterischen Flächen einer Vorlage entstehen: die deckende Hintergrundfläche, die abgerundete
Preis- oder CTA-Pille, der Verlauf, der Text über einem Foto lesbar macht, und ein fest in der
Vorlage hinterlegter Text – alles aus reinen Vorlagen- und Markendaten, ohne eine Zeile fest
verdrahtetes Layout.

## Modul & Datei
- Modul: `template-canvas` (Renderer, geteilt)
- Datei: `src/renderer/template-canvas/zone-deko.ts`
- Vertrag: Technisches Konzept **9.11.1** (Zonen-Modell, `deko`, die eingebauten Vorlagen),
  **9.11.2** (Marke: Farb-Rollen) – Quelle der Wahrheit
- Prozess/Speicher: Renderer, reine Zeichenfunktion; **kein** IPC, **kein** Dateizugriff

## Warum das im Gesamtsystem wichtig ist
Diese Funktion ist der Grund, warum eigene Vorlagen (FA-13) ein **reiner Datensatz** bleiben können.
Alles, was ein Nutzer gestalterisch ergänzen darf – eine farbige Fläche, eine abgerundete Pille, ein
Verlauf, ein fester Text –, entsteht hier aus vier Feldern des Zonen-Modells. Wird stattdessen auch
nur ein Element hart in den Code geschrieben („die Preis-Pille ist immer rot mit Radius 40"), ist
FA-13 gebrochen: Jede neue Gestaltungsidee bräuchte dann wieder einen Code-Umbau, und ein
Marken-Wechsel wäre keine Datenänderung mehr.

Zwei der eingebauten Zonen hängen unmittelbar an dieser Funktion:

- Die Zone **`hintergrund`** wird in allen drei eingebauten Vorlagen **als erstes** gezeichnet.
  Fehlt sie oder wird sie nicht gefüllt, rendert eine Aktion **ohne** Motiv schwarz statt
  markenkonform – und ein Bild ist laut FA-02 ausdrücklich optional.
- Die Zone **`scrim`** der Vorlage „Vollbild" ist nichts anderes als ein Verlauf von
  durchsichtigem zu dunklem Schwarz. Sie ist der einzige Grund, warum weißer Text über einem hellen
  Foto überhaupt lesbar bleibt. Läuft der Verlauf in die falsche Richtung, verdunkelt er das Foto
  oben und lässt den Text unten ungeschützt – das Ergebnis sieht in einem kleinen Vorschaufenster
  noch akzeptabel aus und ist auf 85 Zoll unlesbar.

## Signatur (verbindlich – NICHT ändern)
```ts
// src/renderer/template-canvas/zone-deko.ts
import type { Zone } from '../../shared/contracts/vorlage'
import type { Marke } from '../../shared/contracts/marke'
import type { Aktion } from '../../shared/contracts/aktion'

export function zeichneDekoZone(
  ctx: CanvasRenderingContext2D,
  zone: Zone,
  marke: Marke,
  aktion: Aktion,
): void
```

**ENTSCHIEDEN (TK v3.0, 9.10.9) – die `Aktion` kommt herein, wird aber NUR durchgereicht.**
Die Akzentfarbe einer Aktion **ersetzt** beim Zeichnen die drei Akzent-Rollen ihrer Vorlage
(`akzent`, `akzentKraeftig`, `akzentTief`); alle übrigen Rollen bleiben unberührt, und ohne gesetzte
Akzentfarbe gilt der Markenwert. Das geschieht **ausschließlich in `loeseFarbe` (M4-18)** – wörtlich:
„**Es gibt genau eine Auflösungsstelle.** Keine Zonen-Sorte (Text, Bild, Deko, Verlauf) darf
`marke.farben[...]` direkt lesen – sonst wirkt die Akzentfarbe in der Pille, aber nicht im Verlauf
dahinter, und niemand fände den Grund. Auch `deko.verlauf` (`vonFarbRolle`/`bisFarbRolle`) läuft
durch dieselbe Funktion." (TK 9.10.9)

**Diese Datei ist der namentlich genannte Anlassfall.** Die Preis-Pille und die CTA-Pille der
eingebauten Vorlagen sind `deko`-Füllungen mit einer Akzent-Rolle – hier landet die Farbwahl des
Nutzers sichtbar, und der `scrim`-Verlauf dahinter ist die Stelle, an der ein zweiter
Auflösungsweg auffliegen würde. Für die Datei heißt das **genau zweierlei** und sonst nichts: Sie
nimmt die `Aktion` als weiteren Parameter entgegen und gibt sie unverändert als **drittes**
Argument an `loeseFarbe` weiter – bei der Füllung **und** bei **beiden** Verlaufs-Stopps. Sie liest
`aktion.akzentfarbe` **nicht selbst**, tauscht **keine** Rolle aus und kennt die Liste der
Akzent-Rollen **nicht**.

Kein Rückgabewert und **keine** `Ergebnis<T>`-Hülle: keine IPC-Grenze, Teil der reinen, synchron
aufrufbaren Renderer-Funktion `zeichneSegment` (TK 9.10.8). **Synchron, kein `await`.**

**Wichtig – diese Funktion gilt für jede Zone mit `deko`, auch für gebundene.** Die Preis-Pille der
eingebauten Vorlagen ist die `deko` **derselben** Zone, die auch den Preis-Text trägt (TK 9.11.1,
Tabellen „Vollbild"/„Split": Zone `preis`, `bindung: preis`, Parameter „Pille (Akzent)"). Die
Reihenfolge – erst die Dekoration, dann der Inhalt – stellt `zeichneSegment` (M4-23) her. „Dekorativ"
im Sinne des Konzepts (`bindung: null`) ist nur der Sonderfall einer Zone **ohne** Inhalt.

**Fremde Funktionen, die du aufrufst** (vollständig ausgeschrieben – du siehst die anderen Issues
nicht):

**Weicht die tatsächliche Signatur von der hier ausgeschriebenen ab, ist das ein Vertragsfehler:
melden und NICHT eigenmächtig anpassen.** Genau die gegenteilige Regel („dann passt du den Aufruf

**Die Zonen- und Markenfelder, mit denen du rechnest:**

```ts
// M4-01 – src/shared/contracts/vorlage.ts (Ausschnitt)
export interface Zone {
  id: string
  rolle: 'fest' | 'frei'
  bindung: Bindung | null                       // null = dekorative/statische Zone
  rahmen: { x: number; y: number; breite: number; höhe: number }   // ABSOLUTE Pixel
  ausrichtung: { horizontal: 'links' | 'mitte' | 'rechts'; vertikal: 'oben' | 'mitte' | 'unten' }
  wennLeer: 'leer' | 'ausblenden'
  text?: { schriftRolle: SchriftRolle; farbRolle: FarbRolle; größeMax: number; größeMin: number; maxZeilen: number }
  bild?: { einpassung: 'contain' | 'cover' }
  deko?: {
    füllungFarbRolle?: FarbRolle
    radius?: number                             // ECKENRADIUS IN PIXELN – kein Rollen-Name
    statischerText?: string
    verlauf?: {
      vonFarbRolle: FarbRolle
      bisFarbRolle: FarbRolle
      richtung: 'oben' | 'unten' | 'links' | 'rechts'
    }
  }
}

// #52 – src/shared/contracts/marke.ts (Ausschnitt)
export interface Marke {
  farben: Record<FarbRolle, string>
  schatten: { versatzY: 4; weichzeichnen: 8; farbe: string }
  // …
}
```

**`radius` ist eine Pixelzahl, kein Rollen-Name.** Er wird **unverändert** aus
`zone.deko.radius` genommen; `marke.radien` wird in dieser Datei **nicht** gelesen. Begründung:
TK 9.11.1 Punkt 7 macht ausdrücklich nur **Farben und Schriften** zu Rollen-Verweisen, und das
Zonen-Modell schreibt das konsequent aus (`füllungFarbRolle`, `schriftRolle`, `farbRolle`) – aber
schlicht `radius`. Die eingebauten Vorlagen (M4-02) tragen dort deshalb die Zahlen selbst.
Die **Deckelung** auf `min(breite, höhe) / 2` bleibt trotzdem verbindlich (s. Ablauf Punkt 6): Sie
schadet bei den echten Werten nicht und verhindert eine undefinierte Form bei einer eigenen Vorlage
mit unmöglichem Radius.

**Der Ablauf, verbindlich – in genau dieser Reihenfolge:**

1. Fehlt `zone.deko` vollständig, kehrt die Funktion sofort zurück, ohne `save`/`restore`.
2. `ctx.save()`.
3. `ctx.shadowColor = 'transparent'`, `ctx.shadowBlur = 0`, `ctx.shadowOffsetX = 0`,
   `ctx.shadowOffsetY = 0` – dekorative Flächen bekommen **keinen** Schatten (s. STOPP-Block), und
   ein eventuell von außen hereingereichter Schattenzustand darf nicht durchschlagen.
4. **Füllung**, falls `deko.füllungFarbRolle` gesetzt ist: den Zonenpfad aufbauen (s. Punkt 6), dann
   – **im `try`/`catch`** – `ctx.fillStyle = loeseFarbe(marke, deko.füllungFarbRolle, aktion)`,
   `ctx.fill()`.
   Wirft `loeseFarbe`, wird **dieser Teilschritt übersprungen** (kein `fill()`), und es geht mit
   Punkt 5 weiter.
5. **Verlauf**, falls `deko.verlauf` gesetzt ist: **denselben** Pfad erneut aufbauen,
   `ctx.fillStyle` auf den Verlauf setzen, `ctx.fill()`. Der Verlauf liegt damit **über** einer
   eventuellen Füllung – er ist eine Abschattung, keine Alternative zu ihr. Auch hier stehen die
   **beiden** `loeseFarbe`-Aufrufe (`vonFarbRolle`, `bisFarbRolle`) im `try`/`catch`; wirft einer
   von beiden, wird der **ganze** Verlauf übersprungen (ein Verlauf mit einem geratenen Stopp wäre
   schlimmer als kein Verlauf).
6. **Der Zonenpfad**: `ctx.beginPath()`, dann
   - `radius` gesetzt → `ctx.roundRect(x, y, breite, höhe, r)` mit
     `r = Math.min(deko.radius, Math.min(breite, höhe) / 2)`
   - sonst → `ctx.rect(x, y, breite, höhe)`

   Die Deckelung auf `min(breite, höhe) / 2` ist zwingend: Die Zone `preis` der Band-Vorlage ist
   240 × 72 px groß und trägt `radius: 40`. Ohne Deckelung wäre der Radius größer als die halbe Höhe
   – die Form wäre nicht mehr definiert. Mit Deckelung ergibt sich 36, also exakt die gewünschte
   Pillenform. Bei der Zone `preis` der Vorlage „Vollbild" (524 × 150, `radius: 40`) greift sie
   dagegen nicht, weil `min(524, 150) / 2 = 75` größer ist als 40.
7. **Verlaufskoordinaten** – `createLinearGradient(x0, y0, x1, y1)` mit `addColorStop(0, von)` und
   `addColorStop(1, bis)`; `richtung` benennt, **wohin** der Verlauf läuft (`von` liegt an der
   gegenüberliegenden Kante):

   | `richtung` | `x0, y0` | `x1, y1` |
   |---|---|---|
   | `unten` | `x`, `y` | `x`, `y + höhe` |
   | `oben` | `x`, `y + höhe` | `x`, `y` |
   | `rechts` | `x`, `y` | `x + breite`, `y` |
   | `links` | `x + breite`, `y` | `x`, `y` |

   **Gegenprobe an den echten Daten:** Die Zone `scrim` der Vorlage „Vollbild" hat den Rahmen
   `0, 432, 1920, 648`, `von = scrimStart` (`#00000000`, durchsichtig), `bis = scrimEnde`
   (`#000000B3`, dunkel), `richtung: unten`. Nach der Tabelle ist der Verlauf oben durchsichtig und
   unten dunkel – genau dort, wo Überschrift (y 640–830) und Beschreibung (y 850–950) stehen. Läuft
   er andersherum, ist das Ergebnis nachweislich falsch.

   Die Koordinaten sind **absolute Canvas-Koordinaten** (die Kanten des Zonenrahmens), nicht
   `0, 0, breite, höhe`. Ein Verlauf ist im Canvas an den Raum gebunden, nicht an die Form.
8. **Statischer Text**, falls `deko.statischerText` gesetzt und **`zone.bindung === null`**:
   `zeichneTextZone(ctx, zone, zone.deko.statischerText, marke, aktion)`. Trägt die Zone eine `bindung`,
   wird `statischerText` **ignoriert** – der gebundene Wert der Aktion gewinnt, und M4-23 zeichnet
   ihn ohnehin gleich danach. Zwei Texte in einer Zone gäbe es sonst übereinander.
9. `ctx.restore()` als letzte Anweisung auf jedem Pfad, der nach Schritt 2 endet.

**Warum `loeseFarbe` gefangen wird.** Die Funktion **wirft** bei unbekannter Rolle und bei
unzulässigem Farbformat – so ist es in M4-18 festgelegt, und Vorlagen kommen zur Laufzeit aus einer
JSON-Datei, die TypeScript nicht prüft. Diese Funktion darf aber **niemals** werfen (sie läuft in
einer Schleife über alle Zonen; eine Ausnahme ließe das ganze Segment leer). Deshalb: jeder Aufruf
im `try`/`catch`, im `catch` **nur der betroffene Teilschritt** übersprungen – **keine** Ersatzfarbe,
kein Schwarz, kein Magenta-Warnton –, die Zone im Übrigen normal gezeichnet, und `ctx.restore()`
läuft trotzdem.

**Statischer Text geht durch `zeichneTextZone` – ausnahmslos.** Er wird hier **nicht** selbst
gezeichnet. Sonst gäbe es zwei Stellen, die Text setzen, mit zwei Auffassungen von Umbruch,
Verkleinerung und Ausrichtung: genau der zweite Zeichenpfad, den TK 9.10.1 verbietet.

## Eingang → Ausgang
| Eingang | Bedeutung | Grenzen/Validierung |
|---|---|---|
| `ctx` | der 2D-Kontext des Segment-Canvas (M4-23) | wird nicht hier erzeugt; jede Zustandsänderung mit `save`/`restore` einklammern |
| `zone` | eine Zone mit `deko`-Anteil – gebunden oder nicht | fehlt `deko`, passiert nichts; `rahmen` wird unverändert verwendet |
| `marke` | die gebündelte, read-only Marke (#52) | liefert Farben und Radien ausschließlich über Rollen |

Ausgang bei Erfolg: Füllung, Verlauf und ggf. statischer Text stehen im Zonenrahmen; der Kontext ist
in exakt dem Zustand, in dem er hereinkam.
Ausgang bei Fehler: entfällt – diese Funktion kennt keine Fehlercodes (s. u.).

## Verbindliche Invarianten (wörtlich – Verletzung = Issue nicht erfüllt)
- Das Zonen-Modell, wörtlich (TK 9.11.1):

  ```
  deko?: { füllungFarbRolle?, radius?, statischerText?,
           verlauf?: { vonFarbRolle, bisFarbRolle, richtung: "oben"|"unten"|"links"|"rechts" } }
  ```
- „Die Zone **`hintergrund`** (fest, dekorativ, Markenfarbe) wird **als erstes** gezeichnet. Grund:
  das Bild einer Aktion ist **optional** (FA-02) – ohne diese Zone würde eine Aktion ohne Motiv
  **schwarz** rendern statt markenkonform." (TK 9.11.1) – die Reihenfolge stellt M4-23 her; diese
  Funktion muss die Fläche **wirklich decken** und darf sie nicht teilweise füllen.
- Die Zone `scrim` der eingebauten Vorlage „Vollbild", wörtlich aus der Zonen-Tabelle (TK 9.11.1):
  „Verlauf `scrimStart` → `scrimEnde`, Richtung `unten` – sichert die **Lesbarkeit** von Text über
  Fotos"
- „**Eigene Vorlagen dürfen freie Zonen hinzufügen, ändern, umordnen und entfernen** – auch
  **dekorative** Zonen (`bindung: null`) mit eigener Füllung, Radius oder statischem Text. So lässt
  sich Neues ergänzen, **ohne** das `Aktion`-Datenmodell zu erweitern." (TK 9.11.1, Punkt 5)
- „**Farben und Schriften sind Rollen-Verweise in die `Marke`** (z. B. `farbRolle: "akzent"`,
  `schriftRolle: "headlineDisplay"`), **keine** Hex-Werte oder Font-Namen. So bleibt ein
  Marken-Wechsel ein Datenwert und keine Vorlagen-Änderung." (TK 9.11.1, Punkt 7)
  — *Hinweis zum Zitat:* Das Beispiel `"headlineDisplay"` ist im Konzept veraltet; die tatsächlichen
  Schrift-Rollen heißen `headlineElegant`, `headlinePlakativ`, `fliesstext`, `fliesstextFett`
  (TK 9.11.2, #52). Die **Regel** – nur Rollen, nie Werte – gilt unverändert, aber **ausschließlich
  für Farben und Schriften**: Punkt 7 nennt genau diese beiden. `radius` ist davon nicht erfasst und
  bleibt eine Pixelzahl der Vorlage.
- „**Absolute Pixel** im Raster der Vorlagenart – keine Prozentwerte." (TK 9.11.1, Punkt 1)
- „Es gibt **keinen zweiten Zeichenpfad.** Anzeige und Export stammen immer aus **demselben**
  Aufruf – sonst driften Vorschau und Endvideo auseinander." (TK 9.10.1) – deshalb geht statischer
  Text durch `zeichneTextZone` und wird hier nicht nachgebaut.
- „**Gleiche Eingabe → gleiches Bild.** Keine Zeit-, Zufalls- oder Zustandsabhängigkeit (keine
  Animation, kein Datum, kein `Math.random`)." (TK 9.10.3, Punkt 5)
- **Der Kontext wird lückenlos wiederhergestellt** – zu jedem `ctx.save()` genau ein
  `ctx.restore()`, auch bei vorzeitigem Ende.
- **Niemals `throw`.** Eine Ausnahme in einer einzigen Zone würde das ganze Segment leer lassen –
  in der Vorschau und im Render.

## Fehlerpfade (vollständig)
Keine Fehlercodes (kein Rückgabewert, keine IPC-Grenze). Jede Ausnahmesituation endet in einem
definierten Zeichenergebnis:

| Situation | Verhalten |
|---|---|
| `zone.deko` fehlt | nichts zeichnen, kein `save`/`restore` |
| `deko` vorhanden, aber ohne Füllung, Verlauf und statischen Text | nichts zeichnen (leerer, aber gültiger Datensatz) |
| `deko.füllungFarbRolle` nennt eine Rolle, die `marke.farben` nicht kennt, oder `aktion.akzentfarbe` ist keine Rolle (`loeseFarbe` **wirft**) | Ausnahme fangen, diesen Schritt **überspringen** – keine Ersatzfarbe, kein Schwarz, kein Magenta-Warnton; mit dem Verlauf weitermachen, `restore()` ausführen |
| `deko.radius` ist keine endliche Zahl > 0 (fehlt, `null`, `NaN`, negativ) | wie **ohne** Radius behandeln (rechteckig) |
| `deko.verlauf` nennt eine unbekannte Farb-Rolle (`loeseFarbe` **wirft**) oder eine unbekannte Richtung | Ausnahme fangen, den **ganzen** Verlauf überspringen; eine erratene Richtung oder ein geratener Stopp wäre schlimmer als kein Verlauf |
| `deko.statischerText` gesetzt, aber `zone.text` fehlt | nichts zeichnen – `zeichneTextZone` bricht selbst ab; **keine** Ersatzschrift hier |
| `deko.statischerText` gesetzt und `zone.bindung !== null` | statischen Text ignorieren (der gebundene Wert gewinnt) |
| `zone.rahmen.breite` oder `.höhe` ist ≤ 0 oder nicht endlich | nichts zeichnen |
| `ctx.roundRect` steht nicht zur Verfügung | die Ausnahme fangen und die Zone **rechteckig** füllen; die Fläche ist wichtiger als die Ecke |

## Nicht selbst entscheiden – STOPP und fragen
- **Verbot – keinen Wert hart hinschreiben.** Kein `40`, kein `#FF4040`, kein `rgba(0,0,0,0.7)`.
  Der Radius kommt aus `zone.deko.radius`, die Farbe aus `loeseFarbe(marke, rolle)`. `marke.radien`
  wird in dieser Datei überhaupt nicht gelesen.
- **Verbot – keinen Verlauf umdeuten.** Die Richtungstabelle oben ist an den echten `scrim`-Daten
  geprüft; sie wird nicht „intuitiver" gemacht.
- **Verbot – statischen Text nicht selbst zeichnen** (kein eigenes `fillText`, kein eigener
  Umbruch). **Weicht die tatsächliche Signatur von M4-20 von der oben ausgeschriebenen ab, ist das
  ein Vertragsfehler: melden und NICHT eigenmächtig anpassen** – und die Logik erst recht nicht
  kopieren.
- **Verbot – die Akzent-Ersetzung nicht hier bauen.** Die `Aktion` wird **durchgereicht**, nicht
  ausgewertet: kein `aktion.akzentfarbe` in dieser Datei, kein Vergleich gegen `'akzent'`, kein
  Vertauschen von `deko.füllungFarbRolle` oder einer Verlaufs-Rolle vor dem Aufruf. Die Ersetzung
  sitzt in M4-18 und nirgends sonst (TK 9.10.9: „Es gibt genau eine Auflösungsstelle"). Auch der
  Verlauf ist **kein** Sonderfall: „Auch `deko.verlauf` (`vonFarbRolle`/`bisFarbRolle`) läuft durch
  dieselbe Funktion." (TK 9.10.9)
- **Offen: Wo `marke.schatten` überhaupt angewendet wird.** Die `Marke` führt
  `schatten: { versatzY: 4, weichzeichnen: 8, farbe: "#0000001A" }` (TK 9.11.2), aber **kein** Feld
  des Zonen-Modells verlangt einen Schatten, und keine der drei eingebauten Vorlagen nennt einen.
  Diese Funktion zeichnet deshalb **keinen** – ein pauschaler Schatten unter jeder dekorativen
  Fläche säße auch unter der vollflächigen `hintergrund`-Zone (unsichtbar) und unter dem `scrim`
  (als harte Kante quer durchs Bild). Ob `schatten` ein noch fehlendes Zonen-Feld ist, ein Rest aus
  dem Website-Token-Export oder für den Vorlagen-Editor gedacht ist, ist **nicht hier** zu
  entscheiden: melden.
- **Offen: Ob eine dekorative Zone eine Kontur (Rand/Strich) haben können soll.** Das Zonen-Modell
  kennt nur Füllung, Radius, Verlauf und statischen Text – **keine** Strichfarbe und keine
  Strichstärke. Reicht das für die geplanten eigenen Vorlagen nicht, ist das eine Erweiterung des
  geteilten Datenmodells (M4-01) und keine lokale Zutat: **kein** `strokeRect` ohne Vertragsfeld.

## Definition of Done

**Ohne Browser prüfbar** (Vitest, `ctx` als Aufzeichnungs-Doppel; `createLinearGradient` liefert ein
Doppel, das seine `addColorStop`-Aufrufe mitschreibt):

- [ ] Zone `hintergrund` der eingebauten Vorlagen (`0, 0, 1920, 1080`, Füllung `flaecheDunkel`,
      kein Radius) → genau ein `rect(0, 0, 1920, 1080)` und ein `fill()`, **kein** `roundRect`,
      **kein** Verlauf, **kein** `fillText`
- [ ] Zone `scrim` der Vorlage „Vollbild" (`0, 432, 1920, 648`, `richtung: unten`) →

      Stopp 1 die aufgelöste `scrimEnde`-Farbe
- [ ] Dieselbe Zone mit `richtung: oben` → `createLinearGradient(0, 1080, 0, 432)`;
      mit `rechts` → `(0, 432, 1920, 432)`; mit `links` → `(1920, 432, 0, 432)`
- [ ] Zone `preis` der Vorlage „Vollbild" (`1300, 660, 524, 150`, `radius: 40`) →
      `roundRect(1300, 660, 524, 150, 40)` – der Wert bleibt ungedeckelt, weil
      `min(524, 150) / 2 = 75` größer ist
