### Issue M4-19: [template-canvas] Text-Überlauf-Kaskade umbrechen, verkleinern, kürzen

## Ziel (in einem Satz)
Ein Text und die Parameter seiner Zone ergeben deterministisch die fertigen Zeilen und die gewählte
Schriftgröße – nach der verbindlichen Reihenfolge umbrechen → verkleinern → kürzen, ohne selbst zu
zeichnen.

## Modul & Datei
- Modul: `template-canvas` (Renderer)
- Datei: `src/renderer/template-canvas/text-kaskade.ts`
- Vertrag: Technisches Konzept **9.10.6** (Quelle der Wahrheit), **9.11.1** Punkt 6 (woher die
  Parameter kommen), **9.10.3** Punkt 5 (Determinismus)
- Prozess/Speicher: P2, P3, P4, P5; kein Speicher, keine Nebenwirkung

## Warum das im Gesamtsystem wichtig ist
Jeder Text im System läuft durch diese Funktion: Überschrift, Beschreibung, Preis und CTA in den
Segmenten **und** im Band. Sie entscheidet, ob ein langer Aktionstitel elegant zweizeilig steht, ob
er kleiner gesetzt wird oder ob am Ende ein „…" steht. Und sie entscheidet es **einmal** – dasselbe
Ergebnis geht in die Live-Vorschau des `action-editor`, in die Thumbnails, in den `preview-player`
und als PNG in den finalen Render.

Drei lokale Fehlentscheidungen wären teuer:

**Die Reihenfolge.** Wer zuerst verkleinert und dann umbricht, bekommt bei denselben Daten ein
anderes Bild – kleinere Schrift, wo eine zweite Zeile gereicht hätte. Auf einem Fernseher, der aus
mehreren Metern Entfernung gelesen wird, ist das der Unterschied zwischen lesbar und unlesbar.

**Die Nichtdeterminiertheit.** Jede Abhängigkeit von etwas anderem als den Eingabewerten – ein
zweiter Messkontext, ein Zwischenspeicher, eine Zufallsentscheidung bei Gleichstand – bricht die
Zusage „gleiche Eingabe → gleiches Bild". Weil Vorschau und Render dieselbe Funktion benutzen, fällt
so ein Drift **nirgends** auf, bis der Stick im Fernseher steckt.

**Die Messung.** Textbreiten hängen an der geladenen Schrift. Wird mit einer Ersatzschrift gemessen
(weil die Marken-Schriften noch nicht bereitstehen, M4-16) oder auf einem anderen Kontext als dem,
auf dem später gezeichnet wird, passt der Umbruch nicht zum gezeichneten Text – Zeilen ragen aus der
Zone oder brechen zu früh.

## Signatur (verbindlich – NICHT ändern)
```ts
// src/renderer/template-canvas/text-kaskade.ts

export const ZEILENHOEHE_FAKTOR = 1.2
// Zeilenhöhe = Schriftgröße × ZEILENHOEHE_FAKTOR. Diese Konstante ist die EINZIGE Wahrheit über den
// Zeilenabstand: M4-20 muss sie importieren und für den Zeilenvorschub beim Zeichnen benutzen.
// Rechnet die Kaskade mit 1.2 und das Zeichnen mit einem anderen Wert, ragt der Text aus der Zone.

export interface KaskadenEingang {
  text: string
  breite: number      // Zonenbreite in px   – zone.rahmen.breite
  höhe: number        // Zonenhöhe in px     – zone.rahmen.höhe
  größeMax: number    // zone.text.größeMax
  größeMin: number    // zone.text.größeMin
  maxZeilen: number   // zone.text.maxZeilen
}

export interface KaskadenErgebnis {
  zeilen: string[]    // fertige Zeilen, in Zeichenreihenfolge; keine führenden/folgenden Leerzeichen
  größe: number       // gewählte Schriftgröße in px, ganzzahlig, immer in [größeMin, größeMax]
  gekürzt: boolean    // true, wenn Stufe 3 („…") gegriffen hat
}

export function passeTextEin(
  eingang: KaskadenEingang,
  messeBreite: (text: string, größe: number) => number,
): KaskadenErgebnis
// Reine Funktion: kein Canvas, kein DOM, keine Nebenwirkung. Gemessen wird ausschließlich über den
// übergebenen Messer.
```

## Fremde Funktionen, die du aufrufst
**Keine.** Diese Funktion ruft nichts auf außer dem übergebenen `messeBreite`. Sie importiert weder
`schriften.ts` noch `farben.ts` noch den `Vorlage`-Typ – die Zonenparameter kommen als einfache
Zahlen herein, damit die Kaskade ohne Canvas und ohne Vorlagendaten testbar bleibt.

**Vertrag für den Messer – der Aufrufer (M4-20) MUSS ihn genau so bilden:**
```ts
// im aufrufenden Modul M4-20, NICHT hier:
const messeBreite = (text: string, größe: number): number => {
  ctx.font = schriftKurzform(schrift, größe)   // M4-16: (schrift: Schrift, größePx: number) => string
  return ctx.measureText(text).width
}
// Bedingungen (Verletzung macht das Ergebnis wertlos):
//  - ctx ist DERSELBE Kontext, auf dem anschließend gezeichnet wird – nie ein zweiter Kontext,
//    nie ein Hilfs-Canvas mit anderen Einstellungen.
//  - Die Marken-Schriften sind bereits geladen (M4-16: sindSchriftenBereit() === true).
//  - schrift stammt aus M4-18: loeseSchrift(marke: Marke, rolle: SchriftRolle): Schrift
```

**Weicht die tatsächliche Signatur von der hier ausgeschriebenen ab, ist das ein Vertragsfehler:
melden und NICHT eigenmächtig anpassen.** Wer den Aufruf still an eine abweichende Signatur
anpasst, macht aus einem Vertragsfehler einen unsichtbaren – und dieselbe Funktion existiert dann in
zwei Fassungen im Projekt.

## Eingang → Ausgang
| Eingang | Bedeutung | Grenzen/Validierung |
|---|---|---|
| `text` | der gebundene Aktionstext (Titel, Beschreibung, Preis, CTA) | beliebiger Text; leer/nur Leerraum ist gültig und liefert `zeilen: []` |
| `breite` | verfügbare Breite in px | endlich, > 0; sonst wirft die Funktion |
| `höhe` | verfügbare Höhe in px | endlich, > 0; sonst wirft die Funktion |
| `größeMax` | Startgröße der Kaskade | ganzzahlig, > 0, ≥ `größeMin`; sonst wirft die Funktion |
| `größeMin` | Untergrenze der Kaskade | ganzzahlig, > 0; sonst wirft die Funktion |
| `maxZeilen` | Maximal-Zeilenzahl der Zone | ganzzahlig, ≥ 1; sonst wirft die Funktion |
| `messeBreite` | misst die Breite eines Textes bei einer Größe | Funktion; muss für gleiche Argumente gleiche Werte liefern |

Ausgang bei Erfolg: `{ zeilen, größe, gekürzt }`.
Ausgang bei Fehler: **keine** `Ergebnis<T>`-Hülle – bei unzulässigen Zonenparametern wirft die
Funktion (Begründung s. Festlegung 8).

## Verbindliche Invarianten (wörtlich – Verletzung = Issue nicht erfüllt)
- „Passt ein Text nicht in seine Zone, greift **genau diese Reihenfolge**:
  1. **Umbrechen** bis zur zonenspezifischen Maximal-Zeilenzahl.
  2. **Schriftgröße stufenweise verkleinern** bis zu einer definierten Untergrenze.
  3. **Kürzen mit „…"** als letzter Ausweg." (TK 9.10.6)
- „Die Kaskade ist **verbindlich und deterministisch** – nie ein zerstörtes Layout, nie ein
  zufälliges Ergebnis. Die Zonen-Parameter (Maximal-Zeilen, Schriftgrößen-Bereich) kommen aus der
  `Vorlage` (Datenmodell: 9.11)." (TK 9.10.6)
- „**`text.*` speist die Überlauf-Kaskade** (9.10.6): `maxZeilen` = Stufe 1 (Umbruch),
  `größeMax`→`größeMin` = Stufe 2 (Verkleinern), danach Stufe 3 („…")." (TK 9.11.1, Punkt 6)
- „**Gleiche Eingabe → gleiches Bild.** Keine Zeit-, Zufalls- oder Zustandsabhängigkeit (keine
  Animation, kein Datum, kein `Math.random`)." (TK 9.10.3, Punkt 5)
- „Es gibt **keinen zweiten Zeichenpfad.** Anzeige und Export stammen immer aus **demselben** Aufruf
  – sonst driften Vorschau und Endvideo auseinander." (TK 9.10.1)

## Der Ablauf (verbindlich, genau so und in dieser Reihenfolge)
1. **Vorbereitung.** `text` an Leerraum in Wörter zerlegen; Folgen von Leerraum (Leerzeichen,
   Tabulator, Zeilenumbruch) zählen als **ein** Trenner. Ergibt das keine Wörter, ist das Ergebnis
   `{ zeilen: [], größe: größeMax, gekürzt: false }`.
2. **Stufe 1 + 2 als eine Schleife:** für `größe` von `größeMax` in **1-px-Schritten** abwärts bis
   einschließlich `größeMin`:
   a. **Greedy-Umbruch bei dieser Größe:** Wörter der Reihe nach an die aktuelle Zeile hängen,
      solange `messeBreite(zeile + ' ' + wort, größe) <= breite`; sonst neue Zeile beginnen.
   b. **Passt** das Ergebnis, wenn **alle drei** Bedingungen gelten:
      `zeilen.length <= maxZeilen` **und**
      `zeilen.length * größe * ZEILENHOEHE_FAKTOR <= höhe` **und**
      jede einzelne Zeile misst `<= breite`.
   c. Passt es, sofort zurückgeben: `{ zeilen, größe, gekürzt: false }`.
3. **Stufe 3 („…"), nur wenn keine Größe gepasst hat**, und ausschließlich bei `größeMin`:
   a. Umbruch wie 2a bei `größeMin`.
   b. `maxZeilenEffektiv = min(maxZeilen, floor(höhe / (größeMin * ZEILENHOEHE_FAKTOR)))`.
      Ist `maxZeilenEffektiv < 1`, ist das Ergebnis `{ zeilen: [], größe: größeMin, gekürzt: true }`
      – die Zone ist für eine Zeile zu niedrig, es wird nichts gezeichnet statt über den Rand hinaus.
   c. Auf `maxZeilenEffektiv` Zeilen abschneiden. Von der **letzten** verbleibenden Zeile
      **codepoint-weise von hinten** entfernen, bis `messeBreite(rest + '…', größeMin) <= breite`;
      dann `…` anhängen. Ergebnis `gekürzt: true`.
   d. Passt selbst `…` allein nicht in die Breite, lautet die letzte Zeile genau `…`.

## Festlegungen dieses Issues (verbindlich, keine Zitate)
1. **Wortbasiert, keine Silbentrennung.** Ein einzelnes Wort, das allein zu breit ist, wird **nicht**
   getrennt; es löst über 2b Stufe 2 und schließlich Stufe 3 aus. Begründung: Korrekte deutsche
   Silbentrennung braucht ein Wörterbuch; eine selbstgebaute Regel trennt irgendwann falsch, und ein
   falsch getrenntes Wort auf einem Werbebildschirm ist schlimmer als ein kleiner gesetztes.
2. **1-px-Schritte beim Verkleinern.** Gröbere Schritte springen sichtbar zwischen zwei Aktionen mit
   ähnlich langen Titeln; feinere Schritte kosten zusätzliche Messdurchläufe ohne erkennbaren
   Gewinn. Entscheidend ist allein, dass die Regel **deterministisch** und überall dieselbe ist.
3. **Gemessen wird ausschließlich über `messeBreite`** – auf demselben Kontext, auf dem anschließend
   gezeichnet wird (s. Messer-Vertrag oben). Diese Datei erzeugt selbst **kein** Canvas und ruft
   **nie** `measureText` auf.
4. **Der vertikale Test in 2b ist Pflicht.** Ohne ihn kann ein Text horizontal passen und trotzdem
   unten aus der Zone laufen – TK 9.10.6 verspricht aber „nie ein zerstörtes Layout".
5. **`ZEILENHOEHE_FAKTOR = 1.2`** ist ein üblicher typografischer Grundwert und liegt als **eine**
   exportierte Konstante an **einer** Stelle, damit Kaskade und Zeichnen niemals auseinanderlaufen
   können.
6. **„…" ist genau ein Zeichen (U+2026),** nicht drei Punkte. Drei Punkte messen anders und sehen in
   den Marken-Schriften anders aus; die Kaskade würde mit `...` gemessen und mit `…` gezeichnet
   werden können – ein lautloser Unterschied.
7. **Gekürzt wird über Codepoints** (`Array.from(text)`), nie über `String.prototype.charAt`/
   Index-Zugriff. Sonst zerschneidet der Schnitt Surrogatpaare (Emoji) und erzeugt ein
   Ersatzzeichen-Kästchen im Endvideo.
8. **Keine `Ergebnis<T>`-Hülle, sondern `throw` bei unzulässigen Zonenparametern.** TK 9.1.1 gilt
   laut eigenem Wortlaut für „**jede** Operation über die Renderer↔Main-Grenze"; diese Funktion bleibt im
   Renderer, und `zeichneSegment` liefert laut TK 9.10.1 ein `SegmentBild` ohne Hülle – ein
   `Ergebnis` käme nirgends an. Unzulässige Parameter sind außerdem kein Nutzerfehler, sondern
   kaputte Vorlagendaten.
9. **Kein Zwischenspeicher für Messwerte** über Aufrufe hinweg. Ein solcher Cache lieferte nach
   einem Schriftwechsel alte Breiten; die paar Messungen je Aufruf sind billig.
10. **`gekürzt` wird zurückgegeben, aber hier nicht ausgewertet.** Ob die Oberfläche daraus eine
    Warnung macht, entscheiden die aufrufenden Module – diese Funktion meldet nur die Tatsache.

## Fehlerpfade (vollständig)
| Situation | Code | Verhalten |
|---|---|---|
| `breite` oder `höhe` ≤ 0 bzw. nicht endlich | – (kein IPC-Fehlercode; die Funktion überschreitet keine IPC-Grenze) | wirft; Meldung nennt das Feld und den Wert |
| `größeMax`/`größeMin` nicht ganzzahlig, ≤ 0 oder `größeMax < größeMin` | – | wirft; **kein** stilles Runden oder Vertauschen (zwei Stellen, die unterschiedlich runden, brechen die Pixelgleichheit) |
| `maxZeilen` < 1 oder nicht ganzzahlig | – | wirft |
| `text` leer oder nur Leerraum | – | `{ zeilen: [], größe: größeMax, gekürzt: false }` – **kein** Fehler; ob die Zone dann leer bleibt oder ganz entfällt, entscheidet `wennLeer` beim Aufrufer |
| Kein Umbruch passt, auch bei `größeMin` nicht | – | Stufe 3 (Kürzen), `gekürzt: true` |
| Zone zu niedrig für eine Zeile bei `größeMin` | – | `{ zeilen: [], größe: größeMin, gekürzt: true }` |

## Nicht selbst entscheiden – STOPP und fragen
- **Die eingebauten Vorlagen sind auf den vertikalen Test noch nicht abgestimmt.** Zwei Beispiele
  aus TK 9.11.1: Die Zone `titel` der Band-Vorlage „Band-Standard" ist **72 px** hoch bei
  `64 → 44 px, max 1 Zeile` – eine Zeile mit 64 px braucht aber `64 × 1,2 = 76,8 px`, sodass die
  Kaskade auf 60 px verkleinert. Die Zone `ueberschrift` der Vorlage „Vollbild" ist **190 px** hoch
  bei `96 → 56 px, max 2 Zeilen`; zwei Zeilen zu 96 px bräuchten 230 px, also erreicht ein
  zweizeiliger Titel höchstens 79 px. Das Verhalten der Funktion ist damit korrekt und beabsichtigt,
  aber die Zahlen der Vorlagen (M4-02) treffen erkennbar eine andere Annahme über den Zeilenabstand.
  Ob die Zonenhöhen angepasst werden oder es bei der automatischen Verkleinerung bleibt, ist eine
  **Entscheidung nach dem ersten echten Render** – TK 9.11.1 nennt die Werte selbst „nach dem ersten
  echten Render leicht nachjustierbar". **Ändere hier nichts daran**: den vertikalen Test nicht
  weglassen, den Faktor nicht je Zone variieren, keine Sonderregel für einzeilige Zonen einbauen.
  Melde es und lass entscheiden.
- **Harte Zeilenumbrüche im Nutzertext.** Diese Funktion behandelt `\n` wie jeden anderen Leerraum
  (Festlegung/Ablauf Schritt 1). Ob der `action-editor` (M5) mehrzeilige Eingaben überhaupt zulässt
  und ob ein vom Nutzer gesetzter Umbruch dann **erzwungen** werden soll, ist nirgends festgelegt.
  Nimm die Antwort **nicht** durch eine eigene Sonderbehandlung vorweg – eine erzwungene Zeile würde
  gegen `maxZeilen` laufen und die Kaskade in einen Zustand bringen, den TK 9.10.6 nicht beschreibt.
  Vorlegen, sobald die Frage in M5 auftaucht.
- **Verbote (nicht verhandelbar, hier nur zur Klarstellung):** keine Silbentrennung, kein zweiter
  Messkontext, keine Umstellung der drei Stufen, kein Zwischenspeicher, kein Zeichenbefehl in dieser
  Datei.

## Definition of Done
- [ ] Reihenfolge nachweisbar: ein Text, der bei `größeMax` in `maxZeilen` passt, wird **nicht**
      verkleinert; einer, der erst kleiner passt, wird verkleinert und **nicht** gekürzt; gekürzt
      wird ausschließlich bei `größeMin`
- [ ] Die gelieferte `größe` ist ganzzahlig und liegt immer in `[größeMin, größeMax]`
- [ ] Zwei identische Aufrufe liefern identische Ergebnisse; der Testmesser protokolliert die
      Aufrufe und beweist, dass keine Entscheidung von etwas anderem als Eingabe und Messwert abhängt
- [ ] Ein einzelnes überlanges Wort wird nie zerlegt, sondern verkleinert und zuletzt mit `…` gekürzt
- [ ] Die Kürzung endet auf genau einem `…` (U+2026); die Zeichenkette `...` kommt in der Datei nicht
      vor
- [ ] Kürzen an einer Surrogatpaar-Grenze (Emoji) erzeugt kein zerschnittenes Zeichen
- [ ] Der vertikale Test greift: mit `höhe`, die nur eine Zeile zulässt, entsteht bei zweizeiligem
      Text nachweislich eine kleinere Größe bzw. eine Kürzung, nie zwei Zeilen
