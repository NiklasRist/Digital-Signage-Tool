### Issue M10-02: [shared] Bildplan – die kürzeste Folge, die die Bewegung exakt abspielt

## Ziel (in einem Satz)
Aus der Bildzahl eines Segments entsteht der **kleinste** Plan aus Frames und Wiederholungen, der
die Bewegung **bildgenau** abspielt – die Grundlage dafür, dass ein 45-s-Segment mit Schleife nicht
1350 Bilder kostet.

## Modul & Datei
- Modul: geteilter Bereich (Plan entsteht im Renderer, Main liest ihn)
- Datei: `src/shared/bildplan.ts` (neu)
- Vertrag: Technisches Konzept **9.16.4**
- Anforderung: Anforderungsdokument **4.10**, **FA-25**

## Warum das im Gesamtsystem wichtig ist
Die Bewegung läuft als Schleife über die **ganze** Segmentdauer. Ohne Zusammenfassung wären das bei
45 s **1350** gezeichnete Frames – unbezahlbar an Zeit und Speicher. Der Plan ist die Stelle, an der
„läuft die ganze Zeit" und „kostet nur 60 Bilder" zusammenkommen: Er wiederholt **denselben** Frame,
statt ihn neu zu zeichnen. Wird er falsch, stimmt die Dauer nicht mehr – und die Dauer ist die eine
Zusage, die dieses Projekt nicht verhandelt.

## Signatur (verbindlich – NICHT ändern)
```ts
export interface Lauf {
  erstesBild: number      // Index in bildNummern
  anzahl: number          // Anzahl aufeinanderfolgender Bilder ab erstesBild
  wiederholungen: number  // ≥ 1
}

export interface Rahmenplan {
  /** eindeutige Segment-Bildnummern, in Reihenfolge des ersten Auftretens */
  bildNummern: number[]
  /** Abspielreihenfolge; Summe anzahl × wiederholungen = bilderGesamt */
  laeufe: Lauf[]
}

export function rahmenplan(
  effekte: EffektSatz | null | undefined,
  bilderGesamt: number,
): Rahmenplan | null

/** Prüfhilfe: die expandierte Folge von Segment-Bildnummern. Länge MUSS bilderGesamt sein. */
export function expandiere(plan: Rahmenplan): number[]
```

**Warum `| null` (Nachtrag beim Bau, 09.11.2026):** Der Vertrag sagt „**Ohne Effekt gibt es keinen
Plan**" (TK 9.16.4). Ein leerer Plan wäre die schlechteste Antwort: Er sähe aus wie ein Plan und
ergäbe **null** Bilder – ein Aufrufer, der die Regel nicht kennt, bekäme ein schwarzes Segment statt
eines Standbilds. `null` ist die einzige Antwort, die man nicht übersehen kann.

## Eingang → Ausgang
| Eingang | Bedeutung | Grenzen/Validierung |
|---|---|---|
| `effekte` | Effekt-Satz der Aktion | `null`/`undefined`/leer → `null` (kein Plan); Staerke 0 zählt als aus |
| `bilderGesamt` | `dauer × 30` | `≤ 0` → `null` |

Ausgang bei Erfolg: `Rahmenplan`, beide Invarianten erfüllt.
Ausgang bei Fehler: `null` – kein Effekt oder keine Bilder; der Aufrufer nimmt den Einzel-PNG-Weg.
Die Funktion wirft nicht.

## Verbindliche Invarianten (wörtlich – Verletzung = Issue nicht erfüllt)
- „`Σ anzahl × wiederholungen = dauer × 30` – **exakt**, ohne Rundung und ohne Toleranz. Damit ist die
  Dauer unantastbar." (TK 9.16.4)
- „Für jedes Bild `i` ist das expandierte PNG **genau das** Bild, das `zeichneSegment(…,
  effektZustand(…, i, …))` liefert." (TK 9.16.4)
- „Er ist die **kürzeste** Darstellung, die beide Invarianten erfüllt: gleiche aufeinanderfolgende
  Zustände werden zusammengefasst, eine am Ende erkannte Periode als `wiederholungen`." (TK 9.16.4)
- „**Ohne Effekt gibt es keinen Plan** – dann bleibt es beim einzelnen `png` (9.2.2)." (TK 9.16.4)

## Fehlerpfade (vollständig)
| Situation | Verhalten |
|---|---|
| `effekte` fehlt / `null` / `{}` | `null` – **kein** Plan |
| alle Einträge `staerke: 0` | `null` – kein Plan |
| `bilderGesamt ≤ 0` | `null` |
| Plan mit ungleicher Bildzahl | **Aufrufer** wirft bzw. meldet `ungueltiges_element` (M10-06) |
